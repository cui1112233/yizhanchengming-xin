# 00 · 产品定义

## 一句话定义

**doubao-relay 是一个本机桌面客户端,把你电脑上已登录的豆包账号,通过 HTTP API 封装成一个可供自动化调用的生图/生视频服务。**

## 为什么存在

豆包(字节跳动 AI 产品)目前**没有对个人用户开放官方 API**。要用豆包的 Seedream / Seedance 系列模型做批量化工作,只有两条路:

1. 手动在豆包客户端里一张张点
2. 通过模拟客户端操作对接

doubao-relay 走第 2 条,把"模拟客户端操作"工程化、封装成稳定的 HTTP 接口,让任何能发 HTTP 请求的程序(脚本、工作流、Agent)都能调用。

## 目标用户

| 用户 | 典型场景 |
|---|---|
| 个人开发者 | 用脚本批量生成图像素材 |
| AI Agent 开发者 | 让 Agent 调用豆包能力做图像/视频输出 |
| 内容工作室 | 用自己的多个豆包账号并发出图 |
| 测试工程师 | 对豆包的模型做 A/B 对比测试 |

**用户必须自己拥有并已登录豆包账号**。本产品不托管账号、不代理账号登录。

## 使用场景

### 场景 A:单次生图

```
Agent 代码:
  response = POST /api/v1/generate { account: "张三", type: "image",
                                     prompt: "...", model_name: "Seedream 5.0 Pro" }
  task_id = response.task_id
  while not completed:
      sleep 3
      status = GET /api/v1/tasks/{task_id}
  download = GET /api/v1/tasks/{task_id}/download/0
```

### 场景 B:批量视频生成

```
10 条视频任务,每条用不同的 prompt
→ 全部 POST /api/v1/generate 排队
→ 中转程序按账号串行、全局最多 3 个并发
→ 完成后统一下载
```

### 场景 C:多账号并发(高级)

```
用户 A 账号(标准套餐)+ 用户 A 账号 2(高级套餐)
→ 不同任务指定不同 account
→ 中转程序对不同账号并发,同账号串行
```

### 场景 D:观察豆包操作过程

```
打开 Tauri 窗口 → 看账号列表 → 看当前任务进度
→ 发现卡住 → 手动在豆包 UI 里介入
→ 完成后中转程序继续识别结果
```

## 非目标(明确不做的事)

| 不做 | 理由 |
|---|---|
| ❌ 不代理豆包登录(不收密码) | 安全风险 + 违反豆包 ToS |
| ❌ 不自动创建豆包账号 | 账号权属归用户 |
| ❌ 不维护账号池自动轮询 | 触发风控,用户体验差,见 DECISIONS D1 |
| ❌ 不做 web 版 UI(需另开浏览器访问) | 用户选择了 Tauri 桌面客户端 |
| ❌ 不保存 prompt 做二次分析 | 用户隐私 |
| ❌ 不上传任何数据到任何服务器 | 全本地运行 |
| ❌ 不支持豆包以外的 AI 产品 | 另开项目 |
| ❌ 不做 Linux 版 | 豆包桌面端没 Linux 版 |
| ❌ 不做画布式 UI、项目管理、素材库 | 这是沈浪的业务,我们不复制 |
| ❌ 不内嵌一个"调用方"做画布/聊天 | 职责分离,我们只是 relay |

## 边界情形

### 账号同名

两个豆包账号都叫"张三"。v0.1 **不支持**,会在账号列表里标注冲突,API 调用会返回 `account_ambiguous` 错误。用户需要在豆包里改名或自己识别。

### 账号未登录

API 调用指定的 account 在豆包里不存在/未登录 → 返回 `account_not_found` 错误,**不自动尝试登录**。

### 豆包正在用

用户正在用豆包聊天时提交生成请求 → 中转程序**仍然接受**,但会在 UI 弹警告"任务进行中,请勿在同一对话里打字"。见 shenlang-analysis/08-anti-conflict.md。

### 豆包升级 UI

豆包升级导致 DOM 结构变化 → 中转程序识别失败,API 返回 `doubao_ui_changed`,**需要等 doubao-relay 发新版适配**。保留一个"UI 版本自检"命令,在启动时跑一遍关键 selector 判断兼容性。

### 账号配额用完

豆包返回"配额用完"或"今日次数耗尽" → API 返回 `account_quota_exhausted`,**不自动切别的账号**(符合 D1)。

## 价值与成本

### 价值(用户视角)

- 把豆包能力接入到你自己的工作流,无需手工点击
- 完整的多账号 + 多任务并发调度
- 本地运行,不经手第三方,privacy by default
- 一次性付出(豆包订阅)覆盖所有调用,不像 OpenAI 按 token 计费

### 成本(用户视角)

- 用户的豆包账号配额按豆包定价消耗
- 中转程序需要用户保持豆包桌面端运行
- 一台电脑同时服务多少调用取决于用户账号数和豆包限速
- **违反豆包 ToS 风险**:用户账号可能被封(风险由用户承担)

### 法律边界

**本产品属于典型"用户账号代操作"工具**。使用本产品可能违反豆包的《用户协议》。本产品:
- 不绕过豆包的鉴权
- 不盗取账号信息
- 不逆向豆包的后端 API
- 仅在用户已登录的豆包客户端上做前端操作

**账号被封等后果,责任归用户**。本产品需在显著位置标注该免责声明。

## 产品哲学

**doubao-relay 是"工具",不是"产品"**。
- 不做 onboarding wizard
- 不做付费订阅
- 不做用户统计
- UI 简单到够用就行
- 开源代码可审计

目标用户是技术人员,不是普通消费者。
