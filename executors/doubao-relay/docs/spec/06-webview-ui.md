# 06 · WebView UI 规格

## 整体风格

**极简工具风**,不是消费应用。设计原则:
- 一页主内容,左侧 slim 导航
- 单色主色(灰 + 一个品牌强调色,如 #3B82F6)
- 深浅主题跟系统
- 中文,无图标文字(可带少量图标)
- 字体系统默认(macOS SF, Windows Segoe UI)

## 页面结构

```
┌─────────────────────────────────────────────────┐
│  doubao-relay                           ⚙ ✕    │  顶栏(窗口标题)
├────────┬────────────────────────────────────────┤

│ 任务   │          主内容区                      │
│ 日志   │                                        │
│ 设置   │                                        │
```

- 左侧 180px 固定宽
- 主内容区自适应
- 底部状态栏显示豆包连接状态 + HTTP server 状态

## 页面 1 · 账号

**路径**:默认页 `/`

**内容**:

```
账号                                   [刷新] [重连豆包]

当前账号: 她是翻哥 (体验套餐)

┌─────────────────────────────────────────┐
│ 名字           套餐        状态          │
├─────────────────────────────────────────┤
│ 她是翻哥 ★    体验套餐    当前           │
│ 李四           高级套餐    [切换]        │
│ 王五           标准套餐    [切换]        │
└─────────────────────────────────────────┘

共 3 个已登录账号。
```

**交互**:
- "刷新"按钮 → `invoke('account.refresh')`
- "重连豆包"按钮 → `invoke('doubao.reconnect', { force: false })`
- "切换"按钮 → 确认弹窗 → `invoke('account.switch', { target })`
- 当前账号前面有 ★ 标记
- 同名账号用 ⚠ 标记并显示"同名,不支持通过 API 调用"

**状态**:
- 豆包未连 → 全页显示空状态 + "连接豆包"按钮
- 加载中 → 骨架屏
- 账号为空 → "豆包尚未登录任何账号,请先在豆包中登录"

## 全局组件

### 顶栏(Tauri 窗口)
- 原生 Tauri window(非 custom chrome,保持系统风格)
- 标题"doubao-relay"

### 侧边导航
- 180px 固定宽
- 4 个主入口:账号 / 任务 / 日志 / 设置
- 底部状态栏:
  - "● 豆包"— 绿(已连)/ 红(未连)/ 黄(重连中)
  - "● API"— 绿(监听中)/ 红(未启动)

### 全局提示 (toast)
- 右下角弹出
- 任务完成、账号切换、错误等场景
- 自动 3 秒消失(错误 persist 直到点关)

### 空状态
- 账号为空、任务为空、日志为空都要有专门空状态画面
- 空状态里带"下一步建议"按钮

### 加载状态
- 骨架屏(账号/任务列表)
- 转圈(切换账号、提交任务等变更操作)

### 错误弹窗
- 全屏错误用居中对话框
- 字段错用 inline 红字 + 下方

## 快捷键

| 键 | 行为 |
|---|---|
| `Cmd/Ctrl + N` | 新建任务 |
| `Cmd/Ctrl + R` | 刷新账号列表 |
| `Cmd/Ctrl + ,` | 打开设置 |
| `Cmd/Ctrl + L` | 跳日志页 |
| `Cmd/Ctrl + K` | 搜索任务(按 prompt / ID) |

## 响应式

**不做响应式**。固定最小宽度 900px,高度 600px。全屏最大化支持。

## 实现技术

- 不用 React 全家桶,**用 Preact + Signals**(体积小,渲染快)
- 或用原生 Web Components + lit-html(更轻)
- 构建:Vite + TypeScript
- CSS:原生 CSS(用 CSS Variables 实现主题)或 Pico.css 极小 CSS framework

**不选择 React 的理由**:单文件复杂度不高,React 带来的 bundle size 不值。
