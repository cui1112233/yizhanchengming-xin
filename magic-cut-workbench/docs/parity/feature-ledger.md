| 状态 | 大白话解释 | 可以使用的证据 |

| `已完成` | 当前定义的功能已经有前后端、测试和真实运行结果 | 源码 + 自动测试 + 4040 实测 |
| `部分完成` | 已有界面或底层代码，但还没有完整走通 | 源码或测试，缺真实结果 |

## 3. 当前完整度结论

- `已完成`：8 项。主要是入口、工程创建、基础导入/探测、基础时间线命令、自动保存和单二进制底座。
- `部分完成`：19 项。基础播放和导出闭环已经有真实运行结果，但多数功能仍只有底层、界面或流程中的一部分，不能当成原版等价功能。
- `未开始`：19 项。集中在字幕/音频/特效和各类业务工作流。
- 静态分析之外仍有 3 个高风险证据缺口：真实像素/弹窗、线上服务端契约、`mcengine` 精确行为。

因此，当前是“核心底座开发中”，不是“1:1 已完成”。下一步先纠正无独立登录页的会话交接和原版首页，再恢复原音/多音轨渲染及导出任务重启恢复。

## 5. 从现在开始的登记铁则

每次功能提交必须同时完成下面四件事：

1. 更新本表对应的 `MC-xxx` 行，不能只改状态而不写验证。
2. 在“已完成步骤登记”追加同一提交的功能、测试和真实结果。
3. 新功能必须至少有一条原版源码证据；原版证据不足就标 `证据不足`，不能猜成事实。
4. 只有真实文件落盘、真实任务恢复或真实页面交互成功，才写运行验收通过。

提交说明统一使用 `feat(magic-cut): ...`、`fix(magic-cut): ...` 或 `docs(magic-cut): ...`。不新建零散分支，不用 Actions 上传部署。
