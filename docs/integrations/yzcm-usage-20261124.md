# 个人中心：YZCM API 用量与实际扣费

基于 v88 维护线实现，交付前与最新 v88 合并，沿用 Go embed 发布路径。

## 已实现

- 按认证后的实际请求发起人记账；共享管理员 Key 不改变成员归属。
- 保存请求 ID、成员、功能、凭据指纹及响应状态；不保存 Key、提示词、图片或生成正文。
- 按请求 ID 和对应 Key 查询 YZCM 消费日志。以 quota 和公开换算参数计算账单金额，不采用供应商 usage.cost_rmb。
- MySQL 8800402 迁移建立按成员/时间、待核账状态索引。每 20 秒单 Worker 查询，批次有界，失败轮转重试。
- 个人、团队成员汇总及最近 20 条明细接入真实账本；读取失败明确报错，未核到账单显示待核账。
- 北京时间日/月边界；费用展示保留实际为零和未知两种状态。
- 成员不能读取其他成员用量。读取时不回传凭据和完整上游响应。

## 范围与验证

仅覆盖接入后能够取得 YZCM 请求 ID 的文本、图片、音频请求；历史共享 Key 日志无法可靠补分到个人，异步视频最终结算另行接入。其他服务商及没有身份的后台请求不猜测归属。

已运行账单转换、共享 Key 成员隔离、失败与零扣费、响应内容保持、账本查询、成员接口鉴权和迁移相关回归。前端构建已通过；最终代码仍需本地 4001 运行验收后才部署。

## YZCM API 配套查询

同目录 patch 为现有 GET /api/log/token 增加可选 request_ids 过滤（最多 50 个），查询条件同时绑定当前 Token ID，不新增管理员权限。

未应用补丁的旧服务会忽略过滤参数；客户端仍严格筛选请求 ID，防止混入其他成员的日志，但只能在旧服务返回的最近记录中核账。生产高流量环境应先发布配套补丁。
