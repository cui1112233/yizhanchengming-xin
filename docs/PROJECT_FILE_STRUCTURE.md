# 项目文件结构与归档规则

## 目标

将正式源码、测试、文档、构建产物和本地运行数据的职责边界固定下来。目录调整必须保证 V88 Go embed 发布链路、各独立执行器和服务的运行边界不变。

## 顶层目录映射

| 路径 | 内容 | 约束 |
| --- | --- | --- |
| `backend/cmd/` | Go 可执行程序入口 | 一个子目录对应一个 Go 程序 |
| `backend/internal/` | Go 服务端业务源码及其 Go 单元测试 | `_test.go` 保持与被测 package 同目录，以支持同包白盒测试；禁止放运行数据和构建产物 |
| `backend/web/dist/` | Go embed 使用的前端构建产物 | 仅由构建脚本生成，禁止手工维护、禁止反向复制成源码 |
| `frontend/src/` | React 应用源码 | 按 `admin`、`user`、`shared` 等业务边界分层；暂存的相邻 `.test.*` 文件仅限依赖同模块源码的单元/source-contract 测试，后续逐模块迁移前须先改写路径与测试入口 |
| `frontend/e2e/` | 浏览器端到端测试 | 测试必须通过公开运行入口操作应用，不得被当作单元测试 |
| `frontend/public/` | 前端运行时静态资源及历史兼容页面 | 运行时资源，不是测试或构建输出目录 |
| `test/` | 当前 V88 跨模块契约、系统集成及根级回归测试 | 只放仍可在 Go-only V88 上验证的测试；不得引用已删除的根级 Node `app.js/routes/lib` |
| `tests/` | 目录结构检查和旧测试清单 | `legacy-node-tests.json` 是已停用旧 Node 主服务测试的索引，不作为可运行测试入口；新根级测试统一放入 `test/` |
| `executors/<name>/` | 独立执行器源码、依赖清单和本组件测试 | 各执行器自包含；测试使用 `test/` 子目录或 Go 同包 `_test.go` 约定，不跨执行器共享私有实现 |
| `services/<name>/` | 独立后台服务源码、依赖清单和本组件测试 | 服务自包含；当前 Browser Worker 使用 `test/` |
| `scripts/` | 构建、验证和批准的发布脚本 | 脚本不得把 Node/Docker 历史链路作为普通 V88 发布入口 |
| `docs/` | 当前有效架构、运行规则、执行记忆和项目规范 | 方案、库存档案与历史记录按主题子目录归档 |
| `_local-archive-20261028/` | 用户明确要求保留的本机临时副本和历史暂存 | `legacy-node-tests/` 存放已从活跃测试树移出的旧 Node 主服务测试，只作为历史证据，不作为运行入口或发布输入 |
| `.local-review/`、`.data-v88-review/` | 本地数据库、缓存、登录态及运行日志 | 运行数据，禁止迁移、清理或纳入源码重构 |
| `frontend/dist/`、`dist/`、`.release/`、`.direct-staging/` | 前端或发布构建产物/暂存 | 由工具生成；禁止当作源码，禁止结构整理时覆盖或删除 |

## 测试分类与命名

- Go 单元测试使用 `*_test.go`，与被测 package 同目录，保证 package、未导出符号和测试 fixture 语义一致。
- 前端纯逻辑/组件测试使用 `*.test.js`、`*.test.jsx`；迁移到集中目录时，必须同步修正源码导入、测试数据相对路径和所有脚本 glob。
- 读取源码文本、验证导入或检查构建配置的测试属于 source-contract 测试，命名为 `*.source.test.js`；不得误标成运行时集成测试。
- 服务/API 与跨模块测试放到所属模块的 `test/` 或仓库 `test/integration/`，不得放在生产源码目录中作为新文件。
- 浏览器端到端测试使用 `*.spec.js` / `*.spec.ts`，放在 `frontend/e2e/`。
- 测试临时数据写入系统临时目录；截图、日志和调试导出不得散落在仓库根目录。

## 迁移顺序

1. 先确认 Git 跟踪清单、当前工作区改动和模块依赖；不得重置、覆盖或批量清理用户文件。
2. 先收口测试命令和路径解析，再逐模块迁移测试；一次只迁移一个模块并运行其原有测试入口。
3. Go 同 package 测试不因物理分离要求跨 package 移动；若确需黑盒测试，新增独立外部测试 package，并保留必要的同包单测。
4. 只有确认没有运行时引用后，才可整理旧目录、历史脚本或构建产物；本地数据和归档内容不在本次源码迁移范围。
5. 每阶段运行对应单测、模块构建和路径引用检查；全量验证未完成前不得宣称结构重构完成。

## 新文件决策

新增前先分类：业务实现放所属模块源码目录；测试放其测试类别；项目规范放 `docs/`；批准的构建/发布逻辑放 `scripts/`；临时产物进入 `_local-archive-20261028/`；持久化运行数据只放现有本地数据目录。禁止为追求目录外观统一而破坏语言工具链约定。
