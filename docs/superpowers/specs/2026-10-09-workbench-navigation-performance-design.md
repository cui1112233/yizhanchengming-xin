# 工作台首次进入性能优化设计

## 目标

让“小说获取”“小说面板”“批量工厂”点击后先快速显示页面外壳，同时提前下载页面代码，减少首次点击等待；不改变页面功能、接口协议、CSS 和主题视觉。

## 当前原因

用户端在 `frontend/src/user/App.jsx` 中使用 `lazy()` 延迟加载业务页面。第一次点击时需要先下载页面 JS。小说获取和小说面板还会继续加载内部 iframe，批量工厂进入后立即请求批量列表，因此页面代码下载、iframe 加载和接口请求会叠加成一次长等待。

## 方案

### 1. 页面代码预加载

在用户应用完成首次渲染后，用浏览器空闲时间触发三个页面模块的动态导入：

- `NovelFetchPage`
- `NovelPanelPage`
- `BatchFactoryWorkbenchPage`

预加载只下载前端代码，不执行页面组件、不发起业务接口请求、不创建 iframe。动态导入失败不阻断当前页面。

### 2. 小说获取首屏

保留现有 iframe 工作台和功能。页面组件先渲染外壳和加载提示，再等待 iframe 的 ready 消息切换为可用状态。避免把额外的数据请求放在 iframe 出现之前。

### 3. 小说面板首屏

保留现有消息桥接、请求取消和安全限制。工作台 iframe 继续按当前路由加载；外层页面立即显示加载状态，ready 后再切换为可用状态。不得改变 API 白名单和请求限制。

### 4. 批量工厂首屏

保留批量列表接口和已有业务流程。进入页面后先渲染工作台标题、操作区和加载状态；列表请求异步进行。创建批量后的分类、刷新等后台动作不能阻挡页面外壳出现。

## 不改内容

- 不修改 CSS、主题文件或视觉布局。
- 不修改 Go 后端和 Node 接口协议。
- 不修改公网配置、数据库、Redis、TOS 或密钥。
- 不读取或输出 `.env.v88-review`。
- 不提交 `frontend/dist/downloads/`、`.local-review/`、`.env.v88-review` 或 `docs/superpowers/`。

## 测试与验收

1. 先增加失败测试，验证用户应用会安排目标页面模块预加载。
2. 验证预加载失败不会让首页报错或阻断导航。
3. 验证三个页面的动态导入仍由原路由使用。
4. 运行前端相关测试。
5. 运行 `npm --prefix frontend run build`。
6. 检查 Git 差异只包含允许的源码和测试文件，不包含构建产物、密钥和 CSS/主题文件。

## 风险控制

预加载只增加浏览器空闲时的代码下载，不能保证首次打开时接口或 iframe 已完成。页面仍必须保留加载状态。若浏览器处于低资源状态，预加载失败或延迟不影响用户正常点击导航。
