# 漫画自动发布、缺页续跑与图片快速回显设计

## 目标

解决批量漫画“立即执行后没有发布”、页图已生成但列表或详情迟迟不显示、在途页第一次冲突就转人工的问题。修复必须复用已有成果，不重新生成成功页，不自动触发付费任务。

## 已确认根因

1. `full_submit` 已强制开启自动发布，但执行前只检查发布配置字段是否存在，没有按每本书的风格、男女频检查实际音频分类和可用音频。无效分类直到图片上传后才失败。
2. 页级 `PAGE_IN_FLIGHT` 被页级账本当成“不计预算且不可修复”，第一次就写成 `needs_manual`，从而跳过了已有的缺页续跑机制。
3. 漫画媒体库主预览直接读取原始大图，候选图区也没有传缩略图；浏览器必须等待原图完整下载后才显示内容。
4. 当前线上 481 页中只有 471 页存在主图，其余页是真实缺失，不能用前端文案伪装为已生成。

## 设计

### 1. 发布前逐书检查

新增只读的漫画发布逐书检查。它根据每本书的发布模式执行以下检查：

- 手动音频：确认保存的分类仍为唯一启用分类，指定音频仍在当前组织和分类下启用。
- 自动匹配：根据书籍风格、男女频计算实际分类，确认该分类唯一启用，并确认当前组织下至少存在一个可用音频。
- 检查不随机选择音频、不写入书籍设置、不创建发布记录。
- `full_submit` 的立即执行预检和恢复预检都调用该检查；失败只阻止对应书籍，并显示可直接理解的原因。

### 2. 在途页只补缺页

`PAGE_IN_FLIGHT` 保持“临时协调状态”，第一次出现时不能进入人工处理。页级账本记录错误，但状态保持可续跑；批次回补队列等待后再次读取，只生成缺失页。已经有主图的页继续复用。

真正的 4xx 拒绝、无效配置和明确软拒绝仍按现有规则停止，避免重复计费。

### 3. 图片渐进显示

漫画图片组件先读取服务端缩略图并立即显示。详情预览需要原图时，在缩略图可见后后台读取原图，成功后无闪烁替换；原图失败时保留缩略图并给出可重试提示。

列表、候选图区和合集图区统一传递 `thumbnailUrl`。列表状态仍以服务端主图记录为准，不把真实缺页显示成成功。

## 数据流

1. 用户点击“立即执行”。
2. 服务端逐书解析有效设置并执行只读发布检查。
3. 通过的书进入生成；失败书直接展示发布配置原因，不消耗生图费用。
4. 出图遇到在途冲突时写入页级账本并排入续跑，只补缺页。
5. 页面通过轻量分页接口获取主图和缩略图地址，先显示缩略图，再按需读取原图。

## 验收标准

- 无效或不存在的自动匹配音频分类在立即执行前被逐书拦截。
- 逐书发布检查不写数据库、不随机选音频。
- `PAGE_IN_FLIGHT` 第一次出现后不会显示“需人工处理”，而是进入缺页续跑。
- 成功页不重新生成。
- 媒体库打开后先显示缩略图，不再等待原始大图才能看到画面。
- 真实缺页仍显示“待生成/生成失败”，成功写回后列表刷新为主图。
- 后端相关 Go 测试、前端相关 Node 测试和前端构建通过。

## 非目标

- 不在本次修改中自动重跑线上任务。
- 不修改图片模型或替用户发起付费生图。
- 不直接部署线上；先完成本地构建和验收。
