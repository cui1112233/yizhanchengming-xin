## 2. 实施边界与方案选择

采用用户确认的方案：保留已有Go流水线和React页面，按四个相互衔接的闭环补齐：可靠创作、自动执行、六模式与资料、界面与验收。相比只修错误提示，此方案修复实际断链；相比全部推倒，保留有效实现和已有作品、章节、日志。

- 在当前`v88`维护，保留其他聊天的变更，不建零散分支，不恢复旧文件覆盖新源码。
- 延续现有Go后端、React/Antd、MySQL、Redis、TOS和Go embed；本次不搬迁整个仓库目录。
- MySQL是正式任务、输入快照、作品与结果的持久记录；Redis用于队列通知、锁、取消与实时唤醒，不能用内存状态冒充持久成功。
- 系统提示词由后端prompt模块管理、版本化；模型走现有管理员/组员模型目录和后端调用能力，不复制洛水私有服务、账号或提示词原文。
- 组员可以选择当前授权模型，不能因此看到管理员密钥或收到要求自己配置管理员密钥的提示。
- 复用现有全站作品归档/恢复边界，不新增第二套不兼容的作品清理制度。
- 不使用Actions部署。先4001，源码提交与运行包身份一致后才具备后续发布条件；当前执行不自动包含公网发布或收费模型调用。

## 4. 统一且可追溯的运行输入

每次正式提交都生成不可变输入快照，至少包含：账号/作品/会话/模式、用户原始指令、模式附加输入、选定模型ID、实际解析模型与通道的安全标识、思考强度、提示词版本、Agent参数版本、参考资料/备忘录/文风的ID与内容快照、前文章节及版本、蓝图版本、事实和记忆、目标章号、来源类型（手动/定时/批量/重试）及来源轮次。

- 正常发送、定时、立即执行、批量、继续和重试统一走此合同。保存定时/批量时就校验所需材料和归属，不能到点才发现必填材料未传。
- 用户消息、运行记录和待派发记录在同一数据库事务提交；排队成功只能在正式记录可查询后返回。重复幂等键返回同一运行，不重复追加用户消息。
- 缺失已存在的记忆/资料或读取失败不能默默转换成空输入。首次创作允许无前文；已有章节必须可读取对应内容及版本，否则显示明确的修复提示并停止新调用。
- 快照不可包含密钥。任务开始前再次验证模型是否仍有权限；管理员删除/禁用所选模型则明确失败，不暗中切到另一付费模型。相同模型ID更新服务配置可使用当前合法配置，记录实际配置版本；历史章节不会因此被重写。
- 手动重试复用失败时用户输入和资料快照；允许用户显式更换模型并显示新一轮关系。最新前文已变更时要求确认重新生成，不把旧快照结果覆盖新章节。

## 5. 连续章节、审核与记忆

长篇已有的可靠链是可复用实现基础，不是六种模式的共同原版合同。长篇、短篇、两种仿写、番外和章节导入分别按第3节分流；原版尚无函数体证据的阶段次序、计数和算法不得由当前Go流程反向定义。

- 第N章从已保存的第N-1章版本读取前文结尾、事实、人物关系变化、时间线与未回收伏笔；较早章节由有来源的摘要补充。上下文超过预算时保留硬规则和最近前文，按确定顺序裁剪历史摘要，并记录裁剪范围。
- 正文、审核、修订、事实和记忆分别记录步骤与版本。模型成功但数据库保存失败时优先重试保存，不重新请求模型。
- Agent恢复原17项路由及文本/图像区分、reviewCycle、自定义审稿项、37维开关、三类写作要求。原配置没有作品/会话参数，应按账号提供共享长期设置；不能继续以每作品表单冒充。原生隐含profile与物理文件未知，Go仍须账号隔离。原Agent页没有目标章字数/思考强度控件，不能擅自加进去。
- 后写校验与AI味检测遵守原版明确的零模型调用合同，不改成模型润色。长度归一化仅在偏离目标>45%时有触发资格；原生计字、规则、检测阈值和归一化路由仍未知，先补证，不能以新提示词冒充恢复算法。
- 审核分数0–100，最大修订次数0–5，基础温度0–2，修订温度增量0–0.5；新设置默认通过分80、温度0.65、增量0.15、修订3轮，旧作品保留已明确保存的修订轮数。模型不支持温度等参数时标明“不支持，未发送”，不伪称生效。
- 修订上限耗尽后，有正文则保存为“完成，有审核提醒”并展示未解决问题；无有效正文则失败。解析输出合同失败最多一次结构修复；仍失败停止。结构修复与内容修订分别计数，避免叠加成无限重试。
- 设置0次修订表示不强制再修订一轮；原保存吞0是已证实原版缺陷，保留我们显式0正确保存的修复并注明差异。“最大修订轮次”不是总模型尝试数。二次确认是大纲/蓝图/基础设定生成后的内容检查点，允许右侧保存文件后按当前模型/思考参数继续；不得变成逐外部请求批准。内部幂等令牌保留，不据此新增用户确认卡。
- 3/80/0.15/0.65及范围有原前端证据；具体温度递增、37维评分、修订回退算法尚未恢复。当前Go的否决项/结构修复/评分回退均应标为独立实现，不能声称已经证明原算法一致。

## 6. 可靠执行、取消与恢复

- MySQL保存待派发记录与运行租约；Redis只负责通知和协调。工作进程领取任务后原子更新状态，禁止既入队又由HTTP路由直接启动第二个后台调用。
- 同一作品同一时刻只允许一个写作运行。租约默认90秒、每30秒续租；所有结果提交同时校验数据库租约和运行版本。续租失效即停止继续派发，过期旧进程不能提交覆盖新运行结果。
- 服务启动扫描所有非终态任务，包含手动、定时、批量；待派发任务恢复领取，已保存步骤从最后可靠记录恢复。
- 已向上游发送请求但没有确定结果时显示“上游结果待确认，已暂停自动重试”，不自动重新收费调用。明确未发出、明确可重试失败和单纯保存失败分别处理；不承诺本地无法保证的跨供应商恰好一次调用。
- 取消先持久记录取消请求，再通知Redis和当前执行上下文；后续步骤必须检查取消。若供应商不能中止已发请求，界面明确说明“已停止后续步骤，已发送请求可能仍由上游处理”，不承诺上游零扣费。
- 页面关闭不取消运行。重新进入作品/会话时读取消息、最新运行、检查点、章节和增量事件；不依赖浏览器内存里的runId。切换作品时丢弃旧页面请求结果，防止串作品显示。
- 页面轮询一次只允许一个在途请求，使用事件游标；等待确认和终态不继续高频轮询。轮询失败显示连接状态、退避后恢复，不反复弹出同一错误。

## 7. 定时与批量的执行规则

### 7.1 定时写作

- 参数：作品/会话/模型及完整输入，写作间隔1–1440分钟、每日章节上限1–100、连续失败阈值1–10。新任务默认30分钟/10章/3次，默认时区Asia/Shanghai，数据库时间统一UTC。
- 保存后不立即生成；首次到期为保存时间加间隔。立即执行是独立的显式轮次，但也受每日上限和当前作品占用限制。
- 正常轮次成功或明确失败后，下一轮按本轮完成处理的时间加间隔计算，避免慢任务结束时连续补发。重启最多恢复一个过期轮次，不把停机期间每个时间点补成收费任务。手动立即执行不改写原计划的下一到期时刻，同作品占用时原计划显示等待。
- 状态：未启动、运行中、等待中、已暂停、已停止；展示本日/累计成功章数、连续失败数、最近失败、下次时间及逐轮日志。等待确认、等待作品空闲、待确认上游结果须说明原因。
- 每个计划到期时刻只有一个正式执行记录，跨进程使用数据库原子领取及唯一键去重。作品占用时保留待执行轮次，不算成功/模型失败，也不创建无限积压轮次。
- 成功保存章节才增加日/累计计数并清零连续失败。达到日上限后等次日00:00恢复资格，不在午夜额外强制生成。暂停/停止优先，次日不自动恢复被用户暂停的计划。
- 明确可重试的临时上游失败按间隔安排下一轮；连续失败达到阈值暂停。鉴权、模型不存在、输入失效等确定错误立即暂停并提示操作；不等阈值重复扣费。结果不确定的调用按第6节暂停确认。
- 暂停只阻止后续派发，当前章可正常保存；停止同时请求取消当前章。恢复后从最后正式结果继续，不重复成功章。
- 旧任务超出新输入范围时保留原记录、标记“配置需调整”并暂停，不悄悄夹值或删除；页面展示可修改字段。

### 7.2 批量写作

- 参数：完整输入、总章数1–50、连续失败停止阈值1–10；默认5章/3次。每章复用同一正式运行链，不能绕过审核与保存。
- 展示目标/已保存章数、当前章、连续失败、停止原因与逐章日志。失败本身不算完成一章；成功后才推进下一章。
- 临时明确失败可按有界策略继续尝试同一章；达到阈值停止。确定配置错误、输入失效、上游结果不确定立即停止并说明。不会在页面断线后无限继续尝试。
- 暂停/继续/停止语义同定时；继续复用已成功章节与前文，失败轮次使用新的幂等键并关联上一轮。

## 8. 素材、文风、备忘录与内容管理

- 文件导入先支持UTF-8/带BOM文本、DOCX正文与无密码可提取文本的PDF；单文件不超过20MiB，每批不超过8个。前端和后端均校验；不支持格式、加密PDF或无文本扫描件明确提示，不生成空素材冒充成功。
- 上传原文件走TOS并保存对象标识；解析结果、来源、编码和摘要写MySQL。解析失败保留状态和重试入口，不创建可用的空章节。未配置TOS时上传入口说明原因，手动粘贴文本仍可用。
- 文本按显式章节标题识别；无标题作为一个片段处理。仿写多章默认最近5章，支持3/5/10及自选；确定后按源章节序号排列，不能按点击先后拼接；记录来源版本。
- 仿写要求至少100非空白参考字符，校验在附加备忘录前；不再接受“只选文风即满足仿写输入”的错误原版合同。文风支持多选，保存来源文本和风格说明；原表单指纹为本地算法、零模型。风格页说明为空时自动分析的真实算法/费用尚未知，不能与统计指纹混同。
- 备忘录支持新增/编辑/删除/选择引用；选中内容进入不可变输入快照。删除资料不改写历史运行，后续引用失效时提示重新选择。资料和作品按账号授权隔离。
- 作品与会话支持真正的新建、加载、重命名、归档及恢复；“删除作品”进入全站已有归档机制，不立即永久删除。运行中的作品归档前要求先停止运行；不新增隐蔽自动删除。
- 章节支持查看、编辑、版本历史和显式恢复；手动编辑生成新版本并标记后续事实/记忆需刷新，不能让旧记忆继续冒充最新状态。恢复版本是新记录，不抹除历史。
- 整本及短篇支持TXT/Markdown导出，按已保存顺序汇总；空作品提示“暂无可导出正文”。生成中的未保存片段不得混入正式导出。

## 9. 界面与使用合同

## 11. 失败提示规则

| 场景 | 用户提示与动作 | 是否继续外部调用 |
| --- | --- | --- |
| 缺输入/资料失效 | 指出具体字段或资料，保留草稿，允许修改 | 否 |
| 模型禁用、无权限或鉴权失败 | “所选文本模型当前不可用”，组员联系管理员或换授权模型 | 否 |
| 作品占用 | “该作品正在创作，等待空闲”，可停止当前任务 | 不新增调用 |
| 临时限流/繁忙 | 显示原因、计数、下次尝试时间；达到阈值暂停/停止 | 仅明确可重试且未超限时 |
| 上游请求结果未知 | “上游结果待确认，已暂停自动重试”，显示原轮次 | 否，须明确确认后重试 |
| 输出无效 | 一次结构修复后仍失败，展示可读原因和换模型/重试 | 有界 |
| 数据保存失败 | “结果保存失败”，保留可恢复结果并重试保存 | 不重新生成 |
| 记忆/事实读取失败 | “前文资料读取失败，已停止本次创作”，允许重试读取 | 否 |
| 连接中断或页面刷新 | 显示连接状态，重连后恢复已保存运行 | 不因刷新新建运行 |
| 用户取消 | 显示已停止后续步骤，并准确说明上游已发送请求限制 | 不派发后续步骤 |
