# 小程序“功能优先、工作台执行”设计

## 目标

把小程序四个主导航调整为“功能、工作台、任务、我的”。用户先在功能页看全并选择能力，再到工作台配置、开始或继续执行；任务页只负责查看全量任务记录。

完成标准：用户能从第一个标签页找到任一真实功能，选择后明确进入第二个标签页的对应工作区，并在工作台看到当前功能、正在执行内容及继续操作，不再把“选功能”和“执行功能”混在两个首页里。

## 最终视觉合同

以下四张原稿是实现和验收的唯一视觉基准：

- `docs/design-references/miniprogram-functions-first/01-functions-home.png`：功能页。使用用户最终指定的“我的创作空间”原稿，保留继续创作主图、三组非对称卡片、3D 图标和全部可见层级。
- `docs/design-references/miniprogram-functions-first/02-workbench.png`：工作台，显示当前工作区、唯一继续执行按钮、当前项目进度和本次执行信息。
- `docs/design-references/miniprogram-functions-first/03-tasks.png`：任务中心，显示汇总、筛选和跨功能任务列表。
- `docs/design-references/miniprogram-functions-first/04-profile.png`：我的空间，显示账号、额度、资产、偏好和设置列表。

实现按原稿逐项对照布局、内容、状态和交互。唯一允许主动偏离原稿的地方是底部导航顺序：四张页面都统一为“功能、工作台、任务、我的”，并按当前页面显示选中态。真实接口没有返回的数值不得伪造；使用加载、缺失或空状态替代。

## 页面职责

### 1. 功能：首页与能力目录

- 位于底部导航第一位，标签为“功能”。
- 视觉完全沿用已确认的第 3 套方向：晚霞背景、黑青液态玻璃、插画主视觉、非对称功能卡片和青色关键状态。
- 页面负责展示所有真实一级功能，不展示项目进度或任务列表；原稿中的“继续创作”只作为最近所选功能的快捷入口。
- 功能按“内容创作、生产成片、AI 与工具”分组，七个真实入口各出现一次。
- 点击任一功能时保存所选模块，切换到“工作台”，由工作台承接后续配置和执行。

### 2. 工作台：当前功能与执行中心

- 位于底部导航第二位，标签为“工作台”。
- 顶部显示当前所选功能的名称、说明和状态。
- 主区域提供“开始配置 / 继续执行”入口，并展示该功能最近一次正在执行的项目。
- 下方只展示少量与当前执行直接相关的信息：阶段、进度、最近更新时间和错误恢复。
- 没有选择功能时显示明确空状态，并提供“去选择功能”按钮切回第一标签页。
- 工作台不再展示完整功能目录，也不再重复功能页的大型入口卡片。

### 3. 任务：全量记录

- 位于底部导航第三位，标签为“任务”。
- 保留跨功能的进行中、待确认、失败和完成记录。
- 任务页用于回看、筛选和恢复历史任务；工作台只突出当前所选功能的当前执行。

### 4. 我的：账号与设置

- 位于底部导航第四位，标签为“我的”。
- 保持账号、额度、会员和偏好设置职责，不承载功能入口。

## 交互与数据流

1. 用户在“功能”页点击一个真实功能。
2. 小程序把模块键写入现有 `yzcm.mobile.activeModule` 本地状态。
3. 小程序切换到 `/pages/workspace/index`。
4. 工作台在显示时读取当前模块键，并加载该模块对应的执行摘要。
5. 用户点击“开始配置”或“继续执行”后，进入现有真实功能页面；不新增假页面或假路由。
6. 执行结果进入现有任务聚合，任务页负责全量展示。

功能选择只改变当前模块，不创建任务。真正提交、生成或生产仍由各功能现有操作触发。

## 视觉结构

### 功能页

- 顶部完整保留原稿的“一战晟铭”“我的创作空间”“灵感成稿 · 创意成片”和“继续创作”插画主视觉。
- “继续创作”从现有最近模块或最近真实记录读取，不显示虚构项目进度。
- 重点功能使用较大卡片，其余功能使用紧凑卡片；所有卡片都显示名称、用途和明确箭头。
- 功能卡片的选中反馈只表示“最近选择”，不显示虚构进度。

### 工作台

- 当前功能是唯一主角，视觉层级高于任务摘要。
- 运行状态使用青色强调；失败使用现有错误色；未选择时使用轻量空状态。
- 同一屏只保留一个主要执行按钮，避免“开始、继续、查看、进入”同时竞争。

### 底部导航

- 顺序固定为：功能、工作台、任务、我的。
- 四个标签的文字、图标尺寸和触控区域保持一致。
- 选中态继续使用液态玻璃与青色高光，不新增第五个中央按钮。

## 组件边界

- `pages/functions`：只负责功能目录、选择模块和切换标签。
- `pages/workspace`：只负责当前模块、当前执行摘要和进入真实工作区。
- `config/modules`：继续作为模块名称、图标、分组和路由的唯一来源，页面不复制路由规则。
- `ui/studioNavigation` 与 `custom-tab-bar`：统一新的导航顺序和选中状态。
- 现有模块详情、漫画分包、批量工厂页面保持独立，不在本次重写内部业务流程。

## 异常与恢复

- 当前模块键无效时回退到默认模块，但不自动创建任务。
- 执行摘要读取失败时，工作台保留当前功能，并显示“重新读取”操作。
- 未登录时沿用现有登录流程；登录完成后回到功能页或先前选择的工作台状态。
- 模块页面打开失败时保留当前选择，并给出可重试提示。

## 验证

- 单元测试确认四个标签顺序为“功能、工作台、任务、我的”。
- 功能页测试确认七个真实模块各出现一次，点击后写入模块键并切换到工作台。
- 工作台测试确认读取当前模块、空状态、执行摘要成功和失败状态。
- 路由测试确认所有入口使用 `moduleRoute`，没有新增假功能或硬编码业务提示词。
- 小程序开发构建通过。
- 在 390 × 844 视口检查首屏：主视觉不过高、第一组功能可见、底部导航不遮挡内容。

## 不在本次范围

- 不改变七个功能的后端接口和执行逻辑。
- 不新增系统提示词，也不在前端硬编码提示词。
- 不重做任务详情、会员中心或登录流程。
- 不增加新的顶级功能或虚构线上尚不存在的能力。
