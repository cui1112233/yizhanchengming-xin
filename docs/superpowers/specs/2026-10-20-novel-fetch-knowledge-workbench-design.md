# 小说获取知识库正式工作台设计

## 目标

将 `55420` 的知识库设计预览迁入 `4001/novel-fetch?tab=knowledge`，但正式页面必须继续使用现有 Go API、React 状态和主题变量。预览文件不参与运行。

## 页面结构

1. 顶部为返回入口、页面标题、说明、知识库设置入口和当前资料库状态。
2. 顶部下方为资料数量概览，显示当前库、爆款开头、改文模板和处理规则的真实数量。
3. 主工作区固定为桌面双栏：左侧 300px 资料选择区，右侧为资料编辑区；窄屏改为上下布局。
4. 左侧包含资料库类型、搜索、真实条目的圆柱滚动列表、位置提示、新增、复制和删除。
5. 右侧按资料类型显示真实字段，保存区固定在编辑区底部；高级 JSON 和 AI 优化保持折叠。
6. 爆款开头和处理规则保留为同一知识库页内的独立视图，分别继续调用现有拆解入库和规则配置逻辑。

## 交互与数据

- 页面加载、切换资料库、搜索、选择、保存、复制、删除、AI 优化均复用现有 `NovelFetchPage.jsx` 状态和 API。
- 圆柱效果只改变列表视觉：滚动和键盘选择仍准确更新 `knowledgeSelectedId`，不制造本地假条目。
- 资料为空、读取中、请求失败均显示在真实页面，不能由演示状态替代。
- 返回按钮回到小说获取处理页；知识库设置继续使用现有抽屉。

## 视觉与主题

- 使用页面现有的 `--legacy-*`、`--text-*` 变量；不把设计预览的 `light-dark()` 颜色硬写进业务页面。
- 采用细边框、8px 以内圆角、紧凑操作条和 300px 左侧资料区，避免空白和嵌套卡片。
- 深色与浅色仅切换变量，维持相同结构、间距和可读性。

## 验证

- 为布局和圆柱列表补充前端测试。
- 构建 React 并重新嵌入本机 Go 服务。
- 在真实登录浏览器中检查知识库、爆款开头、处理规则，以及浅色和深色主题。
