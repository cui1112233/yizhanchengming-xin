# Agent 技能中心、工作区与执行链对标设计

日期：2026-11-09

状态：待用户审阅

上位设计：`2026-11-09-luoshui-v29-v88-parity-master-design.md`

范围：本地 V88 设计与后续分期实施，不发布公网，不在验收中消耗付费模型额度

## 1. 目标

在一战晟铭 V88 现有 Agent 项目、画布、故事板、素材、任务和对话基础上，补齐参考应用 v2.9.0 已确认的完整 Agent 技能使用链。

本设计不把“显示技能列表”当作完成。用户必须能走通以下链路：

```text
进入 Agent 工作区
  → 管理平台技能、个人技能和项目技能
  → 创建或选择项目工作区
  → 新建会话
  → 通过 / 选择技能，通过 @ 引用技能、任务、文件和素材
  → 选择模型、权限模式和附件
  → 后端校验并读取技能版本
  → 生成计划或执行受控工具
  → 实时显示步骤、日志、写入、产物和失败原因
  → 结果写回项目并可继续、重试、取消或由子任务续跑
```

## 2. 证据与边界

本设计依据三类证据，三者必须分开描述：

1. 当前已登录桌面应用的只读界面结构；
2. 当前活动前端构建包中的页面事件、参数和状态文案；
3. 当前本地 `data/agent` 下的工作区、技能注册、设置和技能包结构。

已确认的参考事实包括：

- 左侧 Agent 导航包含“新 Agent 会话”“自动任务”“Agent 技能”和项目工作区；
- Agent 技能入口当前显示 52，技能中心包含 Skills、MCP、Codex 三个栏目；
- 技能中心支持搜索、分类、启停、批量开启、详情、导入、卸载和 CLI 安装入口；
- 全局技能位于技能注册和安装目录，项目可用 `skills/{id}/` 提供同名覆盖；
- 输入框支持 `/` 选择已开启技能，支持 `@` 引用技能、自动任务、MCP 和工作区文件；
- 会话请求同时携带技能、模型、工作模型、权限模式、附件、工作区、会话和续跑信息；
- 执行结果包含流式正文、工具卡片、事件、写入、产物、子任务、待回答和失败信息。

参考应用的编译文件、安装目录和提示词原文不得复制进 V88。V88 只实现经过确认的用户行为、输入输出和业务作用。

## 3. 品牌与命名硬规则

所有进入一战晟铭正式产品面的参考名称必须按以下规则转换：

| 参考名称 | 一战晟铭正式名称 |
|---|---|
| 洛水 | CM |
| 小洛 | 小Y |

转换范围包括：

- 页面标题、按钮、菜单、空状态、帮助文案和提示信息；
- 平台技能名称、作者名、说明和分类；
- 后端 PromptDefinition 的显示名称和说明；
- 自动任务模板、执行日志、事件摘要和失败原因；
- 默认工作区、默认会话、产物标题和导出文件中的产品署名；
- 测试夹具、演示数据和浏览器验收数据。

内部代码可以保留中性的 `agent`、`skill`、`workspace` 等技术名，但不得新增长期存在的 `luoshui` 或 `xiaoluo` 产品常量。历史分析文档可保留参考产品原名，用于说明证据来源。

完成前必须运行仓库范围文本检查。正式前端、Go 运行代码、PromptDefinition、迁移种子和测试夹具中出现未获豁免的“洛水”或“小洛”即验收失败。

## 4. 用户入口和点击路径

### 4.1 Agent 一级入口

用户从主侧栏点击“Agent 工作区”进入 `/agent`。Agent 内部增加一条固定的二级导航：

1. `新 Agent 会话`；
2. `自动任务 {数量}`；
3. `Agent 技能 {数量}`；
4. `项目`标题；
5. `添加工作区`；
6. 项目工作区列表。

工作区卡片支持点击进入，并在更多菜单提供：

- 置顶/取消置顶；
- 在项目文件页中打开；
- 重命名；
- 归档/取消归档；
- 删除非默认工作区。

V88 是 Web + Go 服务，不调用服务器资源管理器。参考应用的“在资源管理器中打开”在 V88 中等价实现为“打开项目文件”，进入项目素材/文件视图。

### 4.2 Agent 技能中心

用户点击 `Agent 技能 {数量}` 后进入 `/agent/skills`，使用完整页面，不使用输入框旁的小弹层代替。

页面顶部栏目：

- `Skills {数量}`；
- `MCP {数量}`；
- `Codex {数量}`。

Skills 页面从上到下提供：

1. 搜索技能；
2. 全部开启/全部停用；
3. 导入 Skill；
4. 管理执行器；
5. 分类筛选；
6. 技能卡片列表；
7. 使用帮助。

技能卡片必须显示：

- 显示名称和稳定 ID；
- 版本；
- 一句话说明；
- 来源：平台、个人、项目；
- 作者：CM、小Y或用户；
- 启用状态；
- 运行环境状态；
- 详情入口；
- 个人/项目技能的编辑和删除入口。

点击技能卡片打开详情抽屉或对话框，显示完整说明、触发方式、需要的工具、需要的输入、产生的输出、当前版本和来源。前端不得显示系统提示词正文。

“导入 Skill”在 V88 中上传包含 `SKILL.md` 的压缩包或目录清单。Go 后端先解析、校验和入库，不在 Web 服务器上直接执行技能包携带的安装命令。

“管理执行器”替代桌面应用的任意 CLI 安装命令，进入管理员配置的本地执行器、MCP 和外部连接列表。普通成员不能提交任意 shell 命令。

### 4.3 新 Agent 会话

用户点击“新 Agent 会话”后：

1. 选择或创建项目工作区；
2. 填写目标；
3. 选择主模型和工作模型；
4. 选择思考强度；
5. 选择权限模式；
6. 添加附件、项目文件或素材；
7. 通过 `/` 或 `@` 选择上下文；
8. 点击“开始创作”。

未选择工作区时允许先输入，但发送前必须提示选择或创建工作区，不得静默创建孤立项目。

### 4.4 `/` 选择器

输入 `/` 打开键盘可操作的选择器，包含：

- 已开启技能；
- 已启用 MCP；
- 自动任务；
- 思考强度。

技能列表只展示当前成员可用、当前工作区启用且环境检查通过的技能。选择后插入可删除的上下文胶囊，并保存稳定 ID，不依赖显示名称反查。

### 4.5 `@` 引用选择器

输入 `@` 打开统一引用选择器，包含：

- 技能；
- 自动任务；
- MCP；
- 项目文件；
- 项目素材；
- 画布节点和故事板镜头。

引用项在消息中显示名称和类型，发送时转换为稳定 ID、版本和来源。刷新后必须能重新解析为同一对象；对象已删除时显示“引用已失效”，不得误配同名对象。

### 4.6 故事板和画布

技能、权限模式、附件和引用入口在画布、故事板、素材和任务四个视图中保持一致，不得像当前实现一样在故事板隐藏技能和专家入口。

“专家”不再是前端写死的三个名称。CM 创作顾问、广告策划、短剧编剧等能力改成平台技能，统一使用技能版本、权限和后端提示词链。

## 5. 权限模式

会话提供三档权限：

| 模式 | 用户可见说明 | 执行规则 |
|---|---|---|
| `plan` | 计划模式：仅规划不执行 | 允许读取已选上下文并产出计划；不调用写入、生成、外部连接或技能工具 |
| `auto` | 自动审批：只读自动执行 | 只读工具可执行；写入、生成、外部连接和技能工具进入待确认计划 |
| `bypass` | 完全运行：按计划连续执行 | 在当前用户和项目权限内执行已允许工具；删除、发布、付费生成和外部发送仍需独立确认 |

权限模式不能由技能正文提升。后端根据工具注册表决定工具风险等级，前端只展示结果。

涉及付费模型、删除、发布、外部消息、账号授权和敏感数据传输时，三种模式都不能绕过对应确认。

## 6. 技能解析和提示词链

技能解析优先级固定为：

```text
项目工作区固定版本
  > 当前成员个人技能
  > 平台已发布技能
```

后端收到技能 ID 后执行：

1. 校验技能存在、已发布或属于当前成员；
2. 校验当前工作区是否启用；
3. 解析项目覆盖和固定版本；
4. 记录本轮使用的技能 ID、版本和内容摘要；
5. 从后端 prompt 模块读取基础 Agent、权限和技能组合模板；
6. 将技能规则、引用上下文和工具定义组合成模型请求；
7. 保存本轮实际生效的 PromptDefinition ID 和版本。

系统提示词统一放在 Go 后端 `prompt` 模块。React 前端只能读取技能名称、说明、输入模板、输出说明和版本，不能硬编码真实系统提示词。

技能正文与用户文件都属于不可信输入。技能不得覆盖平台安全规则、权限模式、项目边界和工具白名单。

## 7. Agent 执行链

一次运行分为以下状态：

```text
draft
  → planning
  → awaiting_approval（可选）
  → queued
  → running
  → awaiting_user（可选）
  → succeeded / failed / cancelled
```

后端按顺序执行：

1. 创建运行记录并快照会话、技能、模型、权限和引用；
2. 构建计划；
3. 根据权限模式拆分可直接执行和待确认步骤；
4. 将后台步骤放入 Redis 队列；
5. 通过运行事件流向前端发送状态；
6. 将文本、工具结果、文件写入和媒体产物分别持久化；
7. 将成功产物挂到当前项目素材、画布节点或故事板镜头；
8. 保存失败原因、已完成步骤和可续跑位置。

取消只停止未完成步骤，不删除已经成功写入的项目结果。重试默认从第一个失败步骤继续，不重复已确认写入。

## 8. 执行过程交互

助手消息中按事件顺序显示：

- 计划卡片；
- 正在读取的文件和素材；
- 技能调用卡片；
- 工具名称、开始时间、结束时间和状态；
- 可折叠日志；
- 写入文件、项目素材、画布节点和故事板镜头；
- 子任务卡片；
- 待用户回答卡片；
- 失败原因和恢复按钮。

运行中的主按钮显示“停止生成”。停止后保留已完成步骤，并显示“继续执行”或“从失败处重试”。

子任务必须显示父运行、职责、当前状态和产物。用户回答子任务问题后，答案回到原子任务，不另开没有关联的普通聊天。

## 9. 工作区和产物

V88 继续以 Agent 项目作为正式工作区，不建立第二套项目实体。

项目工作区包含逻辑目录：

- `input`：用户上传和选入的输入；
- `context`：项目上下文和结构化资料；
- `assets`：图片、视频、音频和其他媒体；
- `outputs`：文本、JSON、报告和导出包；
- `runs`：运行事件和日志索引；
- `skills`：项目技能覆盖和固定版本关系。

MySQL 保存元数据、关系、状态、版本和索引；TOS 保存上传文件和媒体产物；Redis 保存队列、取消信号、短期锁和运行事件流。Go `embed` 继续打包 React 前端，最终发布单个后端二进制。

## 10. 自动任务

用户点击“自动任务”进入 `/agent/automations`，可以：

- 查看启用、暂停、运行中、失败的任务；
- 按名称和工作区筛选；
- 新建、编辑、暂停、恢复和手动运行；
- 查看每次运行记录和失败原因；
- 打开本次运行对应的 Agent 会话。

创建自动任务时设置：

- 名称和目标；
- 工作区；
- 上下文模式；
- 主模型和工作模型；
- 权限模式；
- 技能和引用；
- 每小时、每天、工作日、每周或自定义间隔；
- 失败后停止或按规则重试。

自动任务触发后创建正式 Agent 运行，标记来源自动任务 ID。它和普通会话使用同一套技能解析、事件、产物和恢复链，不建立另一套执行器。

定时调度使用 MySQL 持久状态和 Redis 锁。服务重启后从 MySQL 恢复，不依赖浏览器定时器。

## 11. MCP、Codex 和执行器

### MCP

管理员配置可用 MCP 连接，成员只能启用已授权连接。MCP 工具进入统一工具注册表，接受权限模式、超时、取消、日志和审计控制。

### Codex

Codex 作为可选模型/执行渠道，不作为独立项目系统。渠道状态、可用模型和授权状态在技能中心 Codex 栏目展示。任何账号授权由用户本人完成。

### 本地执行器

需要本地软件或 CLI 的技能通过现有本地执行器/Relay 注册能力，不允许 Go 服务直接运行技能包提供的任意安装命令。环境检查结果显示为“可用、缺少执行器、缺少配置、无权限”。

## 12. 数据设计

新增或扩展以下正式数据：

- `agent_skills`：技能 ID、所有者、来源、显示信息、当前版本和状态；
- `agent_skill_versions`：版本、规则正文、输入输出说明、工具需求和内容摘要；
- `agent_project_skills`：项目启用、固定版本和覆盖关系；
- `agent_sessions`：项目、模型、权限模式、状态和上下文预算；
- `agent_runs`：本次运行、来源、快照、状态、失败和续跑位置；
- `agent_run_events`：计划、工具、日志、写入、产物、问题和子任务事件；
- `agent_run_artifacts`：TOS 对象、类型、来源步骤和项目归属；
- `agent_automations`：调度、工作区、技能、权限和恢复策略；
- `agent_automation_runs`：自动任务与 Agent 运行的关联；
- `agent_tool_registry`：工具风险、执行器、超时和权限要求。

删除、重命名或更新技能不能改写历史运行快照。历史消息始终显示当时使用的版本。

## 13. HTTP 与事件接口

前端使用以下职责清晰的接口：

- `GET /api/agent/skills`：按成员和工作区返回可见技能；
- `POST /api/agent/skills/import`：上传并校验技能包；
- `POST /api/agent/skills/{id}/enable`：启用或停用；
- `GET /api/agent/skills/{id}`：读取安全的技能详情；
- `POST /api/agent/sessions`：创建项目会话；
- `POST /api/agent/sessions/{id}/runs`：创建运行；
- `GET /api/agent/runs/{id}`：读取正式状态；
- `GET /api/agent/runs/{id}/events`：订阅运行事件；
- `POST /api/agent/runs/{id}/approve`：批准待确认步骤；
- `POST /api/agent/runs/{id}/answer`：回答待用户问题；
- `POST /api/agent/runs/{id}/cancel`：取消未完成步骤；
- `POST /api/agent/runs/{id}/retry`：从失败位置继续；
- `GET/POST/PATCH /api/agent/automations`：管理自动任务。

旧 `/api/agent/chat` 在迁移期调用新的运行服务，不再自己忽略 `skillIds` 并直接请求模型。

## 14. 前端组件边界

为避免继续扩大 `AgentPageV2.jsx`，实施时拆出：

- `AgentWorkspaceSidebar`：Agent 导航和项目工作区；
- `AgentSkillCenter`：Skills/MCP/Codex 页面；
- `AgentSkillCard` 和 `AgentSkillDetail`：技能卡和详情；
- `AgentComposer`：输入、附件、模型、权限和发送；
- `AgentSlashPicker`：`/` 选择器；
- `AgentMentionPicker`：统一 `@` 引用；
- `AgentPermissionModeSelector`：三档权限；
- `AgentRunTimeline`：计划和运行事件；
- `AgentToolCallCard`：工具与日志；
- `AgentDelegationCard`：子任务和待回答；
- `AgentAutomationPage`：自动任务；
- `AgentWorkspaceFiles`：项目文件和产物。

所有组件复用 V88 主题令牌、Ant Design 和 Lucide 图标，不复制参考应用皮肤。

## 15. 分期实施顺序

### 第 1 期：技能中心与真实技能注入

- 建立技能、版本和项目启用数据；
- 建立独立技能中心；
- 完成品牌转换；
- 完成 `/` 与 `@` 选择器；
- 后端真正读取技能并保存版本快照；
- 故事板和画布显示相同入口。

### 第 2 期：权限、计划和运行事件

- 三档权限模式；
- Agent 运行状态机；
- 工具注册表；
- 计划卡、工具卡、日志、写入和产物事件；
- 停止、批准、失败重试和续跑。

### 第 3 期：工作区文件、子任务与自动任务

- 项目逻辑目录；
- 文件和素材引用；
- 子任务和待回答；
- 自动任务创建、调度、暂停、恢复和运行历史。

### 第 4 期：MCP、Codex 和本地执行器

- MCP 管理和工具适配；
- Codex 渠道状态与模型适配；
- 本地执行器环境检查；
- 技能工具调用的统一审计和失败恢复。

四期均属于完整目标。分期只决定实现和验收顺序，不代表后续能力被排除。

## 16. 验收标准

每一期至少完成：

1. 前端聚焦测试；
2. Go 领域和 HTTP 测试；
3. MySQL 迁移和重启恢复测试；
4. Redis 取消、锁和事件测试；
5. 前端完整测试与构建；
6. Go 嵌入构建和本地运行身份检查；
7. 已登录浏览器逐步点击验收；
8. 不消耗付费额度的固定模型/工具夹具验收。

第 1 期验收必须证明：

- 从 Agent 导航可以进入独立技能中心；
- 技能能启停、筛选、查看详情并按工作区恢复；
- `/` 和 `@` 能选择并刷新恢复；
- 故事板和画布都能选择技能；
- 请求到达后端后技能正文确实参与组合；
- 历史消息记录技能 ID 和版本；
- 未授权或停用技能会被后端拒绝；
- 产品面出现 CM 和小Y，不出现未获豁免的参考品牌名。

只有按钮存在、请求返回 200、测试通过或构建成功，均不足以宣称功能一致。必须提供入口、操作、后端生效、持久化、状态、恢复和下游产物的完整证据。

## 17. 不在本设计中执行的动作

- 不复制参考应用编译包、提示词原文或本地账号数据；
- 不在浏览器验收中点击真实付费生成；
- 不允许普通成员执行任意安装命令；
- 不通过 GitHub Actions 上传或部署；
- 不发布公网；
- 不改动无关业务和用户现有数据。
