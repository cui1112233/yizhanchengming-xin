# V88 导演台分阶段对标设计

## 目标

在保留 V88 现有 Go 内嵌发布链路、项目素材和画布数据的前提下，把当前基础 3D 导演台优化成一套可实际使用的导演工作区。

视觉和交互参考 Liblib 导演台，但所有按钮必须对应 V88 已有能力或本设计明确新增的真实能力，不放置只有外观、没有作用的占位按钮。

本设计覆盖：

- 三栏导演台工作区和主题适配；
- 场景对象列表；
- 角色与摄像机属性编辑；
- 导演视角和机位视角；
- 画幅比例；
- 底部场景描述框与截图操作；
- 现有数据迁移、保存和浏览器验收。

姿势骨骼和动画时间轴不在本轮伪造实现。它们需要独立的数据结构、持久化和导出流程，后续另写设计。

## 已确认事实

REA 静态分析和实际页面检查确认，Liblib 导演台由以下区域组成：

- 左侧固定工具栏和随工具切换的内容面板；
- 中央全屏 3D 视口；
- 右侧随当前对象变化的属性面板；
- 顶部居中的“导演视角 / 机位视角”切换；
- 底部移动、截图、动画时间轴工具；
- 独立于画布缩放的场景描述框；
- 场景对象、角色、多个摄像机、画幅、姿势和轨道数据。

V88 当前已经具备：

- 全屏导演台入口；
- 项目图片列表；
- 图片设为场景；
- 图片作为平面角色加入 3D 场景；
- 角色选择和基础拖动；
- OrbitControls 摄像机；
- 单个导演视角预设；
- 截图回写为画布图片素材。

因此本轮采用“在现有真实能力上增量扩展”，不替换 V88 的项目、资产、上传、画布保存或 Go 发布路径。

## 总体布局

导演台是独立的全屏工作区，不跟随 Agent Canvas 的缩放比例。

```text
+----------------+--------------------------------------+----------------+
| 左侧工具与对象 |              3D 视口                 | 右侧属性检查器 |
| 272px          |                                      | 288px          |
|                |      导演视角 / 机位视角             |                |
|                |                                      |                |
|                |      底部工具 + 场景描述框           |                |
+----------------+--------------------------------------+----------------+
```

响应式规则：

- 宽度大于等于 1180px：左侧 272px，右侧 288px，中间自适应；
- 宽度小于 1180px：两侧面板可收起，中间视口不得被覆盖；
- 高度不足时，左右面板各自滚动，顶部切换和底部工具保持可见；
- 全屏导演台继续避开展开或收起后的全局侧栏，并隐藏桌面宠物覆盖层；
- 任何主题下，面板、文本、输入框、选中态和图标都必须达到清晰可见的对比度。

## 左侧工具和对象列表

左侧分成 44px 图标栏和 228px 内容区。

第一阶段提供真实可用的入口：

- 场景对象；
- 项目图片；
- 添加角色；
- 添加机位；
- 画幅比例。

“姿势”和“动画时间轴”在对应数据能力完成前不显示，不做无效入口。

场景对象列表由当前项目状态实时生成：

- 场景图；
- 角色；
- 摄像机。

点击列表项会选中对应对象、在 3D 视口中高亮，并让右侧显示对应属性。每个对象提供定位操作；删除只对角色和非主摄像机开放，并使用现有保存流程。

项目图片沿用 `adapter.listProjectImages()`，不建立第二套素材库。图片项提供“设为场景”和“加入角色”，保持与当前真实功能一致。

## 中央 3D 视口

中央保持 Three.js 全屏渲染，不放入装饰卡片。

交互规则：

- 点击角色或摄像机模型：选中对象；
- 拖动选中对象：移动对象；
- 拖动空白区域：控制导演视角；
- 滚轮：缩放导演视角；
- 点击“机位视角”：使用当前活动摄像机渲染；
- 点击“导演视角”：回到自由观察摄像机；
- 选择画幅后：显示真实取景遮罩，并让截图使用同一比例；
- 切换视角和面板不会改变 Agent Canvas 的缩放。

本轮角色继续使用 V88 项目图片平面，不假装已支持骨骼模型。选中对象显示简洁边框或变换支点，未选中时不出现厚重外框。

## 右侧属性检查器

右侧内容由当前选中对象决定。

角色属性：

- 名称；
- 位置 X/Y/Z；
- 旋转 X/Y/Z；
- 缩放 X/Y/Z；
- 统一缩放。

摄像机属性：

- 名称；
- 位置 X/Y/Z；
- 旋转 X/Y/Z；
- 注视坐标 X/Y/Z；
- FOV；
- 设为活动机位。

场景属性：

- 场景图片名称；
- 当前画幅；
- 更换场景图片。

数值修改必须立即反映到 3D 视口，并通过现有 `adapter.writeState()` 保存。输入非法数值时保留上一次有效值，并在控件旁显示简短错误，不让整个导演台崩溃。

## 顶部和底部控制

顶部居中使用紧凑分段按钮：

- 导演视角；
- 机位视角。

机位视角没有可用摄像机时禁用，并显示原因提示。

底部采用两个独立区域：

1. 视口工具条：移动模式、重置视角、截图到画布；
2. 场景描述框：上传参考图、场景描述、保存按钮。

场景描述框复用 `project.scene.prompt`。发送图标在 V88 中执行“保存场景描述”，不会调用不存在的 AI 场景生成接口，也不会在验收时消耗额度。

截图按钮继续使用现有 `adapter.storeCapture()` 和 `onCapture()`，生成普通项目图片节点和导演台到图片的连接。

## 数据结构

沿用 `node.data.config.directorProject`，从 `3d-v1` 增量迁移到 `3d-v2`：

```js
{
  rendererVersion: '3d-v2',
  scene: {
    assetId,
    url,
    name,
    prompt
  },
  actors: [{
    id,
    assetId,
    name,
    position: [x, y, z],
    rotation: [x, y, z],
    scale: [x, y, z]
  }],
  cameras: [{
    id,
    name,
    position: [x, y, z],
    rotation: [x, y, z],
    target: [x, y, z],
    fov
  }],
  activeCameraId,
  aspectRatio,
  directorCamera: {
    position: [x, y, z],
    target: [x, y, z],
    fov
  },
  captures: [{ assetId, url, name, createdAt }]
}
```

规则：

- `3d-v1` 的单个 `camera` 原值迁移为 `directorCamera`；同时复制其位置、目标和 FOV，生成固定 ID 为 `camera-main` 的默认活动机位，旋转由位置和目标确定；
- 旧的标量角色缩放迁移为三个轴相同的数组；
- 资产 ID 是持久引用，URL 只用于显示；
- 当前选中对象、面板展开状态属于临时界面状态，不写入项目；
- 迁移只发生在读取和规范化阶段，不删除旧节点。

## 组件边界

- `DirectorDeskApp`：加载项目、协调保存、选择状态、错误状态和截图；
- `DirectorDeskShell`：三栏全屏布局、主题变量和响应式收起；
- `DirectorToolRail`：左侧图标入口；
- `DirectorSceneTree`：场景、角色和摄像机对象列表；
- `DirectorAssetPanel`：项目图片及“设为场景 / 加入角色”；
- `DirectorViewport`：Three.js 场景、视角切换、画幅遮罩和对象选择；
- `DirectorInspector`：按对象类型渲染真实属性；
- `DirectorBottomDock`：视口工具和场景描述保存；
- `DirectorDeskHostAdapter`：唯一的 V88 数据、素材上传和截图回写边界。

组件只能通过明确的状态和回调通信。Three.js 视口不直接请求 V88 接口，属性面板不直接操作画布节点。

## 保存和错误处理

```text
属性或 3D 交互
  -> 更新内存中的 directorProject
  -> 规范化为 3d-v2
  -> adapter.writeState
  -> 现有画布持久化

截图到画布
  -> 按当前画幅渲染 PNG
  -> adapter.storeCapture
  -> onCapture
  -> 创建图片节点和连接
  -> 现有画布持久化
```

- 保存失败时保留当前编辑状态，并显示“尚未同步”；
- 截图上传失败时不创建图片节点或连线；
- 动态模块加载失败时显示可重试错误，不允许只剩空白或星空背景；
- 关闭导演台前刷新最后一次待保存状态；
- 任何错误都不能触发真实模型生成。

## 主题和视觉规则

- 使用导演台自己的语义变量，并从全局亮色/暗色主题派生；
- 不在组件内散落硬编码背景色和文本色；
- 面板使用低对比边线和紧凑间距，不使用厚重卡片堆叠；
- 图标统一使用现有 Lucide 图标；
- 普通图标按钮使用图标和悬浮提示，明确命令才使用文字按钮；
- 选中态只突出当前对象、当前工具和当前视角；
- 输入框、滑块和数值步进器在两个主题下都必须保持清晰。

## 实施阶段

### 阶段 0：运行链路确认

- 确认源代码、`frontend/dist`、Go 内嵌资源和 `:4001` 运行包一致；
- 为动态模块失败添加可见错误和重试；
- 保留当前可用导演台作为回归基线。

### 阶段 1：工作区外壳和现有功能重排

- 三栏布局、左侧工具、顶部视角切换、底部工具和主题变量；
- 将现有图片、场景、角色和截图能力放入新布局；
- 不改变后端接口。

### 阶段 2：真实对象与属性检查器

- `3d-v2` 数据迁移；
- 场景对象树；
- 角色位置、旋转、缩放；
- 多摄像机、活动机位、FOV 和机位视角；
- 属性变化持久化。

### 阶段 3：画幅和底部描述框

- 自适应、21:9、16:9、4:3、1:1、3:4、9:16；
- 取景遮罩和同画幅截图；
- 场景描述保存和参考图入口；
- 完整主题、尺寸和浏览器验收。

### 后续独立设计

- 骨骼角色与姿势预设；
- 关节微调；
- 动画轨道、关键帧和轨迹；
- 30/60 帧视频导出。

## 测试和验收

源测试：

- `3d-v1 -> 3d-v2` 迁移；
- 角色和摄像机数据规范化；
- 对象选择与属性更新；
- 画幅到截图尺寸映射；
- 保存失败和截图失败；
- 动态模块加载失败可见且可重试；
- 亮色和暗色主题变量完整。

浏览器验收：

- 打开导演台后不是空白画面；
- 左右面板不覆盖中央视口；
- 两种主题下控件和文本都清晰；
- 场景、角色和摄像机可从左侧选择；
- 角色和摄像机属性修改后 3D 画面立即变化；
- 导演视角和机位视角可以往返切换；
- 画幅遮罩和截图结果比例一致；
- 关闭、重新打开和刷新后数据仍存在；
- 截图回到画布后形成图片节点和连接；
- 不点击或触发任何真实模型生成。

Three.js 验收还必须检查桌面和窄屏截图，并做画布像素检查，证明 3D 画面不是空白、构图没有被两侧面板遮挡、控件不会互相覆盖。

发布验收：

- 前端构建通过；
- Go 内嵌资源构建通过；
- 只使用 `scripts/deploy-go-embedded.ps1` 规定的 Go 发布路径；
- `/health` 返回 `200`；
- `/api/runtime-build-info` 中 `runtime` 为 `go`；
- `git_sha` 和 `runtime_manifest_sha` 对应实施提交；
- 在当前已登录的 Agent Canvas 页面完成可见交互验收。

## 完成标准

本轮完成不是“页面看起来像 Liblib”，而是用户能够在新布局中使用 V88 的真实项目图片搭建场景，管理角色和机位，调整属性和画幅，保存后重新打开仍保持状态，并把当前构图可靠地截图回现有画布。

姿势和时间轴只有在后续真实数据能力完成后才进入界面。
