# Agent Canvas LibLib Layout Design

## Scope

本轮只优化工作流画布（`/agent/canvas?view=workflow`）的节点展示和连线交互。故事板、批量工厂和后端生成接口不在本轮重做范围内。现有模型、素材、生成任务、草稿保存和权限逻辑继续复用。

参考页面为用户提供的 LibLib 画布快照。参考内容只用于交互和视觉分析，不复制其项目数据、素材或页面代码。

## Goals

1. 节点预览、提示词输入、参考素材、模型、参数、设置和生成按钮形成一个连续的节点卡片。
2. 未编辑节点保持紧凑，只显示标题和预览；点击标题或预览后，在同一张卡片内展开编辑区。
3. 模型选择、类型/画幅/质量/时长等参数和设置按钮位于输入框下方，模型名称不会被窄宽度截断。
4. 节点右侧的加号是实际 source handle，不再渲染成脱离节点的独立按钮。
5. 从加号拖到已有目标句柄时只创建一条真实连线；拖到空白处才显示后续节点选择菜单。
6. 鼠标中键拖动画布、滚轮缩放、节点拖拽、边选择/删除和快捷键继续可用。
7. 点击画布空白处收起当前编辑器，但不会清除已输入文本、已选模型或收藏素材。

## Non-goals

- 不改变生成 API、执行器绑定、模型目录、连线关系计算或数据库结构。
- 不把 LibLib 的账号、节点、素材、网络请求或页面源码复制进项目。
- 不在本轮引入右侧属性面板替代节点内编辑器。

## Proposed UI

### Node card

`CanvasNode` 保留 React Flow 节点外壳和两个 Handle。节点卡片内部按以下顺序渲染：

1. 顶部标题栏：节点类型、节点名称、来源标签和拖拽区域。
2. 预览区：图片、视频、音频、文本或导演台预览。
3. 编辑区（仅 `isEditorOpen`）：
   - 参考素材缩略图与单一 `+` 添加入口；图片节点继续支持更换当前图片。
   - 提示词输入框，保持原有草稿状态和失焦保存。
   - 实际输入预览与校验提示。
   - 单行底部控制条：模型选择、参数摘要、设置按钮、生成/取消/重试操作。

编辑区不再使用相对画布中心的 `left: 50%` 和固定视口宽度；宽度跟随节点卡片，最大宽度只由节点本身决定。这样预览和输入区始终对齐，节点外部不会出现悬浮编辑框。

### Toolbar and side rail

保留现有顶部项目栏、左侧工具栏、顶部编辑条、底部缩放/对话栏的功能，但统一为低对比度半透明面板、紧凑图标按钮和明确 tooltip。按钮尺寸保持稳定，移动端继续允许横向滚动，不增加新的常驻面板。

### Connections

- source handle 位于节点卡片右侧垂直居中，默认只在节点悬停、选中或正在连线时显示。
- target handle 位于节点卡片左侧垂直居中，只有正在连线或目标有效时显示。
- 连接线使用现有 `createTypedCanvasEdge` 和 `syncCanvasEffectiveReferences`，按节点类型推导 `first_frame`、`sequence`、`audio_source`、`script_source` 或 `reference`。
- `onConnect` 命中目标句柄时调用现有连接提交逻辑并关闭连接菜单。
- `onConnectEnd` 只有在没有命中目标句柄的空白画布上松手时才打开 `connectionDropChoices`；菜单定位在松手点附近，选择后创建节点并自动连线。
- 删除边使用现有边选择和 Delete 快捷键；删除节点时同步清理相关边和自动引用。

## Component boundaries

- `CanvasNode`：只负责节点外壳、预览、Handle 和展开/收起触发。
- `AgentNodeComposer`：负责编辑区内容和生成操作，接口保持现有回调不变。
- `agent-canvas-connections.js`：继续负责关系推导、边创建和自动引用同步，不把连线判断写进 JSX。
- `agent-workspace.css`：负责节点卡片内布局、Handle 可见性、工具栏视觉和响应式规则。

## Interaction and state flow

1. 用户点击节点标题或媒体预览，`activeEditorNodeID` 设置为该节点。
2. `CanvasNode` 在卡片内部渲染 `AgentNodeComposer`；输入框使用现有 `draftPrompt`，失焦后调用 `onConfigChange`。
3. 用户点击画布空白处时，保留节点数据，只清空 `activeEditorNodeID` 和临时菜单/素材面板状态。
4. 用户从 source handle 拖动到 target handle，创建 typed edge，提交一次画布变更并同步目标节点自动引用。
5. 用户从 source handle 拖到空白处，显示后续节点菜单；选择节点类型后创建新节点、创建 typed edge、选中新节点并展开其编辑区。
6. 所有画布变更继续进入现有草稿/服务器保存队列，不新增逐字符保存。

## Error and empty states

- 模型缺失时，模型选择器显示原因，生成按钮保持禁用并给出可读 tooltip。
- 连接目标类型不兼容时，target handle 使用无效态，不创建边，也不弹后续节点菜单。
- 连接保存失败时保留画面和输入，显示一次性错误状态，允许重试，不回滚用户其他编辑。
- 会话冲突仍显示现有会话提示，不通过 UI 重排掩盖冲突。
- 参考素材为空时只显示轻量 `+` 入口，不重复显示“视频输入”一类与节点类型无关的入口。

## Verification

### Automated

- 更新/新增 `AgentCanvas` 源码契约测试：编辑区位于节点卡片内部、Handle 仍存在、空白拖放菜单和目标连线分支保持区分。
- 更新 CSS 源码契约测试：不再存在固定视口宽度和 `left: 50%` 的悬浮编辑器规则；source/target handle 的可见性规则存在。
- 运行画布连接、上下文菜单、节点配置、模型选择和布局相关前端测试。
- 运行 React 构建，确认 Go embed 构建可继续使用。

### Browser acceptance

在本地真实页面验证：

1. 点击图片/视频预览，输入区紧贴预览下方展开。
2. 点击空白处，输入区消失，提示词、收藏素材和模型选择保留。
3. 从右侧加号拖到另一个节点，线条可见且目标节点显示自动引用。
4. 从右侧加号拖到空白处，显示两个后续节点选项，选择后自动创建节点并连线。
5. 中键拖动画布、滚轮缩放、选择边后 Delete 删除边均可用。
6. 在窄窗口下模型完整显示或可横向滚动，不遮挡生成按钮。

## Acceptance criteria

本轮完成的标准是：工作流画布的节点编辑器不再脱离节点；模型/参数/设置位于输入框下方；加号只作为连线句柄；连到已有节点和拖到空白处的行为分开且可验证；现有生成、素材、保存和快捷键测试不回归。
