# 一战晟铭执行器配对、任务接收与安装包设计

日期：2026-10-20  
状态：已与用户确认，待实施

## 1. 目标

把现有豆包本地执行器整理为面向普通用户的一体化 Windows 客户端：

- 正式名称统一为“一战晟铭执行器”。
- 普通用户只需下载安装、登录豆包并输入一次配对码。
- Bearer Token、HTTP API、监听端口和任务领取等技术细节不出现在普通操作流程中。
- 图片和视频任务由执行器自动接收、执行、上传，并在 V88 网页中显示。
- 保留面向开发者的本机 HTTP API，但默认关闭并隐藏在开发者模式中。
- Windows 交付物为单个安装程序 EXE，不再要求用户下载 ZIP 后解压。

## 2. 普通用户流程

1. 用户从 V88 设置页下载 `一战晟铭执行器-安装版.exe`。
2. 安装程序仅为当前 Windows 用户安装，不要求管理员权限。
3. 用户启动“一战晟铭执行器”并完成豆包登录。
4. 用户在 V88 设置页生成 10 分钟有效的一次性配对码。
5. 用户在执行器中输入配对码并完成连接。
6. 配对成功后，执行器保存长期设备凭证；以后启动时自动连接，不再重复配对。
7. 用户在 V88 网页中选择豆包执行器并提交图片或视频任务。
8. 执行器自动接收任务、生成、上传结果；网页显示结果并保存到资产库。

普通用户界面不展示 HTTP API、Bearer Token、监听端口、“领取任务”或租约等内部概念。

## 3. 凭证边界

三类凭证必须分开：

- 配对码：由 V88 网页生成，一次性、10 分钟有效；配对成功后立即失效。
- 设备凭证：配对成功后由 V88 签发，执行器自动保存，用于心跳、领取任务、续期、上传和回报结果。
- 本机 Bearer Token：只用于开发者模式下的本机 HTTP API，与配对码和设备凭证不能互相复用。

界面上普通用户只接触配对码。设备凭证和本机 Bearer Token 不得写入普通日志、网页或错误提示。

## 4. 任务接收方案

### 4.1 长等待领取

用长等待领取替换当前空闲时每 2 秒领取一次的方式：

- 执行器发起领取请求后，服务器最多保持约 25 秒。
- 有任务时服务器立即返回任务。
- 没有任务时服务器返回空结果，执行器立即建立下一次长等待。
- 网络错误后按 2 秒、5 秒、10 秒、30 秒逐步降低重试频率。
- 网络恢复后自动回到正常长等待，不要求用户操作。

该方案保留任务队列和数据库状态，减少空请求，同时不引入 WebSocket 的额外维护复杂度。

### 4.2 执行保护

- 执行器领取任务后继续使用租约，防止同一任务被多台设备重复执行。
- 执行期间定期续期，并向 V88 回报准备中、提交中、生成中、下载中和上传中等状态。
- 程序异常退出或租约失效后，服务器可重新排队未完成任务。
- 上传失败时保留本地结果并继续重试上传，不重新发起豆包生成，避免重复消耗生成次数。
- 执行器重启后恢复可恢复任务；无法恢复时给出明确失败原因，由服务器重新排队。

## 5. 状态设计

### 5.1 V88 设置页

网页显示以下用户状态：

- 未配对：尚未连接执行器，可生成配对码。
- 等待配对：显示配对码和剩余有效时间。
- 已连接：显示设备名称、版本和在线状态。
- 暂时离线：显示最后在线时间，并提示检查执行器是否启动。
- 正在执行：显示正在处理的图片或视频任务数量。
- 版本过旧：提示下载新的安装程序覆盖升级。
- 配对失效：可删除旧设备并重新配对。

设置页保留图片和视频真实测试入口，并展示排队中、生成中、上传中、成功、失败及预览结果。

### 5.2 执行器

执行器显示：

- 豆包状态：未登录、已登录、连接中或连接失败。
- V88 状态：未配对、正在连接、已连接、网络中断或正在重连。
- 任务状态：等待任务、生成中、上传中、完成或失败。
- 失败信息必须使用普通用户能理解的文案，并在适用时提供重试操作。

正常网络重连不反复弹窗，只更新状态；需要用户处理的登录失效、凭证失效等问题才使用明显提示。

## 6. 隐藏开发者模式

### 6.1 开启方式

- 在执行器“关于”页面连续点击版本号 7 次开启。
- 从第 3 次有效点击开始提示“再点击 N 次即可开启开发者模式”。
- 开启成功后提示“开发者模式已开启”。
- 开发者模式状态只保存在本机。
- 用户可以关闭开发者模式；关闭只隐藏入口，不删除原有开发者配置。

### 6.2 开发者选项

开发者模式中提供：

- HTTP API 开关；新安装默认关闭。
- HTTP API 当前状态：关闭、启动中、正常运行或启动失败。
- 实际监听地址，仅允许 `127.0.0.1`。
- 监听端口，默认 `8787`。
- 端口冲突的明确提示，以及“自动选择可用端口”操作。
- 本机 Bearer Token 的隐藏显示、复制和重新生成。
- 重新生成 Token 前二次确认；生成后旧 Token 立即失效。
- 当前有效地址和 Token 对应的调用示例。

HTTP API 的开启、关闭或故障不得影响 V88 配对、长等待领取以及网页图片/视频生成。

## 7. Windows 单文件安装包

### 7.1 产品信息

- 产品名称：一战晟铭执行器
- 安装包名称：`一战晟铭执行器-安装版.exe`
- 安装后的程序名称：`一战晟铭执行器.exe`
- 窗口标题、桌面快捷方式、开始菜单、任务栏、系统托盘和卸载列表统一使用产品名称。

### 7.2 安装行为

- 生成单个 Windows 安装程序 EXE。
- 默认仅为当前用户安装，不请求管理员权限。
- 安装完成后可选择立即启动，并创建桌面和开始菜单入口。
- 新版本支持覆盖安装，不要求先卸载。
- 覆盖安装保留豆包登录、V88 配对、设备凭证、本机 Bearer Token、用户配置、任务记录和本地结果。
- 新安装默认关闭 HTTP API；老版本中已经明确启用 HTTP API 的用户升级后保留原设置。

### 7.3 Logo

正式 Logo 来源：`G:\Backup\Pictures\一战晟铭图标.png`。

已确认源图为 1254 x 1254、32 位 ARGB，四角透明。实施时从该源图生成 Windows 多尺寸 ICO，并检查 16、24、32、48、64、128 和 256 像素显示效果。安装程序、应用程序、窗口、桌面、任务栏、托盘和卸载列表使用同一视觉标识。

## 8. 安全要求

- HTTP API 只能绑定回环地址，禁止监听局域网或公网地址。
- 配对码必须在 10 分钟内有效、单次使用，并与用户账号绑定。
- 设备凭证和本机 Bearer Token 必须安全保存，不在日志和界面中默认明文显示。
- 删除已配对设备后，对应设备凭证立即失效，未完成任务重新排队。
- Bearer Token 重新生成后旧 Token 立即失效。
- 服务器不得通过用户提供的地址主动访问用户本机执行器。

## 9. 验收标准

### 9.1 安装与品牌

- 单个安装 EXE 可在干净的 Windows 用户环境安装、启动、覆盖升级和卸载。
- 安装过程不要求管理员权限。
- 程序名、窗口、快捷方式、任务栏、托盘和卸载列表均显示“一战晟铭执行器”和指定 Logo。
- 覆盖升级后已有配对和用户数据保持不变。

### 9.2 配对与状态

- 连续点击版本号 7 次前，普通界面看不到开发者选项。
- 配对码过期后不能使用，配对成功后不能再次使用。
- 配对成功后重启执行器或电脑仍能自动连接。
- 网页能准确显示已配对、在线、离线、最后在线时间和任务状态。
- 凭证失效时执行器和网页都提供明确的重新配对提示。

### 9.3 任务与恢复

- 图片和视频均可从网页下发，经执行器生成、上传并在网页显示和保存。
- 空闲执行器采用长等待，不再固定每 2 秒发送空领取请求。
- 多台执行器同时在线时，同一任务不会被重复领取。
- 断网后自动退避和重连，不持续高频请求或反复弹窗。
- 生成过程中断网不会重复提交生成。
- 上传失败保留本地结果，联网后继续上传。
- 执行器异常退出后，任务可以恢复或安全重新排队。

### 9.4 开发者 HTTP API

- 新安装默认关闭 HTTP API，关闭时不影响 V88 功能。
- 开启后只监听 `127.0.0.1`。
- 端口占用时显示明确错误，并能自动选择可用端口。
- Bearer Token 鉴权、复制、重新生成和旧 Token 失效均有效。
- 图片与视频调用示例能得到真实生成结果。

## 10. 发布说明

未签名的 Windows 安装包可能触发 SmartScreen 的“Windows 已保护你的电脑”提示。首版可在明确说明的前提下测试和内部发布；面向普通用户正式公开发布时，建议使用 Windows 代码签名证书对安装包和主程序签名。
