# 小说获取控件与 REA 旧版链路对齐设计

日期：2026-10-26
范围：小说获取页面的处理、任务、配置、知识库、处理规则、提交与记录，以及与批量工厂/画布的跳转链路。
参考：REA 旧版源码 `static/app.js`、`main.py` 及旧版回归脚本。

## 目标

让小说获取页面上出现的每个按钮、开关、选择项都有真实作用，并让用户能看懂任务到底卡在抓取、敏感词 AI、改文、配置、登录、生成还是提交。

本次不把旧版界面原样搬回来，只恢复旧版已有且当前用户仍需要的行为；没有后端链路的入口不继续保留为可点击的假按钮。

## 现状问题

1. 敏感词处理页面显示了模式选择，但旧版的整组/逐条并发、并发数、上下文长度、最大命中数等参数没有完整对应。
2. 任务列表和提交页把多个等待状态压成单一状态，无法区分等待抓取重试、等待敏感词 AI、等待配置、等待登录、待生成 AI、待提交和远端待核验。
3. 提交状态只展示总状态或总数量，旧版的待生成版本、待提交版本、部分接收、失败版本、已确认版本等明细没有完整展示。
4. 低频操作入口较多，需要逐一确认是否有 API、是否有成功/失败反馈；没有真实链路的按钮要删除或置灰，而不是继续显示成可用功能。
5. REA 旧版的输入格式记忆、自动队列参数和提交版本选择需要与当前保存配置逐项核验，防止“页面显示已保存但后端未使用”。

## 方案

### 1. 页面控件与真实链路清单

建立一份前端控件到 API 到 Go 路由的静态契约测试。每个可点击控件必须满足：

- 有明确的处理函数；
- 处理函数调用当前 Go API；
- 成功后刷新对应数据或状态；
- 失败时显示具体原因；
- 无法满足以上条件的入口删除或置灰并说明原因。

重点覆盖：抓取原文、开始处理、预览、重试、停止、恢复原文、生成 AI、应用规则、规则建议、知识库新增/复制/删除/优化、提交环境检测、同步配置/组织/风格、提交预览、开始提交和失败重试。

### 2. 敏感词设置对齐

保留当前页面结构，但补齐 REA 旧版实际使用的字段，并统一保存到后端配置：

- 逐条并发 / 整组一次发送；
- 并发数；
- 每任务最大命中数；
- 上下文字符数；
- 重试次数；
- 温度和自定义提示词。

前端只编辑配置，后端负责执行和校验。AI 返回仍包含命中词、整组返回数量不完整或服务失败时，不保存局部结果，并显示可定位的失败原因。

### 3. 状态与提交明细

后端返回并保留旧版字段，前端按优先级展示：

- 正在执行；
- 等待抓取重试；
- 等待敏感词 AI；
- 等待配置；
- 等待登录；
- 待生成 AI；
- 待提交；
- 部分接收；
- 失败版本；
- 远端待核验；
- 已提交/已确认。

任务列表至少显示状态、当前阶段、版本明细和阻塞原因；提交页显示每个版本的结果，不再只显示一个 `0/数量`。

### 4. 配置回读与跨页面链路

对输入格式、最大字数、自动抓取、自动改文、自动提交、自动队列、提交版本、配置档和组织目录做保存后回读测试。小说获取跳转批量工厂/画布时，明确传递任务 ID、原文/编辑后正文版本和选中的 AI 版本；目标页面没有接收能力时给出提示，不显示成功假象。

## 错误处理

- 网络暂时失败：保留上一次已确认状态，显示“暂时无法刷新”，不把任务伪装成暂停或完成。
- 外部登录/组织配置缺失：状态显示为等待登录或等待配置，并提供对应操作入口。
- AI 输出不安全或不完整：任务进入可重试状态，原文和已完成版本不被半成品覆盖。
- 删除、停止和提交均保留明确的确认和结果反馈。

## 验证

1. 先增加失败的前端契约测试和 Go 状态/配置测试。
2. 修复后运行小说获取相关前端测试、`backend/internal/novelfetchworkshop` 和 `backend/internal/httpapi` 测试。
3. 构建前端并重新打包 Go embed。
4. 在本地 `:4001` 页面逐个检查按钮可见性、点击反馈、状态刷新和跨页跳转；不执行真实外部上传或消耗真实 AI 配额。

## 不做的事情

- 不把 REA 旧版全部界面原样复制回来。
- 不保留没有后端实现的假按钮。
- 不修改与小说获取无关的批量工厂、画布视觉设计。
- 不执行真实小说抓取、真实 AI 生成或真实视频管理系统上传。
