# 洛水 v2.9 工具箱与 AI-CUT 证据化对标设计

## 1. 目标

依据已恢复的洛水 v2.9.0 前端包、451 个桥接方法、72 个原生模块和 181 条提示词，重写一战晟铭的插件中心与 AI-CUT。对标的是用户能看到并完成的操作链路，不复制洛水品牌、源码或不可验证的服务端实现。

本设计禁止把“卡片存在”“弹出说明”“接口返回 200”当成功。每个开放功能必须具备输入、执行、进度、结果、持久化和失败提示。

## 2. 证据基线

- E-004：格式化前端与桥接调用，证明入口、控件、交互和桥接方法。
- E-005：原生模块目录，证明本地文件、媒体、草稿和 AI-CUT 的执行边界。
- E-006：数据库提示词，证明模型工具的真实任务定义；提示词只能放后端 prompt 模块。
- E-008：登录后界面与中文字符串，证明用户可见名称、顺序和页面层级。
- 详细功能映射见 `F:\脚本测试\work\洛水2026-v2.9.0-反编译分析\report\2026-11-09_功能到实现对照矩阵.md`。

这些材料是发布包恢复物，不等于原始源码仓库。未知参数必须标记为推断或用一战晟铭现有能力重新设计，不能伪称一比一源码复制。

## 3. 产品边界

### 3.1 保留的一战晟铭能力

首页、私人定制、小说获取、水货生产和现有 Agent 工作区继续保持一战晟铭自身设计。水货生产中的创作漫剧另行对标洛水“漫剧解说”。

### 3.2 新增或重做

- 插件中心：保持洛水当前 30 个可见入口的名称和顺序，但执行界面使用一战晟铭的暗色主题和现有组件。
- 独立 AI-CUT：是顶层剪辑工作台，不是插件中心弹窗，也不是 momo 画布或 Agent 工作区。
- 资产参考：必须是图片模型与项目素材链路，不能要求剪映。
- AI-Shot：必须是成片高光抽取与媒体导出，不能要求剪映草稿。
- AI-分段：优先作用于 AI-CUT 当前时间轴；只有选择草稿适配器时才涉及剪映。

## 4. 功能分层

### A. 网页文件工具

格式化文本、文档合并、字幕合并、分镜整理等能确定性处理的功能，直接在网页或 Go 后端完成，结果可预览和下载，不调用模型。

### B. 网页模型工具

小说转剧、AI 改文、分镜大师、爆款开头、女频性转、角色修改、长篇拆书、世界观、书名生成等走后端 prompt 模块和已配置模型。前端只提交结构化参数，不保存系统提示词。

### C. 模型与素材工作台

资产参考、封面生成、角色三视图、声音克隆、音色设计需要项目、素材、模型、任务状态和结果确认。结果进入当前项目资产库。

### D. 本地媒体工作台

AI-Upscale、字幕对轴、AI-Shot 通过本地执行器或后端媒体任务运行，必须显示执行器状态和可下载产物。

### E. 剪映适配器

AI-Subtitle、AI-Filler、AI-双语字幕、AI-CUT 插件版、AI-BGM 的剪映模式、AI-Split、草稿合并、剪映关键帧通过独立适配器读取和写入草稿。未检测到执行器时保持禁用并说明缺什么，不能假装运行。

## 5. 第一项真实实现：资产参考

### 5.1 用户流程

1. 用户点击插件中心“资产参考”。
2. 选择已有项目，或创建“图片”项目。
3. 上传 1 至多张参考图；上传后立即进入该项目素材库并显示缩略图、文件名和上传状态。
4. 填写画面要求，选择图片模型、比例和候选数量。
5. 点击生成后创建真实图片生成任务，引用已上传素材 ID。
6. 页面显示排队、生成、待选择、失败或完成状态。
7. 用户选择候选图并确认；确认结果写入项目画布/素材库，可继续在 Agent 工作区编辑。

### 5.2 复用边界

复用现有 `/api/agent/tasks`、项目素材上传、图片生成、任务查询和候选确认接口。不得新建一套重复的临时素材协议。对象数据仍使用现有对象存储抽象，项目和任务仍使用现有 MySQL 存储。

### 5.3 页面状态

- 没有项目：显示创建按钮。
- 没有图片模型：生成按钮禁用，明确引导到设置；上传仍可用。
- 没有参考图：禁止生成并提示至少上传一张。
- 上传中、生成中：防止重复提交。
- 模型失败：保留用户输入和参考图，展示后端真实错误。
- 成功：展示候选图并要求用户确认，不自动覆盖原图。

### 5.4 验收

- 本地 4001 能创建/选择项目并真实上传图片，刷新后仍能列出素材。
- 请求体包含真实 `referenceAssetIds`，不是文件名占位。
- 无模型配置时不会发起付费调用；页面明确显示不可生成的原因。
- 测试环境用假执行器验证候选和确认，不消费真实额度。
- 卡片状态显示“网页可用”，不再弹“尚未接入”。

## 6. 独立 AI-CUT 目标结构

- 项目列表：新建、打开、重命名、删除、最近项目。
- 素材池：视频、音频、图片、字幕上传与元数据读取。
- 时间轴：视频、音频、字幕多轨，缩放、吸附、选择、拖动、裁切、删除、分割。
- 智能能力：ASR/SRT、智能分段、音频分离、Agent 时间轴编辑。
- 导出：后端/本地执行器渲染；剪映仅作为可选导出适配器。

AI-CUT 的项目、轨道、片段、任务和导出记录必须持久化。第一阶段不以静态画布冒充完整时间轴。

## 7. 开放状态

插件卡片只有三种状态：

- `可用`：当前环境能完成完整闭环。
- `需配置`：代码已完整，但缺模型、执行器或目录授权；点击进入真实配置/工作台。
- `开发中`：尚未实现；不可弹出伪操作界面。

不再使用笼统的“待接入对应能力”掩盖不同依赖。

## 8. 品牌与命名

写入本项目的用户文案使用 CM 和小Y，不出现洛水、小洛。证据文件和内部对照文档可保留来源名称以便审计。

## 9. 完成定义

每批只在以下全部满足后标记完成：测试通过、前端构建通过、Go embed 资源更新、确认运行的是本次二进制、4001 页面可见、真实状态持久化、错误路径可复现。未覆盖的 30 项继续明确标记为开发中。
