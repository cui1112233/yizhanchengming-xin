# 个人中心一体化工作区设计

日期：2026-10-09  
状态：已确认，待实施

## 目标

个人中心不再是覆盖在原业务外壳上的抽屉菜单。访问个人资料、会员中心、账号安全、联合治理、API 配置、用量与制作、组员管理和账号与角色时，用户看到的是一个独立、完整的个人中心工作区。

进入个人中心后只保留个人中心导航。用户可以通过左上角“返回工作台”回到进入个人中心前所在的业务页面；没有可用来源时回到首页。

## 现状与根因

当前 `UserLayout` 同时保留 220px 的业务侧栏，并把 284px 的个人中心菜单作为 `position: fixed` 的覆盖层显示。个人中心打开时，业务主内容额外加上 284px 左外边距避让菜单。

因此页面实际形成“业务侧栏 + 覆盖式个人中心菜单 + 被压缩的业务内容”三段结构，而不是同一工作区。被压缩的内容容器会触发 `max-width: 900px` 的容器断点，使个人资料等页面由并排布局降为上下堆叠。原业务顶栏仍存在但标题被隐藏，也会造成视觉断层。

## 页面结构

个人中心路由使用独立的 `AccountCenterLayout`：

```text
个人中心工作区
├─ 个人中心侧栏
│  ├─ 返回工作台
│  ├─ 当前用户摘要
│  ├─ 资料、会员、安全、联合治理
│  ├─ API 配置、用量与制作、组员管理
│  ├─ 开发者工具（按权限显示）
│  └─ 退出登录
└─ 内容画布
   └─ 当前个人中心子页面
```

该布局不渲染业务 `legacy-sidebar`、业务顶栏或固定的 `account-center-popover`。侧栏和内容画布属于同一个页面级布局，宽度由同一套网格或 flex 规则分配。

## 路由与返回规则

1. 从任一非个人中心业务路由进入个人中心时，保存完整来源地址（路径和查询参数）。
2. 在个人中心的任何子页面之间切换时，保留首次进入时的来源地址，不覆盖它。
3. 点击“返回工作台”时，优先回到该来源地址。
4. 直接打开、刷新、书签进入个人中心，或保存的来源地址不可用时，“返回工作台”回到首页 `/`。
5. 退出登录仍沿用现有登录清理和跳转行为。

## 响应式规则

宽屏下使用固定宽度的个人中心侧栏与占满剩余空间的内容画布；内容区域不再因隐藏的业务侧栏和覆盖菜单被重复挤压。

窄屏下侧栏可以收窄为图标栏或展开菜单，但必须仍处于个人中心工作区内，不能覆盖并遮挡内容画布。所有个人中心页面的容器断点仅基于实际内容画布宽度工作。

## 实施范围

- `frontend/src/shared/layouts/UserLayout.jsx`：按路由选择业务外壳或个人中心工作区；维护来源地址和返回行为。
- 新增或抽取个人中心工作区布局组件：承载侧栏、权限菜单和返回按钮。
- `frontend/src/shared/styles/account-center-visual-rebuild.css`：删除固定覆盖层与业务主内容避让规则，改为统一工作区布局和响应式规则。
- 现有个人中心各页面仅作为内容画布渲染，保留其数据请求、权限和表单行为。

## 验证

1. 从水货生产、剧本生成等业务页面进入个人中心，再点击返回：回到原路径及原查询参数。
2. 在个人资料、会员中心、账号安全、API 配置等子页切换后再返回：仍回到最初业务来源。
3. 直接访问或刷新 `/profile` 后点击返回：回到首页。
4. 宽屏下确认只有一套个人中心导航，内容区不被二次压缩，资料和概览按设计并排。
5. 窄屏下确认导航和内容保持同一工作区，导航不覆盖内容。
6. 回归 DEV、MANAGER、MEMBER 三种身份的权限菜单与退出登录流程。
