# Agent 画布无感草稿与同步设计

日期：2026-10-21  
状态：待用户审阅  
范围：本机 V88 的 `/agent/canvas`；不发布公网。

## 1. 目标

让 Agent 画布和剧本生成一样，用户操作后画面立即变化，切换视图、返回项目、刷新页面或短暂断网都不丢内容；同时不再因每次轻微操作都马上发一次远端保存请求。

画布不显示“保存”按钮。用户看到的是无感恢复和无感同步；只有无法同步时才显示简短、可处理的提示。

## 2. 已确认的问题

当前画布的所有结构改动都会走：

`AgentCanvas.commit -> onChange -> AgentPageV2.enqueue -> PATCH /canvas`

现有队列虽有 220ms 的等待，但没有本地草稿层。节点拖动松手、编辑参数、连线、添加素材、引用图片和外观设置都会直接排队请求远端。因此连续操作会频繁出现“正在保存”，网络失败后也没有独立的离线草稿作为恢复来源。

剧本生成已经采用浏览器本地草稿：按账号和浏览器标签保存，进入页面先恢复，页面状态变化和离开页面时更新本地内容。画布采用相同思路，但键必须按账号和 Agent 项目 ID 区分，不能按临时标签区分。

## 3. 状态边界

每个 Agent 项目维护三份互不混淆的状态：

1. **正在编辑的画布**：React 当前渲染的节点、连线、视图和允许恢复的画布外观；操作立即更新这一份。
2. **本地草稿**：浏览器 `localStorage` 中的完整可恢复快照，键为 `qiantie:agent-canvas-draft:<账号>:<项目ID>`。每次结构修改后立即覆盖这一份，不发网络请求。
3. **已同步版本**：服务端返回的画布版本与修订号，只用于后续合并上传和处理冲突。

React Flow 的临时选中状态、右键菜单、已打开的编辑器、素材面板、鼠标拖动状态和正在展开的下拉层不进入草稿或服务端画布，避免刷新后出现假选中或卡住的浮层。

## 4. 用户操作与同步规则

### 4.1 正常编辑

- 节点移动、编辑节点、添加或删除节点、连线、分组、素材主图/参考图变更、外观设置，先立即改画面，再立即写本地草稿。
- 每次新操作重置同步计时；用户连续操作期间不发远端请求。
- 停止操作 1.2 秒后，把最新完整画布合并为一次远端保存。无论中间改了多少次，只上传最后一份。
- 平移、缩放、选择和悬浮不写入远端画布；视图位置只在实际停止移动后写本地草稿，并与下一次结构同步一起上传。

### 4.2 页面切换、刷新和关闭

- 同一项目重新进入时，先读取服务端画布，再读取本地草稿。
- 本地草稿的基准修订号等于或高于服务端版本时，立刻显示本地草稿，并在后台安排一次合并同步。
- 本地草稿明显落后于服务端时，保留服务端画布并清理过期草稿。
- 路由切换和 `pagehide` 时，本地草稿已经存在；同时尝试立即提交尚未同步的最新版本。浏览器来不及完成请求也不影响下次恢复。

### 4.3 断网和恢复网络

- 远端同步失败时，继续保留本地草稿，不回滚用户画面，也不弹出连续报错。
- 页面只显示一次“内容已暂存在本机，网络恢复后会继续同步”的状态；不显示保存按钮。
- 浏览器恢复联网、重新聚焦页面或用户再次编辑时，自动尝试同步最近草稿。
- 成功同步后以服务端返回版本更新基准，并删除已确认同步的本地草稿；若仍有新操作，则保留更新后的草稿并等待下一轮。

## 5. 冲突、素材与生成结果

- 冲突时不能直接用服务端画布覆盖本地草稿。先取得最新服务端版本，再按现有节点 ID、连线 ID 和项目资源引用规则合并本地未同步改动，随后重试一次。
- 若同一个节点的同一字段在本地和服务端均有不可自动判断的修改，保留本地草稿，并显示一次“此项目在另一处更新过，请刷新后确认”的提示；绝不静默丢弃本地内容。
- 图片主图、参考图、生成完成后的结果确认，统一使用“节点补丁 -> 当前画布 -> 本地草稿 -> 合并同步”链路。它们不能因为点击事件顺序不同而绕过草稿层。
- 正在运行的图片、视频、音频生成任务仍以服务端任务记录为事实来源。草稿只保存节点对任务的展示状态和用户未同步的配置，不伪造任务成功或结果素材。

## 6. 代码边界

- 新增专门的 `agent-canvas-draft-storage` 模块：负责键生成、版本校验、读取、写入、删除和坏数据保护。它不直接调用 React 或接口。
- 扩展 `agent-canvas-state`：保存队列只负责合并、延迟同步、冲突恢复和状态回调；本地草稿保存由队列外的明确入口驱动。
- `AgentPageV2` 负责项目切换时的加载、草稿与服务端版本选择、页面离开时的收尾同步，以及向画布传入唯一的“更新画布”入口。
- `AgentCanvas` 只报告用户产生的新完整画布，不直接知道本地存储、网络、修订号或保存提示。

这次不扩大到重做素材库、生成提供方、任务后端或画布视觉。它只修复画布数据从编辑到恢复、同步的可靠链路，并为素材添加、引用和生成结果回填提供同一个稳定入口。

## 7. 测试与本机验收

自动测试覆盖：

1. 草稿按账号和项目隔离；坏 JSON、超版本和无效画布不会让页面崩溃。
2. 连续十次编辑只触发一次延迟远端同步，本地草稿保存十次中的最后一份。
3. 页面切换、刷新、离线失败和恢复联网后，草稿恢复和同步状态正确。
4. 冲突时保留本地未同步节点、连线和引用，旧服务端响应不能覆盖新草稿。
5. 主图、参考图和生成确认都经过相同节点补丁与草稿更新入口。

真实浏览器验收覆盖：

1. 拖动多个节点、连续改提示词和连线时，画面立即变化，停下后只发生一次同步；不显示保存按钮。
2. 操作后立刻切换到故事板、返回工作流、刷新页面，节点位置、主图、参考图和编辑内容仍在。
3. 断网后修改画布、刷新或切换后仍能恢复；恢复网络后自动同步。
4. 从“我的收藏”选一张图片写入图片节点；再给该节点加入参考图；刷新后两者仍存在。
5. 提交一次可用的生成任务，确认结果回填节点后刷新，素材和节点结果仍一致。

## 8. 不做的内容

- 不发布公网。
- 不删除已有项目历史或服务器画布。
- 不把草稿写入 MySQL、Redis 或 TOS；浏览器草稿只用作本机恢复和离线缓冲。
- 不承诺跨浏览器或跨电脑即时共享未同步草稿；跨设备一致性以已完成的服务端同步为准。
