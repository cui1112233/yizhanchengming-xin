# Agent 漫画与视频作品分组设计

## 目标

让 Agent 的每个作品在创建时固定为“视频作品”或“漫画作品”，并让项目列表、画布节点、输入框、模型选择、生成操作、素材和历史记录都遵守同一个作品类型，避免漫画和视频链路混用。

## 现状与问题

- Agent 项目当前通过统一的任务/项目接口创建，项目数据没有明确的创作类型。
- Agent 画布支持剧本、文本、图片、视频、音频节点，并按节点类型加载模型；因此漫画项目也能看到视频节点和视频字段。
- 批量工厂已经有漫画模式，Agent 从批量工厂接入作品时需要继承漫画类型，否则回到画布后仍会暴露视频链路。
- 现有项目不能被破坏。没有类型字段的旧项目必须按视频兼容。

## 设计

### 1. 作品类型是项目级事实

项目增加 `projectType` 字段，允许值为 `video` 或 `comic`。创建项目时必须选择类型；旧记录缺少该字段时归一化为 `video`。批量工厂创建或绑定 Agent 项目时，将批量的漫画/视频模式映射为对应类型。服务端保存和读取项目详情时返回该字段，不能只由前端临时判断。

### 2. 项目列表按类型分组

Agent 首页项目列表增加“全部、视频、漫画”三个筛选入口。项目卡显示类型标签。新建项目弹窗先选择类型，再填写名称/描述；默认选择视频以兼容现有入口，但提交的数据必须明确带上 `projectType`。切换筛选只改变列表，不复制或移动项目。

### 3. 画布能力按类型收敛

视频作品保持现有剧本、文本、图片、视频、音频节点和视频生产链路，包括视频提示词、时长、运镜、视频模型、视频工具、合成及上传。

漫画作品允许剧本、文本、图片节点；图片节点使用漫画提示词、漫画参考图、画幅和图片模型。漫画作品隐藏并禁止新增视频节点、视频提示词、视频模型、时长、运镜、视频处理、视频合成和视频上传入口。已有异常漫画项目中的视频节点只读展示，不能继续提交视频任务。漫画项目的音频不作为独立创作节点，已有音频节点只读展示。

右键菜单、顶部“新增节点”、节点编辑器、模型选择器和节点快捷工具必须使用同一份类型能力表；不能只通过 CSS 隐藏。服务端生成接口也要校验项目类型，拒绝漫画项目的视频任务，防止绕过前端。

### 4. 数据与资源隔离

项目素材、生成历史和模型选择继续使用项目 ID 作为范围，同时在读取和展示时使用 `projectType` 做能力过滤。漫画项目的图片提示词字段与视频项目的视频提示词字段分开读取；共享的剧本和文本只作为上游内容，不把视频提示词带进漫画图片请求。批量工厂同步到 Agent 时复用已有资产和生成记录，不复制媒体文件。

### 5. 迁移与错误处理

- 不新增破坏性迁移；为项目表增加可回填的类型字段或在现有 JSON/配置存储中加入 `projectType`，按当前仓库的数据存储方式落地。
- 读取到未知类型时回退为视频并记录可读错误，不阻塞旧项目打开。
- 用户在漫画项目中尝试访问被禁用的功能时，界面不显示入口；如果通过旧链接或接口请求，返回明确的“漫画作品不支持视频生成”错误。

## 验收标准

1. 新建项目必须能选择视频或漫画，列表可按类型筛选，项目卡显示类型。
2. 旧项目不丢失，打开后按视频项目兼容。
3. 漫画项目画布不提供视频节点和视频专属输入框/模型/按钮；图片生成仍可选择已启用图片模型并提交漫画提示词。
4. 视频项目现有节点、模型、生成、合成、上传链路不回归。
5. 批量工厂创建的漫画项目进入 Agent 后仍保持漫画能力边界，视频项目保持视频边界。
6. 前端源代码测试覆盖筛选、类型能力表和输入框隐藏；后端测试覆盖创建/读取类型和漫画项目拒绝视频任务。
7. 本机 Go 嵌入运行版本重新构建后，页面和 API 运行版本一致。

## 取舍

采用“项目单一类型”而不是一个项目内再嵌套漫画组/视频组。这样能让模型、提示词和生成状态保持单一语义，避免同一项目中出现相互冲突的输入框；需要两种产物时创建两个作品，素材仍通过现有项目素材库互用能力引用。
