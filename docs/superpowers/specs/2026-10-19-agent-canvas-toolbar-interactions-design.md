# V88 Agent 画布工具与交互设计

日期：2026-10-19
范围：本地 V88 Agent 创作画布，不发布公网

## 1. 目标

在现有 `/agent/canvas` 和 `@xyflow/react` 画布上补齐专业画布操作，同时保留已经存在的 Agent 对话、项目切换、MySQL 画布保存、节点引用和 revision 冲突保护。

本阶段交付以下真实可用能力：

- 节点选择和多选。
- 节点连线与删除连线。
- 画布缩放、适合屏幕和聚焦选中。
- 节点分组和解组。
- 左对齐、水平居中、右对齐、顶对齐、垂直居中、底对齐。
- 水平等距和垂直等距。
- 撤销和重做。
- 自动保存与手动保存。

## 2. 实现选择

继续扩展 `frontend/src/user/components/AgentCanvas.jsx`，不搬入独立 `智能画布` 目录，也不建立第二套画布或第二套数据源。

原因：现有 Agent 画布已经接入项目、节点、边、视图状态和 MySQL revision 保存。增量扩展可以保留当前数据链路，避免再次出现旧入口、旧数据或两套保存逻辑。

## 3. 页面布局

采用已确认的 A 方案：

- 顶部项目栏：项目名称、保存状态、手动保存和对话面板开关。
- 左侧竖向工具栏：选择、拖动画布、添加节点和连线模式。
- 画布顶部中央浮动工具栏：撤销、重做、分组、解组、对齐和等距。
- 画布底部中央缩放栏：缩小、当前比例、放大、适合屏幕和聚焦选中。
- 右侧 Agent 面板：保持当前对话和节点引用能力，可收起释放画布空间。

分组、解组、对齐和等距按钮始终显示。当前选择不满足执行条件时按钮变灰，并通过提示文字说明需要选择几个节点。

桌面端工具栏不得遮住节点主要操作区域；窄屏时顶部浮动工具栏允许横向滚动，右侧 Agent 面板使用现有收起方式，不与底部缩放栏重叠。

## 4. 操作规则

### 4.1 选择与连线

- 单击节点为单选；按住 Shift 单击或框选为多选。
- 连线模式下从节点连接点拖向另一个节点创建边。
- 不允许节点连接到自己。
- 相同来源和目标之间不重复创建同类连接。
- 删除节点时一并删除与它相连的边，并作为一次可撤销操作处理。

### 4.2 分组与解组

- 选择两个或以上节点时可以建立画布分组。
- 分组只改变画布组织关系，不改变业务节点类型、版本或素材引用。
- 拖动分组时成员节点一起移动。
- 解组保留成员节点当前绝对位置。
- 保存时组信息随画布一起进入正式数据源，刷新后能够恢复。

### 4.3 对齐与等距

- 对齐至少需要两个节点。
- 水平或垂直等距至少需要三个节点。
- 对齐以当前选择范围为基准，不移动未选中的节点。
- 每次对齐或等距作为一个历史步骤，撤销一次即可整体恢复。

### 4.4 缩放与视图

- 缩放范围继续使用 25% 到 200%。
- 支持按钮缩放、鼠标滚轮或触控板缩放。
- “适合屏幕”展示全部节点；“聚焦选中”只适配当前选中节点。
- 视图位置和缩放比例继续进入现有画布保存数据。

### 4.5 撤销与重做

- 节点移动、节点新增或删除、边新增或删除、分组、解组、对齐和等距进入历史记录。
- 单纯的选中状态和面板开关不进入历史记录。
- 每个项目维护独立的前端历史，切换项目时清空旧项目历史并以服务端画布作为新基线。
- 快捷键使用 `Ctrl+Z` 撤销、`Ctrl+Shift+Z` 或 `Ctrl+Y` 重做。

### 4.6 保存

- 所有持久化变化继续进入现有串行防抖保存队列。
- 自动保存状态显示“未保存、正在保存、已保存、保存冲突、保存失败”。
- 手动保存立即刷新保存队列，不建立第二套保存接口。
- 服务端返回 409 时继续以服务端画布为准重新加载，不能静默覆盖较新的 revision。
- 保存失败时保留当前页面内容和明确的重试入口。

## 5. 组件边界

- `AgentCanvas.jsx`：React Flow 实例、节点和边交互、选择状态、视图控制。
- 新的画布命令模块：分组、解组、对齐、等距、历史记录和命令可用性判断，使用可单测的纯函数。
- `AgentPageV2.jsx`：项目、保存队列、手动保存状态和右侧 Agent 面板。
- `agent-workspace.css`：浮动工具栏、稳定尺寸、按钮状态和响应式布局。
- Go Agent API：给画布节点增加可选 `groupId`，沿用现有画布读写接口；不建立独立接口或旧文件写入路径。

## 6. 数据兼容

- 现有没有 `groupId` 的画布节点按未分组读取。
- 节点新增可选 `groupId` 字段，旧项目无需补数据即可继续打开。
- 保存仍使用现有 `version`、`revision`、`nodes`、`edges` 和 `viewport` 结构。
- Go 节点类型和 `agent_canvas_nodes` 使用同一个可选分组编号；画布背景分组框由成员节点位置计算，本阶段不支持分组改名。
- `groupId` 通过实施时高于现有最大编号的全新幂等迁移追加到节点表。
- 不修改、删除或伪造任何已执行 MySQL 迁移记录。

## 7. 错误与边界处理

- 不满足操作条件的命令保持不可点击，避免执行后无反馈。
- 已删除或不存在的节点不能参与分组、对齐或连线。
- 读取到无效组成员时忽略无效成员，其他节点仍可显示。
- 画布保存冲突、网络失败和服务端失败必须显示不同状态。
- 用户切换项目时，旧项目仍在保存中的请求不得覆盖新项目画布。

## 8. 测试与验收

开发必须先写失败测试，再写实现。

自动测试覆盖：

- 命令启用和禁用条件。
- 六种对齐、两种等距以及分组和解组结果。
- 历史记录撤销和重做，选择变化不进入历史。
- 自连接和重复边被拒绝。
- 手动保存复用现有保存队列。
- 项目切换、revision 冲突和保存失败不会丢失或串写数据。
- 桌面和窄屏布局存在稳定的工具栏区域，不遮挡 Agent 输入区。

本地已登录浏览器验收覆盖：

1. 新建或打开一个真实 Agent 项目。
2. 创建并连接至少三个节点。
3. 多选节点执行分组、对齐、等距，再逐步撤销和重做。
4. 修改缩放和视图，刷新页面后确认恢复。
5. 收起和打开右侧 Agent 面板，确认工具栏和节点不重叠。
6. 等待自动保存并点击手动保存，确认状态和 MySQL 数据一致。

不能把静态按钮、前端构建成功、HTTP 200 或未登录页面当成完成证据。

## 9. 本阶段不做

- 不在本阶段加入 AI 图片生成、AI 视频生成、豆包自动化或声音视频工具。
- 不复制沈浪品牌、Logo、安装包资产或私有代码。
- 不清理现有工作区，不回退其他功能改动。
- 不发布公网，不恢复 Node 发布链，不使用 GitHub Actions 部署。
