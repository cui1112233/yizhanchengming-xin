# 批量测书第一批：规则与知识库一致性

日期：2026-11-15。状态：路线已确认；本详细规格待用户审阅。此文件不表示功能已经实施或上线。

## 目标和范围

用户在页面上保存的规则，必须与刷新后显示、摘要统计、规则预览、原文处理、AI 文案处理所使用的规则一致。先处理这条基础链，再继续原系统 34 项行为的全量验收。

依据：`docs/audit/2026-11-15-batch-book-parity-reassessment.md`、`docs/requirements/batch-book-reference/behavior-spec.md`。原包源码位置和 SHA256 沿用参照目录；用户后来确认的需求优先于原包默认行为。

本批不改定时调度、作品生成、提交策略或删除作品，不新建执行器。摘要加载完整正文的问题留在下一批。沿用现有 Go、React、MySQL、Redis 与 Go embed 发布路径，保持 v88 分支，不迁移目录和基础设施。

## 一、写入用户提供的替换清单

用户于本轮明确纠正：`原词&&替换词` 只是告诉代理如何理解清单，要求把对应关系写进现有规则库，不是要求页面支持新的导入语法。本批取消增加 && 解析、导入预览和新导入交互的计划，不因该清单扩展产品功能。

只按清单更新当前 TextLayoutToolAI敏感词库中同名规则，没有同名项才追加；保留其他词组、顺序、适用范围和额外字段。保留给定字形，不擅自修改同音字、斜线或替换内容。右侧为空表示明确删除。

已有写入记录：清单共 182 对，其中 12 对为空替换；更新已有 72 个原词并新增 110 个原词，总条目从 862 变为 972。2026-11-15 本轮重新核对此前接口写后读回保存的 sensitive-after.json，182 对全部匹配。该文件是此前写入验收证据，不冒充当前运行版的实时配置。

验收重点为保存结果、刷新后保留及原文/AI 实际处理，不增加清单未要求的导入功能。

## 二、明确留空表示删除

输入分三类：没有提供替换值、明确设置非空替换值、明确设置空字符串。页面编辑替换框或带分隔符导入时，统一写入后端已有的明确设置标记；仅修改启用开关等其他字段不能改变替换含义。

明确空字符串表示删去命中原词，保存、补默认值、重启和重新读取后都必须仍为空。仅缺省的历史数据允许使用已有默认补值逻辑。不得把“明确原词替换成自己”当成坏配置偷偷改写。

所有规则继续遵守词组启用状态以及“处理原文 / 处理 AI”开关。原始全文保持原样；删除发生在相应处理结果中。

验收：`甲代孕乙` 搭配明确空替换后，原文和 AI 范围输出都为 `甲乙`；关闭相应范围时输出原文。页面保存→读取→预览→处理必须覆盖同一用例。

## 三、统一数据读取与统计

在现有 novelfetchworkshop 模块内形成共用的规则读取与规范化逻辑，不另建配置服务。`knowledgeLibraries.sensitive` 为规范化敏感规则来源，现有兼容字段只作为旧配置迁移输入及兼容输出。

配置已明确存在规范来源时，包括空 groups 或已停用词组，不能再拼接旧 layout_rules 中的敏感词把它们重新启用。只有规范字段缺失时才按已明确记录的旧字段来源迁移，迁移结果用于显示、统计、预览和执行。旧版本来源冲突必须报告，不任意合并用户数据。

配置保存仍使用现有 configRevision 检查及持久化流程，只更新本次提交的类型。并发版本冲突时拒绝覆盖，提示“配置已在其他页面更新，请重新读取后再保存”，保留当前未保存输入。

摘要数量定义为所有词组中的实际规则条目总数，包含停用项，与编辑器逐组数量相加一致；执行时另按启用和适用范围筛选。保留已有重复条目时统计实际条目，不以去重数冒充条目数。

兼容输出由规范数据派生；读取、预览和统计不触发隐藏的持久化写入。错误配置返回明确原因，不能返回空规则伪装正常。

## 四、乱码检查与恢复

不把正常的问号、替换删除或用户自定义内容直接当成乱码。只对有可信原始资料可对照的导入条目提出恢复候选。

候选要求：类型正确，记录 ID 唯一且一致，字符长度相同，所有保留字符与原文相同，每个差异只能是问号或 Unicode 替换字符对应原始非 ASCII 字符。按 ID 匹配记录，禁止按当前列表位置覆盖。重复 ID、用户改写、来源无法确认的记录不自动恢复。

source=go 不足以证明资料是用户新建，也不足以证明它来自原包。需结合可信导入记录及上述逐字段核对判断；证据不足只列候选和跳过原因。不能全局删除现有来源保护。

恢复流程继续使用现有 Go 恢复入口：先只读预览→显示将改的资料、字段和跳过原因→用户明确应用→校验 configRevision→备份本次受影响资料→保存→读取核对。每次应用保留独立恢复记录，不覆盖第一次备份，也不把密钥或完整用户配置写入备份。

普通读取不自动修复；不会为了修复而调用收费模型。没有可信原文时明确提示“缺少可核对原文，未修改”。写入失败不得返回成功，重复应用已经完成的恢复应报告无需修改。

本批只能避免错误修复和把损坏资料当作正常资料使用；最初中文变成问号的写入来源仍需单独调查，不能宣称已确定或彻底消除。

## 五、运行版本识别

本地验收必须能读到构建的源码 SHA、嵌入页面入口及构建清单信息。缺失时显示“版本信息缺失，尚不能确认当前运行版”，不伪造 SHA。

沿用现有构建清单、runtime-build-info 和本地启动脚本补全传递关系；改动前核对监听进程路径和当前任务，避免误停其他程序。源码、前端资源、Go 二进制必须来自同一次记录清楚的构建；无关脏改动不能静默混入发布。

先在本地 4001 验收。未经本地验收的程序不发布；本批不自动续跑历史任务、不调用生成模型、不触发作品上传。正式上线另按已授权的发布范围执行。

## 六、验收与完成条件

1. 先写能重现缺陷的测试，再修改对应代码；不以仅检查源码字符串存在代替处理结果。
2. 核对用户给出的 182 对替换关系及 12 处明确删除，保证重复应用不反复追加；不新增 && 导入格式或相应产品交互。
3. 规则覆盖页面编辑→接口保存→存储读取→摘要→预览→原文和 AI 处理。验证其他词组、开关、自定义字段和原始全文不变。
4. 迁移覆盖规范字段缺失、明确空配置、停用词组、旧副本非空及多来源冲突；读取与预览不得写入配置。
5. 恢复覆盖只读预览不变性、ID 重排、重复 ID、外来来源、自定义内容、正常问号、版本冲突、备份范围和重复应用。
6. 先跑相关 Go 与前端处理测试，再构建嵌入页面和 Go 程序；最后使用本地真实登录页面完成新增、修改、保存、刷新和预览的操作验证。
7. 完成报告分开列源码通过、当前运行版通过和真实外部链路通过；本批没有真实外部执行，不填成成功。
