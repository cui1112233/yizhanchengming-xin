# AI-CUT 创作画布与剪辑分工

用户已在本轮“执行”批准上一轮提出的分工：Agent 剪已有素材；画布准备故事、分镜、角色和生成素材，再送去剪辑。沿用已有 AgentCanvas 与 Go/数据库服务，避免另造无法生成的节点演示。

创作画布嵌入真实 AgentCanvas，每个 AI-CUT 工程对应一个服务端持久化创作项目。支持节点添加、拖动、连线、文本/剧本/图片/视频/音频编辑、现有生成流程、故事与角色/场景/道具卡模板。卡片通过现有文本节点的名称、正文及连线复用引用机制，不假称已新增独立生成引擎。

画布工具条明确“准备素材”，剪辑 Agent 明确“剪已有素材”。画布移除四步空引导及重复嵌入剪辑 Agent。通过“送入剪辑”面板选择画布素材，后端按当前用户和对应创作项目验证真实资源，复制到当前剪辑素材库；重复送入复用稳定标识，不重复复制。完成后进入专业剪辑并可打开现有自动成片审核流程。不会直接覆盖时间线。

持久化由既有 MySQL AgentWorkspace 承担。绑定项目采用后端稳定派生 ID，不由浏览器自由指定其他项目。保存使用现有 revision 冲突检查、保存队列和本地草稿恢复；切换工程避免旧异步结果写入新工程。生成、导入失败明确展示原因，不把失败当成功；收费生成仅由用户点击提交，本轮不调用真实付费供应商。

验收：真实节点可新增、移动、连接，刷新仍在；图片等资源真实送入目标素材库、可读取内容，重复送入不重复；其他用户和其他创作项目不能越权；画布与专业剪辑切换保留工程，Agent 入口仍能使用。React 与 Go embed 构建、本地 4001 页面验收。保留其他任务改动，不创建分支、不推送、不公开部署。
