# 小说获取功能闭环补齐设计

日期：2026-10-20

## 目标

在不改变现有小说获取五个一级页面、地址和主视觉的前提下，补齐对照工具已经具备、但本地缺失或未完整展示的业务闭环。

一级页面保持不变：处理、任务、知识库、配置、提交与记录。知识库内的处理规则、提交与记录内的操作日志继续作为二级工作页；二级页要有独立地址状态、返回处理页入口、加载状态和保存结果，不能只是临时弹窗。

本次不复制对照工具的实现，不接回 Node 发布链。后端继续使用 Go；任务和配置落在现有 MySQL 数据结构；队列、去重和锁继续使用 Redis；前端继续使用 React 与 Ant Design；前端构建物继续由 Go embed 打入单一应用二进制。

## 现状与边界

已有 Go 能力包括：Redis 队列、五秒定时调度、任务运行记录、任务级日志、规则处理、敏感词 AI 修复、自动提交、网站提交预览与结果回读。设计优先补齐前端入口、接口返回字段和持久化配置，而不是用假状态或浏览器端定时器模拟。

不在本次范围：更换现有五页的信息架构；导入或覆盖用户知识库数据；直接保存外部站点账号密码；用页面成功提示代替外站实际提交结果。

## 页面设计

### 处理页

保留现有批量输入区，新增输入格式选择和列顺序预设：智能识别、表头识别、多表头识别、固定列顺序、自定义列顺序、书城 ID 抓取。每一行解析后必须回显平台、书籍 ID、书名、男女频和错误原因；不合法行不能静默丢弃。

定时任务从单一启动入口补齐为可管理列表：计划时间、任务数量、选中文本模型、处理版本、自动提交开关、状态、最近一次运行结果。用户可以查看、取消和删除尚未执行的计划；已运行记录只能查看，不能伪装为可编辑。

当前批次继续显示队列和实时日志，但日志按书籍聚合展示，并能跳转到任务详情。单书详情必须展示分类模型、原文抓取、规则追踪、敏感词命中和修复、AI 版本、改文方案、开头词、高仿参考、提交结果和可重试原因。

### 任务页

任务表补充来源解析方式、推送时间、原文处理状态、各 AI 版本状态、每版本提交状态、敏感词命中/修复数、下一次抓取时间和明确的失败阶段。

补齐批量操作：调整选中任务、调整待处理任务、重试选中、规则处理选中、规则处理全部、删除选中、删除失败。每个会产生外部提交或数据修改的操作必须在执行前展示影响数量；任务完成只表示处理链完成，未提交版本必须显示为未提交，不能与完成混淆。

自动队列状态使用后端 Redis 队列和运行注册表的真实数据，显示已开启/暂停、当前运行任务、处理中数量、排队数量、等待重试数量、最近任务和刷新时间。空队列时停止派发；新任务进入后恢复派发；抓取为空或失败时按配置保留下一次抓取时间。

### 知识库与处理规则

知识库现有资料库、爆款开头拆解和处理规则结构保持不变。处理规则二级页补齐敏感词 AI 参数：整组一次发送或逐条并发、逐条并发数、每任务最大命中数、AI 修复重试次数、命中句前后扩展字数、修复温度和独立提示词。

词组继续支持启用、处理原文、处理 AI 文案和规则替换。关闭 AI 修复或 AI 修复失败时才使用配置的直接替换；每次处理把命中词、上下文、修复前后文本和实际使用的模式写入任务规则追踪，供任务详情和日志页读取。

知识库数量取当前账号实际配置，不用对照工具的数量覆盖本地。资料加载失败需要显示读取错误，禁止将空结果保存回知识库。

### 配置页

保留当前分组，补齐自动处理配置、AI 接口参数、模型职责和版本配置档。

自动处理配置增加抓取并发、重试、超时、失败重试间隔、自动提交批次大小和最大等待时间。AI 接口配置支持受保护的 API 地址、模型、超时、最大并发、重试、输出参数、流式/JSON/思考开关和测试结果；密钥只能由后端保存和掩码返回。

版本配置档支持原文与 AI1-AI5 分别跟随默认配置档或绑定特定配置档。保存前校验选中的版本和配置档存在；提交时将实际使用的配置档写入每个版本的提交记录。

### 提交与记录

保留提交准备、本次结果、提交历史、操作日志四个二级页。补齐提交环境字段：后台/可视化执行模式、浏览器路径、Python 路径、并发组数、最小文件字节、重试次数和跳过已提交。

环境检测、登录验证、同步配置档、同步组织归属、同步网站风格、预览和提交使用真实后端接口。预览必须只读；提交完成后按任务、版本和上传组记录成功、失败、未知结果、可重试和外部运行 ID。未知结果只能先回读确认，不能直接二次上传。

操作日志二级页按运行 ID、任务 ID、书籍 ID、阶段和时间筛选，覆盖抓取、规则、AI、提交、重试和回读。日志不足时明确显示缺失原因，不显示伪造的成功状态。

## 数据与接口

现有任务文档扩展为稳定的阶段状态：`classify`、`original`、`rules`、`sensitive`、`rewrite`、`submit`。每个阶段存状态、开始结束时间、尝试次数、错误码、可重试时间和简短可读说明。

配置按账号隔离保存。敏感词 AI 参数、输入预设、调度选项、提交环境和版本配置档写入同一份受版本保护的小说获取配置；保存时做字段校验，读取时返回掩码后的敏感字段。

Redis 仅负责排队、租约、去重和取消标记。MySQL 保存任务、批次、计划、配置和可查询日志。任务执行器在取得 Redis 租约后更新 MySQL 状态，结束时确认或失败回队；避免页面刷新导致任务重复执行。

## 错误处理

- 解析失败：保留原始输入行和具体列错误。
- 抓取为空：记录为空原因和下次重试时间，不生成空 AI 文案或提交任务。
- AI 或敏感词修复失败：保存原始处理结果、错误和重试策略；不覆盖原文。
- 提交失败或未知：逐版本保存失败原因和运行 ID；已确认提交的版本不再次上传。
- 权限不足：仅管理员可查看其组员，开发者可查看全部账号；页面和接口同时校验。

## 验收与测试

Go 测试覆盖输入解析、计划 CRUD/调度、队列停启和去重、阶段状态、敏感词整组/逐条模式、版本配置档映射、提交预览、未知提交回读和日志筛选。

React 测试覆盖五页路由、二级页返回、配置加载失败、空知识库保护、任务状态与提交状态区分、批量操作影响数量、主题切换和窄屏布局。

浏览器验收用已登录账号完成：创建混合输入批次、创建/取消计划、观察自动队列、查看单书追踪、修改并预览规则、保存版本映射、生成提交预览、执行一次可控提交或验证失败路径，并核对任务页与操作日志的同一运行 ID。

## 交付顺序

1. 先补处理页输入/定时和任务状态模型，保证任务链真实可追踪。
2. 再补任务批量操作与详情，保证失败可查、可重试。
3. 补规则参数和追踪，保证敏感词行为可解释。
4. 补配置与版本映射，保证选择值和生效值一致。
5. 最后补提交环境、逐版本提交记录和操作日志，并执行端到端验收。
