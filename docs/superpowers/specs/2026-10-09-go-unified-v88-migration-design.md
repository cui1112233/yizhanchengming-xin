# V88 公网功能统一 Go 迁移设计

## 目标

以 V88 公网为用户可见行为和视觉规格，把功能完整迁入本仓库，同时收敛为一套可维护的实现：Go 是唯一生产后端语言；用户前台和管理后台都使用 React + Ant Design；最终由一个包含前端静态资源的 Go 二进制运行。

这不是把旧 Node 文件逐行翻译成 Go。迁移必须保留真实用户流程、权限、数据归属和失败语义，删除重复的调用链、浏览器事实存储和旧生产依赖。

## 已确认约束

- 只维护 `main` 作为发布主线；不以长期功能分支承载迁移。
- 不创建、修改或触发 `.github/workflows`、GitHub Actions，也不把它们作为构建或发布路径。
- 未得到单独授权前，不连接、不修改、不部署公网。
- 旧 Node 生产实现仅在替代链路已验收后删除；不得无证据覆盖或删除仍可能承担数据迁移、恢复或线上依赖的内容。
- V88 公网是视觉和行为规格；旧源码仅为实现语义参考，不能直接复制其 hash 构建产物、认证材料或运行时状态。
- 旧功能源码以 `cui1112233/-` 的干净 `origin/v88` 为依据；新系统只进入 `yizhanchengming-xin/main`，不合并旧仓库历史，也不延续 V11/V12 并行分支。
- Agent 本轮只保留 `/agent` 与 `/agent/canvas` 的产品位置和安全占位，不继续迁移或将现有实现认定为完成；后续另行重新设计。
- 用户前台不提供 `/issues`，第一阶段管理后台也不提供错误日志 UI。系统仍保留结构化服务日志、请求编号、健康检查和项目任务失败事实。

## 架构

```text
前台 React + Ant Design ─┐
                         ├─ 统一 API 客户端 ── Go api/ ── MySQL
后台 React + Ant Design ─┘                       ├── Redis
                                                 ├── TOS
                                                 └── 外部 Provider / 本地执行器

前台、后台构建物 ── Go embed ── 单个 Go 二进制
```

### 固定职责

|边界|职责|禁止事项|
|---|---|---|
|`api/`|认证、授权、业务服务、HTTP handler、任务运行时、migration、TOS、Provider 适配、prompt、embed。|Node 生产后端、第二套认证/队列/Worker、将业务事实放入进程内存。|
|`前台/`|用户工作区页面、共享用户外壳、统一请求封装、AntD 组件。|页面自行拼请求、直接调用 Provider、保存业务事实或密钥。|
|`后台/`|管理页面、统一请求封装、AntD 数据/运营界面。|普通用户权限绕过、独立 auth/token 机制。|
|MySQL|用户/团队、项目、任务状态机、历史、设置、媒体元数据、权限归属和审计的事实源。|明文密码、Provider 密钥、可恢复任务仅存 Redis。|
|Redis|待执行队列、租约、分布式锁、短期缓存和协调状态。|唯一业务事实源、无法从 MySQL 恢复的任务记录。|
|TOS|经授权的真实图片、音频、视频对象。|脱离 MySQL 归属/访问校验的业务索引。|

账号密码只以安全哈希方式存储；Session、Cookie、MFA secret、恢复码和 Provider 密钥永不回显到前端。所有写请求继续使用 Cookie Session、同源 CSRF、capability 与项目归属校验。

## 统一调用与提示词规则

前台和后台分别只能有一个受控 API 客户端入口。页面通过该入口获得认证处理、CSRF、统一错误结构、请求编号和重试提示；业务组件不得直接 `fetch` 不同风格的接口。

系统预设提示词保存在 `api/internal/prompt/`（及其受控持久化/版本机制）。后端替换变量并向前端返回必要的安全视图；前端不硬编码完整系统提示词、模型密钥或 Provider 配置。

统一调用链为：

```text
React 页面 → 前端 API 模块 → Go handler/service → MySQL / Redis / TOS / Provider
```

“统一”指合同、错误和权限规则统一，不是把所有业务写成一个巨型 Go 文件。认证、项目、历史、媒体、批量生产、提示词和管理能力保持小而清晰的模块边界。

## 视觉系统

公网是唯一视觉规格：Sidebar、Header、主题切换、用户菜单、卡片、间距、按钮、抽屉、空态、加载态和响应式布局逐页对齐。

- 前台和后台共享主题 token、颜色、字号、字重、行高、图标和基础控件规范；后台仅可调整表格信息密度。
- 先从公网实际 CSS/计算样式核验字体栈。存在许可明确的字体文件才作为受控静态资产迁入；否则保持同等系统字体栈，绝不从压缩 bundle 猜测或抽取字体。
- 授权且可追溯的品牌图和首页视频可在审查后作为静态资源迁入；旧 hash `dist/assets`、用户头像、项目媒体、Provider 资源均不可复制。
- 旧 CSS 只能按页面或 `.user-shell`/组件根节点隔离提取，以 AntD token/局部覆盖落地；禁止整份全局 CSS 造成路由污染。

## 分阶段迁移

### 第一阶段：统一底座

完成统一认证/权限、前后台 API 客户端、MySQL migration 模式、Redis 任务协调、TOS 归属、prompt 模块、错误格式、Go embed 和共享主题/字体 token。

### 第二阶段：全局外壳与首页

恢复公网用户 Sidebar、Header、主题、用户菜单、移动端折叠和首页 Hero/入口。首页只能显示 MySQL 事实投影出的最近项目/创作，不能写假卡片。

### 第三阶段：用户工作流

按独立事实源完成小说获取、改文工作台、剧本、小说面板、批量工厂、水货生产与 TTS。每页先完成真实数据、权限、空/加载/错误/恢复，再迁移视觉。

特别约束：`/novel-fetch`、`/batch-factory`、`/shuihuo-production` 必须是三条独立路由和工作流，不得继续共用单一 `IntakeWorkbench` 页面。

Agent 不进入本阶段的功能迁移或验收清单。其路由只显示明确的“待重新设计”状态；已经存在的 Go/React 实现先隔离保留，待后续设计决定复用或删除，避免提前制造不可恢复的数据或代码损失。

### 第四阶段：账户与运营

完成历史、设置、个人中心、成员/团队和管理后台。管理后台是 capability 隔离的运营面，不得作为普通用户页面暴露。

用户导航和路由中删除“问题日志”。业务任务失败仍在所属项目或任务页面展示；普通请求故障只显示脱敏错误、`request_id` 和允许的重试动作。第一阶段不建设管理后台错误日志页面，避免重复建设专业日志系统。

### 第五阶段：真实链路验收与清理

逐项验收 Provider、执行器、TOS 媒体上传与读回、任务恢复、无权限、刷新恢复和真实失败态。Provider 或执行器未配置时必须返回真实安全的 `executor_unavailable`/未配置状态，绝不伪造成功。完成替代证据后，才移除旧 Node 生产依赖和未引用代码。

## 数据、错误与恢复

- 每条项目、历史、设置、任务、媒体记录都有用户/团队归属；所有读取和写入都在 Go 层校验 capability 与项目访问权。
- MySQL 保存任务状态、尝试、审计和恢复依据；Redis lease/lock 超时后以 MySQL 事实恢复或重新调度，避免重复执行。
- 普通用户只看到脱敏错误摘要、请求编号和允许的重试动作。完整堆栈、Provider 原文和安全材料只进入访问受控、具有保留期的结构化日志，不写入用户页面。
- 结构化日志写入独立日志目录或未来的专业采集系统；不得保存密码、Cookie、Token、MFA、完整系统提示词或 Provider 密钥。MySQL 只保存属于业务事实的任务失败状态和安全摘要，不承担通用日志仓库职责。
- 刷新后项目、任务、历史和服务端设置从 MySQL/Redis 恢复。浏览器本地存储仅能保存深浅主题、侧栏折叠等非敏感 UI 偏好。

## 验收与删除门槛

每个迁移模块必须有相称的 Go 测试、前端测试、构建测试及本机 Go embed 浏览器验收。每页至少验证：路由、真实数据、按钮 API、loading、空态、错误、401/403、刷新恢复、用户/团队隔离和无 Provider 时的安全失败。Agent 占位页只验收路由和说明，不计入业务功能完成率。

删除旧实现前必须同时满足：

1. 新 Go API 已覆盖其业务合同并具有权限测试；
2. MySQL 数据迁移/读取已覆盖存量事实，且恢复语义明确；
3. 前台或后台已改用新统一 API 客户端；
4. 测试、构建和本机 embed 验收通过；
5. 真实失败、刷新恢复和无权限场景已验证，且无公网/迁移/恢复依赖残留。

## 范围外与后续授权

本设计不授权公网部署、ECS 连接、GitHub Actions、付费 Provider 调用或删除数据。它定义后续计划和实现所需的边界；每一阶段仍需在最新 `main` 上核对公网规格、当前实现和数据库事实源。Agent 重新设计、用户问题日志页面和管理后台错误日志 UI 均不属于本轮范围。
