# 本地最新版运行收口设计

## 目标

本地 `http://localhost:4001` 只运行 `v88` 当前源码构建出的 Go 程序和前端页面。旧页面、旧程序、日志和临时文件安全保留，但不能被启动器或浏览器路径使用。

## 唯一正式运行链路

```text
frontend/src + backend 源码
  → 前端构建 frontend/dist
  → 复制到 backend/web/dist
  → 构建 backend/qiantie-local.exe
  → start-local-go-review.ps1 启动 4001
```

运行页面必须能同时标识当前 Git SHA 和前端构建标识。任何一环缺失、过期或不匹配时，启动应停止并给出错误，不能回退到旧构建。

## 处理原则

1. `v88` 是唯一可维护分支；不创建新的长期分支或运行入口。
2. 只允许编辑 `frontend/src`、`backend` 源码和正式脚本；`frontend/dist`、`backend/web/dist`、本地 exe、日志、缓存和运行数据是生成物或运行物。
3. 启动脚本先清理并重新生成嵌入资源，再编译 Go 程序；禁止复用来源不明的旧产物。
4. `batch-rewrite` 等历史页面即使作为参考留在磁盘，也必须在构建与嵌入阶段排除，并继续由服务端拒绝访问。
5. 每次启动写入一个忽略的运行清单，记录源码 SHA、前端入口脚本、二进制时间和构建时间；运行时 API 与前端读取同一清单。
6. 当浏览器仍持有旧入口脚本时，入口 HTML 不可缓存；前端检测到与 API 不同的构建标识时只显示“版本已更新，请刷新”，不得继续展示旧工作台。
7. 旧文件安全保留在忽略目录，不删除、不作为构建输入、不作为启动候选。

## 验收

1. 清理后重新启动 4001，`/api/runtime-build-info` 的 SHA 与当前 `v88` HEAD 一致。
2. `/shuihuo-production` 的入口脚本来自刚构建的哈希文件。
3. 新标签页与已有标签页均不能再进入旧 `batch-rewrite` 或出现“分镜资产”表头。
4. 构建失败时启动脚本退出并显示失败原因，不启动已有旧二进制。
5. 生成物、日志、运行状态不再污染 Git 状态；真实源码改动仍可被清晰识别。
