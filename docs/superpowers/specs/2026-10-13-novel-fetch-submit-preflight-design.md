# 小说获取网站提交预检与失败日志设计

## 目标

让小说获取任务在提交到视频管理系统前，对缺失的上传分类信息给出明确、可追溯的错误；每次提交失败均能在“提交日志”中查看，避免用户只看到“失败：AI1”却没有原因。

## 已确认问题

测试任务 `2091926811672429633` 已完成原文抓取、分类和 AI1 改文，但 `style` 为“待判定”。Go 提交接口会在组装上传字段时拒绝无法映射为视频管理系统风格 ID 的值，记录失败版本却不追加 `site_submit` 日志。因此任务列表显示“失败：AI1”，提交日志为空，用户无法判断是否请求过外部平台。

## 方案

### 1. 在预览阶段返回明确的不可提交项

`POST /api/batch-rewrite/web-submit/preview` 遍历选中任务和版本时：

- 保留已提交、正文缺失等现有跳过逻辑。
- 对风格为空、“待判定”或“未判定”的任务，将该版本加入 `skipped`，状态为 `blocked`。
- 错误文案固定为：`该任务尚未识别或选择上传风格，无法提交到视频管理系统。`
- 不创建上传请求，也不修改已提交记录。

前端预览界面将该项显示为不可提交原因，用户在点击确认提交前即可知道缺少风格。

### 2. 提交阶段持久化每次结果

`POST /api/web-submit/submit` 与别名 `/api/batch-rewrite/web-submit/submit` 对每一个版本写入一条任务日志：

- 事件：`site_submit`。
- 字段：版本、状态、错误信息、发生时间、是否已经向外部平台发出 HTTP 请求。
- 本地预检失败（缺风格、缺正文、字段组装失败）：`externalRequested=false`。
- 请求创建、网络错误或外部响应错误：`externalRequested=true`（请求创建失败除外）。
- 成功提交：写入已确认成功的版本状态，与现有 `siteSubmitDoneVersions` 语义保持一致。

任务元数据中的 `siteSubmitFailedVersions` 和 `siteSubmitFailedErrors` 继续作为列表展示来源；日志成为详情和历史记录的事实来源。

### 3. 失败信息保持一致

所有本地预检失败都通过统一的失败记录函数写入：

- 任务列表显示 `失败：AI1`；
- 任务详情显示完整错误；
- 提交日志显示同一错误、版本和时间；
- 文案明确说明未向外部平台发起上传。

不自动猜测或擅自替换用户选择的上传风格。风格仍应由既有分类流程或用户配置获得。

## 测试

新增或扩展 Go HTTP API 测试，覆盖：

1. 提交预览遇到“待判定”风格时返回 `blocked` 条目和指定错误文案。
2. 提交遇到“待判定”风格时：
   - 返回失败结果；
   - `siteSubmitFailedVersions` 包含 `ai1`；
   - 文档日志增加 `site_submit` 事件；
   - 日志标记未发起外部请求。
3. 已有有效风格、正文缺失的场景也写入失败日志。
4. 现有成功/跳过语义保持不变。

## 非目标

- 不改变 121 登录、Cookie 管理或外部上传协议。
- 不自动上传测试任务。
- 不重新设计网站提交页面。
- 不提交、删除或修改现有无关任务和构建产物。
