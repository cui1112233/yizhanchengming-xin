# 小说获取配置页布局整理设计

## 目标

解决配置页中间表单过长、左右栏过早结束、页面下半部大量留白的问题。在不删除任何配置项、不改变字段路径和保存行为的前提下，让配置项按使用目的分组，并保持深色、浅色主题一致。

## 页面结构

配置页继续使用三栏工作区：左侧为配置分组，中间为当前分组表单，右侧为“当前选择 / 已生效”摘要。

左侧新增“提示词配置”分组，说明文字为“改文、规则和知识库提示词”。分组顺序为：

1. 工作流与原文抓取
2. 提示词配置
3. 补充设置
4. AI 接口参数
5. 平台与风格目录
6. 版本配置档

“工作流与原文抓取”只保留原文接口、抓取参数、改文基础参数和自动处理选项。“提示词配置”承载三个已有长文本字段：

- `rewrite.prompt`
- `rewrite.processing_rule_prompt`
- `knowledge.usage_prompt`

字段名称、表单绑定、加载值、脏状态判断和保存数据结构保持不变。

## 交互与视觉

点击左侧“提示词配置”后，只显示三个提示词编辑区。编辑区采用统一的纵向间距，并给输入框稳定的可编辑高度，不在工作流页继续占用纵向空间。

左侧导航和右侧摘要在桌面宽度下保持吸顶。用户滚动较长配置时，仍可切换分组并对照当前选择与已生效值。窄屏下恢复单列流式布局，导航和摘要不吸顶，避免遮挡内容。

所有颜色继续使用现有主题变量，不新增固定的浅色背景或深色文字，因此切换深色、浅色主题时跟随应用主题。

## 数据与错误边界

本次不改 Go 接口、不改 MySQL 配置结构、不改表单提交方法，也不引入新的本地存储。分组切换仅改变可见区域，未保存内容继续保留在同一个 Ant Design Form 实例中。

已有的“有未保存修改 / 配置已同步”状态继续工作。保存失败、加载失败等行为沿用现有页面逻辑，不在本次布局调整中扩展。

## 验收标准

- 左侧存在“提示词配置”分组。
- 三个提示词字段只出现在该分组，不再拉长“工作流与原文抓取”。
- 字段路径和保存数据结构保持原样。
- 桌面端左右栏吸顶，窄屏下三栏正确转为单列。
- 深色和浅色主题下文字、边框、输入框均清晰，无固定颜色冲突。
- 分组切换、编辑、未保存提示和保存按钮正常。
- 配置页相关测试、完整前端测试和前端构建通过。
- 本地 Go 嵌入版更新后，在 `http://localhost:4001/novel-fetch?tab=config` 完成真实页面检查，且控制台无新增错误。

## 不在本次范围

- 不修改提示词内容或默认值。
- 不增加提示词版本管理、预览或 AI 生成能力。
- 不调整其他小说获取子页面。
- 不发布公网。
