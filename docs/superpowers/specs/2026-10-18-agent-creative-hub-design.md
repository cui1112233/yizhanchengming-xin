# V88 Agent 智能创作中枢设计

日期：2026-10-18  
状态：设计已确认，等待用户审阅正式文档  
实施范围：本地 V88，不发布公网

## 1. 目标

把现有 Agent 工作区升级为面向小说视频生产的智能创作中枢。

核心体验参考 Lovart 的工作方式，但不复制其电商设计业务：

- 中央是可以缩放、拖动和选择内容的无限画布。
- 右侧是持续存在、可以收起的 Agent 对话区。
- 小说分析、剧本、人物、场景、道具、分镜、TTS、图片、视频、完整成片和上传结果都直接显示在画布上。
- 用户可以选中任意结果，用自然语言要求 Agent 修改、重做、继续生成或删除。
- Agent 能调用 V88 已有生产能力真正执行任务，不只提供说明或跳转链接。
- 用户明确要求全自动时，Agent 可以连续完成整条生产链。

最终成功标准是：用户只通过聊天，就能从一本小说开始，完成分析、资产、分镜、配音、视频、合成和上传；中间结果始终可见、可选、可改、可恢复。

## 2. 已确认的产品规则

### 2.1 执行方式由用户原话决定

- 用户说“做这本书”时，使用监督模式。
- 监督模式自动推进流程，但在人物资产、剧本等关键阶段展示结果并等待用户反馈。
- 用户说“全自动完成这本书”时，连续完成生产步骤，不逐项等待。
- 用户只要求修改某个人物、某个分镜或某段视频时，只修改目标以及真正受影响的下游内容。
- 用户表达不清楚、缺少必需设置或存在多种合理理解时，Agent 直接提一个清楚的问题，不擅自猜测。

### 2.2 上传必须来自明确意图

- “全自动”默认执行到完整合成视频。
- 只有用户明确说“上传”“提交视频管理系统”或“全自动并上传”时，Agent 才允许执行上传。
- 上传使用当前有效的小说 ID、编辑内容和版本数据。
- 上传前必须展示将要上传的视频数量、版本名称、小说 ID 和正文来源。

### 2.3 删除永远需要确认

- 删除项目、节点、素材、生成结果、执行记录或历史版本前都弹出确认框。
- 确认框必须说明具体删除对象以及会受影响的下游内容。
- Agent 在聊天中收到删除指令后，只能生成待确认操作，不能直接永久删除。
- 本设计不引入不经确认的自动清理。

### 2.4 用户编辑内容是新的事实来源

- 用户编辑过的正文、剧本、提示词、资产说明、分镜或上传文案保存为新版本。
- 后续任务读取当前有效版本，而不是回到旧生成内容。
- 修改时保留用户没有要求改变的有效字段。

## 3. 当前基线

现有代码已经具备可复用基础：

- 前端已有 `AgentPage.jsx`、`AgentCanvas.jsx` 和 `@xyflow/react`。
- 画布已有节点、边、选择、拖动、缩放和 revision 字段。
- 已有 Agent 任务、消息、画布、执行记录和技能接口。
- 已有页面上下文和选中对象传给 Agent 的机制。
- Go 已提供 `/api/agent/*` 兼容接口。

当前限制：

- Agent 任务和画布仍主要保存在用户目录的 `agent-tasks.json`。
- 当前聊天只调用文本模型回答，系统提示词直接写在兼容处理器中。
- 当前 Agent 不能通过受控工具真正执行完整生产链。
- 节点展示较通用，没有完整表达小说视频业务。
- 当前工作区仍受站点宽侧栏约束，不是独立创作空间。

实施时应扩展现有 React Flow 画布，不另写一套画布引擎。兼容接口路径可以保留，但数据和执行必须迁移到正式 Go + MySQL + Redis 架构。

## 4. 页面结构

### 4.1 Agent 首页

`/agent` 是简洁入口页：

- 窄图标导航，不显示当前站点的宽侧栏。
- 页面中央是自然语言输入框。
- 输入框支持添加小说、图片、音频、视频和已有项目。
- 下方展示最近项目、常用技能和可继续的任务。
- 快捷能力使用 V88 业务名称：小说分析、剧本、人物资产、分镜、TTS、视频生成、完整合成和上传。

### 4.2 创作画布

`/agent/canvas?task=<id>` 是主要生产页面：

- 顶部左侧显示返回入口、项目名称和项目菜单。
- 中央画布占据主要空间。
- 右侧 Agent 对话区默认展开，可收起。
- 画布底部提供选择、添加、画板、文字、图片、视频、缩放、图层、小地图和搜索入口。
- 任务记录、导出和项目设置放在顶部，不占用画布空间。

### 4.3 右侧 Agent 面板

面板包含：

- 新对话、历史对话和收起按钮。
- 用户消息、Agent 回复和工具执行记录。
- 当前执行计划及每一步状态。
- 等待审核、缺少配置、失败重试和上传预览等可操作提示。
- 已选中画布对象的引用。
- 监督模式、全自动模式和定点修改状态。
- 模型与生产设置入口。

面板不显示内部提示词正文、密钥、令牌或基础设施细节。

### 4.4 窄屏规则

- 画布保持可缩放和拖动，不把节点压成不可读的小卡片。
- Agent 面板改为底部抽屉或全屏页签。
- 关键按钮使用图标和工具提示。
- 不允许聊天区、节点工具栏和底部工具栏互相遮挡。

## 5. 画布节点

### 5.1 节点类型

第一阶段到第五阶段逐步提供以下业务节点：

1. 输入节点：小说原文、编辑内容、上传文件、参考资料。
2. 分析节点：男女频、题材、风格、人物关系、故事钩子和敏感检查。
3. 文本创作节点：剧本、资产提示词、分镜提示词、标题和上传文案。
4. 资产节点：人物、场景、道具、参考图和音色。
5. 分镜节点：镜头画面、台词、提示词、时长和顺序。
6. 音频节点：TTS、音乐、音效、音色和真实时长。
7. 视频节点：单分镜视频、换开头版本和生成参数。
8. 交付节点：完整合成视频、上传版本和视频管理系统结果。

### 5.2 节点通用字段

每个节点必须具有：

- 节点 ID、项目 ID、所有者账号 ID。
- 类型、标题、摘要和当前位置。
- 当前版本号和当前有效版本 ID。
- 状态：草稿、排队中、运行中、等待审核、已确认、失败、已过期、已删除。
- 上游节点和下游节点关系。
- 对应业务实体 ID、任务 ID 和素材 ID。
- 创建时间、更新时间和最后操作者。

### 5.3 节点选择与聊天引用

- 单击节点只选择，不立即修改或重新生成。
- 选中节点后，右侧输入框显示引用胶囊。
- 用户发送消息时，Go 后端收到节点 ID 和允许公开的当前版本摘要。
- 前端不直接拼接私密地址、访问令牌或系统提示词。
- 多选用于批量重做、移动、导出和删除；删除仍需确认。

### 5.4 依赖与失效

节点之间保存明确依赖关系。例如：

`沈鸢人物资产 -> 含沈鸢的分镜图 -> 对应分镜视频 -> 完整合成视频 -> 上传版本`

上游发生有效修改时：

- 下游不立即删除。
- 下游标记为“上游已变化”。
- Agent 计算确实受影响的节点集合。
- 监督模式先说明影响范围，再等待用户继续。
- 全自动模式自动重新生成受影响节点，但上传仍遵守明确上传意图。

## 6. Agent 执行架构

### 6.1 核心组件

Go 后端新增边界清楚的组件：

- `AgentPlanner`：理解用户目标、模式、对象和缺失参数。
- `AgentToolRegistry`：登记允许 Agent 调用的 V88 工具及输入输出结构。
- `AgentExecutor`：执行计划、记录步骤和调用业务服务。
- `AgentDependencyService`：计算节点依赖和修改影响范围。
- `AgentConfirmationService`：管理删除和其他需要确认的待执行操作。
- `AgentProjectStore`：保存项目、会话、节点、边和版本。
- `AgentExecutionStore`：保存执行、步骤、幂等标识、状态和错误。

组件只能通过明确接口访问小说获取、水货生产、TTS、图片、视频、合成和上传服务。Agent 不允许根据模型生成内容任意调用 URL、执行命令或写数据库。

### 6.2 受控工具

工具按用途分为：

- 读取工具：读取项目、配置、资产、任务和结果。
- 生成工具：分析小说、生成剧本、资产提示词、分镜、TTS、图片和视频。
- 生产工具：合成、创建换开头版本、导出。
- 外部操作工具：上传视频管理系统。
- 破坏性工具：删除项目、节点、素材和结果。

每个工具必须声明：

- 输入结构和必填字段。
- 可作用的账号和项目范围。
- 是否需要确认。
- 幂等键生成规则。
- 返回的节点、任务和素材类型。
- 可重试错误与不可重试错误。

系统预设和工具使用规则统一放在 Go 后端 prompt 模块。前端只接收可展示的名称、说明和表单结构。

### 6.3 单次对话执行流程

1. 接收用户消息、当前项目、选中节点和模式。
2. 读取当前有效版本和项目设置。
3. Planner 生成结构化意图和候选步骤。
4. 后端验证权限、工具白名单和必填字段。
5. 信息不足时只返回澄清问题，不创建生产任务。
6. 删除操作创建待确认操作；上传意图或目标不明确时返回澄清问题。
7. 其余操作写入执行记录并进入 Redis 队列。
8. Executor 调用现有 Go 业务服务。
9. 每个结果写入新节点或新节点版本。
10. 前端通过轮询或现有实时机制刷新执行状态和画布。

## 7. 数据与存储

### 7.1 MySQL

MySQL 是 Agent 事实数据源，保存：

- 项目和会话。
- 消息和可展示的工具记录。
- 画布节点、边、位置和视图状态。
- 节点版本和当前有效版本。
- 执行、执行步骤、确认操作和幂等键。
- 业务实体、任务和素材的引用关系。

实施时使用高于仓库现有最大编号的全新 Goose 追加迁移。不得修改、删除或伪造任何已执行迁移记录。

### 7.2 Redis

Redis 只负责：

- 执行队列。
- 运行锁和并发控制。
- 短期进度事件和取消信号。

Redis 不是任务事实来源。Redis 丢失或 Go 重启后，系统必须能根据 MySQL 状态恢复、重排或明确标记待处理任务。

### 7.3 TOS

图片、音频、视频和导出文件保存在 TOS。MySQL 保存素材 ID、对象键、媒体类型、尺寸、时长、校验信息和业务来源。

私有素材继续通过同源鉴权接口读取，前端使用 Blob URL 展示并及时释放，不把私有 API 地址直接放入媒体标签。

### 7.4 旧文件数据迁移

现有 `agent-tasks.json` 只作为迁移输入：

- 新 MySQL 表上线后，Go 在账号范围内执行一次幂等导入。
- 导入成功后记录来源文件摘要和导入标记。
- 接口随后只读写 MySQL，不进行长期双写。
- 原文件不自动删除，直到单独阶段验证迁移完整性并获得用户授权。
- 兼容 API 路径继续服务前端，避免一次性改坏全部调用方。

## 8. 版本、恢复和并发

- 用户编辑或 Agent 生成不会覆盖旧版本，而是创建新版本并切换当前有效版本。
- 每个版本记录生成参数、来源节点、执行步骤和素材引用。
- 恢复历史版本会创建新的当前版本，不改写历史记录。
- 画布位置更新使用 revision 乐观锁，过期 revision 返回冲突并要求重新加载。
- 生产操作使用项目 ID、节点版本和操作类型生成幂等键。
- 重复点击、网络重试或浏览器刷新不能创建重复生成或重复上传。

## 9. 错误处理

### 9.1 部分失败

- 失败只暂停受影响分支。
- 已成功的节点和素材保持可用。
- 节点显示用户能理解的错误、失败步骤和重试按钮。
- 单项重试默认沿用原参数；修改参数后重试创建新版本。

### 9.2 缺少设置

缺少文本模型、图片模型、视频模型、音色、上传账号或连接器时：

- Agent 明确指出缺少哪一项。
- 提供进入对应设置位置的按钮。
- 不创建必然失败的任务。
- 设置完成后可以从原步骤继续。

### 9.3 服务重启

- Go 启动时检查 MySQL 中处于排队或运行状态的执行。
- 能确认未开始的步骤重新排队。
- 无法确认外部结果的步骤先查询提供方或业务记录，再决定完成、重试或人工处理。
- 上传等外部操作禁止盲目重复提交。

## 10. 安全与权限

- 所有项目、节点、消息、任务和素材按当前登录账号隔离。
- 所有工具调用在 Go 后端再次验证账号和项目归属。
- Agent 上下文只包含完成任务所需的信息。
- API 密钥、访问令牌、密码、私有对象地址和系统提示词不得进入聊天记录。
- 删除确认令牌绑定账号、项目、目标集合和短有效期，不能跨项目复用。
- 上传前按当前账号权限再次检查视频管理系统配置。

## 11. 六阶段实施计划

### 阶段 1：画布基础

交付：

- 独立 Agent 首页和创作工作区。
- 复用并扩展现有 React Flow 画布。
- 右侧 Agent 面板、节点选择引用和项目切换。
- MySQL Agent 基础表和旧文件幂等导入。
- 画布位置、边、视图和 revision 持久化。

验收：

- 本地 4001 可创建和打开 Agent 项目。
- 刷新后节点、位置、连接和消息恢复。
- 选中节点能进入聊天上下文。
- 桌面和窄屏均无重叠，基础键鼠操作可用。

### 阶段 2：智能执行

交付：

- Planner、工具注册表、Executor 和确认服务。
- 监督、全自动和定点修改模式。
- 执行计划、进度、取消、失败和重试。
- 删除统一确认。

验收：

- 不明确指令会询问用户。
- 相同指令和网络重试不会重复建任务。
- Go 重启后执行状态可恢复。
- 失败仅暂停受影响分支。

### 阶段 3：小说与资产

交付：

- 小说原文、分类分析、剧本、人物、场景、道具和提示词节点。
- 审核、编辑、版本和定点重新生成。
- 系统提示词迁入 Go prompt 模块。

验收：

- 从一本真实小说建立完整前半程节点。
- 用户编辑内容成为后续有效输入。
- 修改一个人物不会无差别重做全部资产。

### 阶段 4：分镜与媒体

交付：

- 分镜、TTS、图片和视频节点。
- 批量生成、单项重试和依赖失效提示。
- 实际音频时长进入视频生成和合成链路。

验收：

- 某个分镜失败可以单独重试。
- 已完成分镜和媒体不会因局部失败丢失。
- 修改分镜后只重做受影响媒体。

### 阶段 5：成片与上传

交付：

- 完整视频合成、换开头多版本和交付节点。
- 上传预览、正文来源、小说 ID 和提交结果。
- 明确上传意图和幂等提交保护。

验收：

- 选择 4 个开头时生成并展示 4 个完整成片。
- 每个成片由对应开头加后续全部分镜组成。
- 上传 4 个视频，并使用准确的小说 ID 和当前编辑内容。

### 阶段 6：长期体验完善

交付：

- 历史版本恢复、图层、小地图、搜索和批量选择。
- 快捷编辑、项目导出和大型项目性能优化。
- 移除已被替代的 Agent 旧入口和双实现，但不提前删除其他历史基础设施。

验收：

- 大型项目画布仍能流畅选择、缩放和保存。
- 历史版本可查看和恢复。
- 不会跳回旧 Agent 页面或旧数据写入路径。

## 12. 测试与验证

每个阶段必须同时包含：

- Go 单元测试：规划、工具校验、权限、幂等、依赖、确认和状态转换。
- Go 接口测试：项目、消息、节点、版本、执行和确认 API。
- MySQL 迁移测试：全新库、已有库和重复执行。
- Redis 队列测试：排队、锁、取消、重启恢复和重复消息。
- React 测试：首页、画布、节点、选择引用、保存冲突、右侧面板和窄屏布局。
- 本地 Go embed 构建测试。
- 本地 4001 已登录浏览器验收。

不能把以下结果单独当成完成：

- 只通过构建。
- 只返回 HTTP 200。
- 只显示静态节点。
- 只接受上传请求但未核对目标结果。
- 只在未登录状态看到页面。

## 13. 技术与发布边界

- 应用后端、Agent 编排和业务执行全部使用 Go。
- 用户前端继续使用 React + Ant Design 和现有 `@xyflow/react`。
- React 构建产物通过 Go embed 打入单个 Go 二进制。
- MySQL 保存关系与事实数据，Redis 负责队列和锁，TOS 保存对象文件。
- 不恢复 Node 应用发布链，不创建 `deploy/v88-direct`。
- 不使用 GitHub Actions 上传或部署。
- 本设计和后续阶段默认只在本地 V88 开发、构建和验证。
