# 批量工厂雪漫画资产推导与三视图设计

## 文档关系

本规格补充 `2026-10-25-batch-factory-comic-production-design.md` 和 `2026-10-26-batch-factory-comic-style-reference-design.md`，并替换其中较笼统的漫画资产提取语义。

本规格只处理漫画人物、场景、道具的文字推导、覆盖规则、资产图片模板和后续漫画页引用。生产模式、画风库、漫画分镜、漫画页、主图、漫画合集继续遵循既有规格。

## 目标

把雪漫画反编译与受限运行时观察确认的资产提示词和人物三视图能力接入现有批量工厂，不新增第二套漫画工厂或资产页面。

最终链路为：

```text
小说正文、剧情梗概和分镜
  -> 一次文本 AI 调用提取人物、场景、道具
  -> 保存本书漫画资产
  -> 可按类型或单资产重新推导
  -> 使用资产描述生成候选资产图
  -> 用户选择资产主图
  -> 漫画分镜保存明确的资产编号
  -> 漫画页生成上传命中资产的主图
```

## 非目标

- 不改变视频资产、视频提示词、视频生成、配音或音频链路。
- 不新增独立的“漫画资产提示词”控件；继续复用资产设置中的现有提示词选择器。
- 不在前端硬编码系统提示词正文。
- 不因重新生成资产图而删除旧候选图或主图。
- 不在本阶段改变漫画合集上传后台的路径或协议。

## 系统提示词

后端 `prompt` 模块提供以下系统预设：

| 预设 | 用途 | 调用方式 |
| --- | --- | --- |
| `雪漫画·漫画资产统一推导` | 一次返回人物、场景、道具 | 全部提取或全部重新提取 |
| `VIP 智能角色推导` | 推导人物外形、妆造、服装和年龄阶段 | 单独推导人物或单个人物 |
| `雪漫画·主要场景推导` | 推导带明确时段的主要场景 | 单独推导场景或单个场景 |
| `雪漫画·关键道具推导` | 推导推动剧情或反复出现的关键器物 | 单独推导道具或单个道具 |
| `雪漫画·角色三视图` | 人物资产生图模板 | 人物资产图片生成 |

提示词正文采用雪漫画运行时确认的原提示词。为接入批量工厂，只允许调整变量占位、统一 JSON 外壳和字段名称，不删减人物、场景、道具及三视图的核心约束。

`VIP 智能角色推导` 只是系统预设名称，不绑定会员、付费或权限判断。

### 统一推导返回契约

首次提取和全部重新提取只调用一次文本 AI。统一提示词在后端组合三套原规则，并要求返回：

```json
{
  "characters": [{"name": "苏晚成年", "content": "完整人物视觉描述", "aliases": ["苏晚"]}],
  "scenes": [{"name": "古庙庭院月夜", "content": "完整环境视觉描述", "aliases": ["古庙"]}],
  "props": [{"name": "宗主玉佩", "content": "完整器物视觉描述", "aliases": ["玉佩"]}]
}
```

人物遵守年龄阶段拆分规则；场景名称和正文包含明确昼夜或时段；道具只保留推动剧情或反复出现的关键器物，无关键道具时返回空数组。

### 管理员编辑与版本

- 内置原文保存在 Go 后端 `prompt` 模块中，作为初始化和恢复原版的来源。
- 管理后台允许管理员直接编辑并发布系统原版提示词，不要求先复制为自定义提示词。
- 每次发布生成新版本，记录预设编号、版本号、修改人、修改时间和旧正文。
- 管理员可以回滚历史版本，也可以恢复后端内置原版。
- 用户前台只接收预设元数据和当前发布选择，不包含硬编码提示词正文。
- 每次推导开始时冻结预设编号、版本号和正文快照；任务执行期间不受后续管理员修改影响。
- 用户主动重新推导时重新读取最新发布版本，并保存新快照。

## 调用次数和重新推导范围

| 操作 | 文本 AI 调用 | 覆盖范围 |
| --- | --- | --- |
| 首次提取漫画资产 | 1 次 | 创建人物、场景、道具三类资产 |
| 重新提取全部资产 | 1 次 | 替换三类漫画资产活动清单 |
| 只重新推导人物 | 1 次 | 只替换人物活动清单 |
| 只重新推导场景 | 1 次 | 只替换场景活动清单 |
| 只重新推导道具 | 1 次 | 只替换道具活动清单 |
| 重新推导当前资产 | 1 次 | 只更新当前资产，不增删其他资产 |
| 生成或重新生成资产图 | 每张候选图 1 次图片 AI | 只增加候选图，不执行文字推导 |

三类单独提示词用于分类重提和单资产重提，不要求每本书首次提取固定调用三次文本 AI。

## 资产覆盖与去重

覆盖只作用于当前书的漫画资产域，不读取、覆盖或删除视频资产。

资产匹配键为规范化后的“资产类型 + 正式名称”。名称规范化至少处理首尾空白、连续空白、常用全半角符号和已保存别名；人物、场景、道具之间不得跨类型合并。

规则如下：

1. 新结果与现有资产同类型、同名称或命中别名时，沿用原资产编号，更新名称、别名和提示词正文。
2. 沿用资产编号时保留已有参考图、候选图、主图和用户上传图片。
3. 全部重新提取以三类新结果为唯一活动清单；用户手动新增的漫画资产若不在新结果中，也从活动清单移除。
4. 分类重新推导只以该类型的新结果替换该类型活动清单，另外两类完全不变。
5. 单资产重新推导只更新指定资产，不删除、不新增其他资产。
6. 被新清单移除的资产和图片进入可恢复归档，不继续显示、不参与分镜匹配和漫画页生成；本阶段不执行不可恢复的物理文件删除。
7. 新结果完整解析并校验成功后才一次性提交覆盖；响应缺字段、JSON 错误、名称冲突无法消解或调用失败时，旧清单保持不变。

这些规则避免重复资产不断累积，同时避免同名更新导致已经生成的资产图片丢失。

## 资产设置界面

继续使用现有资产设置页面和人物、场景、道具页签。

### 顶部操作

- 保留现有“选择资产提示词”下拉框。
- 视频模式显示视频资产预设；漫画模式显示漫画资产统一推导预设。
- 漫画模式主按钮显示“提取漫画资产”。
- 主按钮菜单提供“重新提取全部资产”“只重新推导人物”“只重新推导场景”“只重新推导道具”。

### 分类和单资产操作

- 人物、场景、道具页签右上角分别显示当前类型的“重新推导”按钮。
- 每张资产卡片的操作菜单增加“重新推导当前资产”。
- 覆盖操作执行前明确显示范围和数量，例如“将覆盖全部人物资产，共 12 条；场景和道具不受影响”。
- 推导完成后显示新增、更新、归档和沿用图片的数量。

## 资产图片生成

人物资产的图片模板提供：

- `三视图`：默认；使用雪漫画原三视图提示词。
- `单人设定图`：不注入三视图版式要求，只使用人物视觉描述和漫画画风约束。

三视图要求一张图包含正面近照、正面全身、侧面全身和背面全身，白色底图，无文字注释和分割线。场景和道具不显示人物图片模板选择。

最终资产图提示词继续由后端统一编译：

```text
画风预设
+ 用户图片描述词全局前缀
+ 人物三视图模板（仅人物选择三视图时）
+ 当前资产视觉描述
+ 身份保留与忽略参考图原画风规则
+ 用户图片描述词全局后缀
```

生成资产图时可发送当前资产自己的手动参考图；漫画全局参考图启用“用于资产图”时一并发送。画风预览图仍不自动成为参考图。

生成或重新生成资产图只新增候选图。旧候选图、当前主图和资产提示词保持不变，用户显式选择后才更换主图。

## 漫画分镜与资产主图

新漫画分镜推导结果除显示文本外，还必须保存当前页使用的漫画资产编号列表，覆盖人物、场景和道具。

- 后端先使用 AI 返回的角色、场景和道具名称解析当前书活动资产。
- 解析成功后保存稳定资产编号，不能在图片生成时再次只靠字符串包含关系猜测。
- 生成漫画页时按保存的资产编号读取各资产主图。
- 旧数据没有资产编号时允许名称匹配作为兼容回退；重新推导该分镜后必须补齐编号。
- 某个已关联资产没有主图时，界面列出缺失资产并阻止静默忽略。
- 参考图发送顺序继续是：本页手动参考图、当前页资产主图、启用的漫画全局参考图。

## 持久化与事务

- MySQL 是资产、提示词版本、快照、归档状态和资产关联的事实来源。
- 如需新增字段或表，只能增加新的 Goose 迁移，不得修改已执行迁移。
- 图片二进制继续走现有本地制品或 TOS；MySQL 只保存归属、状态和存储引用。
- 全部覆盖必须在一个数据库事务中同时提交三类结果，不能只替换其中一类而让另外两类停留在旧版本；分类覆盖也必须在一个事务中完成该类型的更新与归档。
- 文本 AI 和图片 AI 任务可以使用现有 Redis 队列、重试和锁，但 Redis 不保存最终资产事实。

## 异常处理

- 未选择漫画资产预设：禁止提取并提示选择提示词。
- 文本模型不可用：保留旧资产，记录失败原因并允许重试。
- 返回 JSON 无法解析或三类字段不符合契约：不覆盖旧资产。
- 规范化后出现两个同类型同名资产：阻止覆盖并展示冲突名称，不能静默保留重复项。
- 单资产重提返回多个资产：只接受明确匹配当前资产的一项，否则提示人工选择，不改数据。
- 图片模型不支持参考图：明确提示改用支持参考图的豆包执行器，不能静默丢掉参考图。
- 资产归档后仍有旧漫画页引用：旧结果保留；新生成必须重新推导分镜或修复资产关联。

## 验收标准

1. 首次提取漫画资产只产生一次文本 AI 请求，并同时保存人物、场景和道具。
2. 雪漫画人物、场景、道具和三视图原提示词存在于后端系统预设，可由管理员直接编辑、发布、回滚和恢复原版。
3. 提示词发布后，新任务使用新版本；已运行任务继续使用冻结快照。
4. 全部重提、分类重提和单资产重提严格遵守各自覆盖范围。
5. 用户手动新增的漫画资产在全部或对应分类重提后不形成重复活动资产；同名资产沿用编号和已有图片。
6. 失败或无效响应不会覆盖旧资产。
7. 人物资产默认生成三视图，场景和道具不显示三视图模板。
8. 重新生成资产图只新增候选图，不删除旧图、不自动更换主图。
9. 新漫画分镜保存明确资产编号，漫画页按编号发送人物、场景和道具主图；旧数据才使用名称匹配回退。
10. 视频模式不显示或执行漫画资产提示词、三视图或漫画资产覆盖操作。
11. 前端源码、后端测试、MySQL 迁移和 Go embed 本地运行验证通过后才可视为实现完成；验证不得以编译产物替代源码。
