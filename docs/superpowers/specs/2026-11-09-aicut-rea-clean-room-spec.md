# AI-CUT REA 证据与 Clean-room 需求规格

日期：2026-11-09

## 1. 范围与结论

本报告只分析用户提供的本地洛水 2.9.0 安装包和已经恢复出的前端/Nuitka 常量，不启动原应用、不登录、不发出网络请求。我们的实现只复现可观察行为，不复制原代码、密钥、私有接口、模型账号、图标或其他专有资源。

AI-CUT 不是“只有一个提示词的弹窗”。它是独立工程工作台，主链路是：顶层入口 → 项目/素材 → 时间线与字幕 → 本地 FFmpeg/ASR 或已配置模型 → 进度事件 → 保存或导出。插件市场里的“AI-CUT 插件版”是另一条入口，不能代替独立工作台。

## 3. 可验证需求规格

### 3.1 工程与素材

- 输入：项目名、画面比例；图片/视频/音频/SRT 文件。
- 输出：属于当前登录用户的项目、素材元数据、可访问对象 URL、可持久化时间线。
- 边界：空项目名使用明确提示；比例只接受产品列出的值；文件类型/大小受限；跨用户不可读取；重复项目/素材不能静默覆盖。
- 失败：分别提示“项目不存在”“素材不存在”“素材信息无效”“上传失败”，不能统一显示成功。

### 3.2 时间线编辑

- 输入：轨道、片段、开始时间、时长、源区间、变速/分割/删除动作和当前 revision。
- 输出：revision 加一的完整时间线；保存必须原子化。
- 边界：ID 唯一，时间非负，时长大于零，源区间不可越界；并发旧 revision 不得覆盖新版本。
- 失败：版本冲突提示“时间线已更新，请刷新后重试”；坏时间线提示具体动作失败并保留旧版本。

### 3.3 SRT 导入（本轮已实现）

- 输入：UTF-8 SRT 文本、文件名、项目 ID、当前 revision；上限 2 MB。
- 输出：每个有效 cue 变成一个字幕片段；开始/时长来自时间码；多行字幕保留换行；保存后返回导入条数、轨道 ID 和新 revision。
- 边界：兼容 CRLF/LF、BOM、逗号或点毫秒；优先复用未锁定的空字幕轨；已有字幕时重复导入创建新字幕轨，不覆盖旧字幕；文件选择取消时不发请求；整个导入要么全成功，要么完全不改。
- 失败：空内容“没有读取到有效字幕”；错误时间码指出第几条；结束不晚于开始提示时间无效；旧 revision 提示刷新重试。

### 3.4 ASR 与字幕工具（字幕纠错及首批在线 ASR 已实现）

- 输入：首批实现接收已保存的音频或视频素材 ID、独立 `asr` 模型 ID、可选语言和当前时间线 revision。模型配置必须在 API 配置页保存为 OpenAI 兼容 ASR，密钥只保留在服务端。说话人区分、AssemblyAI 和本地 Whisper 暂未实现。
- 输出：MySQL 持久任务记录（排队、识别中、正在取消、成功、失败、已取消）、0–100 进度，以及带开始/结束时间的按句字幕。成功时优先复用未锁定空字幕轨，否则创建新字幕轨；一次原子保存令 revision + 1。
- 边界：提交前前端先保存当前时间线；只接受音频或视频；空素材/空模型不建任务；模型必须启用且返回 `verbose_json.segments`；无有效带时间码分段视为失败，不伪造字幕；Redis 只唤醒，MySQL 是任务事实来源；重复唤醒由原子领取避免重复执行。
- 失败：素材不存在返回 404；缺模型或模型未启用返回明确配置错误；Redis 不可用把任务标成失败；供应商 HTTP 错误保留状态码和短错误正文；旧 revision 标记失败且不覆盖时间线；排队取消直接完成，运行中取消先为“正在取消”，并中断上游请求，最终“已取消”。

字幕纠错当前实现：前端提交剧本、可选文本模型 ID 和时间线 revision；Go 后端从时间线提取字幕，以后端独立提示词调用账号已配置的文本模型，只接受 `{corrections:[{clipId,text,reason}]}`。后端拒绝未知/重复字幕 ID 和无效 JSON，只更新未锁定字幕轨的文字，保存时仍做 revision 冲突检查。浏览器取消会中断请求；模型缺失、模型失败、取消和坏输出分别返回不同提示。

ASR 当前实现：`backend/internal/aicut/asr.go` 负责 OpenAI 兼容 multipart 请求和分段解析；`asr_service.go` 负责领取、读取对象、调用模型、取消检查和字幕落轨；`asr_queue.go` 用 Redis 做唤醒；`aicut_asr_jobs` 保存任务事实。API 为 `POST/GET /api/ai-cut/projects/{id}/asr-jobs` 与 `POST .../{jobID}/cancel`。这是 clean-room 独立实现，没有复制洛水代码、密钥、私有接口或专有资源。

### 3.5 智能拆分、音频与渲染（待实现）

- 输入：素材片段、阈值、最小间隔、开始/时长；降噪强度；导出尺寸/FPS/编码/CRF。
- 输出：共享源素材的拆分片段；独立音频素材；最终视频文件和进度。
- 边界：拆分并发最多 10；不能切出源范围；缺 ffmpeg/ffprobe 时不执行；缺可渲染片段不建任务。
- 失败：保留原工程并显示 ffmpeg/ffprobe 解析错误、降噪失败、导出失败或取消。

### 3.6 Agent 与提示词（待实现）

- 输入：用户指令、工程只读快照、选中技能、对话历史、允许的工具 schema、模型配置和取消信号。
- 输出：流式说明/推理状态/工具计划；只有 schema 校验通过且用户权限允许的工具才能变更时间线。
- 边界：不编造不存在素材；不得让模型直接写数据库；模型不可用时走本地规则兜底；工具失败必须反馈失败；瞬时错误最多自动重试一次；长历史压缩但保留已改内容、时间、失败原因和未完成事项。
- 失败：未选模型、模型不可用、空响应、非法 JSON、工具参数不合法、用户取消要分开显示。
- 提示词实现规则：只在 Go 后端 `prompt` 模块保存我们独立撰写的规则；前端只传任务和结构化数据。不得复制恢复文件中的原提示词文本。

#### 3.6.1 已核实的 Agent 精确链路（2026-11-10 补充）

洛水恢复前端显示，AI-CUT Agent 与素材、轨道、片段、字幕、脚本共用同一个项目状态；它不是另一个剪辑器。Agent 模式可调用工具修改时间线，Q&A 模式只回答问题并明确提示不会修改时间轴。原版链路按可观察行为归纳为：

`instruction + mode + modelId + activeSkill + project snapshot + recent messages -> model -> validated toolCalls -> tool executor -> saved timeline revision -> tool result -> next model turn -> final reply`

工具调用最多循环 30 轮。每轮必须记录 thinking、tool_start、tool_done 或 tool_failed；工具结果必须回到下一轮模型上下文。用户取消后不得开始新的工具；已经失败的工具不能被助手描述成成功。项目重新打开后，Agent 聊天、当前技能和编辑时间线必须属于同一个项目并恢复。

输入边界和失败规则：

- 空指令：不创建运行、不调用模型、不修改时间线，提示“请输入剪辑要求”。
- 重复提交：同一 clientRequestId 返回同一运行；同一 callId 不得重复修改时间线。
- 非法工具或参数：不执行，写入 tool_failed，并让模型基于失败原因修正。
- revision 冲突：不覆盖较新的时间线，提示“时间线已更新，请刷新后重试”。
- 模型缺失：提示先到 API 配置启用文本模型，不提供伪造结果。
- Q&A 返回工具：丢弃工具调用并提示“问答模式不会改时间轴”。
- 用户取消：运行进入 canceled，停止后续模型轮次和工具执行，保留已经成功提交的历史 revision。
- 达到 30 轮：失败并提示“执行步骤过多，请缩小任务范围”。

折叠是两个独立状态：全局导航由一战晟铭共用布局控制；AI-CUT Agent 面板还必须具有自己的完整态和 56px 窄轨态。二者不能共用状态，也不能因为收起 Agent 而卸载素材、预览或时间线。

## 5. 实施顺序

1. 已有：项目、素材上传、对象读取、时间线保存、基础预览/分割。
2. 本轮完成：SRT 解析、原子导入、独立 UI 入口、正常/空值/重复/错误/取消/版本冲突测试。
3. 已完成：字幕纠错、后端提示词、模型路由、原子保存和取消。
4. 已完成：首批在线 ASR；任务事实走 MySQL、唤醒走 Redis、素材走本地/TOS统一对象接口，模型走独立 ASR 配置。
5. 下一批：智能拆分、分离音频、FFmpeg 渲染；线上服务只做服务器可执行功能。其他 ASR 厂商适配器按真实需求逐个补，不伪装成已支持。
6. 最后：Agent 工具协议、Go 后端提示词、取消/进度；剪映草稿仅作为可选本地执行器，不冒充纯网页能力。
