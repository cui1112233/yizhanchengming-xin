# 小说创作 Clean-room 一比一对标规格

日期：2026-11-11  
状态：界面方向已确认，等待用户复核本规格  
实施方式：A——按真实业务链逐段打通，每一段都必须可用  
目标分支：`v88`（基线 `b167c4d7e1f89e1e6da852692141e806358e987e`）  
范围：本地 V88 源码、测试和本地 Go embed 运行包；不发布公网，不调用真实付费模型  

## 1. 目标和完成定义

在一战晟铭中新增独立的“小说创作”工作台，保留一战晟铭现有首页、私人定制、小说获取、水货生产和 Agent 工作区，不用“小说获取”或普通聊天冒充创作工作台。[E1][E2]

完整范围包括：

1. 长篇原创、短篇原创、仿写长篇、仿写短篇、番外创作、续写创作；[E1][E2]
2. 我的作品、会话记录、新建会话；[E1][E2]
3. 写作风格、导入素材、Agent 设置、定时写作、数据看板、备忘录；[E1][E2]
4. 模型选择、思考强度、流式对话、取消和失败恢复；[E2][E3]
5. 规划、写作、审核、自动修订、真相结算、记忆索引；[E3]
6. 与现有 Agent 工作区、Skills、工作区文件、自动任务和批次执行复用同一套正式能力，不复制第二套 Agent 系统。[E4][E5][E7]

完成不是“页面能打开”或“接口返回 200”。每一种创作模式都必须有真实输入、任务、状态、持久化、输出、取消、重试和可见结果；同一组输入与参考应用的入口顺序、必填规则、状态变化和用户结果一致，才算完成。

## 2. Clean-room 边界

- 只复刻可观察行为、数据契约、交互顺序和业务效果。
- 不复制参考应用的 Python/Cython 原代码、编译包、账号数据、密钥、私有接口、私有服务地址、品牌资源和受保护提示词原文。
- 系统提示词在 `backend/internal/prompt/novelcreation/` 独立编写并版本化；React 只收到安全的名称、说明和版本，不硬编码系统提示词。
- 模型请求走一战晟铭现有模型目录、成员配置和后端调用层，不依赖参考应用服务。
- MySQL 保存正式状态和关系；Redis 保存队列、取消信号、锁和短期事件；TOS 保存上传文件与导出物；Go embed 打包 React。
- 不通过 GitHub Actions 上传或部署，不修改公网。

## 4. 用户入口和界面合同

### 4.1 主导航

- 主侧栏新增“小说创作”，建议路径 `/novel-creation`。
- 入口位于“小说获取”之后、“水货生产”之前；不删除或改名现有业务。
- 页面继续使用全站主题变量、窗口背景和折叠侧栏，不写死白色或深色。
- CM/小Y品牌规则沿用现有 V88 设计，不在正式产品面显示参考品牌名。[E1][E7][E8]

### 4.2 页面三段结构

1. 全站主侧栏：保留一战晟铭业务导航。
2. 小说二级栏：六种创作、我的作品、会话记录和六个工具入口。
3. 主工作区：消息/步骤/结果流，底部输入框、模型、思考强度、上下文状态、发送/停止按钮。

二级栏可折叠。折叠只改变布局，不中止任务、不清空输入、不丢失选择。窄屏时改为抽屉，主工作区优先。[E1][E2]

### 4.3 六种创作入口

| 显示名 | 稳定键 | 默认行为 |
|---|---|---|
| 长篇原创 | `book-create` | 新建会话，先澄清设定，再创建作品 |
| 短篇原创 | `short` | 新建独立短篇任务，不创建长篇章节树 |
| 仿写长篇 | `imitation` | 先导入参考、选章节、提取文风，再创建长篇 |
| 仿写短篇 | `imitation-short` | 先导入参考、选章节、提取文风，再生成短篇 |
| 番外创作 | `spinoff` | 必须选择已有作品和番外锚点 |
| 续写创作 | `chapters` | 选择已有作品或导入正文，识别最后章节后续写 |

切换入口时：未发送的纯文本草稿按“会话 + 模式”本地保存；正在运行的任务不自动取消；若当前模式已有未完成配置，离开前提示“保留草稿/放弃”。[E2][E3]

## 5. 核心领域数据

### 5.1 正式实体

- `novel_projects`：作品标题、模式、题材、状态、当前卷章、模型策略、所有者。
- `novel_sessions`：模式、绑定作品、消息游标、上下文预算、当前运行。
- `novel_messages`：用户/助手/系统可见消息、流式状态、引用、模型和 token 使用摘要。
- `novel_volumes`、`novel_chapters`：卷章顺序、标题、正文、字数、审核状态、版本。
- `novel_chapter_versions`：每次写作/修订的不可变快照和来源运行。
- `novel_runs`、`novel_run_steps`、`novel_run_events`：任务状态、步骤、事件、取消和续跑点。
- `novel_foundations`：世界观、人物、时间线、规则、伏笔、故事弧。
- `novel_memories`：章节摘要、事实、关系变化、未回收伏笔和索引。
- `novel_audits`、`novel_revisions`：审核维度、分数、问题、修订策略和结果。
- `novel_style_profiles`：文风名称、来源摘要、指纹、版本和适用范围。
- `novel_materials`：用户上传文件、解析状态、章节索引、TOS对象和去重摘要。
- `novel_schedules`、`novel_schedule_runs`：定时规则、状态、每日计数和运行关联。
- `novel_memos`：作品/会话备忘、置顶、完成状态。

所有表按用户隔离。删除作品采用软删除；历史运行、提示词版本、章节版本和审核记录不得被改写。

### 5.2 Redis 和 TOS

- Redis：`novel:queue`、`novel:cancel:{runID}`、`novel:lock:project:{projectID}`、`novel:events:{runID}`、`novel:schedule:lock:{scheduleID}`。
- TOS：导入原文、参考文档、封面、导出 txt/md/epub 和大体积运行产物。
- 正文和结构化状态以 MySQL 为准；TOS 不是作品状态真相源。

## 6. 运行状态和通用调用链

```text
draft
  → clarifying
  → awaiting_confirmation
  → queued
  → planning
  → writing
  → normalizing
  → auditing
  → revising（0..N轮）
  → settling
  → indexing
  → succeeded / succeeded_with_warnings / failed / cancelled
```

通用链路：[E3]

1. 前端发送模式、会话、作品、用户输入、模型、思考强度和引用快照。
2. Go 校验权限、模式、幂等键和必填数据，创建运行。
3. 后端从 prompt 模块解析本次 PromptDefinition 与版本。
4. Redis 排队并对作品加短期锁；MySQL 保存正式状态。
5. planner/architect 形成计划，writer/composer 生成正文。
6. 字数标准化，auditor 按启用维度审核。
7. 达不到阈值时 reviser 局部修补或结构重写；不变好则回退最佳版本。
8. settler 更新世界观、人物、时间线、伏笔和章节状态。
9. memory index 写入检索摘要；章节与版本持久化。
10. 事件流驱动前端步骤卡、正文、警告、错误、停止和继续按钮。

取消只终止尚未完成的模型/队列步骤。已完成章节、审核和记忆更新必须保持事务一致；取消发生在结算前时，不把草稿标为正式章节。

## 7. 六种模式的输入、输出、边界和失败提示

### 7.1 长篇原创

- 输入：题材、世界观、主角、核心冲突；可选目标总字数、章节字数、叙事视角、受众、文风和模型。
- 输出：作品、基础设定、卷/章计划、章节正文、审核、修订记录、真相文件和记忆索引。
- 边界：首次信息不足先追问；空输入不创建任务；同一会话流式中不重复发送；同一幂等键只生成一个运行。
- 失败提示：分别显示“模型不可用”“生成超时”“审核未通过，正文已保存为待修订”“保存失败，未写入正式章节”。

### 7.2 短篇原创

- 输入：题材、篇幅、人物、叙事视角、结局倾向、文风和模型。
- 输出：独立短篇正文、审核报告、修订版本和导出物。
- 边界：短篇不创建空的长篇卷章树；长度使用允许区间，不在半句话截断；重复提交由幂等键阻止。
- 失败提示：需求不足时给补充项；取消后保留会话但不生成残缺成品；导出失败不删除正文。

### 7.3 仿写长篇/短篇

- 输入：一个或多个 txt/docx 参考文件、选定章节、新题材/人物/冲突、目标类型和模型。
- 输出：文件解析结果、章节目录、文风指纹、新作品或短篇、相似性/抄袭风险检查。
- 边界：有效参考正文少于 100 字不可继续；文件按内容摘要去重；支持最近 3/5/10 章（默认 5）、全选和清空；空章节选择不可生成。
- 失败提示：区分格式不支持、文件读取失败、没有识别到章节、重复文件已跳过、模型失败和风险检查失败。
- 安全规则：只抽取节奏、句长、视角、描写密度等风格特征，不把参考原文作为可直接复述的目标。

### 7.4 番外创作

- 输入：已有作品、人物、时间点、主题、篇幅和是否影响主线。
- 输出：番外正文、一致性审核、与原作品的关联和可选事实更新。
- 边界：作品、人物或时间锚点不存在时禁止生成；默认不改主线真相文件；用户明确选择“计入主线”后才结算。
- 失败提示：列出缺失设定或冲突事实，并提供“修改要求/返回作品/保存为非正史”操作。

### 7.5 续写创作

- 输入：已有作品或导入正文、续写方向、目标章数/字数、模型。
- 输出：识别后的章节树、新章节、更新后的计划、真相和记忆。
- 边界：没有有效正文不可续写；章节号或标题冲突时要求选择“跳过/新版本/另存”；长上下文按核心设定、近章、摘要分层预算。
- 失败提示：解析失败、上下文超限、模型失败、章节冲突和保存失败分别提示，不用统一“操作失败”。

## 8. 工具入口规格

### 8.1 我的作品和会话记录

- 作品列表支持搜索、状态、更新时间、模式筛选、重命名、软删除、恢复和进入。
- 会话按模式分组，支持新建、重命名、绑定/解绑作品和删除空会话。
- 删除运行中会话前必须先取消运行；重复删除返回已删除状态而不是 500。[E3]

### 8.2 写作风格

- 支持手动建立、从文本分析、从导入参考生成、编辑、复制、删除和应用到作品。
- 历史运行保存风格版本快照；后续修改不改变旧章节的运行记录。[E3][E6]

### 8.3 导入素材

- 支持点击、拖拽和粘贴上传；文件进入 TOS，MySQL 保存解析状态和摘要。
- 解析任务可取消；重复内容提示并复用已有素材；删除被作品引用的素材需二次确认。

### 8.4 Agent 设置

- 模型路由至少区分规划、正文、审核和修订。
- 审核维度可启停并添加自定义维度；配置多轮修订、通过阈值、最大轮次和上下文预算。
- 默认通过阈值可设为 85，但必须允许管理员/用户配置；不得把参考应用私有提示词复制进来。[E3]

### 8.5 定时写作

- 输入：作品、开始时间、间隔、每次章数、每日上限、失败策略。
- 输出：倒计时、运行状态、章节结果、今日计数、警告和失败历史。
- 状态：stopped/running/paused/writing/error/auto_paused。
- 边界：服务重启从 MySQL 恢复；同一作品用 Redis 锁防止并发；达到每日上限自动暂停；重复点击开始保持幂等。
- 失败提示：配置无效、作品占用、模型失败、章节警告、达到上限、连续失败自动暂停。[E3]

### 8.6 数据看板和备忘录

- 看板只展示真实聚合：作品、章节、字数、审核通过率、修订次数、模型耗时/用量和定时任务结果。
- 无数据时显示空状态，不造示例数据。
- 备忘录支持作品/会话范围、置顶、完成和搜索；保存失败保留本地草稿并可重试。

## 9. Agent、Skills 和小说创作的关系

小说创作不是现有 Agent 工作区的替代品。它是一个有严格小说数据合同的专业工作台；需要通用工具时调用现有 Agent 运行服务。[E4][E5][E7]

- 小说会话可引用 `@Skill`、`@文件`、`@自动任务` 和工作区素材。
- 小说专用动作以受控工具注册：创建作品、写下一章、批量写作、审核、修订、导出和更新真相文件。
- 工具不得绕过小说领域服务直接写数据库。
- 高影响操作（覆盖章节、删除素材、批量写作、主线真相变更）进入确认状态。
- Agent run 保存 skill ID/version、模型、权限、引用和产物快照。
- 小说自动写作与通用自动任务复用同一调度基础，但使用小说领域锁和每日上限。

## 10. HTTP 和事件合同

建议前缀 `/api/novel-creation`：

- `GET/POST /projects`，`GET/PATCH/DELETE /projects/{id}`；
- `GET/POST /sessions`，`PATCH/DELETE /sessions/{id}`；
- `GET/POST /sessions/{id}/messages`；
- `POST /runs`，`GET /runs/{id}`，`GET /runs/{id}/events`；
- `POST /runs/{id}/confirm|cancel|retry|answer`；
- `GET/POST/PATCH /projects/{id}/chapters`；
- `POST /projects/{id}/write-next|write-batch|audit|revise|export`；
- `GET/POST/PATCH/DELETE /styles`；
- `POST /materials`，`GET /materials/{id}/parse`，`DELETE /materials/{id}`；
- `GET/PATCH /agent-settings`；
- `GET/POST/PATCH /schedules`，`POST /schedules/{id}/start|pause|resume|stop`；
- `GET /dashboard`；
- `GET/POST/PATCH/DELETE /memos`。

事件统一包含：`eventId`、`runId`、`sessionId`、`projectId`、`type`、`step`、`status`、`message`、`progress`、`createdAt`。前端断线后用最后 eventId 补拉，不因刷新丢失运行状态。

## 12. 同输入对照测试

固定使用不计费的 fake model 和固定文本夹具；参考应用若必须真实调用付费模型，则只比较调用前规则、状态和可观察输出结构，不发送付费请求。

| 场景 | 固定输入 | 必须验证 |
|---|---|---|
| 正常 | “都市悬疑，女记者主角，失踪案，单章约2000字” | 创建会话/作品，进入规划和写作，保存章节、审核、记忆 |
| 空值 | 空格、换行、空文件、未选章节 | 不创建 run；显示对应必填提示 |
| 重复 | 连点发送、重复上传、同幂等键、重复开始定时器 | 只有一个 run/文件/计划，返回已有状态 |

| 权限 | 访问他人作品/会话/文件/运行 | 后端拒绝且不泄漏存在性和内容 |

## 13. 分段实施和每段完成门槛

### 第 1 段：长篇原创闭环

页面骨架、作品/会话、输入、模型、运行状态、规划、写一章、审核、修订、结算、记忆、取消/重试、持久化和真实浏览器验收全部完成。

### 第 2 段：短篇原创和导出

短篇专用状态、正文、审核、修订、txt/md/epub 导出完成。

### 第 3 段：仿写长篇/短篇

上传、去重、章节识别/选择、文风指纹、生成和风险检查完成。

### 第 4 段：番外和续写

作品选择、时间线/人物锚点、章节导入、上下文预算和冲突处理完成。

### 第 5 段：工具入口

文风、素材、Agent设置、定时写作、看板和备忘录全部是真实数据与操作。

### 第 6 段：Agent/Skills/工作区整合

`/`、`@`、技能版本、工具确认、运行事件、自动任务和小说产物回写走通。

每一段都必须通过：Go 单元/HTTP/迁移测试、Redis 锁和取消测试、前端聚焦测试、完整前端构建、Go embed 构建、`/health`、`/api/runtime-build-info` 和已登录浏览器逐步验收。上一段没有真实闭环，不进入下一段。

## 14. 不得作为完成证据

- 只有截图、设计图、按钮、弹窗或静态列表；
- 使用 setTimeout 伪造运行进度；
- 前端 localStorage 伪装服务端持久化；

- 测试通过但浏览器中的按钮仍无效；
