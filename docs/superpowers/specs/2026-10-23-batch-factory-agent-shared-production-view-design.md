# 批量工厂与 Agent 共用生产链设计

日期：2026-10-23

## 目标

批量工厂和 Agent 工作区不是两套生产系统，而是同一套作品生产数据的两种操作界面。

- 批量工厂适合按书、分镜和生产任务批量执行。
- Agent 画布适合查看素材引用关系、逐项调整提示词、补素材和重做结果。
- 两边必须共用同一份书、素材、任务、版本、合成和发布记录，不能复制文件或维护两条状态链。

## 范围和边界

### 本次包含

1. 一个批量工厂作品对应一个 Agent 项目。
2. 一个作品中的每一本书对应画布中的一个书籍分组。
3. 批量工厂和 Agent 共用素材、生成任务、结果版本、合成记录和视频管理系统发布记录。
4. 画布按既有五种节点呈现书内生产关系：剧本、文本、图片、视频、音频。
5. 画布支持自动保存、刷新恢复、状态显示、版本选择和双向跳转。

### 明确不做

- 不创建“资产节点”“人物节点”“场景节点”“道具节点”“分镜节点”这些新节点类型。
- 不重写现有图片、视频、音频、合成或发布执行器。
- 不复制一份媒体文件到 Agent，也不做浏览器端视频剪辑、转码或波形编辑。
- 不改变批量工厂已有的生产、合成和视频管理系统发布能力，只让 Agent 使用同一条能力链。

## 核心数据关系

```text
作品
  ├─ 书 A（画布分组 A）
  │   ├─ 剧本节点
  │   ├─ 图片节点：人物 / 场景 / 道具
  │   ├─ 音频节点：台词 / 配乐 / 音效
  │   ├─ 视频节点：分镜视频
  │   └─ 视频节点：最终合成视频
  └─ 书 B（画布分组 B）
```

书、素材文件、生成任务、版本和发布记录各自只有一份真实记录。画布节点保存的是对这些记录的引用、位置和连线；批量工厂页面和画布读取同一个来源。

`人物`、`场景`、`道具`、`分镜`、`合成视频`是节点用途或标签，不是额外的节点类型。

## 书籍分组中的生产关系

### 剧本节点

剧本节点保存该书的正文、选中行数和剧本处理动作，例如生成爆款开头、拆分或整理内容。它连接到由该剧本产生的素材和分镜，但不强迫用户建立文本节点。

### 文本节点

文本节点用于独立的文字工作，例如改写、扩写、对话、摘要或提示词草稿。它不是批量工厂默认生产链的必经节点。

### 图片节点

图片节点直接保存人物、场景或道具的图片提示词、参考图、生成设置和历史版本。它可以连接到使用该图片的一个或多个视频节点。

### 音频节点

音频节点和图片节点一样属于该书的素材区，用于台词、配音、配乐或音效。它保存文本、声音设置、生成结果、真实时长和历史版本。

音频连到视频节点后，视频以该音频的真实时长为默认目标。模型只提供固定视频时长时，系统选择最接近的档位并显示实际时长。用户可以手动改视频时长；此时保留该选择并显示清楚的不一致提示。

### 视频节点

视频节点直接保存自己的视频提示词、模型与参数、引用的图片/音频/视频、任务状态和版本。

- 每个分镜都是一个视频节点。
- 分镜只连接它真实使用的图片和音频，不能把同书所有素材自动全部连上。
- 最终合成仍是一个视频节点，连接选中的分镜视频和需要的音频；它调用批量工厂既有合成能力，产物和发布记录不另存一份。

## 共享和同步规则

1. 从批量工厂打开“Agent 优化”或“编辑内容”时，直接进入相同作品、相同书的画布分组，不要求导入或复制。
2. 批量工厂已有的剧本、素材、分镜、成片和发布记录进入画布时自动显示为对应节点和关系。
3. 在画布生成、重试、选择版本、合成或发布后，批量工厂立刻读取相同任务和同一个当前版本。
4. 在批量工厂生成、重试、选择版本、合成或发布后，画布刷新或回到该书时显示相同结果。
5. 同一素材默认只属于来源书。用户可以明确设为作品共享素材；其他书引用它时仍使用同一文件和提示词，不制造副本。
6. 删除画布节点默认只删除该画布引用和连线，不删除真实文件、任务、版本或批量工厂记录。永久删除必须是单独明确的操作，并列出受影响的书和节点。

## 画布交互

- 书籍分组可以展开、折叠和定位；进入某本书时展开该组，其他书可折叠，避免多本书混杂。
- 拖线表示真实引用关系：图片/音频到使用它们的视频，分镜视频到最终合成视频。
- 用户在任何节点直接编辑文字、选择模型、发起生成、重试和选择历史版本。
- 同类节点默认沿用该书已经选择的模型和执行器；每个节点仍可单独改写，不影响其他节点。
- 节点移动、连线、文字和设置变更自动保存并合并写入后台；页面不会要求用户每次移动后手动保存。刷新、切换视图或重新进入时恢复最后可靠状态。
- 每项任务统一显示排队、执行中、成功、失败、已取消等状态。失败展示可安全显示的原因及可用的重试动作，不阻塞同书其他节点。

## 版本、合成和发布

每次生成都是一个保留的版本，包含生成参数、时间、状态、可安全显示的失败原因、媒体引用和来源节点。用户可把任意成功版本设为当前版本；下游节点和批量工厂默认使用当前版本。

最终合成视频使用批量工厂的既有合成任务和顺序。画布只呈现哪些分镜视频和音频参与合成，不私自创建新的合成引擎或发布通道。发布到视频管理系统的状态、地址、失败信息和重试记录在两个界面中一致可见。

## 状态和失败原则

- 提交后先显示排队或执行中，只有真实任务完成并持久化后才显示成功。
- 一个节点失败不影响其他素材、分镜、合成任务继续执行。
- 模型不支持的时长、引用数量或媒体类型要在提交前说明；执行器返回失败时保留实际错误和可用重试路径。
- 画布节点、批量工厂列表、项目素材和任务记录使用同一状态来源，不能分别拼出互相矛盾的“成功”或“失败”。

## 验收标准

1. 一个含多本书的作品在 Agent 中按“一本书一个组”显示，组内只有五种既有节点类型。
2. 一书有五个图片素材、一个音频、两个分镜和一个成片时，画布显示对应节点及真实引用连线。
3. 在 Agent 生成或改选一个版本后，批量工厂的对应素材或分镜显示同一结果；反向操作也相同。
4. 音频引用到视频时，视频默认使用音频时长或最接近的模型档位；手动修改后有可见的不一致提示。
5. 删除画布节点后，批量工厂文件与记录仍存在；只有用户明确永久删除时才删除真实资源。
6. 刷新页面、切换批量工厂和 Agent、重新进入该书后，节点、连线、当前版本和任务状态都不丢失。
7. 从合成到发布视频管理系统的记录在两个界面一致，失败原因和重试状态也一致。

## 验证方式

1. 为共享作品/书/素材/版本映射、删除边界、音频时长映射和状态同步补充后端测试。
2. 为分组显示、双向跳转、节点连线、自动保存、版本选择和失败状态补充前端测试。
3. 使用真实 MySQL 与 Redis 验证刷新恢复、任务状态和并发更新。
4. 用本地 `http://localhost:4001` 的实际浏览器做双向验收：从批量工厂进入画布、在画布生成/选版本、回到批量工厂确认、再反向操作并刷新确认。
5. 前端构建后打进 Go 内嵌二进制，再验证最终本地运行界面；不能仅以源码或开发服务通过作为完成依据。
