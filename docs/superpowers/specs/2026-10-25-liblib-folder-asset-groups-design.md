# Liblib 文件夹式资源分组设计

## 背景

Agent Canvas 左侧项目抽屉目前已经能按书籍识别素材分组，但分组仍是普通标题行；图片预览也会使用原始高度，竖图会把整个资源列表撑开。Liblib 的参考画布使用可展开/收起的文件夹按钮和固定尺寸缩略图。

## 目标

- 每本书显示为一个独立的文件夹分组。
- 文件夹可单独展开和收起，收起后隐藏全部子项。
- 当前书籍默认展开，其他书籍默认收起；用户手动状态只在当前页面会话内保留。
- 图片、视频使用受约束的预览框，横图与竖图都不能撑高列表。
- 音频、文本等非视觉素材保持紧凑列表行。
- 保留现有搜索、类型筛选、拖拽到画布和点击添加能力。

## 设计

### 分组模型

沿用现有的 `bookId`、`groupId` 和画布节点关联字段识别书籍。分组输出统一为 `{ id, title, children }`，无法关联书籍的素材进入“未分组”。单个项目只有一个书籍分组时，缺少显式素材归属的项目素材归入该分组，避免当前项目出现无意义的平铺“未分组”。

### 文件夹交互

素材分组标题使用原生按钮语义，包含展开箭头、书名和子项数量，并通过 `aria-expanded` 表达状态。点击标题只切换该组，不影响其他分组。分组内容使用条件渲染隐藏，避免收起后仍占用滚动高度。

### 预览布局

图片和视频预览使用固定的缩略图容器，容器尺寸适配侧栏宽度，媒体使用 `object-fit: cover` 并限制最大高度；资源名称和媒介类型放在预览下方或右侧的紧凑信息区。音频、文本继续使用类型图标，不渲染大尺寸媒体。

### 数据流与错误处理

分组只在前端对已加载的项目素材和画布节点做派生计算，不新增接口，也不改变保存的画布数据。素材加载失败继续显示现有错误状态；单条素材缺少 URL、类型或书籍字段时回退到类型图标和“未分组”。

## 验证

- 单元测试覆盖显式书籍字段、节点关联分组和未分组回退。
- 浏览器验证至少包含：展开/收起一个分组、多个分组互不影响、横图/竖图/音频混合列表、拖拽和点击添加仍可用。
- 构建并通过 Go embed 运行时验证。

## 范围边界

本次只调整 Agent Canvas 项目抽屉的展示和交互，不改变批量工厂数据、画布节点结构、资源上传接口或生成流程。
