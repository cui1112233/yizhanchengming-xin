# 小程序任务中心原稿对齐设计

## 已确认基线

视觉基线使用 `docs/design-references/miniprogram-functions-first/03-tasks.png`。本轮只优化第三个底部页面“任务”，不连带修改功能、工作台或我的页面。整体继续使用已经确认的晚霞背景、深海军蓝液态玻璃、青色高光和四项底部导航。

## 页面职责

- 汇总剧本、Agent、小说获取、批量工厂和水货生产的真实任务。
- 提供跨功能的任务状态查看、筛选、恢复和重试入口。
- 不承担新建功能；新建仍从“功能”页进入。
- 不展示固定示例项目、示例数量或虚构进度。

## 页面结构

### 顶部任务主视觉

- 保留品牌栏，标题改为“任务中心”，副标题为“追踪全部创作与生产记录”。
- 手机首屏内压缩主视觉高度，不照搬原稿的超高海报比例。
- 右侧角色插画只复用项目现有高清龙角色资产，不重新生成重复素材。

### 真实数量概览

- 三列显示“进行中、待确认、已完成”。
- 数量从当前任务汇总实时计算，加载期间显示占位，不使用原稿的 `3 / 2 / 12`。
- 失败数不挤进概览，保留在筛选和列表状态中，避免五种状态同时抢首屏。

### 状态分类

- 四项固定为“全部、进行中、待确认、已完成”。
- “待确认”仅接收服务端明确表达人工确认或审核的状态，例如 `waiting-review`、`pending_confirmation`、`accepted_pending`、待确认和待审核。
- `queued`、`pending`、`waiting` 等普通执行排队状态仍归“进行中”。
- 失败任务在“全部”中以红色状态清楚显示，同时任务操作显示“重试”或“查看详情”；不把失败任务偷偷归入待确认。

### 任务列表

- 所有任务放在一张统一的液态玻璃列表中，不给每行套一张独立大卡。
- 每行包括真实功能插画、任务标题、功能来源、更新时间、进度或状态、操作箭头。
- 只有服务端返回合法 `completed / total` 时才显示进度条和百分比。
- 任务缺少 ID 时禁用跳转，并明确显示“记录 ID 未返回”。
- 空列表、部分来源失败、全部来源失败和接口未配置都有独立状态，不清空仍可展示的真实任务。

## 数据边界

- `services/taskSummary.ts` 继续负责跨来源归一化、排序、筛选和跳转目标。
- 新增 `attention` 归一化状态，但只匹配明确需要人工处理的服务端值。
- 页面统计直接从归一化后的真实任务列表计算。
- 页面不会根据标题或功能类型猜测任务状态。

## 移动端尺寸

- 390px 基准左右留白 15px。
- 标题约 30–32px，列表标题约 16px，正文约 12–13px。
- 概览卡约 100–112px，筛选条约 52px，单行任务约 94–108px。
- 底部导航固定为“功能、工作台、任务、我的”，第三项选中，最后一条任务不被安全区遮挡。

## 验证标准

- 微信开发者工具中可看到任务中心完整布局，控制台没有业务错误。
- 有任务、无任务、部分来源失败、全部来源失败、刷新中均能正常显示。
- 统计数量与筛选结果来自同一批真实数据。
- 待确认与进行中不会混淆，失败任务不会消失。
- 与 `03-tasks.png` 做同尺寸并排对比，P0、P1、P2 差异清零。
- 任务相关测试、全量小程序测试和正式微信构建通过。

## 不在本轮范围

- 不修改后端接口或数据库。
- 不伪造任务、进度、时间、模型或项目名称。
- 不上传、不部署，不碰工作区无关改动。
