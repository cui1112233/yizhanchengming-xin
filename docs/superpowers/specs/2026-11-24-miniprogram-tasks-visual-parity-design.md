# 小程序任务中心真实状态与移动布局修正设计

## 已确认基线

视觉基线使用 `docs/design-references/miniprogram-functions-first/03-tasks.png`。本轮只优化第三个底部页面“任务”，不连带修改功能、工作台或我的页面。整体继续使用已经确认的晚霞背景、深海军蓝液态玻璃、青色高光和四项底部导航。

## 页面职责

- 汇总剧本、Agent、小说获取、批量工厂和水货生产的真实任务。
- 提供跨功能的任务状态查看、筛选、恢复和重试入口。
- 不承担新建功能；新建仍从“功能”页进入。
- 不展示固定示例项目、示例数量或虚构进度。

## 页面结构

### 顶部任务主视觉

- 保留品牌栏，标题改为“任务中心”，副标题为“追踪全部创作与生产记录”。
- 手机首屏内压缩主视觉高度，不照搬原稿的超高海报比例。
- 背景使用单独的晚霞山景与薰衣草花田素材，保持原稿的紫蓝层次，不再用当前偏灰、裁切错误的通用背景。
- 右侧使用独立的 3D 任务插画，只表现清单、进度环、数据图和影片元素，不包含文字、数字或固定百分比。
- `68%` 这类百分比必须由页面根据服务端返回的真实进度动态计算并实时展示，不能预先画死在背景图或插画里；顶部主视觉可以叠加真实的总体进度环，具体任务行继续展示各自的真实进度。

### 真实数量概览

- 三列显示“进行中、需重试、已完成”。
- 数量从当前任务汇总实时计算，加载期间显示占位，不使用原稿的 `3 / 2 / 12`。
- “需重试”只统计后端明确返回的失败、等待重试或已经停止且允许恢复的任务，不拿普通待配置、待分类或状态缺失记录凑数。

### 状态分类

- 四项固定为“全部、进行中、需重试、已完成”。
- `queued`、`pending`、`processing`、`running`、`scheduled_waiting` 等正在排队或执行的状态归“进行中”。
- `waiting_retry`、`failed`、`error` 等明确失败或等待重跑的状态归“需重试”。
- `completed`、`done`、`success`、`succeeded` 等明确终态归“已完成”。
- `waiting_classification`、`waiting_configuration`、`waiting_login`、`waiting_sensitive_ai`、`pending_submit`、`upload_pending` 等状态保留各自的中文说明；除非后端明确允许重试，否则不擅自归为失败。
- 状态缺失时显示“状态未返回”，不再把所有未知记录统一写成“状态同步中”。

### 任务列表

- 所有任务放在一张统一的液态玻璃列表中，不给每行套一张独立大卡。
- 每行包括真实功能插画、任务标题、功能来源、更新时间、进度或状态、操作箭头。
- 只有服务端返回合法 `completed / total` 时才显示进度条和百分比。
- 百分比按服务端的 `completed / total` 计算；没有总数、总数为零或字段缺失时完全隐藏，不使用默认百分比。
- 任务缺少 ID 时禁用跳转，并明确显示“记录 ID 未返回”。
- 空列表、部分来源失败、全部来源失败和接口未配置都有独立状态，不清空仍可展示的真实任务。

### 右侧真实状态区

- 进行中：服务端有真实 `completed / total` 时显示百分比、进度条和“进行中”；只有状态没有进度时只显示“进行中”，不补假数字。
- 需重试：显示红色失败标记与“需重试”；只有对应功能存在真实安全重试入口时才显示“重试”按钮，否则显示“查看处理”并进入所属功能详情。
- 已完成：显示绿色完成勾与“已完成”，不再显示进度条或多余按钮。
- 待确认、待配置、待登录、待提交等其他真实状态使用各自中文名称，不能统一降级为“状态同步中”。
- 右侧状态区宽度固定，状态文字右对齐；它不能覆盖中间标题，也不能被底部导航或屏幕胶囊遮挡。

### 手机列表布局

- 不再复用旧版 `.studio-task-record` 与 `.studio-task-action` 公共类，防止高优先级旧样式覆盖任务页间距。
- 每行固定为“图标区、正文区、状态区、箭头区”四块：图标不绝对压在文字上，正文可以省略，状态始终靠右。
- 390px 基准下图标区约 48px，状态区约 72px，箭头区约 16px，中间正文吃掉剩余空间。
- 窄屏只缩小图标和间距，不把状态覆盖到标题上；标题最多一行，来源和时间最多一行。

## 图标对应

- 顶部任务主视觉使用独立的任务组合插画，不再复用水货生产功能图。
- 三项统计分别使用播放场记板、紫色时钟、绿色完成勾三枚独立 3D 图标。
- 列表图标优先读取接口已有的 `kind / type / stage / taskType`，再用任务标题中的明确功能词做视觉分类，最后才按来源回退。
- 图标分类只影响显示，不参与任务状态判断，不修改接口数据，也不伪造任务类型文案。
- 使用项目里的高清透明 3D 资产；不再使用同一张“批量测书”图片覆盖全部任务。
- 图标匹配首先认任务所属功能标识，而不是靠标题猜测：剧本使用剧本/纸笔图标，私人定制使用人物场景图标，小说创作与续写使用书本羽毛图标，批量测书使用叠放书籍图标，漫剧创作使用漫画分格图标，分镜生成使用场记板图标，水货生产使用水货生产图标，AI-CUT 使用剪刀或成片导出图标，Agent 使用机器人工作台图标。
- 同一个功能内部再按真实阶段细分图标，例如漫剧的分镜阶段使用场记板、成片阶段使用影片导出；接口没有阶段时才使用该功能的主图标。
- 匹配顺序固定为：`moduleKey / source` → `kind / taskType` → `stage` → 明确标题词 → 所属功能默认图标。任何一个任务都不得因为字段缺少而直接套用“批量测书”或其他无关图标。
- 图标直接复用“功能”页已经确认的同一套资产和颜色，不在任务页重新画一套不同造型，保证用户看到图标就能认出任务来自哪个功能。

## 数据边界

- `services/taskSummary.ts` 继续负责跨来源归一化、排序、筛选和跳转目标。
- 归一化状态改为 `running / retry / completed / attention / unknown`；`attention` 仅用于展示真实待确认说明，不占顶部三项统计。
- 页面统计直接从归一化后的真实任务列表计算。
- 页面不会根据标题或功能类型猜测任务状态；标题关键词只允许选择展示图标。
- `/api/batch-factory/v12/batches/summary` 返回的是批次资料，不是执行状态，不能直接当任务。批量工厂必须读取对应批次的 `runtime-summary` 后再产生任务记录。
- 水货项目列表也不是任务；只使用项目下 `/tasks` 返回的真实生成任务。
- 任一来源读取失败只显示该来源的重试提示，不能把失败请求转换成零统计或虚构任务。

## 移动端尺寸

- 390px 基准左右留白 15px。
- 标题约 30–32px，列表标题约 16px，正文约 12–13px。
- 概览卡约 72–82px，筛选条约 42px，单行任务约 72–80px，保持微信手机屏幕内的信息密度。
- 底部导航固定为“功能、工作台、任务、我的”，第三项选中，最后一条任务不被安全区遮挡。

## 验证标准

- 微信开发者工具中可看到任务中心完整布局，控制台没有业务错误。
- 有任务、无任务、部分来源失败、全部来源失败、刷新中均能正常显示。
- 统计数量与筛选结果来自同一批真实数据。
- 进行中、需重试和已完成互不混淆，失败任务不会消失，未知状态不会伪装成同步中。
- 服务端未返回真实进度时页面中不存在百分比；返回 `2 / 5` 时只显示对应的 `40%`。
- 360px、390px 和 430px 三档宽度下，图标、标题、状态和箭头均不重叠。
- 与 `03-tasks.png` 做同尺寸并排对比，P0、P1、P2 差异清零。
- 任务相关测试、全量小程序测试和正式微信构建通过。

## 不在本轮范围

- 不修改后端接口或数据库。
- 不伪造任务、进度、时间、模型或项目名称。
- 不上传、不部署，不碰工作区无关改动。
