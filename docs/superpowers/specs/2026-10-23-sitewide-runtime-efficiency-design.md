# 全站运行一致性与资源效率设计

日期：2026-10-23

## 目标和边界

本次只处理 `localhost:4001` 当前网站及其直接依赖。目标是让实际运行页面与源码一致，减少无意义的页面下载和重复请求，并把高频状态刷新限制在真正需要时。豆包执行器的配对、在线状态和可用模型应由网站统一管理，供需要图片或视频生成的页面共用。

不处理本机执行器、历史目录、部署工作流、数据库历史数据和已删除模块的物理清理。它们只在确实仍被当前网站引用时进入检查范围。

## 已确认的问题

1. 当前运行侧栏仍显示“小说面板”，但源码和后端已拒绝该路由。运行中的内嵌前端与当前源码不一致。
2. `UserApp` 在任意页面打开后都会预加载小说获取和批量工厂。用户没有进入这些页面时也会下载它们的脚本和样式。
3. 批量工厂的本机执行器状态由三个独立定时器刷新；批量书籍页在执行状态、媒体弹窗或内容弹窗打开时还可能并行读取同一运行状态。
4. 现有对象 URL、事件监听器和动画大多已经有清理逻辑。不能仅因代码中出现计时器或 URL API 就删除，需以实际重复请求和卸载行为为准。
5. 豆包执行器已被 Agent 画布和批量工厂部分功能使用，但配对、在线状态和模型可用性分散在各页面；巨量素材执行器又是批量工厂的专用能力，当前界面没有清楚区分两者。

## 设计

### 导航与运行版本一致

- 以 `frontend/src/shared/layouts/UserLayout.jsx` 的导航定义为唯一来源，不保留已移除页面的入口。
- 改动完成后重建 React 资源、重建 Go 内嵌二进制并重启本地 `4001` 服务。
- 验证运行页面侧栏不再出现“小说面板”，直接访问该旧地址仍由后端稳定拒绝，不改回旧功能。

### 页面加载

- 取消应用启动后无差别预加载两个大型工作台。
- 保留 React 的按路由加载。只有用户把鼠标移到对应导航项、或明确进入相应工作流时，才提前加载目标页面。
- 预加载应只执行一次；页面离开前不保留不必要的重复任务。

### 状态刷新

- 为本机执行器状态建立单一刷新节奏：组件可见时读取必要状态；组件卸载、页面隐藏或不再需要状态时停止。
- 批量书籍页同一时刻只允许一个运行状态刷新在途。自动化、媒体和弹窗状态通过同一刷新入口合并，仍保留任务结束时的最后一次补刷。
- 不改变服务端任务执行、失败状态、手动刷新或后台任务持续运行的既有语义。

### 统一执行器中心

- 设置页作为豆包执行器的唯一配对与状态入口，保存当前账号对应的已配对设备、在线状态和可用的图片/视频能力。
- 剧本生成、Agent 画布和批量工厂不再各自维护一套配对判断；它们读取同一份能力状态，只展示与当前操作匹配的模型。
- 用户在剧本生成、Agent 画布或批量工厂中选择“本地豆包执行器模型”后即可提交图片或视频任务。执行器离线、未配对或不支持当前能力时，页面说明原因并让任务进入明确失败状态，不把正常操作入口提前隐藏或禁用。
- 巨量素材执行器继续只服务于巨量素材解析和导入，界面明确标记为“巨量素材专用”，不与豆包生成执行器混合。

### 大页面治理

- 不在本次把四千多行页面整体重写。
- 先将已确认的状态刷新与执行器状态整理为边界清楚的小模块；后续再按“任务状态、书籍设置、素材编辑、发布”逐块拆分。
- 每个拆分必须保持当前数据字段、页面操作和任务状态显示不变。

## 错误处理与兼容

- 任一状态请求失败只显示已有错误状态，不制造循环重试或重复弹窗。
- 页面从后台回到前台时补一次状态，不在后台持续刷接口。
- 继续保留 URL 回收、事件解绑及现有取消标志，防止异步请求在组件卸载后更新页面。

## 验证

1. 前端测试和生产构建通过；Go 内嵌资源重新生成并能启动。
2. 实际浏览 `localhost:4001` 的设置、批量工厂、小说获取和 Agent 页面，确认导航、跳转、宠物和现有任务入口正常。
3. 在批量工厂打开和关闭任务相关界面，确认不会出现重复的同类状态请求；切到后台后停止定时刷新，切回时只补刷一次。
4. 在设置完成一次豆包执行器配对后，确认剧本生成、Agent 画布和批量工厂读取同一在线状态，并只显示该执行器支持的模型。
5. 检查浏览器控制台没有新增错误；确认旧小说面板地址不再有可点击入口。

## 不纳入本次

- 不删除历史 Git 分支、工作流、执行器安装包或未追踪目录。
- 不做公网发布、提交或推送。
- 不改变模型供应商、账号、任务队列或业务提示词。
