# 私人定制漫画生成状态展示设计

## 目标

私人定制漫画是单本精细制作。用户必须在不点击菜单、不依赖临时弹窗的情况下，随时看清“漫画提示词”和“漫画图片”各自有没有生成、正在生成多少、是否失败，以及下一步可以做什么。

## 方案选择

采用两个常驻状态卡，分别展示“漫画提示词”和“漫画图片”。状态由已保存任务、后端 `comicReadiness` 和已加载漫画页共同推导，刷新页面后能够恢复。

不采用以下方案：

- 只改变主按钮文字：只能表达下一步动作，无法完整表达已完成和失败情况。
- 只使用消息弹窗：提示会消失，刷新后也无法恢复，不适合作为生产状态。

## 展示位置

状态卡放在右侧创作画布的操作工具栏下方、漫画结果区上方，始终可见。它不挤占左侧正文和资产区域，也不与通用任务错误卡重复。

每张卡包含：

- 阶段名称。
- 当前状态文案。
- 完成数量，例如 `12/20 页`。
- 需要用户处理时的动作入口。

## 漫画提示词状态

- `未生成`：已经有资产，但没有漫画页或没有完整提示词。
- `生成中`：当前正在执行提示词生成。
- `已完成 X/Y 页`：`comicPrompt` 和 `imagePrompt` 同时存在的页数为 X，总页数为 Y。
- `部分完成 X/Y 页`：已经生成部分页面提示词，但尚未全部完成。
- `生成失败`：任务失败且提示词未全部完成；展示可读错误，并提供“重试未完成项”。

提示词完成口径保持现有规则：一页必须同时具备 `comicPrompt` 和 `imagePrompt`，才算提示词完成。

## 漫画图片状态

- `等待提示词`：提示词还未全部完成。
- `未生成 0/Y 页`：提示词已完成，但还没有图片。
- `生成中 X/Y 页`：当前正在批量生图，同时展示已经完成的图片页数。
- `部分完成 X/Y 页`：已有部分页面图片，但当前没有任务运行。
- `已完成 X/Y 页`：每一页至少存在一张图片。
- `生成失败 X/Y 页`：存在失败页且图片尚未全部完成；提供“重试未完成项”。

图片状态只统计漫画页主图片是否存在，不把可选资产图计入漫画图片进度。

## 状态来源和优先级

1. 运行中的本地动作 `action` 用于立即显示“生成中”，避免点击后界面没有反馈。
2. 后端 `comicReadiness` 提供稳定的 `pagesTotal`、`promptReadyCount` 和 `imageReadyCount`，作为刷新后的主要统计口径。
3. 当前已加载漫画页用于补充页面级失败状态；后端就绪度缺失时才回退到页面统计。
4. 已完成状态优先于历史失败，防止成功后仍显示旧错误。

不新增新的状态存储，不再复制一套前端任务状态；只把现有真实数据转换成清楚的展示。

## 操作规则

- 提示词失败或部分完成时，“重试未完成项”调用现有 `onGeneratePrompts`，由现有接口补齐缺失提示词。
- 图片失败或部分完成时，“重试未完成项”调用现有 `onGenerateAllPageImages`，只生成缺失图片。
- 运行中禁止重复点击。
- 全部完成后不显示重试按钮。
- 通用任务错误卡继续保留详细错误，状态卡只显示简洁状态和必要动作。

## 可访问性

- 状态容器使用 `role="status"` 和 `aria-live="polite"`，生成状态变化时可以被辅助工具读取。
- 失败状态使用可读中文，不把内部状态码或接口路径直接展示给用户。
- 颜色只作为辅助，状态文字和数量必须单独表达完整含义。

## 验收标准

- 私人定制漫画页始终同时显示“漫画提示词”和“漫画图片”两个状态卡。
- 当前本地任务有 5 个资产、0 个提示词时，显示“漫画提示词：未生成”和“漫画图片：等待提示词”。
- 提示词或图片生成中时，状态立即变为“生成中”，并显示完成页数。
- 部分完成、失败、全部完成均有独立可读状态。
- 刷新页面后，状态按照后端已保存数据恢复。
- 重试只补未完成项，不重头重复生成已完成页面。
- 不调用真实模型完成验收；使用状态推导单元测试和本地已有数据验证。
