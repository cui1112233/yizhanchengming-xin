# 漫画发布音频按小说风格匹配设计

## 目标

漫画发布时，不再给整个批次固定使用同一个音频分类和同一首音频。系统针对每本书，读取已经识别并保存的“男女频”和“风格”，自动匹配 N8 音频分类，再从该分类当前可用的音频中随机选择一首。

同一本书第一次选定音频后保存结果。后续失败重试、断点续跑或重复进入发布流程时继续复用，不重新随机，避免一次任务前后使用不同音频。

## 每本书的处理流程

1. 读取本书已经保存的男女频、风格以及手动音频选择。
2. 如果用户已经手动指定音频，直接复用手动结果，不执行自动匹配。
3. 如果本书此前已经自动选定并保存音频，直接复用，不重新随机。
4. 根据上表得到目标音频分类名称。
5. 从 N8 实时启用目录中按名称查找唯一分类，同时取得分类名称和分类 ID。
6. 使用当前组织和分类 ID 查询启用音频列表。
7. 从可用列表中等概率随机选择一首，并把分类名称、分类 ID、音频名称、音频 ID 和选择方式保存到本书。
8. 发布时只使用本书保存的分类 ID 和音频 ID。

一个批次中即使包含不同风格的书，也按照每本书分别处理，不再要求整个批次只能推断出同一个音频分类。

## 手动设置与显示

- 统一配置保留自动匹配能力，但不再用一个自动结果覆盖整批书。
- 单书发布预览需要显示：`男女频 + 风格 → 音频分类名称（ID）→ 音频名称（ID）`。
- 用户手动选择分类或音频后，该书进入手动模式，自动逻辑不得覆盖。
- 用户主动点击“恢复自动匹配”后，才清除该书原有手动结果，并重新按规则随机一次。
- 分类名称和 ID 始终作为一对显示和保存，禁止出现名称属于一个分类、ID 属于另一个分类的情况。

## 随机与重试规则

- 随机范围只包含当前组织、目标分类下处于启用状态的音频。
- 每本书独立随机，因此同一批书允许选中不同音频，也允许碰巧选中同一音频。
- 随机结果一旦保存，普通刷新、自动重试、发布重试和断点续跑都必须复用。
- 自动选择的原音频已被目录明确标记为不可用时，允许在同分类内重新随机；手动选择的音频不可用时只提示用户重新选择，不能自动覆盖。
- 并发执行时，以数据库中第一次成功保存的选择为准，避免同一本书同时产生两个随机结果。

## 异常处理

- 目标分类在实时目录中不存在、未启用或同名不唯一：停止当前书发布并显示具体分类名称，不偷偷改用其他分类。
- 目标分类下没有启用音频：停止当前书发布并提示“当前组织的该分类没有可用音频”。
- N8 目录读取失败：保留已经保存的选择；没有历史选择的书暂不发布，等待重试。
- 保存成功但发布失败：重试时使用已保存的原分类和原音频。
- 自动选择的已保存音频后来不可用：在发布前明确提示并在同分类内重新随机；手动选择的音频不可用时停止当前书并提示用户重新选择。

任何一本书的音频问题只影响这本书，不应让已经成功发布或已经选好音频的其他书重新开始。

## 数据保存

每本书至少保存以下信息：

- 音频分类名称和 ID；
- 音频名称和 ID；
- 选择方式：自动或手动；
- 用于匹配的男女频和风格快照；
- 首次选定时间。

这些字段属于本书的漫画发布结果，不能只保存在浏览器页面状态中。

## 验收标准

1. 表中每一种小说风格都能得到预期分类，职场打脸和未知风格按男女频分流。
2. 混合风格批次中的每本书能得到各自的分类，不再提示“批次分类不一致”。
3. 分类名称和 ID 始终与 N8 实时目录中的同一条记录一致。
4. 同一分类下有多首启用音频时，每本书随机选一首并保存。
5. 同一本书重试十次仍使用第一次保存的音频。
6. 手动指定结果不会被自动逻辑覆盖；恢复自动匹配后才重新选择。
7. 分类不存在、音频为空或目录失败时有明确提示，并且不会静默换分类。
8. 单书失败不会让同批其他已完成书籍重头处理。

## 不在本次范围内

- 不使用 AI 再次判断音频分类或具体音频。
- 不修改小说男女频和风格的识别方式。
- 不修改发布账号、组织和作品 ID 的匹配规则。
- 不做按照剧情段落、人物情绪或语义标签的逐段配乐。
