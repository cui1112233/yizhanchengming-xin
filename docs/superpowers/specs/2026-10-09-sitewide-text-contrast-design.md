# 全站文字对比度修复设计

## 目标

让用户前台和管理后台在深色、浅色主题下都能清楚阅读标题、正文、表单、按钮、表格、标签、提示和禁用状态；消除透明文字和背景/文字颜色不匹配的问题。

## 范围

- 用户前台：首页、剧本生成、小说获取、小说面板、水货生产、批量工厂、Agent、历史、问题日志、配音、设置、个人中心。
- 管理后台：提示词库、提示词策略、平台技能、模型配置、错误日志等页面。
- 公共层：全局主题变量、Ant Design 主题变量、登录框、侧边栏、顶部栏、弹窗、表格、输入框和按钮。

本次不改变接口、业务流程、页面布局、任务状态语义或外部服务配置。

## 根因

当前前端同时存在全局变量、Ant Design 变量、个人中心私有变量和页面硬编码颜色。静态审计发现 623 处硬编码文字颜色；其中部分样式把实际文本设为 `color: transparent`。主题切换时，文字颜色没有和背景一起切换，导致深色背景上的深灰字、浅色背景上的浅色字，以及渐变/透明区域的低对比文字。

## 设计

### 统一语义颜色

在 `frontend/src/shared/styles/global.css` 定义下列语义变量，并在默认深色和 `[data-theme='light']` 下分别赋值：

```text
--text-primary
--text-secondary
--text-tertiary
--text-disabled
--text-link
--text-on-accent
--text-danger
--text-warning
--text-success
--surface-base
--surface-panel
--surface-input
--border-default
--border-strong
```

规则：页面样式应优先引用语义变量。业务状态可以保留红、黄、绿等状态色，但状态色文字仍必须在所属背景上清晰可读。

### Ant Design 同步

`frontend/src/shared/styles/theme.js` 使用与 CSS 变量同等级的深浅主题 token，至少同步正文、辅助文字、弱提示、禁用文字、容器背景、输入框背景和边框颜色。这样 Ant Design 组件与自定义 CSS 不会出现两个对比标准。

### 禁止透明隐藏真实文本

移除用于真实标题、真实状态和真实正文的 `color: transparent`。只有明确的装饰性渐变文本允许透明字色；这类元素必须有纯色后备显示，并且不能承载唯一业务信息。

### 页面分批替换

1. 公共基础层：全局变量、Ant Design、登录、导航、表单、弹窗、表格。
2. 账号与设置：个人中心、会员、安全、团队、模型和提示词配置。
3. 创作与任务页：剧本、小说获取、小说面板、配音、Agent、历史和问题日志。
4. 高密度业务页：水货生产、批量工厂、巨量素材和相关抽屉/弹窗。
5. 管理后台：使用同一语义变量与 Ant Design token，消除独立硬编码灰色。

每一批完成后，只处理该批页面的文字与边框对比，不顺手重排布局或改业务组件。

## 验收

每个覆盖页面必须在深色、浅色主题下检查：

- 标题、正文、表单标签、输入值、占位符、按钮、链接、表格和标签均清晰可读。
- 辅助信息可弱化但不得融入背景。
- 禁用状态仍可辨认且明显弱于普通文字。
- 业务状态红、黄、绿在其背景上可读。
- 不存在由 `color: transparent` 隐藏的业务文字。
- 前端现有测试与构建继续通过。

## 不在本次范围内

- 不更换全站视觉风格。
- 不调整 Node/Go、MySQL、Redis、Worker、TOS、模型或任何业务接口。
- 不删除旧样式文件；仅在有明确替代规则时移除无效覆盖。
