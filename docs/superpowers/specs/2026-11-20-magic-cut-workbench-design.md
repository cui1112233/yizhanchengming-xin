# 魔剪 4040 独立工作台设计

日期：2026-11-20  
目标仓库：`F:\脚本测试\一战晟铭-v88`  
维护分支：`v88`

## 1. 目标与边界

在一战晟铭仓库内建立独立的魔剪开发区，开发期监听 `4040`，完整后再按模块并入现有 `backend/` 与 `frontend/`。开发期不改现有 `4001` 的魔剪业务数据，不使用公网部署，不调用付费模型。

第一期只实现一条真实可用的核心链路：

`一战晟铭模式下拉 -> 魔剪 -> 首页 -> 新建自由创作 -> 导入素材 -> 时间线编辑 -> 导出 -> 任务中心`

“使用一致”是硬性验收条件，包括入口、页面顺序、按钮文案、默认值、弹窗、快捷键、空状态、加载状态、失败提示、取消、重试、刷新恢复和真实导出结果。静态发布包只能证明页面和能力存在，不能代替运行时交互及像素验收。

## 2. 采用方案

采用“仓库内独立工作台”方案：

```text
magic-cut-workbench/
  api/          独立 Go 服务，开发期监听 4040
  前台/         React 18 + Ant Design 5
  docs/         魔剪页面、交互和接口对照资料
  migrations/   独立 magic_cut 数据表
  README.md      启动、验证和最终合并说明
```

不采用仅有前端、继续把业务请求打到 4001 的空壳方案；也不另建仓库，避免以后合并时复制两套认证、主题和组件。

## 3. 一战晟铭下拉入口

入口以用户提供的现有工作模式下拉截图为准，不新增侧边栏图标。

当前下拉项为：

1. 一战晟铭
2. Agent 代理
3. Duet（未实现）

新增后固定为：

1. 一战晟铭
2. Agent 代理
3. 魔剪
4. Duet（未实现）

开发期行为：

- 在 4001 点击“魔剪”，使用当前协议和主机名跳转到同主机的 `4040`，避免把 `localhost` 和 `127.0.0.1` 写死成两个登录域。
- 4040 顶部保留同款工作模式下拉，“魔剪”显示选中勾号。

- 完整合并后，“魔剪”改为同源 `/magic-cut` 路由，不再跨端口；菜单文案和顺序不变。

## 4. 登录与数据隔离

### 4.1 登录

4040 复用一战晟铭账号，不建立第二套注册和密码系统。

- 浏览器继续使用现有 Bearer token 和账号预览缓存。
- 4040 只把 `/api/login/session`、登录、退出和通行密钥相关请求转发到同主机 4001。
- 转发保留 Authorization 头和必要 Cookie，但不记录 token、密码和通行密钥内容。
- 4001 不可用时，4040 明确显示“无法连接一战晟铭账号服务”，不能伪造登录成功。
- 除认证接口外，魔剪业务请求不得转发到 4001。

### 4.2 MySQL

- 使用独立开发数据库 `qiantie_magic_cut_dev`，表名统一以 `magic_cut_` 开头。
- 第一阶段表：工程、工程版本、素材、时间线快照、任务、任务尝试、导出记录。
- 每条业务记录保存一战晟铭用户 ID/用户名作为所有者，读写均按所有者隔离。
- 迁移文件只放 `magic-cut-workbench/migrations/`，开发期不加入现有 4001 Goose 迁移链。

### 4.3 Redis

- 所有键固定使用 `magic_cut:dev:` 前缀。
- Redis 保存等待队列、运行锁、幂等键、心跳和短期进度。
- MySQL 保存权威任务状态。Redis 丢失后可根据 MySQL 中未完成任务恢复。

### 4.4 TOS

- 对象键固定使用独立测试前缀 `magic-cut/dev/<owner>/...`。
- 浏览器不保存长期 TOS 密钥；上传和下载由 Go 后端签发短期权限或代理执行。
- 没有测试 TOS 配置时允许使用独立本地存储完成免费验收，但界面必须明确显示“本地测试存储”，不能伪装为云空间。

## 5. 第一阶段页面与操作

### 5.1 首页

- 保留原版深色视觉基准和工作流入口顺序。
- 显示近期工程、空状态、新建自由创作入口。
- 工程卡支持打开、重命名和删除确认；失败后保留原卡片并显示明确原因。

### 5.2 新建自由创作

- 字段顺序、标签、默认值、校验提示按原版恢复。
- 创建成功后直接进入编辑器；创建失败不关闭弹窗，不清空用户输入。
- 重复点击由幂等键保护，只产生一个工程。

### 5.3 导入素材

- 支持视频、图片和音频。
- 展示文件名、类型、大小、时长、分辨率、处理进度和失败原因。
- Go 后端使用 FFprobe 获取媒体信息，并通过后台任务生成缩略图、波形或代理文件。
- 无效格式、文件丢失、无权限、空间不足和处理失败分别显示原版对应语义，不能全部归为“上传失败”。

### 5.4 时间线编辑

- 固定区域：左侧素材区、中央播放器、右侧属性区、底部时间线。
- 第一阶段实现播放头、时间线缩放、片段选择、移动、裁切、分割、删除、复制、撤销和重做。
- 所有编辑都经过统一命令层，每条命令能生成反向操作；保存不能清空本地撤销历史。
- 自动保存使用工程版本号，旧版本写入必须返回冲突，前端不能静默覆盖。
- 刷新后恢复最近一次已确认保存的时间线和未完成任务。

### 5.5 导出

- 使用原版导出弹窗顺序和默认参数。
- 创建任务后进入任务中心，可查看准备、执行、成功、失败、取消状态。
- 支持取消和失败重试；重试生成新的任务尝试记录，不覆盖旧失败证据。
- 成功必须产生真实可播放文件，并记录路径、大小、时长、分辨率、编码和 SHA-256。

### 5.6 任务中心

- 汇总导入处理、代理文件、缩略图、波形和导出任务。
- 状态统一为 `queued`、`preparing`、`running`、`paused`、`succeeded`、`failed`、`canceled`。
- 断线重连先补拉 MySQL 权威状态，再接收实时进度，不能只依赖内存百分比。

## 6. 后端模块

```text
api/
  cmd/magic-cut-4040/
  internal/authbridge/   只读复用 4001 身份
  internal/project/      工程和版本
  internal/material/     素材、媒体探测和派生文件
  internal/timeline/     轨道、片段、关键帧和校验
  internal/task/         MySQL 状态、Redis 调度、取消和恢复
  internal/export/       导出计划和 FFmpeg 执行
  internal/storage/      本地测试存储与 TOS
  internal/prompt/       后续 AI 系统提示词；第一阶段不调用模型
```

Go 服务同时提供 API、任务进度流和嵌入后的 React 静态资源。开发构建最终输出一个 4040 测试二进制，完整合并后模块迁入现有 `backend/`，页面迁入 `frontend/` 并由现有 Go embed 统一发布。

## 7. 前端模块

```text
前台/src/
  app/
  shared/auth/
  shared/api/
  shared/work-mode/
  features/home/
  features/project-create/
  features/materials/
  features/player/
  features/timeline/
  features/export/
  features/task-center/
```

- React Query 或等价小型请求层保存服务端数据。
- 时间线编辑状态使用独立 store，不能把大文件内容放进 React state。
- 页面文字建立原版文案清单，组件不得自行改写同一含义的提示。
- 第一阶段不加入原版未出现的新 AI 助手、推荐弹窗或额外步骤。

## 8. 错误与恢复

- 每个后台任务保存阶段、进度、最后心跳、失败代码、用户可见错误和可重试标记。
- 服务重启时扫描 `queued/preparing/running` 任务；确认没有活动 worker 后恢复或标记失败。
- 文件处理使用受控参数调用 FFmpeg，禁止把用户输入直接拼入命令行。
- 删除工程或素材前检查任务和引用；无法删除时说明被哪个工程或任务占用。
- 所有失败均保留用户当前输入、时间线和已完成派生文件，避免重新开始。

## 9. 测试与验收

### 9.1 自动测试

- Go：工程隔离、版本冲突、素材探测、任务状态、取消、恢复、导出计划和路径安全。
- React：工作模式菜单、创建表单、素材状态、时间线命令、自动保存冲突、导出和任务中心。
- 合约：前端 DTO 与 Go 请求响应保持一致。

### 9.2 原版一致性

- 页面：正常、空、加载、失败、无权限、断网和恢复状态逐项对比。
- 操作：从入口开始按相同顺序完成同一个任务，不需要额外学习。
- 文案：按钮、字段、说明、确认和错误提示建立逐项清单。
- 像素：固定窗口、字体和缩放后比较布局、间距、颜色、字号、弹层和时间线几何。
- 媒体：相同无敏感测试素材、相同导出参数做旧/新 A/B，验证时长、帧率、分辨率、编码、音画同步和可播放性。

静态反编译结果不等于运行时一比一。需要启动原程序或使用测试账号做动态观察时，必须另行取得用户明确同意；动态观察不调用付费生成、不上传用户隐私素材。

## 10. 实施阶段

1. 4040 骨架、登录桥、独立配置和健康检查。
2. 一战晟铭工作模式下拉加入“魔剪”，4040 复刻同款菜单。
3. 首页、工程和新建自由创作。
4. 素材导入、媒体探测和派生任务。
5. 播放器、时间线和命令层。
6. 自动保存、刷新恢复和版本冲突。
7. 导出与任务中心。
8. 原版逐状态、逐交互和媒体 A/B 验收。
9. 完整后迁入现有 `backend/`、`frontend/` 和 Go embed；4040 开发入口退出。

## 11. 明确不在第一阶段做的内容

- 高光、钩子、批量短剧、选剧助手、仿剪、数字人、AI 前贴、达人二创和漫剧转译。
- 真实付费模型调用、生产 TOS 写入和公网发布。
- 对原版商标、内部密钥、账号数据、付费素材或服务端私有提示词的复制。

这些能力后续按独立规格逐项加入同一个魔剪工作台，不另外创建零散应用或长期分支。
