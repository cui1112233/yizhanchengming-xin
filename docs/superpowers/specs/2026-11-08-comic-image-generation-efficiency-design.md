# 漫画生图效率与防重复计费设计（2026-11-08）

状态：已确认，执行中
目标分支：`v88`

## 1. 目标

解决“一本书生图很久、上游已完成但图片迟迟不回来、重试可能重复扣费”的问题，同时保持现有漫画页、TOS 上传和 7 天本地清理链路不变。

## 2. 已确认的实际链路

一张漫画图依次经过：等待并发名额 → 上游生成并返回响应头 → 读取响应正文或下载 CDN 图片 → 水印处理 → 保存本地文件 → 漫画页落库 → 现有 Production Media Worker 上传并校验 TOS。

目前日志只有排队时间和总耗时，无法分清慢在上游、响应正文、CDN 下载还是本地保存。现有 Production Media 已负责 TOS 和本地副本清理，本设计不重复建设。

## 3. 方案

### 3.1 分段计时

每次请求记录：

- `queue_ms`：等待生图名额；
- `header_ms`：提交请求到收到响应头，即上游主要生成时间；
- `body_ms`：读取 JSON 正文；
- `download_ms`：从结果 URL 下载图片，base64 模式为 0；
- `save_ms`：水印与本地落盘；
- `total_ms`：整张图端到端耗时。

结构化日志保留现有字段并增加以上字段。这样能直接与上游的 23–44 秒记录对账。

### 3.2 精确结果缓存

生成指纹由账号、实际模型、最终提示词、画幅、参考图列表、是否编辑模式和水印设置共同计算。只有这些输入完全相同，才允许复用已经成功落盘的图片。

缓存只保存稳定的 `storage_ref` 和媒体类型，不复制图片。读取仍走现有 local-first / TOS fallback，因此本地文件已被 7 天清理后也能从 TOS 恢复。

明确点击“重新生成”时绕过缓存；自动化恢复、刷新状态和只补缺页可以使用缓存。

### 3.3 防止重复扣费

- HTTP 200 后正文断流标记为“已计费但未取回”，请求层绝不自动重发；
- 页级自动重试只处理尚无成功图片的页；
- 成功结果立即写缓存和漫画页，不等整本结束；
- 同一个指纹正在生成时，后来的请求等待前一个结果，而不是并发重复提交。

### 3.4 自适应并发

保留用户设置的 1–4 路上限。某个上游主机连续出现断流、连接重置或明显慢响应时，本进程把该主机临时降到 2 路；连续成功后逐步恢复到用户设置。只影响后续请求，不取消正在生成的图片。

第一阶段先实现可测试的控制器和日志，不在故障时主动重发已计费请求。

## 4. 数据设计

新增 `batch_factory_v12_image_generation_cache`：

- 以 `owner_username + fingerprint` 唯一；
- 保存 `storage_ref`、`media_type`、模型、状态和最新分段耗时；
- `generating` 记录带租约，进程崩溃后可回收；
- `ready` 只有图片已成功落盘后才写入；
- `failed` 不作为可复用结果。

不在表内保存密钥、完整提示词或图片二进制。

## 5. 兼容与回滚

- 缓存仓库不可用时退回原有生图路径，不影响基本功能；
- 不修改漫画页与图片表的既有含义；
- 不修改现有 TOS object key 和清理规则；
- 新迁移只新增表，可通过停用缓存组件回滚行为。

## 6. 验收标准

- 单测能分别证明 queue/header/body/download/save/total 的计算正确；
- 相同指纹的第二次自动调用不再请求上游；
- 明确“重新生成”仍会请求上游；
- HTTP 200 后断流不会在请求层二次生成；
- 自动化重试只处理没有成功图片的页；
- 本地 Go 测试、前端构建、4001 健康检查通过；
- 付费 A/B 和线上发布在单测完成后单独执行并记录证据。
