# 私人定制入口与单次漫画生成设计

## 意图

把用户侧导航中的“剧本生成”升级为“私人定制”。私人定制保留现在的剧本创作能力，并新增一个“漫画生成”工作区，允许用户直接粘贴一段内容后生成单次漫画任务。批量工厂继续负责多本小说、批量队列、统一配置和批量发布。

核心区别是：私人定制面向一段内容的快速执行；批量工厂面向书籍批量生产。两者复用同一套漫画生产后端，避免维护两套图片生成、重试、状态和发布逻辑。

## 目标

- 左侧导航、首页入口和页面标题统一显示“私人定制”。
- 保留 `/script` 地址，旧链接和历史记录继续可用。
- 在私人定制页面提供“剧本创作”和“漫画生成”两个工作区。
- 漫画工作区支持直接粘贴正文，填写或自动得到标题，启动单本漫画生成。
- 漫画工作区保留现有“画风库”选择、画风预览、全局参考图和图片描述词前后缀配置。
- 复用现有 Batch Factory 漫画页、资产、重试和状态读取能力。
- 私人定制默认只生成漫画内容和合集，不自动向外部漫画后台发布；发布仍由用户明确操作。
- 任务进行中显示可理解的进度、失败原因和继续查看入口，不暴露批量工厂内部概念。

## 非目标与反目标

- 不重写现有批量工厂漫画流水线。
- 不迁移、删除或改变历史批次和历史剧本记录。
- 不把两个页面复制成两套漫画生成代码。
- 不因改名修改内部 `script` 类型、历史文件目录或已有 API 路径。
- 不在用户点击“生成漫画”时隐式执行外部发布。

## 约束

- 前端继续使用现有 React、Ant Design 和 `/script` 路由。
- 后端继续使用现有 Go Batch Factory API 和 MySQL/Redis 任务机制。
- 预设提示词仍由后端提供，前端不新增硬编码系统提示词。
- Go embed 构建和现有本地运行方式不变。
- 与现有脏工作区无关的文件必须保留，不做清理、回滚、提交或远程发布。

## 方案比较

### 方案一：统一入口、两个工作区（选用）

保留 `/script` 页面作为私人定制入口，在页面顶部增加“剧本创作 / 漫画生成”切换。漫画工作区直接使用粘贴内容创建一个单本 Batch Factory 任务，随后只展示单本任务的进度和结果。批量工厂仍是完整的批次管理入口。

这是当前选择：对现有代码侵入较小，能够复用已经验证过的漫画重试、进度和合集逻辑，同时满足“这里也能直接生成漫画”。

### 方案二：剧本完成后串联漫画

把提取人物、生成剧本、分镜确认、漫画分页和出图串成同一条前端流程。体验最连贯，但需要重新定义剧本输出与漫画分页之间的状态协议，改动范围和回归风险都明显更大。

### 方案三：在私人定制中嵌入现有批量工厂页面

私人定制只负责接收正文，之后打开现有批量工厂单本界面。开发最快，但用户会看到批次、书籍列表等不属于单次定制的概念，两个工作台的边界也会变得模糊。

## 交互与数据流

1. 用户点击“私人定制”，默认进入原有剧本创作工作区。
2. 用户切换到“漫画生成”，粘贴正文并填写标题；标题为空时使用正文第一条非空短句作为默认标题，并允许修改。
3. 用户在同一工作区选择画风库中的画风；默认参考图使用所选画风的预览图，也可以上传自定义全局参考图，并分别控制是否用于资产图和漫画页。已有的图片描述词全局前缀/后缀也沿用。
4. 点击“开始生成漫画”后，前端调用现有批量工厂创建/启动能力，创建一个仅包含当前内容的单本任务，运行模式默认不自动发布。
5. 页面保存任务 ID，并轮询现有运行摘要接口，展示当前阶段、完成页数、失败原因和重试状态。
6. 生成完成后展示漫画页/合集预览；需要发布时由用户点击明确的发布操作进入现有发布流程。
7. 切回“剧本创作”不会清空正文、提取结果或历史状态；两个工作区共享当前账号配置，但不互相覆盖草稿。

## 界面命名

- 左侧导航：`剧本生成` → `私人定制`
- 首页快捷入口：`新建剧本项目` → `私人定制`，描述改为“粘贴内容，生成剧本或漫画制作素材”
- 页面标题：`私人定制`
- 页面工作区：`剧本创作`、`漫画生成`
- 现有 `/script` 路由、内部 script 类型和历史记录名称保持兼容

## 实现边界

- 前端主要改动：`UserLayout`、`HomePage`、`ScriptPage`，以及与脚本页相关的样式和源代码测试。
- 前端漫画提交优先复用 `batchFactoryV12` 现有 API；如果现有创建接口不能表达“单本、只生成不发布”，只补一个最小后端适配字段，不复制整条流程。
- 画风库直接复用现有 `BatchFactoryComicStylePicker` 及其预设目录接口，不在私人定制中重新做一套画风选择器；管理员维护的已发布画风、预览图和参考图规则继续作为唯一来源。
- 后端需要保证单本任务的 owner、批次 ID、运行模式和状态摘要能被私人定制页读取。
- 任务详情和结果只在当前用户范围内可见。

## 验收标准

- 左侧导航和首页入口显示“私人定制”，旧 `/script` 链接仍能打开。
- 私人定制页能在两个工作区间切换，原剧本生成流程不退化。
- 粘贴正文、填写标题后可启动单本漫画生成，页面能显示任务阶段和页数进度。
- 漫画工作区能选择画风库画风，看到预览，使用默认或自定义全局参考图，并将选择保存到本次任务。
- 漫画生成失败时能显示具体失败原因并支持已有重试入口。
- 私人定制不会自动触发外部漫画发布。
- 批量工厂原有批次、漫画生成、任务日志和发布流程通过现有测试及本地运行验证。

## 交给实现者的事项

- 先确认现有单本批量创建接口是否支持“只生成不发布”；能复用就不新增接口。
- 复用现有漫画工作区可用的模型、风格和约束配置，避免在脚本页复制配置表单。
- 画风库沿用现有的封面流选择交互、画风预览、参考图开关和图片描述词前后缀；私人定制只补单本任务所需的展示和保存，不改变管理员画风库数据。
- 为工作区切换、单本任务启动、状态回读和导航改名补充聚焦测试。
