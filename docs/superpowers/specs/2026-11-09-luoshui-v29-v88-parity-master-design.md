# 洛水 v2.9.0 → 一战晟铭 V88 功能对照总设计

日期：2026-11-09

状态：待用户审阅

范围：本地 V88 设计与后续分期实施，不发布公网

参考样本：`F:\脚本测试\work\洛水2026-v2.9.0-反编译分析`

## 1. 目标

本设计把洛水 v2.9.0 已确认的用户功能、页面结构、提示词用途和业务链路，映射到一战晟铭 V88 的现有架构中。

目标不是复制洛水安装包或另建一套孤立系统，而是：

1. 先识别 V88 已有能力，避免重复开发；
2. 把缺失能力按五期逐步补入 V88；
3. 保持 Agent、画布、小说获取、剧本、批量工厂和媒体生产的数据互通；
4. 所有系统提示词由 Go 后端统一管理，前端不硬编码真实提示词；
5. 每期都必须有真实页面、真实数据、真实任务状态和本地嵌入式运行验收。

## 2. 证据与实现边界

洛水参考依据包括：

- v2.9.0 已登录界面的既有只读观察；
- 活动前端构建包中的页面、控件、文案和 451 个桥接方法；
- 72 个 Nuitka 业务模块的常量、函数、接口和数据落点；
- 本地数据库中的 181 条提示词及分类；
- 37 个技能文件和 26 条技能注册记录。

这些证据足以确认功能、页面结构和大部分输入输出，但不等于洛水原始源码。本项目只参考用户可见行为、数据结构和业务作用，不把编译后的 JavaScript、Nuitka 恢复结果或洛水运行文件复制进 V88。

提示词原文作为离线分析证据保存，不直接整库导入。实现时按 V88 的业务语义重写、合并和版本化；若确需逐字采用某条提示词，必须先确认其来源和使用授权，并为该条建立独立审阅记录。

## 4. 分期顺序

### 第一期：Agent、画布、分镜、3D 导演台

复用 V88 当前最成熟的 Agent Canvas 底座，补齐洛水中价值最高、与现有能力重合最多的创作入口。第一期详细设计见：

`docs/superpowers/specs/2026-11-09-agent-canvas-director-parity-phase1-design.md`

### 第二期：小说创作与作品资料

新增长篇原创、短篇原创、仿写、续写和番外等用户流程；补齐作品、章节计划、会话、写作风格、资料导入、备忘录、定时写作和数据看板。小说获取只负责获取与加工来源内容，不与原创写作编排强行合并。

### 第三期：剧本和完整视频生产

在 ScriptPage 和批量工厂基础上统一人物、场景、道具、分镜、图片、视频、音频、字幕和成片版本。加入分镜合并、片段重拍、超长视频分组和多模型配置，但不建立重复资产库。

### 第四期：AI-CUT 与 AI 工具箱

建设多轨时间线、素材库、预览、字幕、转写、智能分割、粗剪、BGM、高光、超分、渲染和剪映草稿导出。媒体处理走本地执行器或后端任务，不在浏览器里伪造进度。

### 第五期：技能、知识库和完整任务编排

补齐技能注册、环境检查、技能权限、自动任务、批次、失败续跑、知识书籍、聊天历史索引和知识推理。外部技能默认受控执行，不允许技能文档自行扩大权限。

## 4.1 功能一致性契约

本项目中的“与洛水功能一致”不是指按钮名称相同或页面外观相似，而是以下九项同时对得上：

1. **入口一致**：用户能在合理且稳定的位置找到该功能；
2. **操作一致**：关键操作步骤、选择范围和确认时机一致；
3. **输入一致**：支持同类文本、素材、参数、引用和批量范围；
4. **输出一致**：产生同类结构化结果、媒体结果或项目变更；
5. **保存一致**：刷新、重新登录或服务重启后仍能恢复正式结果；
6. **状态一致**：排队、执行、待确认、成功、失败和取消状态真实可见；
7. **恢复一致**：失败原因明确，允许的重试、续跑和取消行为一致；
8. **提示词作用一致**：提示词负责的业务判断、输入上下文和输出字段一致；
9. **链路效果一致**：结果能继续流入下一步，而不是停在孤立页面或临时弹窗。

视觉不要求逐像素复制，外部模型和渠道也不要求使用同一家供应商；但替代实现必须达到相同的用户目的，并在对照台账中写清差异。

每个功能只能使用四种状态：

| 状态 | 含义 |
|---|---|
| `matched` | 九项一致性要求均通过验收 |
| `equivalent` | 技术实现不同，但用户作用、输入输出和链路效果等价 |
| `partial` | 页面或部分链路存在，仍缺保存、状态、恢复或下游联动 |
| `excluded` | 经用户确认不做，并记录原因和替代方案 |

禁止把“已有按钮”“接口返回 200”“前端构建通过”单独当作 `matched`。

每一期必须维护一份功能对照台账，至少包含：

```text
feature_id
洛水入口与用户操作
洛水输入/输出
洛水证据位置
V88 页面与代码位置
V88 API、数据表、任务和提示词 ID
一致性状态
已知差异
自动测试证据
本地运行证据
浏览器验收证据
```

台账中的 `matched` 和 `equivalent` 必须有可重复的验收步骤。没有证据时默认为 `partial`。

## 5. UI 参考设计

### 5.1 借鉴范围

参考洛水的页面信息架构和高频交互：

- 左侧一级导航进入小说、作品、剧本、画布、剪辑和 Agent；
- 项目内使用二级导航切换画布、分镜、素材和任务；
- 中央区域始终是主要创作内容；
- 右侧按上下文显示 Agent 对话或对象属性；
- 底部显示生成输入、任务状态或时间轴；
- 画布工具采用悬浮、可收起的轻量控件；
- 大批量操作先展示范围和预计结果，再执行。

### 5.2 不直接复制的部分

- 不照搬洛水构建包的 DOM、CSS、图标文件或品牌素材；
- 不复制一比一颜色和皮肤；
- 不显示尚无真实能力的按钮；
- 不把桌面端本地文件路径直接暴露到 V88 Web 页面；
- 不让一个功能在多个侧栏、弹窗和页面出现三套入口。

### 5.3 V88 视觉规则

- 延续 React + Ant Design 和现有 V88 主题变量；
- 以深浅主题均可读为硬性标准；
- 强调色使用 V88 当前主题色，紫色只作为参考，不固定复制 `#7c3aed`；
- 工作台采用紧凑布局，避免大量厚重卡片；
- 图标命令配悬浮说明，危险操作使用文字和二次确认；
- 抽屉、下拉和悬浮层必须 portal 到 `document.body`，避免被画布裁剪；
- 宽屏保持三栏，窄屏把右栏改为抽屉，中央画布不得被覆盖；
- 空状态必须说明下一步怎么做，不能只显示空白画布。

### 5.4 多主题切换

洛水 v2.9.0 的全局设置中可确认 12 个主题预设：深色、浅色、浅灰白、浅绿、雪山蓝、香草黄、樱花粉、纯黑、鸢尾紫、柳芽黄、象牙白和荷花白。V88 参考这种“用户可选择工作环境”的能力，但不复制洛水的 CSS 类和具体颜色数值。

V88 主题目录设计为：

| 主题 ID | 用户名称 | 类型 | 首期状态 |
|---|---|---|---|
| `system` | 跟随系统 | 自动 | 提供 |
| `dark` | 深夜黑 | 深色 | 提供，兼容当前深色主题 |
| `light` | 明亮白 | 浅色 | 提供，兼容当前浅色主题 |
| `pureblack` | 纯黑 | 深色 | 提供 |
| `graywhite` | 雾灰白 | 浅色 | 提供 |
| `mint` | 薄荷绿 | 浅色 | 提供 |
| `snow` | 雪山蓝 | 浅色 | 提供 |
| `vanilla` | 香草黄 | 浅色 | 提供 |
| `sakura` | 樱花粉 | 浅色 | 提供 |
| `purple` | 鸢尾紫 | 浅色/柔和 | 提供 |
| `willow` | 柳芽黄 | 浅色 | 提供 |
| `ivory` | 象牙白 | 浅色 | 提供 |
| `lotus` | 荷花白 | 浅色 | 提供 |

实现不能在每个组件里写十几组 `theme === ...` 判断。所有主题必须通过统一的语义令牌表达：

```text
background / surface / surfaceElevated
textPrimary / textSecondary / textMuted
border / borderStrong
primary / primaryHover / primaryActive
success / warning / danger / info
canvasBackground / canvasGrid / nodeSurface / edgeColor
viewportBackground / timelineBackground
```

主题令牌同时驱动 CSS 变量和 Ant Design token。页面只使用语义变量，不直接依赖主题 ID。纯黑主题可以覆盖背景层级，但不能把边框、输入框和禁用状态压成不可辨认的一块黑色。

交互规则：

- 侧栏保留快捷主题按钮，点击打开主题预览面板，不再只能在深浅色之间二选一；
- 设置页提供全部主题缩略色卡和名称；
- 选中主题立即预览，不需要刷新页面；
- `system` 监听系统深浅模式，但用户选择具体主题后不再跟随系统；
- 登录用户把主题 ID 保存到账号偏好，本机 localStorage 只做启动缓存；
- 未登录状态使用本机缓存，没有缓存时使用 `system`；
- 遇到不存在的主题 ID 自动回退到 `dark`，不能导致空白页面；
- 画布连线颜色、背景网点等“项目外观”与全局主题分开保存，切主题不能改动画布项目数据。

第一期需要完成全部主题目录和核心工作台覆盖，但验收优先级分两批：先验收 `dark`、`light`、`pureblack`、`mint`、`snow`、`purple`，再验收其余柔和浅色主题。未通过对比度验收的主题不得出现在正式选择面板中。

## 6. 提示词体系

洛水 181 条提示词按用途分布为剧本核心、剧本分镜、视频推理、人设设计、画面推理、中长篇转剧、解说角色、场景设计、小说转剧、改文、爆款开头、旁白解说、封面和音色等。

V88 不按“页面里放一段大文本”的方式迁移，统一建立以下契约：

```text
PromptDefinition
  id                稳定标识
  domain            agent / novel / script / storyboard / image / video / audio / cut
  purpose           业务用途
  version           版本号
  systemTemplate    后端模板
  inputSchema       允许输入的结构
  outputSchema      期望输出的结构
  modelCapability   text / vision / image / video / audio
  safetyRules       必须保留的限制
  active            是否启用
```

调用链固定为：

```text
前端提交用户输入与引用 ID
  → Go API 校验项目归属和输入结构
  → backend/internal/prompt 选择提示词定义
  → 后端读取素材和节点上下文
  → 运行时替换模板变量
  → 模型路由执行
  → 结构化结果校验
  → 保存任务、版本和产物
  → 前端读取结果
```

规则：

1. 前端不得保存或返回完整系统提示词；
2. 提示词必须有稳定 ID 和版本，不以中文标题充当唯一键；
3. 每个调用点明确输入、输出和失败语义；
4. 同类提示词优先合并为“基础模板 + 场景参数”，避免 181 条继续无序增长；
5. 结构化任务优先输出 JSON，并做严格解析和降级提示；
6. 提示词更新不覆盖历史任务所用版本；
7. 用户自定义提示词与系统提示词分层保存；
8. 验收使用脱敏样本和模拟模型，默认不发起付费调用。

| 阶段 | 首批提示词用途 |

| 1 | Agent 项目规划、选中节点理解、剧本拆分分镜、人物/场景/道具提取、分镜图提示词、视频提示词、导演机位描述 |
| 2 | 长短篇原创、仿写、续写、番外、章节计划、风格抽取、上下文压缩、备忘录召回 |
| 3 | 小说转剧、剧本改写、分镜合并、资产一致性、图像/视频推理、字幕和旁白 |

## 7. 统一数据与服务边界

- Go 后端：继续放在 `backend/`，新增逻辑进入现有领域包；
- React 用户前台：继续放在 `frontend/src/user/`；
- React 管理配置：放在 `frontend/src/admin/`；
- 系统提示词：`backend/internal/prompt/`；
- 关系数据与任务历史：MySQL；
- 队列、锁、短期状态：Redis；
- 图片、视频、音频和导出文件：TOS；
- 本地媒体处理：`executors/` 或已有受控执行链；
- 发布：React 构建后进入 Go embed，最终运行单个 Go 二进制；
- 不新增独立 Node 业务后端，不把 SQLite 或洛水本地目录结构带入 V88。

## 8. 跨工作线主链路

```text
小说/素材输入
  → 作品与项目
  → 人物/场景/道具资产
  → 剧本
  → 分镜
  → 画布节点
  → 图片/视频/音频任务
  → 导演台构图与机位
  → 成片或 AI-CUT 时间线
  → 字幕/配音/渲染
  → 导出与发布结果
```

Agent 是操作和编排入口，不拥有第二份项目数据。画布是可视化投影和编辑入口，不替代剧本、资产、任务和成片各自的正式记录。

## 9. 验收原则

每个阶段只有同时满足以下条件才算完成：

- 用户入口可见、可理解且没有空按钮；
- 数据刷新后仍存在；
- 页面状态来自真实后端记录；
- 失败时给出具体原因和可恢复入口；
- 前端测试、Go 测试和构建通过；
- Go embed 产物重建并验证 `/health` 与 `/api/runtime-build-info`；
- 已登录浏览器完成真实布局和交互验收；
- 所有已公开主题在导航、表单、弹窗、画布、分镜、任务和导演台中通过可读性与对比度验收；
- 默认使用模拟模型，不消费真实额度；
- 未经单独授权不发布公网、不推送远端。

### 9.1 同功能 A/B 验收

对可安全复现且不消耗额度的功能，使用同一组脱敏输入分别检查洛水证据和 V88 本地实现：

- 对比可选择参数和默认值；
- 对比操作后的页面状态；
- 对比输出字段、结果数量和下游引用；
- 对比刷新和重启后的持久化结果；
- 对比失败、取消和重试行为；
- 对比提示词承担的业务目的，而不是要求文本逐字相同。

依赖真实付费模型的效果验收分为两层：先用模拟模型验证链路和结构，再由用户明确授权后用少量真实任务验证质量。没有真实任务授权时，只能声明链路一致，不能声明模型效果完全一致。

## 10. 明确不做

- 登录、付费、授权或安全校验绕过；
- 把洛水反编译产物冒充原始源码；
- 整库复制 181 条提示词而不审阅来源和用途；
- 为追求外观相似而放置无功能按钮；
- 一次性同时改完五条工作线；
- 用新的孤立数据库、素材库或任务队列绕开 V88 现有系统。
