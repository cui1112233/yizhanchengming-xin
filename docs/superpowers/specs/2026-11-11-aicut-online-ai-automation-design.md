# AI-CUT 线上 AI 自动剪辑第一阶段设计

日期：2026-11-11  
状态：待用户审阅  
实施范围：一战晟铭 AI-CUT 的首个可验证线上自动剪辑闭环

## 1. 目标

第一阶段不追求一次补齐 Concat 的全部桌面能力，而是先交付一条可以在线稳定使用、可以由 AI-CUT Agent 调用、可以人工复核并能真实导出成片的自动剪辑链路：

```text
上传素材
→ 后台分析素材
→ 识别字幕并提取镜头与静音区间
→ AI 生成结构化剪辑方案
→ 用户预览方案和变化清单
→ 用户确认后写入时间线
→ 用户继续手动调整
→ Redis 排队
→ FFmpeg 渲染
→ 成片保存到 TOS 并提供下载
```

成功标准不是“AI 返回了一段建议”，而是同一个工程中的时间线确实发生可撤销、可保存、可导出的变化。

## 2. 第一阶段范围

### 2.1 必须实现

1. **素材预分析**
   - 读取时长、分辨率、帧率、音视频轨道等媒体信息；
   - 生成缩略图、代表帧和音频波形数据；
   - 检测镜头切换、静音和长停顿；
   - 视频与音频素材均可进入字幕识别任务。

2. **自动字幕完整链路**
   - 选择已配置的 ASR 模型；
   - 识别分段及时间点；
   - 可选按剧本或专有名词进行字幕纠错；
   - 可选删除口头水词；
   - 生成新的字幕轨，不覆盖原字幕；
   - 支持任务取消、失败重试和版本冲突提示。

3. **AI 粗剪方案**
   - 用户输入目标、平台、目标时长、画幅和剪辑风格；
   - AI 读取素材分析、字幕、剧本和当前时间线摘要；
   - AI 只输出受约束的结构化操作，不直接执行系统命令或修改文件；
   - 支持删除静音、压缩停顿、保留指定台词、片段排序、字幕、转场、滤镜、BGM 和文字标题；
   - 每条操作都必须说明对象、时间范围和原因。

4. **方案预览与确认**
   - 默认先生成草案，不直接改时间线；
   - 页面显示预计成片时长、保留/删除片段数量和操作清单；
   - 用户可以整批确认、整批取消，也可以关闭单项操作；
   - 确认后一次性写入时间线，并形成一个可撤销历史节点；
   - 取消或生成失败时不得改变工程。

5. **智能包装**
   - 根据剪辑目的选择现有可导出的滤镜、特效和转场；
   - BGM 从用户已上传或已授权的曲库选择；
   - 自动计算 BGM 裁切、淡入淡出和对白区音量压低；
   - 自动添加片头标题、重点文字和结尾卡片；
   - 所有选择使用稳定资源 ID，浏览器预览与 FFmpeg 导出使用同一参数。

6. **真实导出**
   - 保存工程后创建后台导出任务；
   - 第一阶段支持 MP4、WebM、MP3 和 SRT；
   - 导出任务支持排队、进度、取消、失败原因和重试；
   - 输出文件进入 TOS，并记录工程版本、输入素材和渲染参数；
   - 不把长视频整体放进浏览器内存执行最终渲染。

### 2.2 暂不进入第一阶段

- 背景移除、人物抠像和生成式补帧；
- 声音克隆和本地大模型下载器；
- 关键帧曲线编辑器；
- 4K 60 帧、10-bit、透明通道及硬件编码矩阵；
- 完整代理媒体系统；
- Concat 的全部效果、字体、模型和源码；
- 无人工确认的全自动发布。

这些功能需要 GPU、较高资源成本、额外许可证或更复杂的浏览器兼容验证，后续单独立项。

## 3. 用户入口

AI-CUT 顶栏增加“AI 自动剪辑”主入口，AI-CUT Agent 中保留自然语言入口，两者最终调用同一套后端服务。

### 3.1 自动剪辑向导

第一屏输入：

- 素材：选择工程内一个或多个视频/音频；
- 剧本：可选，使用工程剧本或上传文字；
- 剪辑目标：短剧解说、剧情精剪、口播去停顿、产品展示或自定义；
- 目标时长：自动、30 秒、60 秒、90 秒或自定义；
- 画幅：9:16、16:9、1:1；
- 包装：字幕、转场、滤镜、BGM、片头和结尾分别开关；
- 额外要求：例如“保留所有女主台词，不要快切”。

第二屏显示素材分析和缺失条件。没有字幕、镜头分析或波形时，可提交后台预处理任务，不伪造分析结果。

第三屏显示 AI 草案：

- 原始总时长与预计成片时长；
- 保留、删除、移动、字幕、转场、特效、BGM 和文字操作数量；
- 每项操作的时间、对象、理由和开关；
- “返回修改条件”“取消草案”“应用到时间线”。

### 3.2 Agent 自然语言入口

用户可以输入：

> 删除超过 0.8 秒的停顿，保留人物争吵部分，做成 60 秒竖屏视频，添加中文字幕和低沉 BGM。

Agent 必须先返回可检查的剪辑草案。只有用户点击“应用到时间线”后，操作才写入工程。

## 4. 系统结构

### 4.1 前端

React 前台负责：

- 收集自动剪辑参数；
- 展示预处理任务、AI 草案和操作差异；
- 提交确认或取消；
- 在现有 AI-CUT 时间线上显示结果；
- 轮询轻量任务摘要，只在状态变化后读取完整结果。

前端不包含系统提示词，不执行最终 FFmpeg 渲染，也不信任模型输出中的任意命令或路径。

### 4.2 Go 后端

后端新增清晰分离的五个职责：

- `analysis`：媒体探测、镜头、静音、缩略图和波形；
- `caption`：ASR、字幕纠错和去水词；
- `planner`：构造后端提示词、调用模型并校验剪辑草案；
- `apply`：在事务中把草案变成新时间线版本；
- `render`：把已保存时间线转成 FFmpeg 渲染计划。

系统提示词统一放在 Go 后端 `prompt` 模块。模型只收到完成任务所需的最小数据，不获得数据库密码、对象存储密钥或服务器文件路径。

### 4.3 存储与任务

- MySQL 保存工程、素材、分析结果、字幕、草案、操作、确认记录和导出任务；
- Redis 保存预处理、AI 规划、字幕识别和渲染队列；
- TOS 保存原素材、缩略图、波形、代理文件和最终成片；
- Go embed 继续把用户前台打进单个后端二进制。

## 5. 核心数据结构

### 5.1 自动剪辑草案

草案最少包含：

```json
{
  "id": "plan-123",
  "projectId": "cut-1",
  "baseRevision": 12,
  "state": "ready",
  "summary": {
    "sourceDurationMs": 180000,
    "estimatedDurationMs": 60000
  },
  "operations": [],
  "warnings": []
}
```

草案状态：`queued`、`analyzing`、`planning`、`ready`、`applying`、`applied`、`failed`、`canceled`、`stale`。

### 5.2 允许的操作

第一阶段只接受白名单操作：

- `trim_clip`：裁剪片段；
- `remove_range`：删除时间范围；
- `move_clip`：移动片段；
- `add_caption`：增加字幕；
- `add_title`：增加文字；
- `set_transition`：设置转场；
- `set_filter`：设置滤镜；
- `add_effect_layer`：增加效果层；
- `add_bgm`：增加背景音乐；
- `set_volume_envelope`：设置音量和淡入淡出；
- `set_project_format`：设置画幅和目标导出参数。

每项操作包含唯一编号、对象编号、参数、理由和是否启用。未识别操作、未知资源 ID、负时间、越界时间、空对象和相互冲突的操作必须在后端拒绝。

## 6. 数据流与一致性

1. 前端提交参数和当前工程版本；
2. 后端检查工程归属、素材存在性和模型配置；
3. 缺少分析时创建预处理任务；
4. 分析完成后，后端从数据库构造最小化时间线摘要；
5. 后端提示词模块构造模型请求；
6. 模型返回 JSON；
7. 后端进行结构、资源、时间、冲突和权限校验；
8. 合法草案保存到 MySQL，返回前端预览；
9. 用户确认时再次检查 `baseRevision`；
10. 版本一致才在数据库事务中应用全部启用操作；
11. 应用成功生成一个历史节点，并返回新版本；
12. 导出只读取已保存版本，不读取浏览器临时状态。

同一个 `clientRequestId` 重复提交只能得到同一个活动草案，不重复扣费或重复写时间线。

## 7. 边界与失败提示

### 7.1 输入边界

- 没有素材：提示“请先上传至少一个视频或音频素材”；
- 素材仍在上传：禁止提交并显示进度；
- 不支持格式或文件损坏：指出具体文件；
- 目标时长大于原始有效内容：允许生成，但显示“可用内容不足”；
- 没有剧本：允许按字幕和镜头分析剪辑；
- 没有 ASR 模型：保留入口并跳转 API 配置；
- 没有 AI 模型：不能生成草案，但手动剪辑仍可使用；
- BGM 未授权或不存在：不加入草案并给出警告。

### 7.2 执行边界

- 用户取消预处理或规划：任务进入 `canceled`，不写半成品；
- 模型返回非法 JSON：最多进行一次格式修复，仍失败则保留原始错误摘要；
- 模型返回越界时间：拒绝草案，不自动猜测修正；
- 工程版本变化：草案进入 `stale`，提示重新生成或重新基于最新版本规划；
- 重复点击应用：使用草案状态和幂等键阻止重复应用；
- 应用中任一操作失败：事务整体回滚；
- 导出失败：保留工程和草案，显示 FFmpeg 可理解的中文错误；
- 付费模型调用：未经用户已配置的有效渠道和明确提交，不主动调用。

## 8. AI 与确定性工具的分工

AI 负责：

- 理解用户剪辑目的；
- 根据字幕和镜头摘要判断内容重要度；
- 选择白名单剪辑操作和现有资源；
- 解释每项决定。

确定性代码负责：

- 媒体探测、镜头和静音检测；
- 时间计算、裁剪、移动、吸附和冲突检查；
- 工程版本与权限；
- FFmpeg 参数生成；
- 文件读写、队列和重试。

模型不得生成任意 shell 命令、FFmpeg 命令行、服务器路径、SQL 或外部 URL 供系统直接执行。

## 9. 验收标准

### 9.1 正常流程

- 一个含对白的视频可以完成上传、分析、字幕、草案、确认、保存和 MP4 导出；
- 用户能看到每条 AI 操作及理由；
- 应用后时间线、刷新后的工程和导出结果一致；
- 一次撤销可以回到应用草案前的时间线；
- Agent 与向导产生相同结构的草案。

### 9.2 必测异常

- 空素材；
- 损坏素材；
- 无 ASR 模型；
- 无 AI 模型；
- 模型返回空结果；
- 模型返回非法操作；
- 重复提交；
- 重复应用；
- 规划中取消；
- 应用前工程被修改；
- 渲染中取消；
- FFmpeg 失败；
- TOS 上传失败。

所有失败必须有中文提示、稳定错误码和可重试/不可重试说明，不能只在控制台报错。

### 9.3 交付证据

- Go 单元测试覆盖草案校验、幂等、版本冲突、事务回滚和状态机；
- React 测试覆盖向导、差异预览、取消、确认和错误提示；
- 使用同一组素材对比手动预期与 AI 草案；
- 前端生产构建通过；
- Go 嵌入资源重新构建；
- `/health` 和 `/api/runtime-build-info` 对应当前提交；
- 实际 4001 页面完成一次可见的端到端验收；
- 源码、嵌入静态文件和运行二进制版本一致后才允许报告完成。

## 10. 许可与隐私

- 不复制 Concat 的 AGPL 源码、模型、效果资源、密钥和品牌素材；
- 只参考公开功能规则并在现有技术栈中独立实现；
- 用户素材仅进入其授权的 TOS、模型渠道和渲染任务；
- 模型请求中不发送无关素材、密钥、数据库字段和服务器路径；
- 草案、提示输入摘要、模型结果和人工确认均记录审计信息，但不记录明文密钥。

## 11. 实施分批

为避免再次出现“按钮已经显示、实际链路未接通”，后续实施按可独立验收的纵向闭环拆分：

1. 草案数据结构、校验、版本和幂等；
2. 素材分析任务与可见结果；
3. AI 粗剪规划与后端提示词；
4. 草案预览、取消和确认应用；
5. 字幕、转场、滤镜、BGM 和文字包装；
6. 导出队列与 TOS 结果；
7. Agent 调用同一草案服务；
8. 同一素材端到端对照验收。

每一批必须同时具备真实后端、真实数据变化、中文失败提示、自动测试和 4001 可见验收，不能用空列表、假进度或纯展示按钮代替。
