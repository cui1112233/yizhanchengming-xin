# 小说面板 React 化迁移设计

日期：2026-10-15
维护基线：`v88`

## 1. 目标

以当前 v88 的小说面板行为为最终标准，把现在由 React 外壳加载的旧
`novel-panel/workbench` 功能逐步迁移到可维护的 React 页面中。v78 分支只用于
查找历史功能和接口契约，不作为代码覆盖源。

## 2. 当前边界

- 当前入口是 `frontend/src/user/pages/NovelPanelPage.jsx`。
- 该页面目前负责主题同步、工作台加载、受控 API 桥接、请求取消和错误状态。
- 实际工作台仍位于 `frontend/dist/novel-panel/workbench`（以及对应的旧静态资源）。
- 后端接口以当前 v88 Go API 为准；不新增 Node 后端依赖。
- 当前工作区已有大量未提交改动，本迁移只能修改明确列入实施计划的文件，不能覆盖或清理无关改动。

## 3. 功能迁移原则

1. 先盘点当前工作台真实功能和 v88 后端接口，再拆分 React 组件。
2. v78 代码只做对照，不能把旧分支页面、旧编译产物或旧接口反向覆盖 v88。
3. 前端只负责展示、交互和状态管理；系统提示词仍由 Go 后端统一提供和渲染。
4. 先保留旧 workbench 作为回退路径，React 页面达到功能等价并通过回归后再切换入口。
5. 删除旧 workbench 前必须证明没有路由、静态资源、桥接接口和部署脚本继续引用它。

## 4. 目标结构

React 页面按职责拆分为：

- 页面壳与项目切换
- 项目/剧本基础信息
- 资产与人物场景道具管理
- 故事剧本与分镜编辑
- 提示词预览与版本状态
- 生成、重试、取消、错误和审计状态
- 历史记录与恢复

公共请求逻辑继续复用 `frontend/src/shared/api`，需要新增的接口封装使用明确的
Go API 路径和统一错误结构。

## 5. 数据流

页面加载项目 → 获取项目和版本状态 → 获取资产/剧本/提示词数据 → React 状态渲染；
用户编辑或生成 → 调用现有 Go API → 保存服务端结果和版本号 → 刷新对应局部状态；
失败时保留用户输入、显示可重试原因，并记录请求状态，不通过刷新页面恢复状态。

## 6. 兼容和回退

- 第一阶段保留旧 iframe/workbench 入口。
- 第二阶段增加 React 页面开关，只对当前用户或测试项目启用。
- React 页面功能通过后再将默认入口切换到 React。
- 旧资源至少保留到一次完整回归和可回退发布完成后，再单独提交删除。

## 7. 验收标准

- 当前小说面板已有功能在 React 页面全部可用。
- 主题、项目切换、资产、剧本、分镜、提示词、生成、重试、取消、历史和错误状态行为不回退。
- 浏览器网络请求只走当前 v88 Go API，不出现新增 Node 服务依赖。
- 页面不再依赖 iframe 才能完成核心操作。
- 构建、单元测试、页面源码测试和实际浏览器流程均通过。
- 删除旧 workbench 前，代码搜索确认无运行时引用，并保留可回滚 Git 提交。

## 8. 非目标

- 本阶段不切换 Git 分支。
- 不删除 v78 历史分支。
- 不重写与小说面板无关的批量工厂、小说获取或部署流程。
- 不修改公网运行文件，不绕过 v88 Git 记录。
