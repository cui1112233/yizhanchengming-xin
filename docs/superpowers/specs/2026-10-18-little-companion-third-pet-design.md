# 小家伙作为第三只宠物设计

日期：2026-10-18  
范围：V88 用户前台桌面宠物  
状态：已确认设计，等待实施

## 目标

把用户原创的“小家伙”接入 V88，作为 CM、貔貅之后的第三只可选桌面宠物。小家伙保留源码包中的八套动作，同时复用现有桌面宠物的设置保存、拖拽定位、任务气泡、AI 对话、页面上下文和操作建议能力。

本次只改用户前台源码和静态资源，不新增后端接口、数据库表、运行服务或线上依赖，也不发布公网。

## 接入方式

保留 `CmPenguinCompanion` 作为三只宠物共同的交互外壳。宠物目录增加显示类型字段：CM 和貔貅继续使用现有单张大精灵图显示方式；小家伙使用独立的多动作图集显示器。

小家伙资源放到前端正式静态资源目录，并通过 `/pets/little-companion/` 路径访问。运行时直接使用已经导出的 PNG 图集，不引入源码包中的 Taro、Playwright 或 Sharp 依赖，也不复制小程序专用页面代码。

设置页继续从统一宠物目录生成选项。新增选项名称为“小家伙”，说明为“小家伙，陪你创作的原创桌面宠物。”保存值使用稳定标识 `little-companion`。旧用户配置、未知宠物标识和现有默认值仍回退到 CM。

## 动作与状态

小家伙使用源码包内的八套动作：

| 图集 | 用途 |
| --- | --- |
| `idle` | 普通待机 |
| `walk` | 空闲巡游 |
| `sleep` | 空闲休息 |
| `think` | 任务执行中 |
| `candy` | 空闲互动 |
| `dance` | 空闲互动和成功后的庆祝 |
| `peace` | 任务成功 |
| `peek` | 空闲探头 |

没有任务时按“待机、走路、吃糖、跳舞、睡觉、探头”自动轮播。动作使用各自清单中的帧数和持续时间，播放结束后再进入下一项，避免不同长度图集被错误裁切。

任务状态拥有更高优先级：

- `working` 立即播放 `think`，任务结束前循环；
- `success` 播放 `peace`，随后短暂播放 `dance`，再恢复自动轮播；
- `error` 使用 `idle` 图集配合现有失败抖动，随后恢复自动轮播；
- 用户拖拽、打开对话和页面隐藏时，不得启动重复计时器；页面重新可见后从安全的待机状态恢复。

切换到其他宠物时必须停止小家伙的动作计时器。切换回小家伙时从待机开始，不保存上一次动作进度。

## 显示与交互

小家伙仍占用现有约 120 x 130 像素的桌面区域，角色按比例缩放并居中，不拉伸。图片采用平滑显示，不使用像素化效果。

现有行为保持不变：

- 鼠标或触摸拖拽位置；
- 点击打开 AI 对话；
- 显示任务气泡、分析入口、应用建议和撤销入口；
- 设置页立即预览，保存后刷新仍恢复同一宠物；
- 窄屏沿用现有固定位置规则；
- 系统开启减少动态效果时，停在当前动作的第一帧，不自动轮播。

源码包中的“扒住业务卡片边缘”依赖特定卡片位置，本次不接入，避免宠物在不同 V88 页面寻找不存在的卡片。`peek` 动作仍作为普通空闲动作播放。

## 代码边界

新增一个小家伙动作定义模块，负责动作清单、任务状态映射、帧位置和播放时长。新增一个只负责绘制当前动作帧的显示组件。共同外壳只负责选择显示器和传递当前宠物状态，不承载图集尺寸计算。

宠物目录负责稳定标识、名称、说明、资源类型和预览信息。设置页不得写死第三只宠物名称或资源路径。

后端用户配置继续保存完整宠物对象或标识，并沿用现有合并逻辑；默认宠物保持 CM，不改变存量用户体验。

## 异常处理

单张动作图片加载失败时，显示小家伙名称的简洁占位，不影响对话窗口和页面其他功能。未知动作回退到 `idle`。无效帧数、持续时间或图片尺寸不得产生无限计时器或页面尺寸跳动。

## 验证

实施采用测试先行，至少覆盖：

1. 宠物目录返回第三个“小家伙”选项，未知标识仍回退 CM；
2. 八套动作定义的帧数、行列数和状态映射正确；
3. 空闲自动轮播顺序正确，任务状态会打断空闲动作；
4. 设置页预览能识别两种显示类型；
5. 现有 CM、貔貅的动画节奏和选择行为不回归；
6. 前端完整构建通过；
7. 本地页面实际切换三只宠物，检查待机动画、自动轮播、拖拽、打开对话、任务状态和刷新恢复；
8. Go embed 静态资源产物包含小家伙全部运行时图片，但不把编译产物当作源码提交。
