# 漫剧制作全流程补齐设计

用户“执行”批准按 2026-11-14 全流程对照报告的建议顺序补齐。目标是独立实现同类工作流，使用本系统服务与资源；不复制洛水源码、专有素材、账号或提示词，也不声称未完成的像素/供应商实跑已一致。

## 最终行为

1. 生产由服务器和 Redis 任务机制推进，MySQL 记录批次及逐镜头供应商任务、结果、失败原因；关页继续、进程恢复不重提已知任务。暂停阻止后续提交，正在供应商执行的任务如无法取消明确说明，继续时查询原任务。
2. 三个质量检查读取真实内容调用后端审核提示词，保存问题、通过/阻断及修复建议；不固定通过。结构检查独立显示为结构检查。
3. 资产/镜头可生成、上传和选择图片，参考图进入实际媒体请求。媒体任务有状态与错误；缺少配置明确失败，不能假成功。
4. 独立角色音色、旁白、ASR 字幕和编辑，复用现有 TTS/ASR/AI-CUT 服务；镜头裁切、缩放、顺序和结果进入真实时间线。完成交付必须指向可访问媒体或工程；JSON 数据导出如实命名。
5. 章节编辑/计划、作品内 Assistant/Agent、批量分镜操作、项目显示配置、归档/恢复和团队权限都有真实存储与接口。助手只应用明确支持的结构化编辑；付费生产由明确动作触发。
6. 团队分享按用户和读写/生成权限校验，默认不允许使用项目拥有者的模型配置。未授权用户不能读、改或生成；独立账号配置和用户原项目保持隔离。

## 架构

- 沿用现有 Go/React/MySQL/Redis/TOS/Go embed 目录及运行方式，不做无关搬迁，不新建 Git 分支。
- 生产模块负责 durable job、Redis 互斥/调度和镜头任务生命周期；内容模块负责章节/会话/显示/协作；媒体工作台连接现有图片、音频、字幕、时间线和导出服务。
- 所有系统提示词在后端 prompt 模块。前端只传预设标识、用户内容与操作参数。
- 操作提供修订号/幂等边界和错误状态；不能以页面内循环、内存计数或只改文字冒充后台任务。

## 验收与边界

- 先测试失败、再实现；服务使用真实适配器与模拟供应商验收请求/结果/错误，禁止新增付费测试（此前 50 次图片预算已耗尽）。
- 重点覆盖两个用户共享队列、关闭请求后的继续、服务重启恢复、查询失败不重提、暂停/继续、无权限、参考图/音色真实传入、完整导出包媒体引用。
- 在本地 4001 重建 Go embed 并验证真实页面，保留其他工作区改动；不擅自发布公网或推送 Git。
- 原软件内部全部页面的像素一致性仍未验证，本设计不将此项伪装成已达成。缺配置的外部能力不能归为“已实跑成功”。
