# 豆包执行器独立窗口修复设计

## 目标

执行器启动时必须加载内置界面，不能依赖 `localhost:1477` 或任何开发服务器。若打包产物缺少界面资源，构建或安装流程必须失败，不能覆盖当前可用执行器。

## 原因

当前安装的可执行文件并未携带 Tauri 的 `frontend/dist` 资源。窗口因而尝试使用开发地址，开发服务器未运行时显示“localhost 拒绝连接”。普通 `cargo build` 只用于代码编译，不能作为桌面应用发布产物。

## 方案

1. 在执行器项目内显式允许 `esbuild` 作为唯一前端构建脚本，恢复 `frontend/dist` 的正常构建。
2. 仅允许 `cargo tauri build` 的产物进入安装目录；禁止发布流程使用普通 `cargo build` 的 `target/release/doubao-relay.exe`。
3. 打包脚本在复制前校验：前端入口文件存在、Tauri 打包成功、待安装文件来自 Tauri 输出目录。任一失败则保留已安装版本。
4. 安装后启动执行器并检查窗口加载的是内置页面，同时确认本地 Relay 健康接口可用。

## 验收

- 未运行 `localhost:1477` 时，执行器窗口仍显示自身的账号和任务界面。
- 安装目录中的执行器只来自 Tauri 打包产物。
- 若前端构建失败，安装目录中现有执行器保持不变。
- Relay 健康接口继续返回正常状态。
