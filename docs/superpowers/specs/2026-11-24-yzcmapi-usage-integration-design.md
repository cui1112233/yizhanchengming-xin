# YZCM API 对接个人中心“用量与制作”

日期：2026-11-24。

## 已确认的使用方式

- YZCM API 地址为 http://newapi.yzcm.site/。
- 管理员配置和使用 API，组员调用所属管理员的 API。
- 一战晟铭现有个人用量、团队用量和额度已用量接口仍返回空统计，需要接入真实数据。
- 沿用当前个人中心页面、管理员与组员关系，不新建另一套组织关系。

## 数据口径

1. 管理员账号的真实 Token、调用次数和费用以 YZCM API 为准，明确包含组员的共享调用。
2. 组员只查看自己在一战晟铭发起的调用，不能把管理员总账重复计入每名组员。
3. 制作量、成功量、失败量、上传完成量来自一战晟铭任务记录。模型调用次数不等于制作作品数量；本地文字排版不计为付费模型调用。
4. 历史共享密钥记录如不能确认实际调用人，展示为“历史未归属”，保留在管理员总账中，不平均分摊给组员，也不当成零用量。
5. 接入后的调用记录实际调用人、付费配置所属管理员、功能、模型、任务编号、请求编号、Token 和时间。接口返回的真实费用优先；尚未与上游账单匹配的费用标记为待核对，估算费用明确标记。
6. 使用请求编号和上游日志编号核对及去重。同一作品的不同实际调用仍分别计量，不能为了按作品去重而漏掉真实费用。

## 读取方式

由 Go 后端统一读取 YZCM API，前端继续通过一战晟铭的个人中心接口取数。

已从站点自己的页面资源确认以下只读接口：

- `/api/user/self`：当前 API 账号信息。
- `/api/data/self/`：按时间和模型汇总的用量。
- `/api/log/self/`：调用明细。
- `/api/log/self/stat`：账单统计。

接口权限和实际返回结构需要用管理员授权的统计凭证进行只读验证。模型调用密钥不能未经验证就当作控制台统计访问凭证。管理员凭证仅在后端保存，组员不会拿到管理员的密钥。

优先使用“后端读取上游汇总并短期缓存，本站保存组员调用归属”的方式，保持现有共享调用方式。另一种方式是为组员自动分配独立子密钥，虽然上游分人更直接，但涉及新增密钥和权限管理，本次不自动创建。

## 展示与权限

- 管理员显示账号总用量、已归属组员用量、未归属用量及本站制作结果；组员排行不重复汇总管理员总账。
- 组员只看自身记录；主管只看所属团队；开发者沿用现有管理权限。
- 后端根据登录身份和已有绑定关系决定统计范围，不接受前端随意指定管理员或其他组员。
- “今日”和“本月”统一按北京时间计算。
- 费用换算读取 YZCM API 当前配置，不能把额度直接当成 Token 或写死换算比例。
- 数据读取失败显示失败和重试入口；如展示缓存数据，同时显示更新时间。未绑定、无权限、真实零用量分别展示。

## 验证和交付

- 先验证管理员统计凭证，再核对一段相同时间范围的后台真实数据。
- 验证管理员合计、组员归属、越权拒绝、重复请求去重及上游故障显示。
- 修改本地 4001 并验证后，再按既定顺序推送远端、部署线上。
- 联调使用只读账单和历史记录，不为测试制造付费生成请求。
