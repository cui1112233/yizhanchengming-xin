# 产品更新公告补发设计

## 目标

为本次“失败重试只补未完成内容”修复生成独立的新版本公告，并确保本地二进制、运行版本清单和线上接口使用同一个 `releaseId`。

## 方案

- 使用新编号 `qiantie-202611071037`，显示版本 `v27`。
- 公告仅描述本次已经进入二进制的重试修复，不混入尚未验证的功能。
- 公告 JSON 继续通过 Go `embed` 编进二进制；服务器的 `runtime-release.json` 同步使用相同编号。
- 先用接口测试证明缺少公告时会失败，再添加公告并通过测试。
- 使用 `scripts/release-v88.ps1` 在本地完成前端、Windows/Linux 二进制和本地独立端口验收；本地通过后才上传线上。
- 线上同时原子切换二进制和运行版本清单；保留 `qiantie-202611061717` 作为回滚点。

## 验收

- 本地 `/api/product-updates/latest` 返回 `qiantie-202611071037` 和 `v27`。
- Linux 二进制哈希与服务器文件一致。
- 线上接口返回新公告，服务健康，批量工厂页面为 HTTP 200。
- 浏览器没有看过新 `releaseId` 时会自动展示公告。
