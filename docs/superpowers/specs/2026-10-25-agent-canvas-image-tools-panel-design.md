# Agent Canvas 图片处理面板设计

## 目标

把工作流图片节点中现有的“工具”区域改成正式、易懂、跟随主题的图片处理面板。继续使用现有 Go 图片处理接口，不新增假功能，不修改数据库，也不在验收时实际提交图片处理任务。

## 已确认问题

- 工具区域没有自己的主题样式，Ant Design 数字输入框和原生按钮会显示白色背景。
- 裁剪参数以 `X / Y / 宽 / 高` 四个裸数字平铺，缺少名称和操作层级。
- 顶部快捷操作与编辑框内部操作重复，但内部区域没有说明其用途。
- “工具”这个名称过于笼统，无法表达它只处理当前图片并生成新结果。

## 交互设计

入口名称改为“图片处理”。点击后在节点编辑框上部展开一个紧凑面板，不跳转页面。

面板第一层只显示四个真实能力：

- 旋转 90 度
- 水平镜像
- 2 x 2 拆图
- 裁剪

旋转、镜像和拆图使用图标加短文字按钮。裁剪是可展开选项，第一次点击只展开参数，不立即执行。

裁剪参数使用两行带中文标签的字段：

- 起点：X、Y
- 尺寸：宽、高

参数区末尾使用明确的“生成裁剪结果”按钮。所有图片处理都会生成候选结果，不直接覆盖原图片。

## 功能边界

面板只调用现有操作：`rotate`、`mirror`、`grid_split`、`crop`。源图片不存在、节点忙碌或回调不可用时，处理按钮保持禁用并显示“请先添加图片”。

顶部悬浮快捷条继续保留，负责一键常用操作；编辑框内的“图片处理”面板负责说明和裁剪参数。两者调用同一套现有接口。

## 视觉设计

- 使用 Agent Canvas 已有颜色变量，不写死白色面板。
- 深色主题使用深色面板、低对比边框和清晰文字；浅色主题同步切换。
- 面板圆角不超过 8px，不使用厚重卡片或嵌套卡片。
- 四个操作使用紧凑网格；选中的“裁剪”有明确高亮。
- 数字输入框、步进按钮、图标按钮和禁用态全部跟随主题。
- 窄节点宽度下允许参数自动换行，不出现文字或控件重叠。

## 验收

- 深色和浅色主题下都不存在突兀白块，文字、图标和输入值清晰可见。
- 图片处理入口与四项功能名称清楚。
- 裁剪参数带中文标签，仅在选择裁剪后出现。
- 没有源图片时不会误提交。
- 现有图片处理接口与任务状态逻辑保持不变。
- 运行相关前端测试、完整前端构建、Go 内嵌构建和本地浏览器检查。
- 浏览器验收只打开、切换和填写本地参数，不点击会创建处理任务的按钮。
