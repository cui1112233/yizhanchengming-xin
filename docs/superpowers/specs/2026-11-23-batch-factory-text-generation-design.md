# 批量工厂文本生成模式设计

日期：2026-11-23
适用项目：V88 批量工厂
维护分支：`v88`

## 1. 背景

批量工厂目前具备视频生成和漫画生成，但缺少一种只把原文排成文字图片、生成合集并继续走现有发布链路的生产方式。用户需要把“文本生成”作为第三种正式生产模式，而不是在漫画流程里临时增加一个开关。

文本生成需要保留漫画生产已经成熟的批次、单书、媒体库、合集、上传人、组织、网站配置和自动化能力，同时避免图片模型调用。它的关键难点不是出图提示词，而是完整保存原文、按段落和句子分页、稳定排版、服务端一致渲染、失败恢复以及与漫画/视频任务隔离。

## 2. 已确认的产品规则

以下规则已经确认，实施阶段不再作为开放问题：

1. 批量工厂顶部增加第三种生产模式：`视频生成 | 漫画生成 | 文本生成`。
2. 文本模式默认画幅为 `3:4`，也允许使用现有其他画幅。
3. 新建批次时，“漫画分析字数”替换为“单页字数”，默认约 150 字；内容截取仍默认 4000 字。
4. 系统必须保存完整原文，内容截取只限制本次生产范围，不能破坏原文。
5. 150 字是柔性目标，分页以段落、句子和实际排版空间为准，禁止从句子中间硬截断。
6. 普通段落尽量保持完整；单个超长段落确实放不下时，只能在完整句子后续页。
7. “长段落续页”等信息只作为内部状态，不能写入最终图片内容。
8. 文字区域默认最多占页面高度的 75%，并允许用户调整。
9. 支持字体、字号、字重、行距、段距、边距、对齐、文字颜色、标红颜色、背景和最大占比的实时预览与调整。
10. 背景支持纯色、个人背景库和用户上传图片；默认整本使用同一背景，单页可以覆盖。
11. 标红复用现有插画标红规则，可开关；没有可复用标红数据时正常渲染，不得让任务失败。
12. 用户可以编辑生产文本，但完整原文单独保留；编辑后重新分页、渲染、合成和上传。
13. 用户上传的成品页进入锁定状态，自动重排、重渲染和重试不得覆盖，只有“恢复系统生成”才解锁。
14. 系统可免费生成文字封面：书名、背景和字体排版；用户可上传封面替换并锁定。
15. 文本模式在批次、单书、缩略图、日志、筛选、计数和上传记录中统一显示“文本”标识。
16. 文本合集复用漫画的发布能力、上传人、组织、网站配置、书籍分类和上传记录，但漫画与文本不能混合选择上传。
17. 媒体库沿用漫画现有布局，不新建完全不同的编辑器；只把漫画字段替换成文本字段并增加排版控件。
18. 服务端 Go 渲染器是预览和最终图片的唯一权威实现，前端不能另写一套最终渲染逻辑。
19. 普通分页、排版、背景、标红复用、渲染和合集不调用模型；只有明确启用 AI 功能时才产生文本模型调用。
20. 敏感内容处理为三档：`AI优化 | 系统优化 | 关闭`，视频、漫画、文本共用，默认“系统优化”。
21. 统一配置必须包含全部整批/整书生产设置；单书配置使用相同字段，只负责继承或覆盖。
22. 配置和任务开始时冻结快照，运行途中修改只影响下一次执行或用户明确触发的重新生产。

## 3. 目标与非目标

### 3.1 目标

- 把文本生成作为与视频、漫画并列的正式生产模式。
- 在不调用图片模型的情况下，稳定生成可上传的文字图片合集。
- 用完整语义边界分页，保证不漏字、不重字、不乱序。
- 统一批次配置、单书覆盖、单页覆盖和用户成品页的优先级。
- 复用现有公共服务，但保持视频、漫画、文本外层流程互相隔离。
- 支持自动生产、断点恢复、合集、上传、再次上传和真实状态回读。
- 保留完整原文、生产文本、分页版本、渲染版本和上传记录。

### 3.2 非目标

- 不把文本生成塞进漫画处理器内部。
- 不重写视频或漫画现有媒体库结构。
- 不在前端实现另一套权威分页或最终渲染算法。
- 不默认调用 AI，也不把本地规则伪装成 AI 优化。
- 不允许前端硬编码系统提示词。
- 不把 Redis 作为任务和产物的权威数据来源。
- 不允许漫画、视频和文本的生产状态互相复用或串线。

## 4. 用户入口与新建批次

### 4.1 生产模式

统一配置和新建批次都提供：

```text
视频生成 | 漫画生成 | 文本生成
```

选择文本模式后：

- 隐藏图片模型、图片生成通道和漫画提示词相关设置。
- 文本模型仍然可见，用于 AI 优化、修复和未来可选的 AI 智能分段。
- 新建批次中的“漫画分析”改为“单页字数”，默认 150。
- “内容截取”保留，默认 4000。
- 画幅默认选择 3:4。

系统获取并保存完整原文，生产范围根据内容截取设置生成。以后提高内容截取值时，可直接使用已保存原文，不要求再次从上游读取。

### 4.2 文本标识

文本模式在以下位置统一显示 `文本`：

- 批次标题和筛选项
- 单书卡片和缩略图
- 任务/日志
- 媒体库
- 合集记录
- 上传记录

不得继续显示“漫画”或通过颜色暗示为漫画任务。

## 5. 配置体系

### 5.1 配置范围

统一配置是完整配置，不是精简配置。单书配置与统一配置使用同一份字段定义。

- **统一配置**：设置整个批次默认值，包含全部整书生产选项。
- **单书配置**：默认逐项继承统一配置，只保存用户明确覆盖的字段。
- **单页覆盖**：只处理某一页的正文、背景、排版和成品页。

优先级固定为：

```text
用户上传成品页 > 单页覆盖 > 单书配置 > 统一配置 > 系统默认
```

统一配置修改后，只更新仍处于“继承”状态的单书字段。单书每个覆盖字段都提供“恢复继承”。媒体库的“应用到整本书”写入单书覆盖；影响全部书必须进入统一配置。

### 5.2 文本模式统一配置页签

文本模式显示三组：

```text
模型配置 | 排版配置 | 发布配置
```

#### 模型配置

- 文本模型
- 敏感内容处理：AI优化 / 系统优化 / 关闭
- AI修复开关及可选修复模型覆盖
- 失败策略
- 标红复用开关
- 后续可选的 AI 智能分段开关
- 每个选项明确标注“本地处理”或“会调用模型”

图片模型和图片生成通道在文本模式隐藏。只选择文本模型不会产生费用，只有实际启用并执行 AI 功能才调用模型。

#### 排版配置

- 单页目标字数，默认 150
- 内容截取，默认 4000
- 画幅，默认 3:4
- 字体、字号、字重
- 行距、段距
- 页面内边距
- 对齐方式
- 文字颜色、标红颜色
- 文字最大页面占比，默认高度 75%
- 背景来源与整书默认背景
- 封面背景、标题字体和排版

#### 发布配置

- 上传人
- 组织归属
- 网站配置档
- 书籍分类
- 自动生成合集
- 自动上传
- 上传失败重试设置

### 5.3 敏感内容处理

三种生产模式共用同一个后端敏感处理 service 和同一字段：

- `ai`：调用当前文本模型识别并改写，保留修改前后版本和命中记录，会产生模型费用。
- `system`：只运行后端本地敏感词与替换规则，默认值，不调用模型。
- `off`：不做敏感处理，生产文本直接进入后续流程。

AI 优化失败必须明确失败，不能偷偷降级为系统优化。系统优化也只能修改生产版本，不能覆盖完整原文。

## 6. 背景与排版

### 6.1 背景来源

背景支持：

1. **纯色背景**：颜色选择器、常用预设色、直接输入颜色值。
2. **个人背景库**：选择已经保存的可复用背景。
3. **上传图片**：上传新背景，并可保存到个人背景库。

背景可应用到统一配置、当前书或当前页。封面也可以使用纯色或背景图。修改背景只触发相关页面重新渲染，不重新分页、不调用模型。

系统在文字与背景对比度过低时给出警告，但不擅自改变用户选择的颜色。

### 6.2 预览与最终渲染

前端排版面板只负责修改参数和发起预览请求。预览图片与最终图片都由同一个 Go 渲染器生成，使用同一字体加载、测量、换行、颜色和背景规则。

浏览器中的临时布局不能作为最终产物，避免预览和自动生产不一致。

## 7. 完整语义分页

分页器输入：生产文本、目标字数、画幅、字体、字号、字重、间距、边距和最大占比。

分页按以下顺序执行：

1. 规范换行但保留段落边界。
2. 按完整段落尝试装入当前页。
3. 段落放不下时，先换到下一页重新测量。
4. 单个段落在空白页也放不下时，按完整句子拆分。
5. 每次拆分后使用服务端真实字体重新测量，直到页面不溢出。
6. 保存每页对应的生产文本位置和内容校验值。
7. 全书分页结束后检查拼接结果与输入是否一致。

目标字数只用于控制阅读密度，不能为了接近 150 字破坏段落和句子。分页结果允许高于或低于 150 字。

分页校验必须验证：

- 没有漏字
- 没有重复
- 顺序不变
- 没有句中硬截断
- 页面内容未超过可用区域

## 8. 文本媒体库

文本媒体库保持现有漫画媒体库的整体结构：左侧大预览，右侧页面/合集页签、版本候选、前后翻页和底部操作区。不得另做一套差异巨大的页面。

字段替换：

- `漫画页` → `文字页`
- `本页参考图` → `本页背景`
- `画面内容` → `页面内容`

在现有结构中增加：

- 当前页正文编辑
- 拆页、合页
- 字体与排版调整
- 当前页背景
- 当前页排版覆盖
- 系统生成版本与用户上传版本
- 恢复系统生成

用户上传完成的页面后，该页标记为 `user_locked`。自动重新分页时保留该页，若前后内容变化导致页序关系无法自动确定，任务必须提示用户处理，不能覆盖或悄悄移动成品页。

媒体库右下角保留现有漫画操作结构：

```text
展开 | 合成当前书（或重新合成） | 上传网络（或再次上传）
```

合集未完成时上传按钮不可用；合集就绪后允许上传；已有成功上传记录时显示“再次上传”并二次确认。

## 9. 封面与合集

系统封面由服务端免费生成，内容包含书名、选定背景和标题排版，不调用图片模型。用户上传封面后进入锁定状态，自动重做不得覆盖。

文本合集复用漫画发布链路的公共上传 service 和平台映射，但使用独立的产物类型、状态和任务处理器。合集只能在封面和全部正文页校验通过后生成。

文本与漫画可以使用相同的发布配置，但不得在一次上传请求中混合。混选时前端和后端都必须拦截。

## 10. 自动生产链路

```text
获取并保存完整原文
  → 冻结生效配置
  → 生成生产文本
  → 敏感内容处理
  → 完整语义分页
  → 服务端渲染
  → 页面与内容校验
  → 生成封面和合集
  → 上传
  → 回读确认
```

用户可见状态：

```text
等待处理 → 文本处理 → 正在分页 → 正在渲染 → 正在校验
→ 合集就绪 → 正在上传 → 已上传
```

“已上传”必须以现有发布链路的成功回执/回读规则为准，不能只因提交请求成功就显示完成。

### 10.1 配置快照

任务开始时把统一配置、单书覆盖和相关版本合并为不可变快照。同一次任务所有页面使用同一快照。运行中修改配置只影响下一次任务，或用户明确发起的重新分页/渲染。

### 10.2 局部重做

- 修改生产文本、内容截取、目标字数、字体、字号、间距、边距或画幅：重新分页并重渲染受影响页面。
- 只修改背景或颜色：不重新分页，只重新渲染受影响页面。
- 只修改发布映射：不重新生成图片或合集，只重新上传。
- 单页渲染失败：只重做该页。
- 合集失败：保留页面，只重新合成。
- 上传失败：保留合集，只重试上传。
- 用户上传成品页：任何自动重试都不得覆盖。

一本书失败不能堵住同批次其他书。重复点击执行要复用进行中的任务或补齐缺失阶段，不能重复创建同样的付费调用或重复上传。

## 11. 模块和依赖边界

视频、漫画、文本必须拥有各自独立的外层入口、任务处理器、状态判断和失败恢复。只允许复用底层 service。

建议结构：

```text
api/modules/batch-factory/
  video/          视频业务流程
  comic/          漫画业务流程
  text/           文本业务流程
    workflow/     文本任务阶段
    pagination/   完整语义分页
    render/       文字图片渲染
    collection/   文本合集
    status/       文本状态投影

api/service/
  source/         原文读取
  sensitive/      AI/系统/关闭三档敏感处理
  textmodel/      文本模型调用
  storage/        TOS
  queue/          Redis队列与锁
  publisher/      发布映射与上传

api/prompt/
  sensitive/      系统预设提示词

前台/src/modules/batch-factory/
  video/
  comic/
  text/
  components/     可复用的基础控件
```

实际实施时应结合现有目录逐步迁移，不要求一次性移动全部旧文件。新增系统提示词必须放在后端 `prompt` 模块，前端只接收后端返回的能力和结果，不能硬编码提示词正文。

## 12. 权威数据

MySQL 保存任务、配置快照、页面、版本、合集和上传事实。Redis只承担队列、延迟任务、分布式锁和短期运行状态。图片、背景、字体相关产物和合集文件存入 TOS。

### 12.1 生产模式与敏感模式

```text
production_mode: video | comic | text
sensitive_mode: ai | system | off
```

### 12.2 批次与单书配置

- 批次保存文本模式完整统一配置。
- 单书保存稀疏覆盖字段和每个字段的继承状态。
- 任务保存解析后的完整生效快照和配置版本。

### 12.3 文本页面

每页至少记录：

- 所属书、分页版本和页序
- 页面生产文本
- 在生产文本中的起止位置
- 内容校验值
- 单页排版覆盖
- 背景来源和背景编号/颜色
- 渲染版本、产物地址和状态
- 产物来源：系统生成或用户上传
- 锁定状态
- 失败阶段、错误类型和错误信息

完整原文、生产文本、生产文本版本和分页版本分开保存，禁止用渲染后的页面内容反推或覆盖完整原文。

## 13. 错误和恢复

错误必须包含书、阶段、页面（如适用）、错误类型和可执行建议，不能只显示“生产失败”。

- 字体不存在：停止相关页面渲染，提示重新选择，不能偷偷换字体。
- 背景损坏：保留正文和分页，只要求更换背景。
- 文字溢出：尝试重新分页；仍失败时标出具体页。
- AI优化失败：显示模型错误，不自动降级。
- 系统优化失败：保留完整原文和上一个生产版本，显示本地规则错误。
- 合集缺页：禁止上传并列出缺失页码。
- 组织或上传映射缺失：保留合集，补配置后只重试上传。
- 漫画与文本混选：前后端都拒绝请求。
- 服务重启：从 MySQL 最后成功阶段恢复。
- 重复点击：通过业务幂等键复用当前任务。

可重试的临时错误由自动化继续处理；缺配置、字体缺失、混合类型等确定性错误必须等待用户修正。

## 14. 成本边界

以下操作不产生模型费用：

- 读取已保存原文
- 本地系统优化
- 规则分页
- 字体、颜色、背景和排版调整
- 标红数据复用
- 服务端渲染
- 封面与合集生成

以下操作可能产生成本：

- AI优化或AI修复的文本模型调用
- TOS存储和网络流量
- 第三方发布平台自身的服务费用

界面必须在会调用模型的开关旁明确提示，不能只通过帮助文档说明。

## 15. 测试与验收

### 15.1 配置

- 统一配置包含全部生产字段。
- 单书配置字段一致，支持继承、覆盖和恢复继承。
- 单页覆盖不污染单书或统一配置。
- 三档敏感处理在视频、漫画、文本中行为一致。
- 纯色、背景库和上传背景都可使用。

### 15.2 分页

使用短段落、超长段落、对话和特殊符号的真实文本验证：

- 不漏字、不重字、不乱序。
- 普通段落不被硬切。
- 超长段落只在完整句子后续页。
- 字体、字号和画幅变化后正确重排。
- 内部续页标记不进入最终图片。

### 15.3 渲染

- 预览和最终图片来自同一后端渲染器。
- 默认 3:4 和其他画幅正确。
- 字体、间距、边距、颜色和背景准确生效。
- 低对比度给出警告。
- 用户上传成品页不被覆盖。

### 15.4 自动生产和上传

至少用一本真实书跑通：

```text
获取原文 → 敏感处理 → 分页 → 渲染 → 校验 → 合集 → 上传 → 回读
```

同时验证：

- 统一配置生产
- 单书覆盖生产
- 单页编辑和重新渲染
- 中途失败从断点恢复
- 服务重启后继续
- 重复点击不重复生产或上传
- 一本失败不阻塞其他书
- 文本和漫画混选被拦截
- 后台实际看到上传结果和记录

代码编译、单元测试或前端显示“成功”都不能单独作为完成证据。最终必须在本地 4001 运行页面看到真实产物、合集、状态和上传记录一致。

## 16. 实施约束

- 不新建零散分支，后续小改动直接在当前主开发分支按任务提交。
- 保留工作区现有无关修改，不重置、不清理、不混入本任务提交。
- 后端使用 Go；前端使用 React + Ant Design。
- MySQL 保存业务事实，Redis实现队列、锁和短期状态，TOS保存对象文件。
- 前端资源最终通过 Go `embed` 打入单个后端二进制。
- 禁止使用 GitHub Actions 上传或部署。
- 本设计确认后必须先编写实施计划，再进入产品代码修改。
