# Magic Cut 4040 Core Workbench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first complete Magic Cut workflow on port 4040: enter from the existing work-mode dropdown, reuse Yizhanchengming authentication, create a project, import media, edit a timeline, export a playable video, and inspect the task in Task Center.

**Architecture:** `magic-cut-workbench` is an isolated Go + React application inside the existing v88 repository. Go owns authentication bridging, persistence, media work, task recovery, prompts and embedded assets; React owns the original-use-flow UI. Development data is isolated in `qiantie_magic_cut_dev`, Redis keys use `magic_cut:dev:`, and TOS objects use `magic-cut/dev/<owner>/`.

**Tech Stack:** Go 1.26, React 18, Ant Design 5, Vite 6, MySQL, Redis protocol client, TOS SDK, FFmpeg/FFprobe, Go `embed`, Node test runner.

## Global Constraints

- Work directly on maintained branch `v88`; do not create a new branch or worktree.
- Preserve every unrelated dirty file; stage and commit only files named by the current task.
- Port 4040 is development-only. Existing port 4001 remains the authentication authority and must not receive Magic Cut business writes.
- Use database `qiantie_magic_cut_dev`, Redis prefix `magic_cut:dev:`, and TOS prefix `magic-cut/dev/<owner>/`.
- Frontend must not contain provider secrets or system prompts. All prompt text lives under `magic-cut-workbench/api/internal/prompt/`.
- Do not run paid AI calls, production TOS writes, public deployment, or Git push.
- UI labels, field order, defaults, dialogs, shortcuts, loading states and failure copy are parity requirements.
- Static reverse evidence is not runtime proof. Record unknowns instead of claiming parity without observation.
