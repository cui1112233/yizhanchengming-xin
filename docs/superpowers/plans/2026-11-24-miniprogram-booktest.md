# 批量测书手机实现计划

目标：修复测书误入批量工厂，沿用紧凑布局，将现有测书核心能力对齐线上。

1. 失败测试：booktest路由/工厂旧路由不混，工作台来源匹配，深链定位及错误不冒充空列表，原文/处理字数。
2. 改modules、functionVisuals、功能页及module-detail；FetchWorkspace增加标题/紧凑模式/初始任务编号，旧fetch保持兼容。
3. 拆正文读取帮助函数、补任务加载状态与深链；高级工具默认收起，新入口按需展开。避免改变已有提交保护。
4. 定向测试、类型检查；构建/WXSS处理完成后跑全量测试。微信从功能卡打开，核对真实平台/模型、任务/日期、设置和空状态，不提交执行。
5. 固定截图和边界写进设计参考/功能清单；明确路径本地v88提交，不上传发布。

## 本轮实现与验收

- public目录九项数量不变，批量测书新增booktest key，进入共享FetchWorkspace紧凑模式；原batch工厂入口、批次参数及任务链接保留。旧fetch别名也进入现代测书页面；工作台booktest只匹配fetch任务，任务列表显示批量测书并定位真实taskId。
- 默认书单/平台/模型/处理字数/版本规则；高级工具折叠，参数、版本与定时在独立滚动弹层。正文14px、标题18px、两侧16px、主要按钮44px。平台返回的完整unicode编码名称解码显示，编号不变，过滤禁用模型。
- 排查发现旧/process接口仅导入，所选版本/改文方式未被处理；新增booktestJobs与useBooktestJob，正式开始走与网页相同的/process/start，携带selected_versions/rewrite_methods/text_model_id等；原始/AI1至AI5与四类改文方式都能选择。默认进入只GET最近作业；同一作业只读刷新，离开/隐藏停轮询，恢复不POST；服务端阶段和错误直接展示，不估算百分比。停止携带job_id且pause_auto_queue=false，不改全自动开关。
- 开始前向用户说明获取、AI改文和自动提交视频管理系统。同步锁防连点，结果未知不在当前页面重发，用户到任务页核对最近作业。应用完全关闭后，未收到作业ID的请求没有跨重启持久化恢复记录；不能声称完整未知提交恢复已验收。
- 详情支持服务端正文库的versions映射和旧数组结构；处理后正文/完整原文分开显示及计数；input_ready显示分类信息已就绪，running优先显示正在执行中。任务加载、失败、真实空列表区分，日期只按真实时间筛选。深链缺少任务时明确报错，不打开别的书。
- 定时创建修正原嵌套inputSnapshot无效的问题，改扁平执行参数；auto_submit=false明确传输，编辑只改时间/提交选择并保留旧书单；手机日期与时间选择。新版用cancel端点取消，只允许删除终态记录，不再用无效enabled开关冒充暂停。未实际创建/取消/删除定时。

新增16项测书测试：5项路由/来源/状态/计数/模型/平台输入组合测试，8项手机交互，3项作业请求与正文版本合同测试。全量最终结果写于下方。类型检查仍有8处既有profile/tasks/workspace/taskPageState错误，本轮新增文件无类型错误，不能称全项目类型检查通过。

微信实际只读核对：从功能卡进入booktest，读取10个平台与真实文本模型，黑岩付费名称正常；当前账号测书任务0，最近作业暂无。打开参数、版本及任务页；版本弹层显示真实AI1改文方式，未勾选/修改并保存。没有抓测试书、启动作业、调用收费模型、保存配置、创建定时或网站提交。最初工具命中了旧编译缓存；清编译缓存后功能卡、独立页面和稳定id定位正常。初次nth-child定位命中不可靠，改用页面显式id后任务切换正常，未将定位失败当业务黑屏。

未验收：真实原文获取/改文/自动提交、已有书籍详情与版本结果、作业停止、定时派发/取消/删除。当前账号无数据，这些链路按Go/React合同与模拟接口测试验证。高级全自动队列、组员账号切换、当前批次入厂、完整知识库编辑、跨端草稿和应用重启未知提交恢复未在本轮完成。旧FetchWorkspace的默认非紧凑模式仅保留旧代码测试兼容，公开新旧入口均进入同一现代模式。

最终开发构建26.99秒成功，WXSS后处理剥除49条旧兼容规则；任务标题用显式类布局，不依赖不支持的:first-child。最终产物之后全量138个文件通过、1个跳过，902项通过、3项跳过。已观察最终任务标题/说明分行、定时手机日期与时间选择、版本改文方式，最后返回书单输入页；控制台无业务脚本错误。截图位于docs/design-references/miniprogram-booktest/。
