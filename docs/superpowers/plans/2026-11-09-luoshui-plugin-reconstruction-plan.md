# Luoshui Plugin Clean-room Reconstruction Implementation Plan

> **For Codex:** Execute each item evidence-first. Do not copy proprietary source, credentials, private endpoints, or resources.

**Goal:** 把洛水 v2.9.0 插件逐个转换为可验证规格，并用一战晟铭现有 React + Go + Agent/本地执行器独立实现。

**Architecture:** 前端插件市场只负责入口和交互；提示词统一由 Go `prompt` 模块管理；图片生成复用 Agent 图片任务；需要本机文件或剪映草稿的能力必须通过明确的本地执行器实现。每个插件先建立证据链，再写测试和代码。

**Tech Stack:** React、Ant Design、Go、MySQL/Redis（需要任务时）、Agent workspace API、Go embed。

---

### Task 1: 固化插件目录和入口证据

- [x] 核对 30 个可见目录项、顺序、名称和说明。
- [x] 核对完整点击处理器与关闭处理器范围。
- [x] 纠正“资产参考是开发中占位”的错误结论。
- [ ] 用当前登录界面逐卡截图核对目录版本，记录与 v2.9.0 包的差异。

### Task 2: 资产参考独立实现

- [x] 先写输入、归一化、多任务拆分、重复、取消和结果过滤测试。
- [x] 接入一战晟铭图片模型、Agent 素材上传和图片生成任务。
- [x] 支持 21:9、1 至 20 张独立任务、部分成功和全部取消。
- [x] 完成聚焦前端测试、Go 测试和 Vite 生产构建。
- [ ] 在本地 4001 新二进制中做浏览器可见验收。

### Task 3: 五个文本模型插件

### Task 4: 字幕、文档与剪映草稿插件

### Task 5: AI-CUT 与媒体插件
