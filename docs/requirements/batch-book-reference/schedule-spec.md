# 定时处理规格及当前差异

## 原系统证据

所有原包行号均相对独立解包目录。

| 环节 | 证据 | 行为 |
|---|---|---|
| 输入 | main.py:546 ScheduleCreateRequest | 时间、平台、书单、识别方式、列配置 |
| 保存 | main.py:15221 create_schedule | 校验空输入和时间，解析平台，绑定账号与所有者 |
| 建任务 | main.py:15087 ensure_schedule_tasks_created；15247 调用 | 保存时入库，记录 created_ids / tasks_created_at，到点前不处理 |
| 到点放行 | main.py:15125 release_schedule_tasks_for_execution | 只释放本定时任务所属记录；人工暂停的不自动释放；重试等待未到期的不提前处理 |
| 执行 | main.py:15320 execute_due_schedule | 检查到期、暂停、等待重试，再启动自动队列；已有运行任务时等待 |
| 常驻检查 | main.py:15429 schedule_ingest_worker | 恢复与到点扫描，不能依赖用户保持页面打开 |

复核修正（2026-11-15）：原包 `ingest_tasks_only`（main.py:14772–14798）会跳过尚未终结的同 ID 任务；done/submitted/failed/stopped/cancelled 等终态可建立新实例。因此不能把原包概括为“已有书全部续做”。用户要求的补缺失步骤来自 `retry_task`（main.py:11611–11739），必须与“重新入库”分开。下表 S04/S05 为用户确认的目标规则，不冒称原包定时入口原样具备。

## 可验证规则

| 编号 | 输入 | 输出 | 边界 | 失败提示 |
|---|---|---|---|---|
| S01 保存 | 有效时间、平台、非空书单、处理设置 | 返回定时任务和书籍任务编号、数量 | 空书单、无效时间或平台不得保存假任务 | 明确指出哪个输入无效 |
| S02 时间 | 带时区时间或明确为北京时间的本地输入 | 服务端保存统一时间，页面显示用户可理解时间 | 页面关闭不影响；已到期按约定立即进入队列 | 时间解析失败不得静默跳过 |
| S03 到点 | 已保存且未取消任务 | 只放行所属、未完成任务 | 全自动暂停显示等待；不处理其他用户任务 | 展示等待原因和可执行操作 |
| S04 重复与续做 | 相同书籍已有记录 | 区分已成功、未完成、其他批次占用 | 不能因为“记录存在”就把未完成任务算成功；同一任务不得重复扣费/上传 | 显示跳过或等待的具体原因 |
| S05 中断 | 部分原文/AI/提交已经完成 | 从第一个未完成阶段继续 | 重启恢复不丢失任务；已提交但回查未确认时先回查 | 保留已完成结果及本次失败阶段 |
| S06 账号过期 | 需要提交但目标账号失效 | 等待登录，保留原文和 AI 文案 | 恢复账号后只继续提交；不重生成 | 明确显示“视频管理系统未登录” |
| S07 完成 | 所有要求的阶段成功 | 已完成数量与提交记录一致 | 无需提交的模式另算；提交中/等待回查不能伪装全部完成 | 失败书籍、阶段、原因、重试时间可查 |
| S08 取消 | 用户取消定时任务 | 后续不再派发 | 不删除已有成果，不擅自撤回已提交内容 | 显示已取消，保留执行历史 |

这些规则是目标规格；不能用“原系统函数存在”证明我们已经实现。

## 已确认的代码差异

1. `backend/internal/httpapi/novel_fetch_legacy_workflow.go:211` 的 POST schedules 读取任意 JSON 后直接保存 scheduled，没有原包同级的空书单、有效时间和平台检查，也没有保存时建立书籍任务。
2. `backend/internal/httpapi/novel_fetch_workshop.go:1057` 到点才解析书单并调用 novelFetchNewBookIDs；全部书籍存在时直接标 completed。
3. `backend/internal/httpapi/novel_fetch_workshop.go:1340` novelFetchNewBookIDs 只判断记录是否存在，不判断原文、AI、上传是否完成。因此“已有记录”与“已做完”被混为一谈，违反 S04。这是静态代码确认的缺陷，不等于已经证明某条线上任务因此失败。
4. 现有重试状态协调代码需要继续对照 S05～S07。新增恢复函数不意味着这些组合情况已验收。

## 当前真实记录

2026-11-15 02:32 本地 4001 的 choushiyiguai 账号只读返回 4 条定时记录：两条历史失败、一条历史完成、一条 2026-11-14 11:27 的任务已取消。最后一条有 job_id、237 个 book_ids，错误含原文获取时的书籍信息失败。这证明该条曾派发，不能说它完全没有启动；也不能据此证明线上任务已正常。

仍需获取用户所指线上任务的 ID、状态变化和执行记录，对照平台参数、原文请求、处理版本、提交账号、回查及统计，才能给出那条任务的完整故障结论。

## 实现前验收清单

- 空输入/错误平台/错误时间不产生任务。
- 保存后可看到待执行书籍，到点前不产生收费调用。
- 到点触发和手动重复触发只启动一次。
- 已有未完成书籍继续，成功书籍不重做。
- 关闭页面、重启服务、队列忙、全自动暂停各有明确结果。
- AI 完成但提交未完成、提交成功但回查超时，两种情况分别恢复。
- 登录过期、原文 400、模型 503 分别提示，不能统一显示“已完成”。
- 每个结论带请求、保存记录、队列和页面证据；未验证项保持未验证。
