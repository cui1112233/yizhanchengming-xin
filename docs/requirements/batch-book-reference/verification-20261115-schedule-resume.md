# 定时保存、续做与提交链路：第二轮验证

## 改动

- 保存定时卡片先记录 preparing，再把新书和允许续做的书保存为 scheduled_waiting；部分写入失败后可继续准备。普通全自动扫描不提前执行这些书。
- 保存 requested_book_ids / book_ids / created_ids / skipped_books；活动任务、其他定时占用、人工停止分别说明跳过原因。书籍存在不再等于已经完成。
- 按所选版本的已确认提交账本判断成功；AI1 已提交但 AI2 缺失时仍会安排续做，保留原文、AI1 和已有回执。
- 到点复用原队列、缺失版本生成和提交服务；派发前再次检查停止和占用。旧 dispatching 记录缺文档时从同一原始输入恢复，不改变已保存的执行编号。
- 定时与立即开始使用同一份页面归一化书单；后端也支持直接请求中的列顺序和表头。空列不移位，推荐理由里的“男频”不会冒充人工选择的男女频。
- 取消时，只有本次新建且完全没有正文、版本或正文引用的空记录才可清理；其余成果保留。页面显示“等待定时执行”“正在准备书籍”和可展开的跳过原因。
