# 批量测书行为规格（原包证据版）

日期：2026-11-15。本文把原系统转为可核验规则；不是完成证明。原包位置和指纹见 README。`main.py` 和 `static/app.js` 均指独立保存的原包。原包中部分提示本来存在乱码，不能当作要复刻的文案。

## 共用数据和完成定义

- 输入书目与实际任务不是同一个数量：解析行数、无 ID 行数、输入内重复数、已存在数、实际新建数分开显示。原包 `ingest_tasks_only` main.py:14728–14841。
- 原始全文、处理后原文、AI1～AI N、提交回执分开保存。原包 `task_detail_content` main.py:9942；`task_existing_submit_versions` main.py:12032。
- 一本文案完成，不代表已提交。已提交也不代表所有版本都成功。按书籍、版本、目标账号记录提交结果。原包 `task_pending_submit_versions` main.py:12285。
- 用户点“重试”是补缺失步骤；用户主动点重新获取、重新生成是另一种明确操作。原包 `retry_task` main.py:11611，生成时传 `missing_only=True`（11680）。
- 正文、任务、配置、提交账号必须跟随当前所有者；不能用管理员身份显示组员任务成功。原包 `require_task_visible`、`run_in_task_access_context` 在各任务入口调用，具体可达链见 original-api-call-chains.json。

## 不应照搬的实现与待确认项

1. 原包采用 Python 与本地文件。我们的 Go + MySQL + Redis + TOS 不复制其文件存储方式，只实现数据意义和可验证结果。
2. 原包的任务实例策略和用户要求的断点续做不完全相同：新建、重做、重试必须分开。不能用反向推测代替原包证据。
3. 原包部分敏感日志的英文、乱码提示需要转成清楚中文，不属于“一比一”必须保留内容。
4. 原包账号管理由独立登录系统承载；我们使用统一账号系统，需验收权限和用户隔离，不要求复制第二套账号数据库。
5. 运行时界面像素、动态按钮全部状态、真实上游模型与视频管理系统的成功请求仍须单独验证；静态源码不能证明它们成功。
