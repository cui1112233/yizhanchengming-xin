# 定时保存与续做设计

2026-11-15，延续已确认的“保存即建任务、到点只补缺失步骤”。

## 数据与入口

- 继续使用现有 MySQL 配置、书籍记录、执行快照和 Redis 防重复队列，不引入第二套执行器。
- 定时编号是本次执行身份，book_id 是作品身份。定时卡片分别保存 requested_book_ids、book_ids（本次可执行）、created_ids（本次新建）、skipped_books（跳过原因），不以记录存在表示成功。
- 保存先写 preparing 卡片，再建立/关联待执行记录；完成后置 scheduled。服务中断时扫描器可重做准备，不调用收费服务。
- 新建和待续做记录加 scheduledHold；到点前普通全自动扫描不得捡走。正文、版本、回执一律保留。
- 正在执行、其他未结束定时已占用、用户停止/人工暂停的任务不抢占，卡片说明原因。所有目标版本都已确认提交才算完成；生成完但没提交必须继续提交。
- 到点派发复用已有 worker、版本缺失判断和提交账本。旧卡片没有准备标记时补准备，已有 dispatching 作业继续现有恢复逻辑。
- 页面保存与开始处理使用相同的规范化书单；后端对直接 API 输入同时识别明确列顺序、表头、标准输入，并把元数据保存到作品。

## 边界与验收

1. 保存后立即可查书籍，但到点前队列为空且普通自动化不执行。
2. 已有原文/AI1、缺 AI2：只调用一次 AI2，原文和 AI1 不变。
3. 已提交 AI1、要求 AI1+AI2：仅补 AI2，不能把整本误判成功。
4. 活动任务与人工暂停不能被新定时覆盖。
5. preparing 中途失败可恢复，重复扫描不重复建记录或派发。
6. 调整时间使用新时间，但不会把 book_id 当新作品覆盖内容。
7. 取消只取消所属任务，不给跳过的活动作品写取消标记；有正文的记录不删除。
8. 自定义列顺序、前置表头的输入，预览和实际保存 ID/书名/男女频一致。

主动重新制作整本属于另一种用户操作，本轮不因保存定时任务清空成功成果。不新增数据库迁移；多个历史制作实例的完整历史展示另行定义，不冒称已实现。
