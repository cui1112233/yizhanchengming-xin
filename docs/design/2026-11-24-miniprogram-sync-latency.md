# 手机切换功能同步等待排查

## 已确认的原因

开发工具网络记录中，任务列表接口约51～915毫秒，部分批次`runtime-summary`请求约8～15秒。原工作台只展示所选功能，却先读取七个来源及其子任务；任务中心、个人页离开后仍继续启动排队读取。批量测书等四组读取全部结束后才应用配置，慢历史会拖住已返回的平台与模型。

## 本地修改

- 工作台只同步当前功能；水货继续保留自身及批量作品来源，不截断真实记录。
- 工作台、任务中心、个人页隐藏、切换账号、开始新轮读取后，不再发送旧轮排队请求或应用旧结果。已经发出的最多四个读取仍等待自身结束，不声称已中断服务器处理。
- 任务中心按来源逐项显示已返回的真实记录；同步中明确说明统计尚未完整，所有来源结束后恢复完整统计。
- 批量测书配置/模型、历史任务、定时任务分别应用，不用慢历史阻塞创作选项。
- 个人页任务同步独立于会员资料请求，离开后返回时可正常重新启动。

## 验证

- 定向85项通过；全量1070项通过、3项跳过；类型检查通过。
- 新增延迟响应测试证明：所选测书工作台仅调用自身任务接口；离开后其余排队读取不再请求服务器；慢批次不阻止已返回来源显示；慢历史/定时不阻止平台选项显示；会员请求未结束时往返页面仍能重启任务同步。
- 以上原始网络时长用于定位原因，不能当成修改后全功能的实测速度保证。没有改动线上数据或部署后端。
