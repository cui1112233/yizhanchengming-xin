# 私人定制漫画：小程序与线上链路对照

日期：2026-11-24。结论：**未完整对齐，存在核心链路差异。此前的814项小程序测试与UI验证不等于线上功能对齐。**

## 依据与边界

- 本轮在已登录浏览器实际打开 https://yzcm.site/script，选择“漫画生成”，查看了流程、输入、当前配置弹窗和状态说明。线上显示“提取资产 → 资产图（可选）→ 漫画提示词 → 漫画图片”，并明确提示先生成提示词、确认后生成图片；配置弹窗明确“仅应用到当前这一本漫画”。
- 同时逐项检查当前仓库网页、小程序及后端处理器。下面“源码差异”不冒充线上付费执行结果；未确认线上部署二进制与当前仓库逐字一致。
- 没有输入正文、修改模型或保存线上配置，没有提取/生图/发布/下载，也没有创建测试任务。核对结束已返回原来的 /batch-factory 页面。

## 已覆盖，但不能称全链路验收

- 漫画入口对应私人定制漫画，未指向漫剧；productionMode=comic、scope=private_customization；不自动发布。
- 使用同一 private-comic/tasks 项目接口；8种图片画幅枚举相同。
- 文本模型、图片模型、分页提示词、图片描述、约束目录已有独立数据来源。
- 资产分类、描述编辑、上传图片版本、切主图；页图双提示词编辑、单页再生成、页图版本、预览与保存有接口接入。
- 提示词与图片ZIP、图片合集、抖音图文包已有请求入口；需要解除错误的图片前置门槛，并验证真实下载结果。
- 小程序有已建项目恢复、旧异步回调隔离、重复提交保护，但这些机制不能代替网页行为一致性。

## 下一轮顺序

1. 修复第一次提取：创建/复用项目 → 显式提取 → 回读资产，失败留在当前项目可重试。

3. 对齐资产图默认值、三视图、provider、独立资产画幅与当前项目配置保存。
4. 补草稿保存、20字门槛、手动标题、历史入口和提示词单独导出。
5. 使用同一测试项目在网页/小程序核对读取、修改、恢复、失败重试、实际生成和导出；涉及付费执行需有明确授权。每项分别记录页面、请求、服务端状态及产物，不用测试数量代替验收。
