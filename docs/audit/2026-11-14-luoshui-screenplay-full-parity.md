# 洛水漫剧制作全流程对照：尚未全面一致

日期：2026-11-14。范围经用户确认是**漫剧制作全流程**，对应洛水的“剧本创作”，不是整个洛水软件，也不是“漫剧解说”或独立 AI-CUT。

**结论：目前不能称为完整复刻，也不能称每个页面、功能和链路全面一致。** 新建、剧本文本、文本资产、分镜编辑等基础功能有真实实现；章节、作品内 Agent、图片与参考图、配音字幕、媒体编辑、独立后台推进及完整成片/剪映交付仍有明显差异。

## 本轮实际做了什么

- 使用 REA 打开本机洛水 EXE，核对文件身份，没有执行 EXE。
- Craft Anything 的 MCP 会话起初是 Clean room，动态启用工具后列表仍未刷新。改用**已经安装的官方 CLI**，在本次项目加 `--deep` 静态读取，不修改全局模式或连接配置。
- 使用 Craft 记录 EXE 布局、安装目录、完整主 JavaScript 文件的静态映射，以及 36 个 V88 范围内源文件的独立快照。
- 用户确认窗口查看后，读取已运行洛水的项目库、新建窗口结构，并尝试只读导航。未生成内容、未创建洛水项目、未读取账号密钥或用户项目正文。
- 重新运行 V88 剧本模块和相关接口测试：70 个模块测试/子测试、15 个接口测试、22 个相关前端测试通过。它们主要使用模拟模型，不代表供应商端到端实跑。
- 本轮没有修改产品源码、发布公网、推送 Git、调用付费模型，也没有声称截图失败的页面已完成视觉验收。

## 怎么读状态

- **已接通**：本模块有对应页面/调用、实际存储或执行路径；相关测试或前轮本地验收支持。只代表这项能力存在，不代表与洛水像素、内容质量、全部边界一样。
- **部分**：真实实现存在，但缺少同类的入口、数据、控制粒度或交付环节。
- **未接通**：在本轮限定的工作台页面、专属接口、模型和执行器中没有对应闭环。其他页面有类似能力，不自动算接入。
- **未验证**：没有足够现场或供应商执行证据，不凭函数名判成功。

洛水列中的 API 名称是**当前安装包中的静态属性/调用候选**，带确切文件身份；它们证明包内有相应入口，不单独证明原软件的供应商调用已经执行成功。原窗口可观察的项目库/新建另有 UI 证据。此表覆盖全部制作页面分组，不能把静态候选数当作原软件全部功能数或完成百分比。

## 三条最关键的实际链路

### 已接通的基础制作

`新建输入/文件解析 → POST项目+sourceText → screenplay_projects → 文本生成 → screenplay_documents版本 → 资产文本 → 分镜条目 → 编辑并保存`

其中四档、画风、原文和编辑都是真实功能；不能因为后段不足，把前段也一律叫假按钮。

### 当前视频生产

`浏览器 startBatch 的64次循环 → /batch/run-next → BatchExecutor → screenplayVideoRunner → 账号视频模型 Submit/Poll → 一组镜头链接 → completed标记`

缺的不是视频 Submit 这一步，而是图像/音色引用、逐镜头恢复、字幕、粗剪、分集合成及完整工程输出。关页续跑和长篇推进也需要另外补。

### 当前“审核”和“导出”

`检查内容/数量存在 → 固定通过 Review`；`GET /export → JSON → 浏览器下载.json`。

前者应标为基础结构检查，后者应标为数据导出，不能分别冒充 AI 质量医生和可继续剪辑的成片工程。

## 建议补齐顺序

1. **先修完成口径和恢复可靠性**：结构检查如实命名；镜头任务 ID、结果、失败原因逐条保存；服务器持续推进，消除 64 次限制；明确暂停与上游取消的差别。
2. **打通视觉一致性**：资产图、参考图、多镜头复用、镜头图片历史、图生视频，逐项验证图片真的进入供应商请求。
3. **补齐可交付结果**：角色音色、旁白、ASR 字幕、镜头剪辑、分集渲染、媒体包与剪映草稿。
4. **再补完整操作面**：章节/计划、作品内 Chat/Skill Agent、批量分镜编辑、显示配置、新版工作台和团队权限。

每项都应有“输入→页面操作→接口→保存→执行器→产物→失败恢复”的验收，不能只加入口和图标。本报告是逆向对照结果与补齐依据，**不表示上述缺口已实施完毕**。
