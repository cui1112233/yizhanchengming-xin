# 小说任务扫描 CPU 优化

## 原因与范围

- 线上进程 12 秒 perf 采样共 467 个样本，275 个包含
  `runNovelFetchScheduleDispatcher`，333 个包含 `MySQLStore.GetConfig`。
  这是该时段的样本占比，不等于所有时间或整台机器的 CPU 占比。
- 定时派发每 5 秒、自动任务每 20 秒扫描账号配置。8 份持久化配置共
  14,967,337 字节。每次读取都会重新解析内置预设，并通过 JSON 编解码
  重复复制整套默认库及其子树。
- 本次只改 `novelfetchworkshop/seed.go`：固定预设只解析一次；返回私有副本；
  JSON 数据直接递归复制；合并时已复制的父节点不重复复制。
- 不缓存账号配置或密钥，不改任务检查频率、执行模式、重试、付费生成和发布设置。

## 本地验证

- 先添加分配量回归检查，旧实现实际失败：每次 141,616 个对象，预算 30,000。
- 同机相同基准，旧实现 3 次：空配置 31.3–34.5ms / 18.8–19.3MB；
  已保存配置 61.2–65.7ms / 40.1–40.2MB。
- 新实现 3 次：空配置 6.0–7.3ms / 2.8MB；已保存配置 5.3–6.2ms / 2.8MB。
  已保存配置耗时减少约 90%，分配量减少约 93%。这是配置读取基准，
  不作为整台机器降幅承诺。
- 全部 `internal/novelfetchworkshop` 测试通过；配置隔离、并发读取隔离、
  JSON 值兼容、旧合并结果一致均通过。
- `internal/httpapi` 中 Workshop、NovelFetch 定时/自动任务及漫画
  Queue/Overload/Resume 相关测试通过。
