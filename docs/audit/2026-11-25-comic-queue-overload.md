# 漫画排队误判与上游503提示修复

## 证据与原因

用户截图中排队等待期间同时显示“书籍长时间没有进展”；线上任务记录也存在等待文案持续更新、lastProgressAt仍停留在之前阶段的情况。线上检查时运行源码为36f078ac。

书内看门狗使用独立原子心跳判定40分钟停滞。原排队回调只更新任务文案、updatedAt与生成租约，没有更新看门狗心跳，因而正常排队也会被取消。旧错误还会遗留到新的出图尝试中。

图片HTTP非2xx通用提示把503也描述为“模型可能不支持出图”；截图的原始原因实际为system cpu overloaded。单页重试只覆盖传输错误和聊天通道错误，没有覆盖结构化503响应。

## 修改

- FIFO出图队列在开始等待、每分钟等待回调以及获得槽位时调用现有统一心跳，刷新原子计时与持久化进度时间。等待时间不计入之后实际执行的停滞时间；真正无进展的执行仍保留原超时判断。
- 新出图尝试清理当前顶层error，保留历史执行日志、页级账本、失败次数和已成功图片。
- 408、429、500、502、503、504响应允许使用既有单页重试上限和退避；400、401、403、404仍不走此重试。
- 5xx、429、408/504分别显示服务不可用或负载过高、请求过频、响应超时，不再误导为模型能力问题。

## 验证

- 新回归测试在修改前复现排队未刷新心跳、503误导提示和活动状态遗留旧错误，修改后通过。
- 使用本地假HTTP服务验证“503两次后第三次成功”“持续503最多三次”“400只尝试一次”。不调用真实付费模型。
- 队列FIFO、取消等待、真实停滞保护及本次回归测试重复运行10次通过；相关出图错误和重试测试通过。
