# 文本与漫画合集上传提速（本地）

## 原因和改动

此前上传阶段有两处串行限制：

1. N8图片逐张申请地址、逐张PUT上传，原有5路并发只负责上传后的入库查询。
2. 所有书籍的文本/漫画上传共用发布器的一把全程互斥锁，一本进行网络上传时，其他合集也被阻塞。页面上多本“执行中”并不代表这些书真正同时传输。

提交 `36f078ac`：

- 单个合集最多3张图片同时准备和传输；小于3张的待传批次继续串行。
- 同一N8客户端跨合集共享6个传输名额，防止书本并发乘上图片并发后无限增加请求。
- 原页码和图片ID保持对应，回调串行保存；已有图片ID跳过重传。出现错误时停止新增网络工作，等待在途工作收尾并返回已知进度。
- 本地锁按用户、批次、书籍、合集类型、不可变合集ID隔离；同一合集的重复提交和状态确认仍串行，不同合集不互相等待。等待者引用计数归零后清理锁记录。
- 原有Redis认领、回执比对、确认成功后才标记完成的规则继续保留。此改动没有修改视频管理系统的独立视频上传链路，也没有修改模型价格。
