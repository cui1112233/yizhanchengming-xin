# G12 普通资产库基础实施

本项处于实施中，未完成端到端对照。当前4001仍运行 `af9f8a75`；本次库基础模块尚未接入现有编辑保存链，也没有对用户增加未接通的按钮。

原版规则见 [asset-library-spec.md](asset-library-spec.md)。旧新增、仅更换图片、编辑草稿绑定、保存全局库是不同操作，不能用“复制整个资产”代替。

已实现的基础模块：

- MySQL独立普通库迁移8800116与内存仓库；按账号、人物/场景/道具、分类和名称/描述搜索；保存支持稳定ID幂等及版本冲突。同名不同ID保留，不猜测原生重名覆盖规则。
- 图片保存服务从服务端读取当前资产与已选中、已成功保存的真实图片，检查源资产版本和账号归属；不接受客户端提供的任意路径或图片地址。
- 保存独立图片副本到现有对象存储，库记录保留持久对象信息，接口不返回对象键、来源完整快照或临时签名。保存失败只清理本次独立副本，不删除来源或其他并发请求成功的副本。
- 数据库提交成功但回包丢失时先核对已保存记录；已被记录引用的副本绝不清理。无法核对时保留副本并提示结果待核对，不能误报成功或误删。保存请求同时核对用户看到的选中图片编号，其他窗口换图但资产版本未变时也拒绝旧请求。
- 重复请求找回已保存记录，不重复复制图片；明确同请求标识不同输入报冲突。仅库图片读取不会重新读取已被删除的来源项目。
- 公开列表、保存、图片读取处理器可独立注册测试，目前未接工作流注册；普通库仅限当前账号，分享项目的阅读权限不自动允许跨账号导出库资源。

验证已通过：仓库与迁移测试、MySQL字段往返SQL契约测试、真实上传/生图完成路径的媒体状态兼容、服务/HTTP内存集成。包含来源图片和项目删除后库图片仍可读、跨账号隔离、并发重复保存只留一份、数据库失败清理、版本过期/无选中图片拒绝、来源设定不被覆盖。全部使用合成图片或内存对象存储，无外部模型调用。

这些测试不是本地4001真实MySQL/TOS端到端验收。独立库图片副本、版本校验和严格失败处理属于CM自身存储与可靠性适配；原版原生复制/ID/重名规则仍未知。

独立选择器也已实现并通过受控Edge浏览器测试：旧新增/更换前60项、V2全部项、分类大小写、名称与描述搜索、取消零应用、失败重读、关闭后晚到加载、重复点击、Enter/Space操作。组件尚未接业务入口；其选择回调只返回候选，不等于图片已保存或导入。V2宽640px/max85vw/max70vh，更换600px，旧新增680px；将来接入旧新增窗时需遵循原版内嵌布局，不能将独立测试弹窗当作整页像素通过。

剩余：库图片准备到目标作品、明确保存后才应用选择、仅图片替换与新增的分别接线、全局保存入口、账号库管理、完整正常/空值/错误/重复/取消对照、4001实际部署与持久对象验收，以及原版实时页面对照。G11的真实原版UI/供应商验收同样未关闭，全目标保持进行中。
