# ZIP分镜选择器、排序、搜索和收藏

## 本入口的真实界面

O为ZIP恢复前端主文件。O:120216附近，scriptMaster为true时渲染一个200px宽、tiny尺寸、可清空、可过滤的下拉框，placeholder为“分镜提示词”。value绑定Yn，options绑定Gn。此处并非安装版截图的“收藏/最近/全部”三栏资源弹窗。

O:118779–118792的原加载函数执行`get_all_prompts("剧本分镜",1,1000,"")`。返回success=true且data存在才映射name/id；只有当前Yn为空且返回非空时自动选第一个。其他已保存ID保持不变，即使ID不在候选里。原函数受控执行、连接实际ZIP API和数据库已经验证。

本轮只确认静态渲染属性、原函数状态与原生API。尚未在真实NSelect DOM中键入并截图，所以不能把API搜索规则直接写成本地下拉框过滤规则。

## 数据来源和排序

从固定ZIP数据库复制提示词记录、原created_at/updated_at及收藏/共享标记到隔离SQLite，未复制creator或账户表；使用原生Api/Database。

实际SQL追踪得到`WHERE prompt_type = ... ORDER BY created_at DESC LIMIT ... OFFSET ...`，默认按创建时间降序，而非更新时间。没有第二排序键；相同创建时间的稳定顺序尚未作保证。

固定包本地“剧本分镜”19项的实际返回ID顺序：202、193、192、190、181、180、178、177、176、175、164、157、156、149、147、146、139、138、137。首次未选中时原加载函数选202。已有137时保留137；无效999999也保留，属于需要清晰提示的边界。

这是固定包本地数据，不保证在线同步后的内容仍相同。

## 原生搜索与分页

15组真实查询验证：

- page_size=5时前两页各5项；第99页为空，total仍19。
- page=0会传OFFSET -5，SQLite实际返回前5项；page_size=0返回失败，不可当作正常空结果。
- 搜索SQL匹配name或description；Vidu与vidu均4项，“小云雀”1项，无匹配词0项。
- `%`按SQL通配符匹配，返回该分类全部19项，未进行字面量转义。
- 不存在分类为空；不指定分类84项；共享36项、非共享48项。

CM应明确页码和每页数量的合法范围，错误给出可理解提示；不把内部除零错误直接显示给用户。原生搜索和UI本地filterable过滤分别验收。

## 收藏、最近与持久化

实际`toggle_prompt_saved`在隔离原数据库内将所选项is_saved由0变1，再次点击恢复0；缺失ID返回“提示词不存在”。再次收藏后停止进程并重开，收藏状态保持。原生内容读取前后，受观察的is_saved/stars/likes/dislikes/created_at/updated_at均未改变。

上述只证明原收藏接口及数据库持久化。当前AIChat下拉绑定没有观察到收藏按钮或最近面板；不能将全局提示词库API当成本入口按钮。也不能仅凭内容读取不更新这些字段，断言软件其他地方完全没有最近记录。

## 失败与空值

原加载函数：空库返回空选项；桥接抛错时只写控制台，保留旧选项；既有无效ID没有自动清理。CM需要区分加载失败、空结果和无效已保存选项，不能用旧数据冒充刚加载成功。已有用户收藏数据不能因UI复刻而直接删除。

证据：`analysis/prompt-selector-chain-v1.json`含15组原生查询、5组原前端函数行为、收藏往返与新进程重读；`analysis/native-api-isolated/prompt-query-sql-trace.json`含3组真实SQL。原函数没有改写，服务替身不是数据来源；未调用模型。
