## 正常链路与实际文件

真实原函数Ke/lt通过本地JSON桥接调用真实ZIP原生Api，并在全新原生工作进程中重读。不是假create/save返回值。原函数中的引用状态由测试上下文提供，不是完整Vue页面。

1. 名称仅在trim后非空时进入创建；提交原名称及每行去首尾空白、滤掉空行后的正文。
2. `create_screenplay`参数：name/content/script_mode/style/aspect_ratio/content_type/script_master。该前端分支script_master=true。原生声明api.py:18412。
3. 原生成功返回data.id/name/path/content/created_at。实际创建“剧本创作/作品名”目录、`info.json`及`剧本<作品名>.txt`。
4. 非空内容、有返回路径时，前端解析章节，调用`save_screenplay_chapters({project_path,chapters})`，写`chapters.json`。原生保存声明api.py:20974，加载声明api.py:20996。
5. 切到ai-chat，并经原lt函数O:124908–124928调用`save_screenplay_ai_config`，保存model、promptId、promptName、style、scriptMode、aspectRatio、contentType、scriptMaster到`ai_config.json`。
6. 关闭原生工作进程、创建全新进程，实际`get_screenplays`/load章节/load配置可读回普通作品。此为后台进程和数据重开验证，不是桌面窗口重开截图。

## 分章实测规则

| 输入 | 原版结果 |
|---|---|
| 无章标题的普通正文 | 1章，标题“第1章” |
| 第一章/第二章 | 2章，保留原标题；内容含标题，id按位置0、1 |
| Chapter 1/CHAPTER 2 | 2章 |
| 第1集/第2集及场次 | 仍1章“第1章”，未按集拆分 |
| 前言+两章 | 项目正文保留前言，生成的章节列表不含首章前言 |
| 两个“第一章” | 保存为两条不同位置id，没有因重复章号拒绝 |

不能把安装版或CM现有分集切分规则填入此章入口。集、章及剧本场次的关联要在后续分镜规则中另行确认。

## 边界、失败与取消

- 空白标题：提示“请输入作品名称”，不调用原生接口，窗口保持打开。
- 空正文：可以创建空作品，不调用章节保存；章节读取返回空数组。
- 取消：不调用创建或保存，窗口关闭，仍在作品库状态。
- 非法Windows文件名（本例OWN_BAD<NAME）：原生返回success=false，前端仍提示“创建成功”、关闭窗口并进入ai-chat，没有真实项目路径。这是原版缺陷，不可复制为CM假成功。
- 无桌面桥接：前端会创建仅本地内存条目并进入ai-chat，没有持久化。不能拿此路径充当CM保存成功。
- 连续同名创建：第一次用原名称，后续目录使用秒级时间后缀。同一秒第三/第四次会复用第二次目录，旧正文及章节被覆盖；原生重开后可实际观察到第二次结果变成第四次结果。CM须继续使用独立稳定项目ID，不能移植这一缺陷。

## 章节接口的额外边界

9组真实原生接口试验证明：合法列表、空列表均可保存；字符串、无效列表项、重复id也会保存；chapters=null时，先把旧文件改成null，随后返回失败，重读也失败。缺project_path返回“缺少项目路径”；不存在的路径读取返回空数组，保存空列表会新建路径。

这些是已确认原版行为及缺陷，不是CM应照搬的数据规则。CM必须在写入前校验对象、列表、唯一id、标题和版本，失败保留原有效数据。用户要求不允许假链路，因此假成功、重复覆盖和失败后损坏旧稿列为修正例外。
