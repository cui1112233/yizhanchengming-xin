# ZIP分镜按钮、失败补充与保存重开

来源：O为固定ZIP可读前端。原at(O:117206–117426)、tt(O:117091–117185)、se(O:116417–116428)、et(O:117082)和辅助函数未改写，在受控引用状态中执行；尚未渲染Vue桌面窗口。模型桥接返回本批实际原生调用捕获的结果；保存/读取连接真实原生Api，保存后停止进程再重开。这里是分层串接试验，不是一次真实供应商桌面生成。

## 点击生成

先关闭失败弹窗、清空该章失败列表并触发章节保存，随后校验章节下标、scriptResult、分镜提示词和scenes。故缺提示词等错误用例也会有一次章节保存，但没有生成请求；不能把“没有模型调用”写成“完全没有数据变化”。

scriptResult可为对象或JSON字符串；数组按scenes处理。解析失败提示“剧本JSON解析失败，无法提取场景”；空场景“剧本中未找到场景数据”；无剧本“请先生成剧本内容”；无提示词“请先选择分镜提示词”。

通过后设置生成状态、每场进度及AI消息；读取所选提示词正文，把style替换一次，再发送11中批量参数。返回检查取消标记、success、失败列表和解析结果；有镜头则写storyboardResult，调用save_chapter_storyboard_result，再通过se保存chapters。

全部成功给成功提示；部分成功给包含剩余失败数的警告并打开失败场景处理；全失败给错误。finally恢复旧进度回调、清掉章节生成中状态和取消标记。14组原函数用例中清理均完成。

## 单场继续生成

tt先从失败记录scene或该章scriptResult定位原场景；找不到提示“未找到可继续生成的场景数据”。请求只带目标场景，同时传整章all_scenes，并强制skip_failed_scene_retry=true，避免用户手动重试再次触发整批自动补充。

有新镜头时et按_scene_index替换对应来源场景，按来源/场内顺序排序并重排显示编号。无来源标记时退回追加。已有其他场镜头必须保留；第二场索引错位缺陷见11及10，CM用稳定场景身份合并。

接口失败必须检查success并保留失败项。原tt没有先判断success，仅按failed_scenes是否非空判断；受控返回success=false且failed_scenes=[]时，仍提示“场景1-1已补回”。这一错误不能移植。

## 取消确认

原按钮O:121161–121180：先确认正在生成，再弹“确定要取消当前分镜生成吗？当前进度将会丢失。”。用户拒绝确认时不调用取消API，生成继续。确认则设V/q，显示“正在取消”，依次调用screenplay_agents_cancel和screenplay_ai_chat_cancel。

原处理函数在生成返回后检查取消标记，提示“分镜生成已取消”，不把新镜头写入章结果。真实原生章节保存重开仍为旧镜头。底层在途请求是否停止另行判断，不能仅凭界面恢复就称请求已终止。

## 保存、重开与失败

正常用例真实写入chapter_0_storyboard.json、chapters.json，后者保留该章正文、剧本和storyboardResult。新Python进程通过原load_screenplay_chapters读回storyboardResult完全相同。

原版缺陷：分镜JSON保存抛错只记console.warn，se抛错只记console.error，返回success=false也未阻止完成提示。两种受控保存失败用例均提示“生成完成”，实际新进程读取不到章节。CM必须分别显示“生成成功，保存失败”，保留内存成果供再次保存，不得自动重新付费生成。

重复操作：原at函数直接并发进入两次会发送两次生成请求，本批已记录。尚未通过真实Naive按钮DOM验证loading是否挡住用户双击，因此不宣称原按钮一定可双击；CM前后端仍应以任务标识阻止重复计费。

## 可验证规则

正常：生成后有镜头、原回复、实际章节文件，重开一致。空值/错误：提示原因且无模型调用，不清除已有有效结果。部分失败：成功场景保留，失败场景可单独重试。取消：确认/拒绝分开，确认后不追加新任务，不把晚到结果覆盖旧成果。保存失败：允许只重试保存。重试第二场：第一场内容及身份不变，第二场被替换，重开同样成立。

证据：analysis/storyboard-frontend-storage-v3.json的14组；v4.json单独第二场重试及进程重开；native-api-isolated/storyboard-matrix-v4.json对应真实原生结果；storyboard-validation.json包含38项观察校验。桥接中的生成结果采用捕获数据重放，未冒充真实供应商，UI像素和浏览器点击仍待验收。
