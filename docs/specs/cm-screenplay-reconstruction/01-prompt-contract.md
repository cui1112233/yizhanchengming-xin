# 提示词规格与缺口

## P01：目录和正文是同一条链

原版当前目录63项：剧本大师3、剧本分镜41、人设设计12、场景设计6、音色设计1。原版入口按类型加载目录，再按选中ID取得正文。

证据：恢复后`01-readable-frontend/pretty/index-DszfAkKD.js:448108`读取剧本大师；`:448126`读取剧本分镜；`:442196`的`Js`读取选中剧本正文；`:443434`的`nd`逐项读取设计正文。每份正文的数据库行ID、原始UTF8摘要、文件名在`03-prompts/catalog.json`。正文文件从第1行起可逐字查阅。

输入：提示词ID、用途、正文版本。输出：同用途的正文及其版本摘要。未知/删除ID、用途不匹配和空正文应明确报错，在任何模型请求前停止；不能偷偷换默认模板。重复打开目录不触发生成；取消选择不改变已保存项。

本次只读取既有63个提示词行，隔离调用原版`PromptEncryptor`取得正文；禁止网络、子进程和额外原数据库读取。输出保留原UTF8字节，另存LF归一化摘要，避免把Windows换行差异误认为缺词。`scripts/recover_prompt_catalog.py`和`evidence/prompt-recovery.log`可复查。这里是正文恢复，不是编译模块的Python源码恢复。

## P02：不能只把名称放进下拉框

每项至少登记：`source_id`、CM兼容ID、用途、显示名称、正文版本、输入来源、变量清单、输出协议、响应模式、解析器版本、允许的模型能力。配置中的模型来自自己的目录，不能复制原版私有渠道或把提示词标题中的视频模型名当成文本模型ID。

选择→保存→重读→最终请求必须使用同一项及同一正文版本。画风文字、额外前缀、资产库和规划必须按明确顺序拼接，原文不能悄悄变成摘要。后端产生最终正文，前端不得硬编码系统提示词。

现有代码不是“全没写”，也不是“全写了”：`backend/internal/prompt/creative.go:37`只枚举固定基础项，再加入18项设计模板。用当前Go解析器实际遍历63项后，21项能在现有`CreativePromptOptions`中找到换行归一化后相同的可选正文，数字原ID能直接解析20项。其余还要区分“正文在其他模块”“旧版不同正文”“没有可选入口”；音色127走独立服务，不能因为不在这个下拉目录就称它完全没接。逐项结果见`04-analysis/prompt-coverage.csv`，不能把21这个数字当作已验证21条供应商链路。

## P03：每类正文有自己的输出协议

例如137/138/139含`image_prompt`、`source_elements`、`voice_actor`、`emotion`、`line`等约定；307/310主要使用`video_desc`和`duration_sec`，不能统一成一种“六字段”模型。137还要求JSON外的自检报告。字段提示来自正文，完整协议需逐项校订，不能仅靠字段字符串出现次数决定解析规则。

当前`backend/internal/screenplay/storyboard_service.go:106`只接受3个提示词协议分支，其余直接“输出协议未登记”。`:528`的解析器、`backend/internal/screenplay/model.go:242`只保留现有六字段结构，无法完整承接前述其他协议。**不能先把所有名称放进UI，再用同一个解析器凑数。**

输出：原始模型回包、解析后的结构和对应解析版本均须保存；下游需要的图像词、原文元素关联、台词、音色等字段不能在转换中丢失。不同提示词的时长范围分别验证，不能把30秒规则用于15秒模板。带JSON外报告的模板不能强制使用与其要求矛盾的纯JSON模式。

失败：非法JSON/字段缺失/报告未完整时保留原回包供核对，标明具体错误；不覆盖上一次成功结果，不伪造空成功。重复重试先核对请求标识和已保存输出，取消后的晚到结果不得覆盖当前作品。

## P04：规划提示词尚未等同原版

原版规划入口传入所选分镜词ID、名称和密度，并检查`complete/rounds/plan_chars`（恢复JS`:442503`）；是否续写与原生内部如何组装仍需补原生证据。当前`backend/internal/screenplay/storyboard_planning.go:126`调用的是`prompt.ScreenplayStoryboardPlanning`加密度规则，该常量明确写着独立实现（`backend/internal/prompt/screenplay_storyboard_planning.go:3`）。

当前Go探针已实际记录：选中307时规划请求里没有307正文，仅一次通用规划请求。证据`06-cm-trace/current-request-probe.json`。这是有证据的差异，不能把“规划按钮可用”写成“原版规划提示词已接”。原版内部固定规划正文、续写结束判据尚未恢复，先列未知，禁止编造原文。
