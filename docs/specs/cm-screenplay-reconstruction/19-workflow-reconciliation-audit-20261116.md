## 一、这个功能究竟做什么

它是故事/剧本进入可制作状态的工作台。上游接收内容，下游形成可保存、编辑和复用的分集剧本、资产卡、站位、音色及分镜，之后再进入图片、声音、视频或剪辑。剧本、资产、分镜是三个不同阶段。

至少有两种内容路径，不能强制混为一条：

1. **已有剧本**：导入并检查分集/场次 → 建立资产 → 分镜。没有必要先让AI重新改写一遍。
2. **小说/故事原文**：建立章节 → 需要时逐章改成剧本 → 资产/分镜。原版同时存在按章节原文直接分镜的选项，不能假造一份“已生成剧本”解锁下一步。

证据：O:476536–476626创建及分章保存；O:439363–439444章节剧本生成；O:440594–440618明确区分original_content与script_result。原版新建弹窗还提示小说原文生成剧可前往Agent/Chat（O:478618附近），这不是所有用户必须先生成剧本的证据。

## 二、逐阶段操作、选项与输出

### 1. 新建与导入

输入：作品名称、内容、文本模型、可选剧本词、画风、比例、资产解析程度。原版新建弹窗可见TXT/DOCX剧本格式说明；CM按用户要求额外支持直接输入，这个扩展保留，但不能改变后续数据含义。

原版新建比例提供9:16、16:9；后续模型配置提供更多比例，不能把两个入口的选项数量混算。原版默认9:16、解析master。画风有预览、名称和移除操作，不是只记一个颜色或名称。

解析程度四项，O:476379–476396及478680–478690：

| 选择 | 原界面明确说明 |
|---|---|
| 大师模式-3D（master） | 人物、场景、道具，包含颜值定位、出现集数 |
| 大师模式-写实（master_real） | 同样覆盖三类资产，写实方向 |
| 差异化（more_diff） | 该档策略仅作用于人物 |
| 标准（standard） | 该档策略仅作用于人物 |

“仅作用于人物”不能解读为整套软件不能手动管理场景/道具。四档内部原生提示词与全部字段差异尚未逐份恢复，不能由标签推断已完全对齐。

输出：项目记录、原内容、章节列表及所选配置。O:476536–476626调用create_screenplay、save_screenplay_chapters；无标题识别时保留整篇为一章。原版标题识别包括中文章/回/节/篇/卷/部/集、chapter、episode，见O:476398–476400及476590以后。

边界：空名称、空内容、错误文件、重复标题、空章、重复点击、取消及导入后重开要分别测；不能只测试成功导入。

### 2. 顶部模型、画风和模型配置

模型配置分三栏：

| 栏 | 用户选什么 | 应影响什么 |
|---|---|---|
| 剧本与资产策略 | 10种比例；1K/2K/4K；通用/海外 | 后续请求的比例、尺寸、资产策略；原版默认2K |
| 图像与音色模型 | 生图、改图、音色设计服务；核心指令；资产处理词 | 各自对应的生成或处理动作 |
| 出图模板与显示 | 人设模板、场景模板、显示原文 | 角色/场景出图结构及原文显示 |

比例为9:16、16:9、1:1、3:4、4:3、2:3、3:2、21:9、4:5、5:4。配置重开应沿用。原版初始配置O:442813–442828、模板加载O:443434–443463、持久化说明O:457208。

**模型与服务使用我们自己的目录，不复制原软件不存在于本系统的渠道。** 不能以另一个模型悄悄顶替不可用的已保存选择。CM当前ComicScreenplayModelConfig.jsx:8–31已读取自己的图片/音色服务并保留不可用选择提示。

需要单独审查的差异：原版“场景出图=无”提示是“继续使用当前内置提示词”（O:443431附近），CM说明是“直接使用场景描述，不叠加模板”。内置正文尚未完整恢复，这一项不能声称行为等同。

### 3. 剧本阶段

页面组织：标题、标签、故事摘要、分集剧本；可查看/编辑、增加或导入集。概要与标签、章节原文和生成剧本不是同一份内容，分别保存与显示。

生成分支：

- 大师模式整章发送；只取所选剧本词，替换画风并加入该步骤额外前缀，再调用screenplay_master_inference。O:439368–439434。
- 普通模式存在分段规则，不是整章请求换个标签。O:439482以后有编号行与约500字符边界等不同处理；具体服务端组合仍需核查。
- 返回parsed_data/content，记录到该章scriptResult，支持save_chapter_screenplay_result。O:439434–439444。
- 取消检查在写入结果之前；原生任务取消及最终落盘原子性尚未证实。O:439431、439453–439480。

CM最新两项修复已存在：144的已观察分析前言可以被正确识别，原回包保留、正文单独编辑；角色核心指令不会再混进场景、分镜、站位。报告18及creative_chapter.go:196、226、234，screenplay_creative_image.go:107–109。这不是所有剧本模板回包都已验收。

### 4. 资产阶段

五个页签为人物、场景、道具、站位、AI音色，见O:438220–438244。

- 人物/场景/道具：分析、手动新增、编辑、选择设计词、生成或改图、选择当前使用图、普通库导入、批量处理。
- 资产补充：已有可解析剧本优先，失败或没有时回退本章原文；带已有三类资产及通用/海外策略，仅补遗漏，不覆盖已有资产。O:444520–444579。
- 站位：表达人物在场景中的前后左右、座位等关系；有分析、手动编辑和出图。站位图与人物设定图应独立保存，不能以角色三视图冒充站位。
- 音色：资产阶段的声音身份/设计信息，与最后台词配音任务分开；不能因为能试听一段音频便认定台词配音已绑定。
- 普通库：账号可复用档案与当前作品副本分开。编辑角色后保存应用，与自定义分类即时保存是两种操作。

输出：稳定资产记录、描述/提示词、参考及选用图、站位卡、音色信息。后续分镜必须引用同一份保存结果，而非重新根据名字猜一套关系。

已接入但未完整对照：普通库基本管理、目录导入、已有角色换图、参考音频试听与保存。自定义分类、整库操作、多视图和全部原版状态仍未闭合，不能再称整个普通库“没有”，也不能称全部完成。

### 5. 分镜准备

先确定来源：本章原文，或本章已经保存的剧本。再选分镜词、前缀及规划方式。分镜词与剧本词用途不能混用。

| 选项 | 实际含义/后续影响 |
|---|---|
| 分镜词 | 输出字段、镜头结构和时长要求；41项原目录，不是41项全部真实生成验收 |
| 收藏/最近/搜索 | 选择器的组织和持久偏好，不应改变提示词正文 |
| 前缀 | 独立附加要求，不能与画风或生图指令混用 |
| 新规划 | 先生成该章规划，再带入分镜 |
| 已有规划 | 明确选本章或其他章节已有规划 |
| 无规划 | 明确不带旧规划 |
| 规划密度 | 更少小节/标准/更多小节/SD2.5专项规划 |
| 上下文 | 带最近历史，原前端history_count=5；影响顺序依赖 |
| 预设补充 | 控制遗漏资产同步，不是任意补写剧情 |

证据：O:440574–440618规划分支与提交字段，O:442522不完整规划提示；CM对应StoryboardPrep及StoryboardSettings组件。

**当前CM规划是独立实现，不能称原生规划复刻。** backend/internal/prompt/screenplay_planning_reference.go:5–6明确说明这一点。原生规划正文、续写结束判断仍未知；138分镜与293剧本的分批续写也未闭合。139已有独立可选图片字段适配，不能仅看旧原始目录中的unsupported标志误报仍禁用；需检查最终解析后的目录与协议。

### 6. 场次生成、失败恢复与分镜编辑

原版前端先组织本章scenes/all_scenes，再交给screenplay_master_storyboard_inference，携带来源、规划、画风、前缀、上下文、资产同步开关及失败重试配置；返回scene_summaries与failed_scenes。O:440594–440646。

失败入口按场次子集重试；成功场次应保留，依据场次索引与局部顺序替换对应结果，不整章抹掉重写。O:440066、440075、440112。原生实际并发与重试写入细节尚未完整恢复。

CM已不是旧文档说的“整集只发一次”：当前storyboard_scenes.go:16–43会取结构化场景或拆文本场景，84以后逐场调用。**但当前仍是顺序for循环**，不能认定等于原版同等并发/自动一次失败重试。

结果应保存角色、场景、道具、图像词、视频词、台词/情绪、时长和来源字段。编辑、导入导出、出图、配音、剪辑都读取这份记录。缺图像词时不能把视频词偷偷复制为图像词；未知时长不能装作已确定。

### 7. 制作与交付

分镜结果进入选图、声音、视频和时间线，再输出资料包、兼容草稿或成片。能下载ZIP与在真实剪映成功导入是两种验收；时间线合成静态图片与模型生成视频也不是一回事。

已有测试只证明：手工主链能保存/重读并合成本地MP4；授权4次文本、2张图片测试中，原文直接分镜成功、两张图成功，并得到4秒图片测试片。没有完成AI自动解析全部资产、每个镜头图片、配音、视频和原版同条件整片对照。报告16、17、18分别记录，不能合并成“全自动成功”。本轮没有新增模型调用。

## 五、建议的修复设计（待确认，尚未实施）

三种方案：

1. **推荐：先固定原版规则和验收表，同时先修内容与请求安全，再按页补齐。** 保留已经验证的能力，避免外观接近但生成输入错误。
2. 先外观：更快看到接近截图的效果，但分集、串图和任务恢复仍可能出错，不推荐作为主线。
3. 整体重写：结构可重新整理，但会回退已有保存、权限、换图、音频与取消保护，成本及风险最大。

推荐方案分四批，分别评审和验收：

**第一批：输入和内容对应。** 先定义分章格式与预览，统一前后端，未识别明示单集；建立资产ID关系，旧文本完整名称/类型匹配，歧义不猜。验证中文/数字/井号/无井号/重复标题/空章/前言，以及相近名、同名不同类型、重命名、删除、缺图。

**第二批：请求与草稿保护。** 同次动作保持请求编号，先核对旧任务结果；状态不明不自动重付；只有明确失败才能重新提交。刷新不覆盖未保存文本；版本冲突保留草稿，提示具体下一步。验证重复点击、断网、晚到回复、取消、重开、跨作品。

**第三批：按页面补齐真实能力。** 先模型/提示词/画风最终生效，再剧本、资产和库、分镜/失败操作、交付/Agent。未恢复的原生算法列出未知和可验证的独立替代范围，不能把替代实现冒充原版。

**第四批：同状态UI及完整输出验收。** 每页对照入口、布局、图标、选择态、空态、忙碌态、失败态、取消及重开；每条生成链核对保存配置、最终请求、原回包、保存结果、后续消费和可打开的交付物。真实供应商验证必须在新明确额度内执行；当前额度已用完。

每个按钮的验收表固定为：原版入口/所在页 → 输入及选项 → 实际调用 → 写入什么 → 下一步读取什么 → 成功显示 → 空值/错误提示 → 重复/取消/晚到结果 → 关闭重开 → CM同项证据。缺任意关键列都不能标完整通过。

本文件是调查与设计草案，未获设计确认，不是实施完成报告或已批准规格。
