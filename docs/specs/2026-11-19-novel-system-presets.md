# 小说创作系统预设统一管理

用户已批准：后台展示→编辑发布→实际生成读取→历史任务冻结旧版本。

- 沿用现有后台预设的草稿、发布、回滚、停用机制及目录，不另建提示词管理页面或在前端写提示词。
- 在“系统预设词”加入“小说创作”，按长篇、审稿修订、状态记忆、仿写、短篇、创作对话/文风分区。
- 只登记确实使用的模型提示词；分流程序规则不冒充可编辑提示词，任意新增ID不会变成新功能，因此此模块只编辑固定调用项。
- 默认正文来自后端prompt/novelcreation同一份定义。启动仅补不存在的ID，不覆盖管理员草稿、已发布或停用记录。
- 新任务在创建时一次读取已发布目录，完整保存ID、版本、修订号、正文到MySQL任务快照；执行/续跑只读该快照。旧任务没有该字段，继续原有后端定义，不改变请求指纹。
- 长篇、原生分段修订及增量结算、短篇、仿写、文风/记忆维护均经过同一冻结解析；对话请求在创建请求时解析，原有请求快照保存最终正文。
- 后台停用的提示词不回落到代码默认值，调用到该步骤时明确停止；草稿未发布不生效。
- 输出结构及服务端检查保留在后端，编辑正文不会绕过结构检查。后台只对管理员展示正文。

验收：可见目录包含实际分流/增量结算词；发布A→建任务→发布B，原任务发送A、新任务发送B；未发布/停用/回滚、旧任务、管理员权限、实际MySQL快照及浏览器页面均验证。模拟模型，不消耗真实额度，不推送公网。
