# 07 文档覆盖、剩余缺口及验收

## 本轮能说明什么

当前前端的23个Novel组件已全部进入源码索引、事件/条件清单和文案清单；六个主入口、同人导入、工具页、作品/会话/文件操作已进入规格。不是按用户给出的几张截图只补一个弹窗。

不能据此说明“所有功能都已还原”：440条控件/条件记录只是静态表达式，71条是组件事件声明；动态循环生成的按钮数量会变。原生API名称、常量也不等于已经执行。当前没有可靠的“整个软件已对齐百分比”，禁止编造一个完成率。

## 每一项以后怎么登记

每完成一项，在WORKLOG追加：时间（北京时间）、编号、具体变化、来源文件/行号或原生地址、产物路径、验证命令/真实结果、剩余问题。然后更新README步骤状态。不要删除旧失败记录，也不要用“已写代码”替代“已实跑”。

产品实现验收必须再分开记录：未实现 / 有代码未测 / 离线通过 / 已登录页面通过 / 真实模型通过。当前文档不会把这些状态合并。原版缺陷需要有意修正时，另列差异理由并验证，而非偷偷改规则后说1:1。
