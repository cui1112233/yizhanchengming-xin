## 修复合同与实现步骤

1. 点击番外，打开紧凑表单；正传→书名→番外类型→方向→参考原文/文风。默认后传。取消不创建书、不发生成请求；不改变用户先前选中的作品。
2. 提交只用本系统授权模型。后台校验正传归属/可用状态、标题、类型、参考长度、文风；冻结正传配置、已有设定和已保存章节。没有资料时明确拒绝，不能凭空造正传。
3. 同一账号请求编号在事务内固定：新建番外作品、fanfiction 会话、保存来源、入队初始化。重复请求返回相同作品/任务；更换输入复用编号拒绝；失败回滚。
4. 后台初始化只做正典压缩和番外设定两步，使用可管理的后端预设词与持久模型调用记录。不调用写正文步骤。保存正典、设定和来源记录后才显示完成。
5. 后续正文自动读取已存番外资料，不能依赖浏览器重新粘贴。父书以后修改不偷偷改变已冻结任务。重试使用原快照，取消遵守现有任务控制。
6. 验证：空值、错误类型/跨账号、重复/改号、取消、正常两步模型模拟、后续写作自动带资料；测试不用付费模型。

## 诚实边界

原版同步桥调用在网页实现为可恢复的后台任务；状态展示有适配。Go foundation 的结构保留本系统可验证字段；原版全量设定文件、母本构建器的全部取材顺序及逐像素外观仍需继续核验，不能称完整1:1。不自动输出正文。
