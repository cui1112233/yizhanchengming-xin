# 批量工厂：文案获取

## 需求与交互

- 新建批量的书城菜单增加“文案获取”，支持每行输入一个书籍 ID，单批最多 50 本。
- 使用当前用户已保存的视频管理后台会话，只读查询自定义文案列表，再按每条记录的编号读取全文。
- 同一本书的多条记录分别展示，必须明确选择一份；不自动选第一份，不拼接不同版本。
- 展示书名、记录编号、非空白字数、时间、开头摘要，并能打开完整文案。
- “使用所选文案 · 加入批量”写入当前新建草稿，再沿用原有立即执行/定时生产流程。
- 真实书城 ID 与书籍 ID 保留，所选记录 ID 单独保存。已取正文跳过普通书城抓取。
- 文案全文进入视频剧本、漫画剧本、配音计划；普通原文继续遵守前 N 行范围。手动编辑后的自定义文案发布整份修改稿。
- “文案获取”直接使用选定的原文，不做敏感词替换、AI 去敏或打码。失败重试、强制获取、补正文也复用已保存的选定文案，不能悄悄换成普通书城抓取结果；正文缺失时明确要求重新选文案。普通书城的去敏规则不变。

## 接口与边界

- 本地入口：GET /api/batch-factory/v12/custom-copies/{bookId}。
- 上游列表：/tttadmin/api/zbooklist_get.php；正文：/tttadmin/api/zbooklist_view_text.php。
- 后端按登录身份读取会话，禁止指定其他用户。前端不接收后台凭据。
- 19 位书籍 ID 按字符串处理，上游 JSON 数字使用 UseNumber 解码，逐行核对书籍 ID。
- 完整分页读取，去重记录；重复页、超过上限、登录失效、空正文均明确报错。
- 输入变化、关闭组件、切换账号时隔离旧结果；加入草稿和最终创建前再次核对会话。
- 不操作上游删除、重建、克隆、插队等写接口；不调用 AI 来获取文案。
