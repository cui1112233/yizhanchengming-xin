你的任务是将给定小说内容划分为角色和内容，并输出为结构化剧本格式。


===========================================
步骤1：完整阅读文案中的小说内容
===========================================
分析小说的大致剧情，分析小说题材，提取出角色信息

===========================================
步骤2：阅读下面规则
===========================================

台词识别规则：
1. 必须完整保留原文完整的内容，不得遗漏、删减、修改、省略任何字句，保持原文顺序不变，不要私自添加内容或者移动原文语句顺序。
2. 提取角色对话内容和旁白。识别所有内容，包括带引号（""）、破折号（——）、感叹号（！）、冒号（：）等常见台词标记的文本，其余均为旁白内容。
3. 若角色在已知角色列表<possible_characters>中，则直接使用该角色名；若不在列表中，则根据上下文合理判断角色身份。
4. 相邻台词如属同一角色，可合并为一条，但单条台词长度不得超过150字。
5. 若单条台词超过150字，需按语义完整性拆分为多条，但不要更加语义私自增加或者删除原文内容，每条不超过150字，并确保原文内容不缺失，也没有新增内容。

旁白识别规则：
1. 所有非台词的叙述性内容（包括心理活动、环境描写、动作描写、场景过渡等）均标记为"旁白"。
2. 必须完整保留原文完整的内容，不得遗漏、删减、修改、省略任何字句，保持原文顺序不变，不要私自添加内容或者移动原文语句顺序。
3. 相邻的旁白内容可合并为一条，但单条长度不得超过150字。
4. 若单条台词超过150字，需按语义完整性拆分为多条，但不要更加语义私自增加或者删除原文内容，每条不超过150字，并确保原文内容不缺失，也没有新增内容。

情绪识别规则：
1. 根据上下文语境、语气及场景变化，为每条台词识别情绪。
2. 情绪必须严格从提供的情绪列表（possible_emotions）中选择。
3. "旁白"内容无需标注情绪。
4. 情绪识别不得影响或改变原文内容以及结构，仅用于标注。

特殊情况处理：
1. 多角色连续对话时，确保每条台词对应正确角色，避免角色错配。
2. 当段落中混合出现旁白与台词时，应拆分为独立记录：旁白一条、台词一条。
3. 输出结果不得出现遗漏、重复、合并错误或原文缺失的情况，不得调换原文顺序。
4. 拆分、合并及情绪标注仅为结构化目的，须保证原文内容100%完整保留，不得新增、删除、修改原文的任何内容，不得调整原文语句顺序。

===========================================
步骤3：输出提取内容
===========================================
严格按照以下格式输出

输出格式说明：
只有三种格式类型：

| 类型 | 格式写法 | 说明 |
|------|----------|------|
| 旁白 | `旁白：内容` | 叙述性内容 |
| 台词 | `角色名-台词：内容` 或 `角色名-台词：内容（情绪）` | 角色说出口的话 |
| 内心 | `角色名-内心：内容` 或 `角色名-内心：内容（情绪）` | 角色内心独白 |

格式规范：
- 旁白不标注情绪
- 台词和内心可在内容后用括号标注情绪，如：`角色名-台词：内容（愤怒）`
- 台词不加引号
- 场景转换可用空行分隔

示例：
小说原文：
<novel_content>
一名靠前的灰衣少年似乎与石台上的少年颇为熟悉，他听得大伙的窃窃私语，不由得得意一笑，压低声音道："牧哥可是被选抜出来参加过"灵路"的人，我们整个北灵境中，可就牧哥一人有名额，你们应该也知道参加"灵路"的都是些什么变态吧？当年我们这北灵境可是因为此事沸腾了好一阵的，从那里出来的人，最后基本全部都是被"五大院"给预定了的。"
</novel_content>

输出：
===== 剧本正文 =====

旁白：一名靠前的灰衣少年似乎与石台上的少年颇为熟悉，他听得大伙的窃窃私语，不由得得意一笑，压低声音道
灰衣少年-台词：牧哥可是被选拔出来参加过"灵路"的人，我们整个北灵境中，可就牧哥一人有名额，你们应该也知道参加"灵路"的都是些什么变态吧？当年我们这北灵境可是因为此事沸腾了好一阵的，从那里出来的人，最后基本全部都是被"五大院"给预定了的。（得意）

===========================================
步骤4：输出内容检查
===========================================
将生成的内容与原文逐字对照，查阅是否有串行或者文章内容顺序与原文不一致的情况


质量检验标准：
✅ 生成的内容与原文一致
✅ 输出格式正确（旁白/角色名-台词/角色名-内心）
✅ 无画面、音效、镜头等描述
✅ 台词无引号

脚本执行日志记录：
- 开始时间
- 各步骤完成状态
- 错误处理记录
- 最终输出验证
