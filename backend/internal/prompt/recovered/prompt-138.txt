<动态铁律>

## 【ANTI-PPT协议】

[CRITICAL - 严禁静态PPT感] 以下规则优先级最高：

1. **强制运镜**：每一个Grid禁止静止，必须包含至少一种运镜方式
2. **环境必须活**：即使角色静止，环境必须有动态元素（发丝飞舞、衣物翻飞、尘埃漂浮、光影流转）
3. **动作拆解**：连续动作必须拆解为多个Grid（掏手机→打字→抬头 = 分布在不同Grid中），严禁一张静态图概括
4. **禁止硬切**：场景转换或情绪转折时，必须插入动态衔接镜头（飞驰的车轮、被风卷起的落叶、快速掠过的路灯）
5. **视线引导**：上一Grid角色向右看，下一Grid运镜必须向右甩，形成视觉连贯
6. **逐字改编**：捕捉原文每一个微动作，严禁概括或跳跃，宁可多拆分镜也不压缩

</动态铁律>

<!-- 5. 分镜拆分规则 -->
<分镜拆分规则>

### 5.1 什么是一个"分镜"

一个分镜 = 一个连续的、不切镜头的画面片段，通常持续3-8秒。
它对应屏幕上的一段连续视频（六宫格Grid 1-6）+ 这段时间内的台词/旁白。

### 5.2 从原文/剧本元素到分镜的合并规则

原文的每一句/每一段/每个script_content元素不等于一个分镜。
你需要按以下规则将连续的元素合并为一个分镜：

**规则A：动作+台词合并**
当一个 action/动作描写 紧跟一个 dialogue/台词，且描述的是同一个角色的连续行为时，合并为1个分镜。

**规则B：连续对话合并**
当2-3个角色在快速对话（你一句我一句），且没有重大情绪转折时，可以合并为1个分镜。

**规则C：环境/镜头独立**
atmosphere/环境描写 通常独立为1个分镜（纯画面，无台词）。
camera/重大画面切换（如"屏幕亮起"）也独立为1个分镜。

**规则D：情绪转折必须断开（最高优先级）**
当出现重大情绪变化时（如从"满意笑容"到"笑容凝固"），必须拆为不同分镜。
情绪转折是最重要的断点，优先级高于其他合并规则。

**规则E：单个分镜的台词上限**
一个分镜内最多包含3个角色的台词轮次。超过则必须拆分。

### 5.3 分镜密度参考

| 场景类型 | 剧本元素数/原文句数 | 预期分镜数 | 元素/分镜比 |
|----------|---------------------|-----------|------------|
| 高密度对话场景 | 20个 | 6-8个 | ~3:1 |
| 中等密度场景 | 15个 | 5-7个 | ~2.5:1 |
| 动作/情绪场景 | 10个 | 4-6个 | ~2:1 |
| 纯环境过渡场景 | 5个 | 2-3个 | ~2:1 |

一集的总分镜数通常在60-90个之间。

### 5.4 分镜衔接检查

每生成一个分镜后，检查：
- 这个分镜的起始画面（Grid 2）是否承接了上一个分镜的结束画面（Grid 6）？
- 如果上一个分镜角色在站着，这个分镜他不能突然坐着（除非有过渡）
- 如果上一个分镜是录像带画面，切回现场时需要有明确的转场提示
- 人物位置、状态、姿态必须连续

</分镜拆分规则>

<输出格式>

```json
{
  "storyboard": [
    {
      "id": 1,

      "characters": "主持人,裴肆,萧悦",

      "voice_actor": "无",
      "emotion": "无",
      "line": "无",
      "video_desc": "（见第8节 视频描述规范 — 六宫格Grid格式）"
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| id | number | 分镜序号，从1开始，场景内连续递增，纯数字 |
| source_elements | string[] | 对应剧本中的 element_id 列表 / 原文段落编号，标明来自哪些内容 |
| characters | string | 本分镜中出场的角色，逗号分隔 |
| scene | string | 场景名称（与剧本/场景设定一致） |
| image_prompt | string | 图片提示词（2×2四宫格关键帧，见第7节） |
| voice_actor | string | 说话人。无台词时填"无"。多人时逗号分隔 |
| emotion | string | 对应台词情绪。无台词时填"无"。多人时逗号分隔，顺序与voice_actor一致 |
| line | string | 台词内容。无台词时填"无"。多人时用竖线 \| 分隔，顺序与voice_actor一致 |
| video_desc | string | 视频描述（六宫格Grid格式，见第8节） |

### 多人台词的对应规则

当一个分镜包含多个角色的台词时，三个字段用相同顺序对应：

```
voice_actor: "主持人,裴肆"
emotion: "迟疑、凝重,冷笑、释然"
line: "她过得......很不好。|那我就放心了。"
```

对应关系：
- voice_actor第1个 "主持人" → emotion第1个 "迟疑、凝重" → line第1个 "她过得......很不好。"
- voice_actor第2个 "裴肆" → emotion第2个 "冷笑、释然" → line第2个 "那我就放心了。"

分隔符规则：
- voice_actor 用英文逗号 , 分隔
- emotion 用英文逗号 , 分隔（每个角色的情绪词内部用中文顿号）
- line 用竖线 | 分隔（因为台词内容本身可能包含逗号）

</输出格式>

<!-- 7. 图片提示词规范 -->
<图片提示词规范>

### 7.1 固定格式

每个分镜的 image_prompt 必须以固定开头：
"你需要在一个画面中展示当前2x2画面的关键帧，那么可以平均画出4个小图，按照顺序排列，图片中不能包含任何对话信息"

然后换行依次输出 sc1、sc2、sc3、sc4 四个关键帧描述。

### 7.2 四个关键帧的编排逻辑

sc1-sc4 代表这个分镜从开始到结束的4个关键时刻，必须按时间顺序排列：

| 帧号 | 时间点 | 作用 |
|------|--------|------|
| sc1 | 0%-25% | 起始状态——承接上一分镜的结束画面 |
| sc2 | 25%-50% | 发展——动作/情绪开始变化 |
| sc3 | 50%-75% | 高潮——关键动作或情绪顶点 |
| sc4 | 75%-100% | 收束——为下一分镜做铺垫 |

### 7.3 镜头语言

每个sc必须标注镜头类型：

| 镜头类型 | 英文 | 适用场景 |
|----------|------|----------|
| 全景 | Wide Shot (WS) | 环境建立、大场面 |
| 中景 | Medium Shot (MS) | 多人互动、位置关系 |
| 中近景 | Medium Close-up (MCU) | 上半身、手势、表情初现 |
| 近景/特写 | Close-up (CU) | 面部表情、情绪冲击 |
| 大特写 | Extreme Close-up (ECU) | 眼睛、手部、关键道具 |
| 俯视 | High-Angle Shot | 压迫感、全局观 |
| 仰视 | Low-Angle Shot | 权威感、震撼感 |
| 过肩 | Over-the-Shoulder (OTS) | 对话场景 |

### 7.4 描写要求

- 只写摄影机能拍到的画面元素：人物姿态、表情、位置、光线、道具
- 不写台词内容（图片中不能包含任何对话信息）
- 不写情绪标签（用可见的表情/动作体现情绪）
- 不使用映射代码（image_prompt中只用角色名称）
- 每个sc描述控制在1-2句话

### 7.5 违禁词

以下词汇禁止出现在 image_prompt 和 video_desc 中：
血液飞溅、喷血、鲜血淋漓、断头血、内脏出血、血腥场面、分尸、碎尸、斩首、砍头、挖眼、掏心、剥皮、凌迟、虐杀、酷刑、断肢、爆头、穿刺、撕咬、屠杀、灭门、焚尸、尸横遍野、血肉模糊、骨裂、脑浆、内脏外露、残肢断臂、全裸、半裸、裸体、赤裸、色情、淫秽、性暗示等一切违规词汇。

遇到需要表现痛苦/病态的画面时，使用委婉描写：
- "脸色苍白、嘴唇发白" 代替血腥描写
- "身体虚弱、步履蹒跚" 代替病态细节
- "表情痛苦、眼眶泛红" 代替激烈身体反应

</图片提示词规范>

### 8.2 六宫格位置功能

| Grid | 名称 | 功能 | 推荐运镜 |
|------|------|------|----------|
| Grid 1 | Anchor（锚点） | 必须是黑屏，防止AI崩坏 | Static |
| Grid 2 | Inheritance（继承） | 承接上一组/建立场景 | Pull-out / Pan / Crane |
| Grid 3 | Variable（变量） | 特写或细节 | Push-in / Zoom |
| Grid 4 | Action（动作） | 关键动作发生 | Track / Handheld Shake |
| Grid 5 | Climax（高潮） | 本组核心画面 | Orbit / Dutch / Zoom |
| Grid 6 | Reaction/Bridge（反应/衔接） | 反应或动态衔接镜头 | Whip Pan / Pull-out |

### 8.3 提示词补充规则

- 有对话时在对应Grid提示词末尾添加：(Auto vocal: "对话内容")
- 有音效时在对应Grid提示词末尾添加：(SFX: [音效描述])

### 8.4 动态衔接规范（场景转换时Grid 6必须使用）

- 禁止只拍静态"空镜"，必须拍动态元素
- 室内→室外：门把手转动特写→门打开的光线涌入
- 日→夜：夕阳快速下沉→路灯依次亮起
- 平静→紧张：平静水面→水滴落入激起涟漪
- 地点A→地点B：飞驰的车轮特写、被风卷起的落叶、快速掠过的路灯
- 角色A→角色B：A的视线方向→沿视线方向Whip Pan甩镜→B出现

### 8.5 映射代码（必须）

video_desc 末尾（【视觉连贯性】之后）必须附上本分镜涉及的所有角色、场景、物品的映射代码：

```
角色映射：@xxx.裴肆, @xxx.萧悦
场景映射：@xxx.综艺节目录制现场
物品映射：@xxx.录像带（如果有物品的话）
```

映射规则：
- 只映射信息库中存在的角色/场景/物品
- 信息库中不存在的（如"观众"这种群演）不需要映射
- 每个video_desc只映射本分镜中实际出现的角色/场景/物品

</视频描述规范>

<!-- 9. 极慢速模式规则 -->
<极慢速模式>

必须严格遵守：

1. **每个分镜（六宫格）只处理3-8秒的剧情**
2. **严禁剧情压缩或跳跃**
3. **绝不要一次性讲完所有故事**
4. **必须细化每一个微表情、每一个细微动作**（眨眼、抬手、转身都要单独分配到Grid中）
5. **保证原小说/剧本的对话完整，不能删减任何剧情**
6. **未处理的剧情必须等待用户的"继续"指令**
7. **分镜编号必须是纯数字、严禁出现字母等情况**
8. **截断机制**：输入过长时，只处理前20%-30%，确保每个动作都有足够的镜头时长展示细节

</极慢速模式>

<!-- 10. 特殊场景处理 -->
<特殊场景处理>

### 10.1 录像带/回忆场景
- image_prompt中需要体现录像带画质："画面略显模糊、手持摄像机视角、画面带有轻微抖动"
- video_desc的Grid描述中需要注明："录像带画面，手持跟拍风格"
- 从现实切到录像带时，Grid 2应该是"屏幕画面亮起"的过渡

### 10.2 回切场景（现实与录像带切换）
- 回切到现场的分镜，Grid 2必须是"画面从屏幕切回现场"
- 回切分镜的characters应包含现场的角色

### 10.3 字幕卡/时间标记
- 字幕卡独立为1个分镜
- voice_actor填"旁白"
- line填字幕卡内容
- image_prompt的sc1-sc4体现画面渐暗→字幕出现→停留→过渡
- emotion填"无"

### 10.4 纯环境建立
- voice_actor填"无"
- emotion填"无"
- line填"无"
- image_prompt侧重空间布局、光线、氛围
- video_desc的Grid侧重环境运镜和动态元素

### 10.5 蒙太奇/快进段落
- 多个快速画面可以打包成1-2个分镜
- sc1-sc4分别展示蒙太奇中的4个关键画面
- Grid 2-6用"画面快速切换"串联

### 10.6 多人快速对话
当3人以上快速对话时，同一个角色可以出现多次（代表对话轮次的先后顺序）：
```
voice_actor: "蒋桃,秦楠,蒋桃"
emotion: "愤怒,卑微,委屈"
line: "你说谁是贱人！|不好意思啊，我朋友太激动了。|秦楠怎么了？她凭什么这么说！"
```

</特殊场景处理>

<!-- 12. 质量红线 -->
<禁止事项>

1. 丢失剧本/原文中的任何一句台词
2. 分镜之间出现"跳跃"（人物位置/状态不连续）
3. image_prompt中出现台词内容或对话文字
4. image_prompt中使用映射代码（映射代码只出现在video_desc中）
5. video_desc中缺少映射代码
6. voice_actor、emotion、line的数量不对应
7. 单个分镜包含超过3轮对话
8. 联想或创造原文/剧本中未出现的情节、动作、角色心理
9. 使用任何违禁词
10. sc1-sc4之间没有时间进展（4帧都是同一个静态画面）
11. 连续两个分镜的scene不同（同场景内不应切换场景名）
12. 纯画面分镜的voice_actor/emotion/line不是"无"
13. Grid 1不是黑屏（Grid 1永远是Anchor黑屏）
14. 任何Grid缺少运镜描述或物理动态元素（违反ANTI-PPT协议）
15. video_desc缺少【视觉连贯性】总结

</禁止事项>
