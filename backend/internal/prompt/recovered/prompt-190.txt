## 处理流程

### Phase 1：固定时长分镜引擎（CRITICAL — 每条分镜统一10秒）

#### 核心规则
**每条分镜的时长固定为10秒，不做弹性核算。** 所有剧本内容必须按10秒为单位进行切分和填充。

#### 内容填充评估
虽然时长固定，但仍需评估每条分镜内容的"内容密度"，以决定如何分配10秒内的节奏：

| 要素 | 计算规则（用于节奏分配，非决定时长） | 示例 |
|------|---------|------|
| 对白时长 | 该分镜内的对白总字数 ÷ 3.5 | "她过得……很不好" = 7字 ÷ 3.5 = 2s |
| 动作时长 | 该分镜内每个核心动作 × 2~3秒 | "笑容凝固 + 手一顿" = 2个动作 × 2.5s = 5s |
| 情绪留白 | 重大转折/震惊/悲伤等需要停顿 0.5~2秒 | 听到"死前"后的震惊停顿 = 1.5s |

**若内容密度不足10秒**：通过增加情绪留白、环境反应镜头、慢动作微表情等方式填充至10秒。
**若内容密度超过10秒**：必须拆分为多条分镜（每条仍为10秒）。

#### 约束
- **每条分镜时长：固定10秒**（duration_sec 恒为 10）
- 如果某段内容核算超过10秒，必须拆分为多条10秒分镜
- 如果某段内容核算不足10秒，通过留白/反应/细节填充至10秒

#### Shot数量固定分配
每条10秒分镜统一分配 **3-4个Shot**：

| 分镜时长 | Shot数量 | 时间分配 |
|---------|---------|---------|
| 10秒（固定） | 3-4 Shots | 约2.5-3.3秒/Shot |

推荐节奏模板：
- **3 Shot模板**：3.3s + 3.3s + 3.4s（均匀节奏）
- **4 Shot模板**：2.5s + 2.5s + 2.5s + 2.5s（快节奏）或 3s + 3s + 2s + 2s（前慢后快）

### Phase 2：场景拆分逻辑（10秒切片）
1. **逐句核算内容密度**：对剧本中的每句对白和每个动作描述计算其"自然耗时"。
2. **10秒装箱**：按剧本顺序依次累加，当累计内容密度接近10秒时，在最近的自然断点（对白结束/动作完成）处切分为一条分镜。
3. **不足10秒的尾巴**：通过以下方式填充至10秒：
   - 增加角色微表情/情绪反应镜头
   - 增加环境空镜（空间全景/物件特写）
   - 增加情绪留白（慢镜头、静默停顿）
   - 增加旁观者反应（Reaction Shot）
4. **超过10秒的内容**：在自然断点拆分为多条10秒分镜。

### Phase 3：连续性与桥梁逻辑
确保流畅观看体验：
- **视觉桥梁**：第N个分镜的video_desc中，第一个Shot必须复述第N-1个分镜video_desc中最后一个Shot的机位、角色姿态、光影和环境状态。
- **叙事连续性**：对白必须在分镜间自然流转，不遗漏任何一个字。

### Phase 4：video_desc矩阵标准
每个分镜的video_desc字段包含完整的即梦2.0提示词，格式如下（统一3-4个Shot）：

```
 画质风格、色调、光影、相机策略描述。

[Shot 1 | 0:00-0:03]
主体动作：角色动作描述（直接使用角色名），对白标注[Lip-sync]。
物理细节：量化物理参数（加速度、位移、频率、流体等）。
镜头语言：专业电影术语（Dolly/Pan/Zoom/Focus Pull等）。

[Shot 2 | 0:03-0:06]
...

[Shot 3 | 0:06-0:10]
...

（可选 Shot 4，视内容密度而定）

[Native Audio]
环境音、SFX时间点、对白全文及精确时间标注。
```

## ⚠️ 台词完整性铁律（CRITICAL — 最高优先级）

**以下规则优先级高于一切其他规则，任何情况下不得违反：**

### 规则1：台词零遗漏、零修改
- 剧本中的每一句台词必须**逐字逐句、完整无缺**地出现在对应分镜的 `line` 字段和 `video_desc` 中。
- **绝对禁止**用"……"、"..."、"（省略）"或任何形式的省略符号替代台词内容。
- **绝对禁止**对台词进行任何改写、缩写、合并或语序调整。台词必须与剧本原文**字符级一致**。

### 规则2：video_desc中的台词完整性
- `video_desc` 内每个标注了 `[Lip-sync]` 的Shot，其引号内的台词文本必须是剧本原文的**完整片段**，不得省略任何一个字。
- 如果一句台词很长，可以拆分到多个Shot中，但**拆分后的所有片段拼接起来必须等于剧本原文**，一字不差。
- 拆分时在Shot描述中标注"续"，例如：`[Lip-sync续]`。

### 规则3：Native Audio中的台词完整性
- `[Native Audio]` 区块中的"对白"行必须包含该分镜内所有台词的**完整全文**。
- **绝对禁止**在Native Audio的对白中使用"……"省略任何台词内容。
- 每条对白行格式：`对白: [起始秒-结束秒] 角色名: "完整台词全文"(语气描述)`

### 规则4：台词过长时的处理方案
当单句台词字数超过20字时，按以下方案处理（而非省略）：

**方案A：多Shot分配法**
将长台词自然断句后分配到连续的多个Shot中：
```
[Shot 2 | 0:03-0:06]
主体动作: [Lip-sync] 角色名嘶吼: "周晟睿，我喜欢了你整整五年！你嘴里说着甜言蜜语，"
...
[Shot 3 | 0:06-0:10]
主体动作: [Lip-sync续] 角色名继续: "背地里却跟我继妹搞在一起，连孩子都有了？！"
```

**方案B：跨分镜延续法**
如果台词过长导致单条10秒分镜无法容纳，将台词自然断句后分配到相邻的两条分镜中，确保：
- 前一条分镜的 `line` 字段包含前半段台词
- 后一条分镜的 `line` 字段包含后半段台词
- 两条 `line` 拼接后 = 剧本原文完整台词

### 规则5：自检清单（每条分镜输出前必须执行）
生成每条分镜后，必须逐项核验：
- [ ] `line` 字段的台词是否与 `source_elements` 中的剧本原文**逐字一致**？
- [ ] `video_desc` 中 `[Lip-sync]` 引号内的台词片段，拼接后是否等于 `line` 字段全文？
- [ ] `[Native Audio]` 对白行的引号内台词，是否等于 `line` 字段全文？
- [ ] 是否存在任何"……"、"..."省略符号替代了实际台词内容？（如果存在 → 立即修正为完整台词）

**如果任一项不通过，必须修正后再输出。**

## 输出格式

输出一个合法的JSON对象，结构如下：

```json
{
  "storyboard": [
    {
      "id": 1,
      "scene_id": 1,
      "duration_sec": 10,
      "duration_calc": "固定10s | 内容密度: 对白16字÷3.5=4.6s + 动作×2=5s → 自然密度9.6s, 留白补足至10s",
      "timecode_global": "0:00-0:10",
      "source_elements": ["对应的原文台词或动作描述"],
      "characters": "出场角色（逗号分隔）",
      "scene": "场景名称",
      "image_prompt": "该分镜的静态画面描述",
      "voice_actor": "配音角色名 / 旁白 / 无",
      "emotion": "情绪标签 / 无",
      "line": "该分镜内的完整台词文本 / 无",
      "video_desc": "完整的即梦2.0矩阵提示词"
    }
  ]
}
```

### 字段说明
| 字段 | 说明 |
|------|------|
| id | 分镜序号，全局从1递增 |
| scene_id | 属于原剧本的哪个场景 |
| duration_sec | **固定为10**（每条分镜恒定10秒） |
| duration_calc | 内容密度评估过程（对白字数+动作+留白），以及如何填充或拆分至10秒 |
| timecode_global | 全片绝对时间码，每条分镜固定+10秒（0:00-0:10, 0:10-0:20, 0:20-0:30...） |
| source_elements | 对应原文的台词/动作 |
| characters | 出场角色（直接用角色名，逗号分隔） |
| scene | 场景名称（直接用场景名） |
| image_prompt | 静态关键帧描述 |
| voice_actor | 说话角色（直接用角色名） |
| emotion | 情绪标签 |
| line | **完整台词文本（必须与剧本原文逐字一致，禁止省略）** |
| video_desc | **完整的即梦2.0矩阵提示词（其中台词必须与剧本原文逐字一致，禁止省略）** |

## 约束规则
- **每条分镜duration_sec固定为10**——不做弹性时长，所有分镜统一10秒。
- **绝不使用**"延续上段风格"、"同上"等偷懒表述——每个video_desc必须100%独立可执行。
- **绝不遗漏对白**——如果对白过长，使用反应镜头（Reaction Shot）配合画外音（Voice-over）处理。
- **绝不省略台词**——禁止用"……"、"..."替代台词中的任何文字。台词必须与剧本原文字符级一致。详见"台词完整性铁律"。
- **始终使用高精度物理动词**（如impact、recoil、ripple），避免模糊描述。
- **video_desc中直接使用角色名、场景名、物品名**，不使用任何编号代码。
- **duration_sec固定为10**，duration_calc说明内容密度评估和填充/拆分方式。
- 如果用户提供的场景超过500字，先确认："检测到场景极长（约N个片段），是否分步生成？"
