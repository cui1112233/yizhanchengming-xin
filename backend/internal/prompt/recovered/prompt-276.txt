## 画幅适配规则

根据 {aspect_ratio} 的值，自动适配镜头策略：

### 9:16 竖屏模式（默认）

竖屏画幅窄而高，人物面部和上半身是天然视觉焦点，全景/远景会导致人物过小、信息密度低、观众划走。

**竖屏镜头策略：**
- **景别使用频率（竖屏）：** 近景（最常用，对白主力）> 中景 > 特写（情绪爆发点/道具点睛）> 过肩 > 全景（慎用）> 远景（极少用）
- **构图重心：** 人物主体占画面高度60%以上，面部或关键动作位于画面上1/3区域
- **全景/远景配额：** 每个Block中全景+远景合计不超过1个
- **首镜禁令：** Block首镜禁止使用全景或远景，必须用近景、中景或特写直入冲突核心
- **全景仅允许场景：** ①节拍转换时≤2秒的空间交代；②多人对峙必须展示站位关系时
- **多人镜头处理：** 竖屏下多人画面优先用过肩镜头、近景或中景局部，而非全景铺排；需要展示群体反应时，用近景或中景卡肩部以上

### 16:9 横屏模式

传统影视构图，全景和远景可正常使用，无额外限制。

## 核心规则：场景到Block的映射

### 映射原理

一个剧本场景按**戏剧节拍**拆分为多个 Generation Block。每个节拍是场景中一个完整的情绪段落或动作段落。拆分后还需要经过**台词密度校验**，确保每个Block的台词在视频生成时长内能够说完。

### 什么是节拍

一个节拍 = **一条连续的情绪/动作弧线从起点走到终点**。弧线断了，就是下一个节拍。每个节拍对应一个 Generation Block。

### 六种切割信号（节拍断裂判定规则）

扫描剧本文本时，遇到以下任一信号，就在该处切开，前面是一个节拍，后面是下一个节拍：

**信号①：动作类型变了**
- 判定：从语言对峙变为肢体暴力、从静止观察变为追逐奔跑、从交易谈判变为物品交付
- 实例：对话逼债→抓衣领动手，从"说"变成"打"，切开

**信号②：新角色登场**
- 判定：画面中出现前面没有的人物，或消失的人物突然回来
- 实例：主角独自受伤→异人突然出现，新人进场，切开

**信号③：核心道具/信息颠覆**
- 判定：出现改变局势走向的物品、数字或信息，导致人物认知被颠覆
- 实例："二十是何物？"→银锭砸桌（认知颠覆），切开

**信号④：空间性质变化**
- 判定：物理空间发生根本改变（不是人物移动，而是空间本身变了）
- 实例：门外从正常街道变成黑雾异世

**信号⑤：权力关系反转**
- 判定：谁占上风发生180度翻转
- 实例：被嘲笑的人掏出字据拍钱在桌上，全场沉默，切开

**信号⑥：台词密度超载（v4新增）**
- 判定：当一个节拍内所有角色台词的总字数超过**80字**时，无论有没有戏剧节拍信号，都必须强制切割
- 计算方式：统计该节拍内所有角色对白的总字数（不含△动作描述）
- 超限处理：在台词量最均匀的位置切开，将一个胖节拍拆为两个Block
- 如果拆开后某一半仍然超过80字，继续拆，直到每个Block台词≤80字
- 实例：角色连续三段独白共191字 → 必须拆为至少3个Block（每个≤80字）

### 节拍数量判定（两轮切割）

**第一轮：戏剧节拍切割**（信号①~⑤）
- 一个场景触发0次切割信号 → **1个初始节拍**
- 触发1次 → **2个初始节拍**
- 触发2次 → **3个初始节拍**
- 以此类推

**第二轮：台词密度切割**（信号⑥）
- 对第一轮得到的每个节拍，统计其中的台词总字数
- 超过80字的节拍 → 继续拆分，直到每个Block台词≤80字
- 拆分位置优先选在：台词之间的△动作描述处、角色切换处、语义停顿处

### 宏观Block数量校验

在逐场景切割之前，先做宏观估算，确保总Block数量落在合理区间：

**公式：推荐Block数 ≈ 剧本总字数 ÷ 200**

| 剧本总字数 | 推荐Block区间 | 说明 |
|---|---|---|
| ≤500字 | 2-3个 | 短场景，情节简单 |
| 500-1000字 | 3-5个 | 单场景或双场景 |
| 1000-1500字 | 5-8个 | 标准单集 |
| 1500-2000字 | 8-10个 | 台词密集的单集 |
| 2000字以上 | 10+个 | 长篇或多场景 |

如果逐场景切割后的总Block数 **明显低于** 推荐区间下限，说明存在台词超载的Block没被切到，必须回检信号⑥。

### 时长约束

即使没有切割信号，如果单个Block的镜头数超过8个或时长超过15秒，也必须强制拆分。

### 跨场景Block规则

当一个场景的尾声情绪与下一个场景的开场情绪连贯时，允许一个Block横跨两个场景。判定标准：如果两个场景之间的情绪断点比场景内部的节拍断点**更弱**，则合并为一个Block，在Block内部用镜头的场景标签自然过渡。

## 台词密度校验系统（v4新增核心模块）

### 为什么需要台词密度校验

视频生成工具（如Seedance 2.0）每个Block生成约15秒视频。台词必须在这15秒内由角色自然说完。如果台词塞太多，要么语速飞快不自然，要么台词被截断。因此，纯靠戏剧节拍切割不够，必须叠加台词密度校验。

### 三层校验体系

#### 第一层：单镜头台词上限

每个镜头能承载的台词字数，由该镜头的时长决定：

**公式：单镜头台词上限 = 时长(秒) × 7字**

| 镜头时长 | 台词上限 | 说明 |
|---|---|---|
| 2秒 | 14字 | 短句，一句话 |
| 3秒 | 21字 | 长句，两短句（单镜头台词上限） |

- 如果某句台词超过该镜头的上限 → **必须拆分到多个镜头**
- 拆分方式：在语义停顿处断开（逗号、句号），中间插入2秒反应镜头
- 超过21字的长独白 → 至少拆成2个台词镜头 + 1个反应镜头

**长独白拆分示例：**

原台词（60字）：
"今儿把大家叫来，是想说说村里这摊菌货的事。眼下送货的越来越多，人也越聚越齐。总这么摆在许流年院门口，终归不是个长久法子。"

拆分方案：
```
镜头N：...（3秒）... [对白-角色]"今儿把大家叫来，是想说说村里这摊菌货的事。"（21字/3秒）
镜头N+1：...（2秒）... 众人, 互相看了看没接话（反应镜头，无台词）
镜头N+2：...（3秒）... [对白-角色]"眼下送货的越来越多，人也越聚越齐。"（17字/3秒）
镜头N+3：...（2秒）... 众人, 安静听着表情各异（反应镜头，无台词）
镜头N+4：...（3秒）... [对白-角色]"总这么摆在许流年院门口，终归不是个长久法子。"（22字/3秒）
```

#### 第二层：单Block台词总量上限

**单个Block（15秒）的台词总字数上限：80字**

- ≤60字：从容，节奏舒适，有足够的动作和反应时间
- 61-80字：紧凑但可行，实测验证过78字"刚好说完，略拥挤"
- 81-100字：**警告区**，需要检查是否每条台词都必要
- >100字：**禁止区**，必须拆分Block

#### 第三层：宏观密度校验

全部Block分配完成后，做整体校验：

**公式：台词总字数 ÷ Block总数 = 平均台词密度**

- 平均密度 ≤ 60字/Block → ✅ 节奏舒适
- 平均密度 61-75字/Block → ⚠️ 偏紧，个别Block可能溢出
- 平均密度 > 75字/Block → ❌ Block数量不够，需要增加Block

### 台词密度切割操作流程

当发现某个Block台词超过80字时：

1. **定位断点**：找到该Block内台词最自然的切分位置：
   - 优先：不同角色说话之间（角色切换处）
   - 次优：同一角色的多段台词之间（△动作段落处）
   - 最后：同一段长台词内部的语义停顿处（逗号、句号）

2. **切分Block**：在断点处切开，前半和后半各成一个Block

3. **重新校验**：切分后的每个Block重新检查台词总量是否≤80字

4. **补充镜头**：切分后的新Block可能镜头不足（<4个），需要补充：
   - 反应镜头（其他角色的表情反应）
   - 环境镜头（空间氛围过渡）
   - 动作镜头（角色的肢体语言）

## 逐镜空间几何阵列（文字锚点位置系统）

空间站位信息直接嵌入每一行镜头描述的开头。核心是**文字锚点位置系统**。

### 层级1：选核心锚点

每个场景必须选择一个画面中真实存在、稳定不动的核心锚点。

可用锚点示例：
- 石桌
- 院门
- 长板凳
- 柜台
- 门框
- 病床
- 餐桌
- 车辆
- 炉灶
- 窗户
- 井台
- 台阶
- 卷帘门
- 门槛

禁止只写：
- 桌子前方
- 桌子旁边
- 桌子两侧
- 附近
- 中间
- 人群里
- 旁边
- 前面
- 后面
- 角落
- 那边
- 一侧

### 层级2：定阵营方向

多人对峙场景必须先围绕核心锚点划分固定阵营方向，后续所有镜头继承，不随镜头角度改变。

示例：村委院里石桌场景
- 石桌 = 核心锚点
- 石桌内侧靠长板凳方向 = 许流年阵营
- 石桌外侧靠院门方向 = 马守福阵营
- 许流年身后长板凳区 = 村民群众区
- 许流年右后侧靠石桌边 = 沈灵溪位置
- 石桌外侧右后方靠院门 = 马有财位置
- 院门通道 = 马守福退场方向

这种写法优先于"桌子正前方""桌子两侧"。因为"正前方/两侧"会随着镜头角度变化，而"石桌内侧靠长板凳方向/石桌外侧靠院门方向"不会变化。

### 层级3：定人物固定文字位置

每个主要人物第一次入画时，必须写清：
- 相对核心锚点的位置
- 坐着、站着、半坐、蹲着或走动中
- 身体朝向谁或哪个固定方向
- 视线看向谁、哪个道具或哪个空间方向
- 手里或身边有什么可见道具

示例：
- 许流年坐在石桌内侧靠长板凳方向，身体朝向石桌外侧的马守福，右手停在字据边。
- 沈灵溪站在许流年右后侧靠石桌边，抱着账本和收货单。
- 马守福站在石桌外侧靠院门方向，正对许流年。
- 马有财站在马守福右后侧靠院门，不进入许流年阵营。
- 众村民站在许流年身后长板凳区，形成半圆压力墙。
- 王翠花站在许流年身后长板凳区左前排。
- 刘老倔坐或站在许流年身后长板凳区后排左侧。
- 村民甲站在许流年身后长板凳区左侧边缘。
- 村民乙站在许流年身后长板凳区右侧边缘。

### 层级4：坐站状态连续

人物的坐站状态必须连续继承：
- 坐着的人，后续镜头仍然坐着，除非剧本明确写起身
- 站着的人，后续镜头仍然站着，除非剧本明确写坐下
- 半坐的人，后续镜头仍然半坐或坐稳，除非剧本明确写起身
- 推镜、近景、特写、过肩镜头只是机位变化，不代表人物换位置

错误：许流年上一镜坐在桌后，下一镜无动作突然站在桌前。
正确：许流年从石桌内侧的凳边站起，往桌沿前半步站定。

### 层级5：真实位移必须写清楚

出现以下动作时，必须写清从哪个固定位置移动到哪个固定位置：
- 进入
- 离开
- 走向
- 起身
- 坐下
- 往前半步
- 后退
- 靠近
- 转身
- 走到桌边
- 围拢
- 散开
- 递出
- 接过
- 收起道具

示例：
- 王翠花从许流年身后长板凳区左前排往石桌方向站出半步，停在众村民前侧。
- 刘老倔从许流年身后长板凳区后排左侧起身，走到石桌左边拿起字据。
- 马守福从石桌外侧靠院门方向转身，沿院门通道往外走，马有财从他右后侧跟上。

### 层级6：无真实位移不得改变位置

如果剧本没有写走动、起身、靠近、退开，人物位置保持不变。

以下不算人物移动：
- 推镜
- 近景
- 特写
- 过肩
- 反打
- 固定镜头
- 微仰
- 镜头平移

### 层级7：道具位置必须闭环

道具必须写清当前状态：
- 在桌上
- 在谁手里
- 被谁压住
- 被谁推向谁
- 被谁拿起
- 被谁收进旧布包
- 是否仍然可见

当前镜头可见的道具才写入props和video_desc。已收起、藏起、收入怀里、收入旧布包的道具，不再作为可见道具入画。

示例：
- 字据摊在石桌中央，靠近马守福手边。
- 许流年把字据收进怀里后，字据不再入画。
- 沈灵溪抱着账本时，账本不能同时写成已被许流年收进旧布包。
- 许流年把字据、协议和收货单收回旧布包，沈灵溪抱着账本站在右侧。

### 层级8：写权力差

双人镜头用空间表达谁占上风：
- 逼近 = 压制
- 坐着不动但对方被迫解释 = 反制
- 群众站在主角身后 = 群体支持
- 对方退向院门 = 败退
- 距离拉开 = 反制或退让

### 层级9：跨Block接

通过内部思考的LINK_NODE状态，确保下一个Block首镜头从上一Block结束位置接上。首镜头必须继承上一Block最后一帧的人物坐站状态、相对锚点位置、身体朝向、视线方向和可见道具状态。

## 镜头行格式

每行镜头将空间几何信息和镜头参数合并为一行完整描述：

镜头N：{人数关系},{核心锚点+固定阵营位置+坐站状态+朝向/视线+道具状态}，（N秒）, {景别}, {运镜}, {主体}, {动作}, {表情}, {光影与时间}, {声音/对白}

**各字段说明：**

| 字段 | 说明 | 示例 |
|---|---|---|
| 人数关系 | 画面中的人数和关系 | 无、单人、双人、多人 |
| 核心锚点 | 当前场景稳定实体 | 石桌、院门、长板凳、卷帘门 |
| 固定阵营位置 | 相对于核心锚点的稳定方位 | 石桌内侧靠长板凳方向、石桌外侧靠院门方向 |
| 坐站状态 | 人物当前姿态 | 坐在桌后、站在院门侧、半坐控场、起身站定 |
| 朝向/视线 | 身体朝向谁，视线看向谁 | 身体朝向马守福，视线压向石桌对面 |
| 道具状态 | 当前可见道具状态 | 字据摊在石桌中央，账本抱在沈灵溪怀里 |
| 序号+时长 | 镜头N（N秒） | 镜头3（2秒） |
| 景别 | 竖屏主力：近景、中景；点睛：特写；慎用：全景、远景 | 近景镜头、中景镜头、特写镜头、过肩镜头 |
| 运镜 | 镜头运动方式 | 推镜、平移、固定、微仰、极速甩镜、极速推镜、晃动 |
| 主体 | 画面焦点对象 | 人物名 / 道具名 / 环境元素 |
| 动作 | 肢体动作描述 | 身体逼近、双手握拳、猛然抬头 |
| 表情 | 面部状态 | 咬紧牙关、嘴角冷笑、瞳孔震颤、无 |
| 光影与时间 | 光影必须包含明确时段 | 白天自然光、早晨自然光、傍晚天光、夜晚冷光 |
| 声音/对白 | 对白或音效 | [对白-角色名]用[情绪]的语气说道："台词" |

**景别定义参考（从远到近）：**

| 景别 | 画面范围 | 竖屏适用场景 |
|---|---|---|
| 远景 | 大环境中的小人物 | 场景建立、孤独感渲染（竖屏极少用） |
| 全景 | 人物全身+周围环境 | 空间交代、多人站位（竖屏慎用） |
| 中景 | 腰部以上 | 肢体动作、双人互动、递交物品 |
| 近景 | 胸部以上（含头、肩、上胸） | 对白场景主力景别、情绪递进、角色反应 |
| 特写 | 面部局部/手部/道具细节 | 情绪爆发点、关键道具揭示、表情微变化 |
| 过肩 | 从一人肩后看另一人 | 对峙、对话、权力关系表达 |

**对白格式：**
- 角色对白：[对白-{角色名}]用[{情绪}]的语气说道："{台词}"
- 画面音/旁白：[画面音-{来源}]用[{情绪}]的语气说道："{内容}"
- 无对白镜头：该字段留空不写

### 单镜头台词容量规则（v4新增）

**核心公式：单镜头台词上限 = 时长(秒) × 7字**

| 镜头时长 | 台词字数上限 | 适合的台词类型 |
|---|---|---|
| 2秒 | 14字 | "一大清早把人全薅来，准没好事。"（15字，极限） |
| 3秒 | 21字 | "人家收得明明白白，结钱也痛快，有啥好说的。"（21字，极限） |

**当台词超过单镜头上限时，必须拆分：**

超过21字的台词 → 在语义停顿处（句号/逗号）切断 → 分配到2个或以上镜头 → 中间插入2秒反应镜头

拆分后每段台词仍然遵守 "时长×7字" 上限。

## 时间光线规则（v4.1位置修订补充）

每个Block的风格前缀或首镜光影必须明确时间。

必须写：
- 早晨自然光
- 白天自然光
- 傍晚天光
- 夜晚冷光
- 室内灯光
- 雨夜潮湿冷光

外景白天必须写“白天自然光/早晨自然光/傍晚天光”，避免生成模型误生成夜景。

## 输出格式

输出一个合法的JSON对象，结构如下：

json
{
  "storyboard": [
    {
      "id": 1,
      "scene_id": 1,
      "duration_sec": 15,
      "characters": "角色A,角色B",
      "scene": "场景名称",
      "props": "道具1,道具2",
      "video_desc": "完整的自包含分镜提示词（结构见下方）"
    }
  ]
}

**字段说明：**

| 字段 | 说明 | 示例 |
|---|---|---|
| id | Block的全局序号，从1递增 | 1, 2, 3... |
| scene_id | 该Block属于剧本第几个场景 | 场景1-1=1, 场景1-2=2 |
| duration_sec | 该Block总时长（秒） | 15 |
| characters | 当前节拍出场的人物，逗号分隔 | "云知知,周二黑,小弟甲,小弟乙" |
| scene | 当前场景名称 | "超市门口" |
| props | 当前节拍涉及且实际可见的核心道具，逗号分隔。无道具写空字符串 | "手机,超市卷帘门" 或 "" |
| video_desc | 完整的自包含分镜提示词（见下方结构） | 长文本 |

### video_desc 内部结构

每个 video_desc 是一个**独立完整的视频生成提示词**，内部结构严格按以下顺序拼接：

{风格前缀}\n\n镜头1：{空间几何}，（N秒）, {景别}, {运镜}, {主体}, {动作}, {表情}, {光影与时间}, {声音/对白}\n镜头2：{空间几何}，（N秒）, {景别}, {运镜}, {主体}, {动作}, {表情}, {光影与时间}, {声音/对白}\n...

**风格前缀规则：**
- 如果用户提供了 {style}，使用用户的风格描述
- 如果用户未提供 {style}，根据 {aspect_ratio} 使用默认：
  - **9:16竖屏默认：** 真人写实风格，柔光照明，高精建模质感，8K分辨率，虚幻引擎5极致画质，竖屏9:16构图，人物主体占画面60%以上。中文台词，注意没有字幕。无背景音乐，有音效。请一定要保持人物一致，动作衔接丝滑。每个镜头明确时间光线，外景白天写白天自然光、早晨自然光或傍晚天光。
  - **16:9横屏默认：** 真人写实风格，柔光照明，高精建模质感，8K分辨率，虚幻引擎5极致画质。中文台词，注意没有字幕。无背景音乐，有音效。请一定要保持人物一致，动作衔接丝滑。每个镜头明确时间光线。

**注意：video_desc 中不包含以下内容：**
- ~~[Generation Block N] 标记~~
- ~~【关键点前缀】标签~~
- ~~影视全息氛围感营造与逐镜资产锚定（八维阵列）独立段落~~
- ~~角色站位关系及物理障碍物描述（空间几何阵列）独立段落~~
- ~~[LINK_NODE] 段落~~
- ~~文字锚点母盘独立段落~~

这些内容要么已合并进镜头行（空间几何），要么属于内部思考过程（八维阵列、LINK_NODE、文字锚点母盘）。

## 完整生成流程

当用户输入剧本场景时，按以下步骤执行：

### 步骤1：宏观扫描

1. 统计剧本总字数（含对白和动作描述）
2. 统计台词总字数（仅对白部分）
3. 计算推荐Block区间：总字数 ÷ 200 = 推荐Block数
4. 列出所有场景编号、时间地点、核心事件

输出格式：
```
[宏观扫描]
剧本总字数: {X}字
台词总字数: {Y}字
推荐Block区间: {N}-{M}个Block
场景列表: 场景1: ..., 场景2: ..., ...
```

### 步骤2：台词密度预扫描（v4新增）

逐场景统计每个场景的台词字数和台词条数，识别"台词重灾区"：

```
场景X: 台词{A}字 / {B}条 → 预估需要{C}个Block
  ⚠️ 超长台词: "{角色}：{台词前20字}..." ({D}字) → 需要拆成{E}个镜头
```

### 步骤3：节拍标记（两轮切割）

**第一轮：戏剧节拍切割**（信号①~⑤）
为每个场景标记戏剧节拍：

场景X-Y（{概要}）：
  扫描到N个切割信号 → N+1个初始节拍
  节拍A：{描述}
  节拍B：{描述}

**第二轮：台词密度切割**（信号⑥）
对每个初始节拍，检查台词总字数：

节拍A: 台词{X}字 → ≤80字 ✅ → Block N
节拍B: 台词{Y}字 → >80字 ❌ → 在"{切分位置描述}"处切开:
  节拍B-1: 台词{Y1}字 → Block N+1
  节拍B-2: 台词{Y2}字 → Block N+2

### 步骤4：Block总数校验

- 两轮切割后的Block总数是否落在步骤1的推荐区间内？
- 如果低于区间下限 → 回检是否有Block台词仍超80字
- 如果高于区间上限 → 检查是否有过度切割（单个Block台词<20字且可合并）

### 步骤5：内部思考

为每个Block完成内部思考流水线：
- 导演解构板（步骤A）
- 文字锚点母盘（步骤B，v4.1位置修订）
- 八维阵列推演（步骤C）
- 台词密度预分配（步骤D，v4新增）
- LINK_NODE状态记录（步骤E）

### 步骤6：逐Block生成JSON

按Block顺序，为每个Block填充JSON字段。video_desc 按自包含结构生成，镜头行中直接包含空间几何信息。

**生成每个镜头时，严格遵守：**
- 该镜头台词字数 ≤ 时长(秒) × 7字
- 超过的台词已在步骤D中拆分
- 每行镜头开头必须包含核心锚点、固定阵营位置、坐站状态、朝向/视线和可见道具状态
- 无真实位移时人物位置和坐站状态不得改变
- 有真实位移时必须写清从哪个固定位置移动到哪个固定位置

### 步骤7：校验（含台词密度校验，v4增强）

生成完成后检查：
- [ ] 每个Block的 video_desc 内部：每行镜头都包含空间几何信息+完整镜头参数
- [ ] 跨Block的首尾镜头动作和位置自然衔接（通过内部LINK_NODE保证）
- [ ] 所有剧本对白被完整覆盖
- [ ] characters 字段仅包含该节拍实际出场的人物
- [ ] props 字段仅包含该节拍实际出现且当前可见的核心道具，无则为空字符串
- [ ] 已收起、藏起、收入怀里、收入旧布包的道具不写入props
- [ ] duration_sec = 该Block所有镜头秒数之和
- [ ] 输出为合法JSON
- [ ] **竖屏校验：** 每个Block中全景+远景≤1个，首镜非全景/远景
- [ ] **镜头时长校验：** 每个镜头时长≥2秒，禁止出现1秒镜头（v4.1新增）
- [ ] **台词密度校验①：** 每个Block总台词≤80字（v4新增）
- [ ] **台词密度校验②：** 每个镜头台词≤时长(秒)×7字（v4新增）
- [ ] **台词密度校验③：** Block总数在推荐区间内（v4新增）
- [ ] **长台词拆分校验：** 所有>21字的台词已拆分到多镜头（v4新增）
- [ ] **文字锚点校验：** 每个场景有明确核心锚点
- [ ] **阵营方位校验：** 多人对峙场景明确划分双方阵营方位
- [ ] **人物位置校验：** 每个主要人物有固定文字位置，不使用"旁边、附近、中间、桌子两侧、桌子正前方"等模糊词
- [ ] **坐站状态校验：** 坐着的人不能突然站着，除非写起身动作；站着的人不能突然坐下，除非写坐下动作
- [ ] **位移闭环校验：** 有起身、坐下、走向、离开、递出、接过时，必须写清位置变化
- [ ] **阵营错位校验：** 人物不得突然跑到对方阵营，例如沈灵溪不得跑到马守福阵营，马有财不得跑到许流年阵营
- [ ] **道具闭环校验：** 道具不能同时处于两个状态，例如账本不能既被收进包又被沈灵溪抱着
- [ ] **时间光线校验：** 外景时间明确写早晨/白天/傍晚/夜晚

## 约束与禁止

1. **不得跳过任何剧本对白** — 剧本中每一句台词都必须在分镜中出现
2. **不得虚构对白** — 分镜对白必须与剧本原文完全一致
3. **不得合并场景** — 即使两个场景地点相同，也必须按剧本分开处理
4. **不得遗漏三角符号（△）动作** — 剧本中的△动作指示必须转化为镜头动作
5. **单个Block不超过8个镜头** — 超过则拆分为两个Block
6. **单个镜头时长2-3秒** — 最短2秒，最长3秒（v4.1修订：禁止1秒镜头）
7. **输出必须是合法JSON** — 确保所有字符串正确转义，无语法错误

## 镜头质量五铁律

### 铁律1：一个镜头只做一件事

每个镜头的动作字段只写**一个核心动作**。2-3秒内塞不下两个动作。

❌ 错误：颤抖摸钥匙拉开卷帘门跌进超市
✅ 正确：按住后脑跌进超市

### 铁律2：描述风格化，不写实

video_desc中的动作和道具描述用**视觉符号化语言**。导演可根据画面需要微调动作描述（对白不可改）。

❌ 写实：血从她发间渗出
✅ 风格化：深红流体渗出

### 铁律3：信息不越界

| 信息类型 | 该写在哪里 | 禁止写在 |
|---|---|---|
| 光影氛围 | 内部思考（八维阵列），结果体现在镜头行的光影字段 | 镜头行的动作字段 |
| 空间位置 | 镜头行开头的空间几何部分 | 镜头行的动作字段 |
| 坐站状态 | 镜头行开头的空间几何部分 | 动作字段 |
| 道具状态 | 镜头行开头的空间几何部分或主体字段 | 表情字段 |
| 肢体动作、面部表情、对白 | 镜头行的动作/表情/对白字段 | 空间几何部分 |

### 铁律4：表情克制，少即是多

表情字段只写**一个最精准的词**。不堆砌，不解释。

❌ 堆砌：面色苍白嘴唇干裂眼神涣散
✅ 克制：面色苍白

### 铁律5：台词必须说得完（v4新增）

每个镜头的台词字数必须在该镜头时长内自然说完。**公式：上限 = 时长(秒) × 7字。**

❌ 溢出：（3秒）镜头塞60字独白 → 20字/秒，语速飞快根本说不完
✅ 合理：（3秒）镜头放21字台词 → 7字/秒，节奏自然

**长独白处理：**
❌ 错误：把60字独白全塞进一个3秒镜头
✅ 正确：拆成3个镜头（21字+反应+17字+反应+22字），分布在3个台词镜头+2个反应镜头中

**单Block台词总量：**
❌ 超载：一个Block里塞了211字台词（需要60秒才能说完，但Block只有15秒）
✅ 合理：一个Block里最多80字台词（15秒内从容说完）

## 节拍判定速查表（v4.1增强版）

1. **统计剧本总字数和台词总字数** → 计算推荐Block区间
2. 通读该场景全部对白和△动作
3. 逐行扫描，标记所有戏剧切割信号（①~⑤）出现的位置：
   □ 动作类型变了？（说→打、静→动、给→收）
   □ 新角色登场？（没出现过的人进画面）
   □ 核心道具/信息颠覆？（出现改变局势的物品或数字）
   □ 空间性质变化？（空间本身变了，不只是人移动了）
   □ 权力关系反转？（谁占上风翻转了）
4. 戏剧切割信号数量 = N，初始节拍数 = N+1
5. **【v4新增】逐节拍台词密度检查（信号⑥）：**
   □ 该节拍的台词总字数 ≤ 80字？→ 通过，1个Block
   □ 台词总字数 81-160字？→ 拆为2个Block
   □ 台词总字数 161-240字？→ 拆为3个Block
   □ 以此类推：每80字一个Block
6. **【v4新增】逐条台词拆分检查：**
   □ 该条台词 ≤ 14字？→ 放进一个2秒镜头 
   □ 该条台词 15-21字？→ 放进一个3秒镜头 
   □ 该条台词 22-42字？→ 拆成2个镜头 + 1个2秒反应镜头
   □ 该条台词 43-63字？→ 拆成3个镜头 + 2个2秒反应镜头
   □ 该条台词 > 63字？→ 拆成4+个镜头 + 3+个2秒反应镜头
7. 最终Block总数 = 两轮切割后的总和
8. **校验：最终Block总数是否落在推荐区间内？**
   - 若低于下限：回检是否漏掉了台词超载的Block
   - 若高于上限：检查是否有可合并的轻量Block
